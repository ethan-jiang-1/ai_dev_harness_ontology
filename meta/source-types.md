# 素材类型与证据天花板

`source_type` 表示**素材是什么**；`provenance` 表示**读到什么程度**。两者正交，不能用一个 `status` 代替。

| source_type | 例子 | 能支撑的最高等级 | 备注 |
|---|---|---|---|
| `paper` | 顶会/期刊论文 | `已核` | 读摘要或正文 |
| `preprint` | arXiv / SSRN | `已核` | 注意版本；优先最新版 |
| `standard` | 法规、标准、W3C 规范 | `已核`（规范要求） | 条款可直接引 |
| `open-source` | 可读代码的真实项目 | `已核`（commit + 文件/符号定位） | `已证` 需 `EXP-xxx` 在仓库外复现；README/star 不支撑结论 |
| `blog` | 工程博客、公众号 | `已核`仅限「作者报告了 X」 | 一般性结论默认 `推测` |
| `engineering` | 内部复盘、事故报告 | 同上 | 一手观察，但不可复现 |
| `talk` | 演讲、幻灯片 | `推测` | 除非有完整文字稿 |
| `survey` | 综述、二手介绍 | `推测` / 转述 | 只作索引，不当论文结论 |

## 三条规则

1. **博客不是论文。** 它可以提供一手工程观察、失败复盘、部署数字，但不能因为「作者是专家」就升到 `已核` 的一般性结论。
2. **博客/工程素材先入 `src/web/`。** 只有改变某条 `E/Q/C` 或填一个开放问题时，才进 `topics/`；否则留在 `frontier.md` 候选队列。
3. **写清 scope。** 博客卡必须写「这是作者在什么场景下的观察」，不能只写结论。
4. **代码是一手原文，README 不是。** 能指到 `文件:符号` 才算 `已核`；README/文档承诺只能支撑「作者声称 X」，默认 `推测`。
5. **跑通 ≠ 有效。** 跑通官方示例只证明代码能执行，不证明机制有效；要升 `已证`，需 `EXP-xxx` 在本仓库外复现，并写清对照。

## 与证据等级的关系

- `paper` / `preprint` / `standard`：可按 [conventions](./conventions.md#证据等级) 升到 `已核`。
- `open-source`：代码定位（`文件:符号`）可到 `已核`；`已证` 需 `EXP-xxx` 复现。README/star/单测覆盖率不能升等级。
- `blog` / `engineering`：卡片可以 `已核`，但指的是「作者报告了 X」；把 X 推广为一般规律时，标 `推测`。
- `talk` / `survey`：默认 `推测`；引用时写「转述自」并标 `待核`。
