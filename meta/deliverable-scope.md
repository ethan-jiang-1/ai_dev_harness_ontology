# 交付物定位（scope）：每份是什么、答什么、边界与红线

> **本页是每份交付物定位的唯一权威**（[ADR 0014](../adr/0014-deliverable-scope-single-home.md)）。初心 / 定性 / in-scope / out-of-scope / 红线只在这里定义。各份 README 的「回答什么 / 不回答什么」是面向读者的钩子，必须与本页一致；冲突时以本页为准。AGENTS 路由与 [loading](./loading.md) 加载集指向本页。**改 / 建任何交付物前，先读它那一节。**

## 为什么有这页（04 的教训）

04 名为 *ontology-in-production*，却长成了一个「不证明生产」的合成教程。根因：从没定义它「是什么 / 答什么 / 哪些在 scope / 哪些是红线」，模型拿不到真实生产证据时，就擅自用一个更容易的问题（**怎么建**）偷换了原问题（**业界落地现状**）。**定位不钉死，跑着跑着就偏。** 本页把每份的初心钉死。

## 三条总规矩

1. **先读 scope 再动手**：改 / 建交付物前读它这一节；写下的每句话都要落在它「回答的问题」里。
2. **答不了就标 gap，不偷换问题**：admitted 证据答不了初心问题时，显式标 gap，并在对应 `frontier` 写「关闭它需要什么」。**禁止改答一个更容易的问题**（合成教程、理想化做法）来冒充回答了原问题。
3. **定性不混**：描述（是什么）与规定（怎么做）分开；实证（真实证据）与合成（编的例子）分开。一份交付物只承担一种定性，越界即漂移。

## 五份定性一览

| 份 | 定性 | 回答的问题 | 读者拿到 |
|---|---|---|---|
| [01 现状](#scope-01) | 判断（描述·证据分级） | 值不值得做？今天能做到哪一步？ | A/B/C/D 判定 + go/no-go |
| [02 工程](#scope-02) | 做法（规定） | 具体怎么做？接口/步骤/验收长什么样？ | 可照做的 recipe |
| [03 机制](#scope-03) | 机制（描述·参考） | 凭什么这么说？边界在哪？ | 位置/形态分类 + 证据边界 |
| [04 示例](#scope-04) | 示例（规定·合成） | 一条最小建用治链长什么样？ | 合成 fixture 走查（**非生产现状**） |
| [05 现状](#scope-05) | 现状（描述·实证） | 业界真实落地如何？靠谱与否有无证据？ | 生产实证 + 成本收益 + 证据 |

> **04 与 05 的分界是本页要点**：04 是「你可以怎么建」的**合成示例**；05 是「业界实际怎么样」的**实证现状**。04 不证明生产；05 必须用真实生产证据，缺证据就标 gap，不许拿合成例子冒充现状。

<a id="scope-01"></a>
## 01 · capability-status（现状判断）

- **初心**：让决策者判断「本体 + harness 值不值得投、今天能做到哪」，不被夸大或已撤回的证据误导。
- **定性**：判断（描述性，证据分级 A/B/C/D/gap）。
- **回答的问题**：今天能做成什么、不能承诺什么？
- **读者拿到**：每项能力的 A/B/C/D 判定 + 证据边界 + go/no-go 依据。
- **in-scope**：能力判定、证据分级、判定口径、X 期待 verdict、边界 / 反例。
- **out-of-scope**：具体怎么做（02）、机制为什么（03）、建用治示例（04）、业界落地现状（05）。
- **红线**：不把撤回源当活证据；不把「已核」升「已证」；不替 02 给步骤、不替 05 报现状。

<a id="scope-02"></a>
## 02 · engineering-playbook（工程做法）

- **初心**：让工程负责人照着把本体接进 harness，知道接口 / 步骤 / 验收 / 停线。
- **定性**：做法（规定性 recipe）。
- **回答的问题**：拿本体做某件事，具体怎么做？
- **读者拿到**：R0–R12 可照做的配方（数据契约 / 步骤 / 验收 / stop / 成本）。
- **in-scope**：配方、接口、数据契约、验收 / 停线、成本量级、账本 / 评测 / 上线。
- **out-of-scope**：值不值得（01）、为什么是这些位置（03）、业界落地现状（05）。
- **红线**：recipe 不是 E、不证明「做了有效」；效应量回 E-xx；gap 配方不冒充可上线。

<a id="scope-03"></a>
## 03 · mechanism-reference（机制参考）

- **初心**：让架构师 / 研究者理解「凭什么这么说」，知道分类与证据边界，不越界解读。
- **定性**：机制（描述性参考）。
- **回答的问题**：为什么是这些位置 / 形态？证据边界在哪？
- **读者拿到**：六位置 / 形态轴分类 + claim 走查 + 证据边界 / 反例。
- **in-scope**：位置 / 形态分类、覆盖率矩阵、claim 走查、边界 / 可证伪、证据台账。
- **out-of-scope**：怎么做（02）、值不值得（01）、建用治示例（04）、业界落地现状（05）。
- **红线**：给分类与边界，不给效应量；不新增 E/L；撤回源只留机制、不留效应量。

<a id="scope-04"></a>
## 04 · ontology-in-production（合成示例）

- **初心**：给要建小型本体查询应用的团队，一条可走查的最小建用治链。
- **定性**：示例（规定性·**合成**）。**不是生产现状。**
- **回答的问题**：如果要建一个小型本体查询应用，一条最小建用治链要哪些产物 / 字段 / 门槛？
- **读者拿到**：合成 fixture 的契约 → TBox → shapes → CQ → policy → audit 走查 + 三关记录。
- **in-scope**：合成示例的建 / 用 / 治链、产物模板、三关记录、fixture 边界。
- **out-of-scope**：**业界真实落地现状 / 生产证据（归 05）**；值不值得（01）；接缝选择（02）；机制（03）。
- **红线**：不声称代表生产现实 / 业界现状；fixture 数字是期望值、非实测；不证明效果 / 跨域 / 生产。
- **备注**：内容维持现状（用户决定不动）。本定位把它如实定性为**合成示例**；「落地现状」之问移交 05。

<a id="scope-05"></a>
## 05 · production-landscape（落地现状·实证）

- **初心**：回答用户真正的问题——本体在业界真实落地到什么程度？有没有可靠证据说它靠谱 / 不靠谱？
- **定性**：现状（描述性·**实证**）。
- **回答的问题**：现在业界谁在上本体、上到什么规模、成本收益如何、靠谱与否有无可靠证据？
- **读者拿到**：真实生产 / 业界落地的实证图景——重型 → 轻型谱系、实测成本收益、成败案例、证据分级。
- **in-scope**：真实生产部署 / 业界采用证据、成本收益实测、采用谱系（Palantir 式重型 → LLM 辅助薄语义轻型）、靠谱与否的证据。
- **out-of-scope**：合成怎么建（04）、配方（02）、机制理论（03）、能力判定（01）。
- **红线**：**必须用真实生产 / 业界证据**（admitted，含 CHARTER §4.4「公司生产报告」窄例外）；**禁止用合成示例 / 理想化做法冒充现状**；缺证据就标 gap + frontier，不编故事。
- **现状**：证据基座缺口——当前 admitted 源里无真实生产案例。**先补原料（过准入门）再写，不许先编。**

## 维护

- 新增 / 重定位一份交付物：先改本页，再改其 README 钩子与 [loading](./loading.md) 加载集；走 [ADR](../adr/README.md) 判据。
- 发现交付物内容与本页定性不符：按[修复回路](../AGENTS.md)处理——要么改内容回 scope，要么走 ADR 重定位；**不允许内容偷偷越界**。
- 本页只管定位，不管计数（[state](./state.md)）、不管质量打分（[rubric](./deliverable-quality.md)）、不管字段（[conventions](./conventions.md)）。
