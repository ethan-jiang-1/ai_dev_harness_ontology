# 写作约定

> **字段、枚举、证据阶梯、阅读深度与编号前缀以 [schema](../schema.md) 为唯一权威**；本页只管写作口径、干货门槛、引用与台账纪律，不重复定义枚举。两者冲突时以 `schema.md` 优先。

## 证据等级

四档定义、最低要求与默认规则见 [schema §3.1](../schema.md#31-证据等级四档)：**升不上去就不许写；没标等级的论断，一律按 `推测` 处理。**

## 干货：一条知识成不成（入仓闸）

> **这一节管“能不能写成判断”。** 适用 `claims.md`（L）、`conclusions.md`（E）、交付物正文；`digest.md` 记录原文主张不受此限，但必须写清“不能说明什么”。

### 立场：这是新工程，不是老概念

本体是**老概念**，历史上大规模实施过、也被证明极贵。但**「本体 + LLM 落地」是一门新的工程实践**——Palantir 那套历史上不是用 LLM 做的；它现在冒出来，是因为 LLM 能力上来了、成本结构变了，这条路才**变得可行**。

所以本仓库要找的干货，主体是**工程实践里独特的东西**：谁真的做成了、用的什么招、绕过了哪个坎、为什么以前不行现在行。**不是数字，也不是“应该怎么做”的规范性套话。**

### 三条本质（缺一条就不是干货）

1. **有人真做成了**：不是“建议这么做”，而是“我们这么做了，它 work（在写明条件下）”。
2. **做法可被另一个团队照着重做**：有具体决定、参数、约束、以及绕过的坑。
3. **回答这道题特有的坎**：语义接地、规模、维护成本、评测口径、跨轮漂移——「本体+LLM 落地」特有的难点，不是泛泛的软件工程。

### 五问（过不了就不许进 L/E）

| # | 问 | 不过的样子 |
|---|---|---|
| 1 | **它解决哪个具体的坎？** | 说不出坎，只能说“这很重要” |
| 2 | **为什么以前不行、现在行？**（能力/成本/工具拐点） | 说不清拐点，只是复述别人结论 |
| 3 | **哪个非显然的设计决定？**（例：不建塔先做命名/单位；投影固定分节；读路径只删 subject） | 只有流程步骤，没有取舍理由 |
| 4 | **换个团队会不会踩同一个坑？坑是什么、怎么绕？** | 说不出失败形态 |
| 5 | **等级对档**：结论强度 ≤ 证据档；**撤回项不得给 L 供等级**；承重句能在引用页逐字找到 | `推测` 放进“已核”节；拿 withdrawn 的 E 当证据 |

### 数字的地位：锚点，不是判据

- 数字用来**定位“做成了没有”**（+54.6pp 说明那一层真起作用），**它本身不构成干货**。
- **禁止用数字密度/数量评价干货**；没有数也可以很硬（“fail-open、只删 subject”）。
- 反过来：一个数字如果没有配套的“怎么做到的”，它只是别人的结论，不是我们的干货。

### E 只做索引：一句做法 + 指向 mechanism（路线 B）

**E 表保持窄**（`结论 / 出处 / 影响 / 状态`），不塞分步程序。但每条 E 必须做到两件事：

1. **一句「做法」**：要用起来得先做什么 / 默认值 / 最容易踩的坑。写不出一句，说明还没吃透。
2. **指向详细程序的链接**：分步、参数表、stop、回滚、第一个 sprint 一律住在 `topics/<派>/<子主题>/mechanism.md`，E 行给出链接。

**为什么不让 E 自包含**：E 越宽，越容易“什么都想塞、什么都塞不全”；实测质量最高的做法内容都长在 mechanism/§6 的形状里。

**消费端规则（交付物）**：引用 E 时，若这段内容涉及“怎么做”，**必须同时给 mechanism 链接**（放「出处/可选」即可，主路径仍自包含）。只引 E 不给做法链接 = 交付物缺一块。

- 例（合规）：E-23 =「10 条用例里 1/4 正常、只看第 1 条会得出相反结论；alias leak 是唯一新发现」+ 链 [read-path](../../topics/01-constraint/commit-gate/read-path.md)（fail-closed 最小策略、alias 前置三层都在那）。
- 例（不合规）：E 行里贴 12 步标定流程——这属于 mechanism。

### 只收「能长期保障质量」的做法（不是一次性技巧）

**判据不是“这招当时有效”，而是“这招让质量长期不掉”。** 一次性技巧（靠某个模型版本、某次调参、某个人的手感）记作候选/轶事，不升 E。

| 测试 | 问什么 | 不过的样子 |
|---|---|---|
| **可重复** | 换个人照着做，还能得到同样结论吗？ | 依赖“有经验的人看一眼”——那不是做法，是手艺 |
| **自带检测** | 出问题时它自己会报警吗？还是有闸门/三态/负控制？ | 只能靠人盯着；错了也看不出来 |
| **抗腐化** | 模型升级、人换手、半年后，它还成立吗？失效条件写清了吗？ | 绑死某个模型/某个数据快照，且没写什么时候该重测 |

- **正例（本仓库已有的，属于这一类）**：`targeted=0` 不是 pass；SHACL 三态（通过/违反/**未检查完**）不折叠成 exit code；读路径 fail-closed 是显式设计选择；rubric 预登记不混报；幂等键 `(head_id, target_id, source_id, period)`。
- **反例（不算）**：“我们调到了 0.777”、“某次 prompt 改法效果很好”。
- **推论**：本仓库的“防守型干货”（验收/闸门/假阳性/负控制）本身就是这一类，要继续加强；“进攻型”做法也要按这三条收。

### 直接拒收的四种形态

- **状态/待办伪装成判断**：「X 未定」「（设计提案，未验证）」→ 去 `frontier`，标（缺口）。
- **框架命名冒充发现**：「可拆成五角色七变量」——除非给出分布、预测力或落地参数。
- **关系陈述冒充判断**：「A 与 B 不矛盾」。
- **恒真的否定句**：「没有一条适用于所有机制的能力曲线」——任何反例都只是“又一条”。
- 另：**自我加冕**（“最有价值的一条”）而给不出判定实验 → 改写成待检验假说。

### 对 digest 的要求：工程用法是主角

- 每篇 digest 的 **§6「工程用法」是主角**：具体决定、参数、绕过的坑、维护方式、失败形态。
- §4「数字与条件」是**支撑**，不是主角；只有数字没有工程做法的 digest = 没消化到位。
- 判据一句话：**读完 digest，另一个团队能不能据此复现“这条路走得通”？**

### 收窄优先于删除

过不了的判断不要直接删——**收窄到可检验的那一半**，或降为「背景/缺口」并注明为何不算判断。删除只在整条都已失效（如唯一锚撤回）时做。

## 引用

| 情况 | 写法 |
|---|---|
| 一手 | 链接到 `src/` 下的原文件，或 arXiv 编号 |
| 二手转述 | 写「转述自 X」，并加 `待核` |
| 未读原文 | 不许写成事实；写成「某文报告」 |

**综述的一句摘要不是论文结论。** 本仓库已经因此踩过一次坑：三篇论文的转述丢了限定条件，见 [综述卡](../audits/2026-11-11-source-purge.md#src-web-weixin-laoliu)。

## 字段使用口径（枚举定义见 [schema](../schema.md)）

**字段词汇冻结（[ADR 0012](../../adr/0012-instruction-layer-single-home.md)）**：本页只说明口径，完整合法值见 [schema.md](../schema.md)。

- **源位阶与术语（[ADR 0011](../../adr/0011-source-standing-and-term-baseline.md)）**：`normative` 可定义术语、定合格性；`informative` 只能举例、佐证；**术语定义只能引 `normative`**。自造词标 `local` 并首现解释，不得写成「业界/标准」；标准卡不能证明「本体提升 agent 效果」。术语差异判定：`aligned` / `narrower` / `broader` / `divergent` / `local`（见 [基线整改计划](../archive/2026-11/plans/2026-11-11-baseline-correction-plan.md)）。
- **`status` vs `reading` vs `L1/L2/L3`**：文档成熟度（`seed`/`draft`/`stabilized`/`superseded`）、阅读进度（`未读`…`已消化`）、digest 深度（`L1/L2/L3`）是三套正交维度，禁止混填。
- **`updated`**：只记实质修订，搬家/改链不刷日期。
- **正文标注**：推断句至少在段末标一次 `已核` / `推测` / `存疑`（映射见 [schema §3.1](../schema.md#31-证据等级四档)）。

## 命名

- 目录：小写短横线；论文目录用 `src/papers/{arxiv_id}-{slug}/`；开源项目目录用 `src/open-source/{org}-{repo}/`（全小写，`/` 换成 `-`，如 `RDFLib/pySHACL` → `rdflib-pyshacl`）。
- 论文文件：`<stem>.pdf`（原文，只读）/ `paper.md` / `references.md` / `appendix.md` / `card.md` / `digest.md` / `figures/`。
- 开源文件：`card.md`（来源卡）/ `digest.md`（代码阅读，下游入口）/ `code-map.md`（文件/符号索引，可选）。
- **模板唯一家**：全仓模板统一放 [meta/templates/](../templates/src/paper-card.md)（`src/` 三套在 `templates/src/`，`topics/` 在 `templates/topics/`）；**`src/` 不再自带 `_templates/`**。
- 网页卡：`src/web/{来源}/<slug>.card.md`，与原文同名。
- 子主题目录：`topics/<派>/<子主题>/README.md`；按子机制命名，不按来源类型。派 README 只做地图，详细论证在子主题。
- 结论/对象/实验编号见 [schema §4](../schema.md#4-编号前缀)。

## 台账纪律

每次动笔后回答三句：

1. 这份材料/这篇文档**改变了哪条判断**？→ 先写本派 `claims.md`；跨派/进交付物才升 [conclusions](../../topics/conclusions.md)
2. **喂给了哪个主题**？→ 去改 [src 台账](../../src/README.md)
3. 如果修正了旧判断，**哪些主题页要回改**？→ 写进卡片的 `updates:`，逐页改。

三句都答不上来，说明这次动笔没有产生信息。
