# 全审计划：从 digest 到 topics，再到可实施/客户价值

> 一句话：**全审不是“再读一遍”，而是验证一条链——论文事实 → digest 工程可实施性 → topics 判断/洞察 → 实施决策 → 客户收益假设——每一环都能被独立检查。**

## 0. 最终目的

本体的价值不在“本体文件正确”，而在**实施后客户获得利益**：少出错、少返工、少审批、快上线、可审计、合规。  
所以全审要回答五个问题：

1. **digest 是否能让工程团队知道“怎么做”？** 机制、接口、数据、参数、成本、失败模式、何时别做。
2. **digest 是否能让工程团队知道“代价是什么”？** 建设/运行/维护/人审/失败成本，不是只有“效果”。
3. **topics 是否把 digest 吸收成了判断，而不是复述？** 有没有非显然的因果/结构结论，能改变一个设计/采购/评测决定。
4. **topics 是否指向实施？** 数据、接口、组织、成本、风险、第一个 sprint。
5. **是否有客户收益假设？** 谁受益、什么指标、反事实是什么、怎么验证；没有就标 `推测`，不装成“洞察”。

## 1. 为什么现在做

- 上一轮完成了结构、自包含、深打磨、抽样 critic；但**抽样不是全审**，且“写得好”不等于“能被 topics 用成实施判断”。
- 现有 topics 多数是“机制解释 + 边界”，少数有成本/前沿；**缺少统一的“实施含义/客户价值”层**。
- 如果 digest 的工程部分空泛，topics 只能复述；如果 topics 不复述实施，交付物就是浮云。

## 2. 审计对象与非对象

**对象（全量，不抽样）**

| 层 | 数量 | 审计问题 |
|---|---|---|
| `src/papers/*/digest.md` | 22 | E0–E4：工程可实施性 |
| `topics/<派>/<子主题>/` | 20 | A0–A4：吸收/洞察/实施 |
| 6 派 README + conclusions/THESIS/feasibility | 1 套 | 跨页判断是否被 digest 支撑；是否有“无根洞察” |
| `sources.md` / claims | 1 套 | 每个 E/L 是否能追到 digest → 原始论文 |

**非对象**

- 不新增论文（除非全审发现关键缺口，先在 frontier 登记）。
- 不跑实验、不写实现；只产出可执行假设/实验设计。
- 不在 deliverables 新增判断；全审通过后才谈交付。

## 3. 三个量表

### 3.1 digest 工程度（E0–E4）

| 级 | 名称 | 判据 | 典型失败 |
|---|---|---|---|
| E0 | 摘要复述 | 只有“提出了什么/效果不错” | 读者不知道怎么做 |
| E1 | 机制可复述 | 术语、流程、关键设计能讲清 | 仍无接口/数据/成本 |
| E2 | 数字可核查 | 关键数字带条件、出处、比较对象；有反例 | 数字对，但无法落地 |
| E3 | 工程配方 | 数据/接口/参数/步骤/失败模式/stop condition/何时别用 | 能开工，但不知道值不值 |
| E4 | 决策级 | 成本/收益**公式** + 替代方案 + 客户价值假设/验证实验；参数可待测，但必须写清输入与决策线 | 能决定 build/buy/不做的边界 |

**全审要求**：

- **22/22 至少 E3**；E3 是硬门。
- **12 篇 L3 至少 E4**（机制/知识/状态/判定/测量各至少 2 篇）。
- 每篇必须能回答：**“如果明天让一个工程团队复刻，第一个 sprint 做什么？”** 答不出 = E2 以下。

### 3.2 topics 吸收度（A0–A4）

| 级 | 名称 | 判据 | 典型失败 |
|---|---|---|---|
| A0 | 复述 digest | 把 digest 的话换个说法 | 没有新判断 |
| A1 | 多源综合 | 把 ≥2 篇 digest 放在一起，指出异同 | 只是“综述” |
| A2 | 判断/决策规则 | 给出“在什么条件下选 A 不选 B”的规则 | 规则不可执行 |
| A3 | 实施含义 | 数据/接口/组织/成本/风险/stop condition | 能开工 |
| A4 | 客户价值假设 | 受益者/痛点/指标/反事实/验证实验 | 能立项/验证 |

**全审要求**：

- **20/20 至少 A3**；A3 是硬门。
- **至少 8 个 A4**，覆盖：动作闸门、判定器、投影、编译、记忆、推理期约束、精化/生成、度量。
- 每个 A3/A4 必须能回答：**“这页会改变哪个实施决策？如果不变，它为什么存在？”**

### 3.3 价值链（V0–V3）

| 级 | 名称 | 判据 |
|---|---|---|
| V0 | 主张 | 一句可检验的“机制 → 效果” |
| V1 | 受益者/痛点 | 谁受益、现在怎么痛 |
| V2 | 指标/反事实 | 哪个指标、没有它会怎样、成本 |
| V3 | 可验证假设 | 有实验/试点设计、成功/失败判据 |

**规则**：

- A3 至少配 V2；A4 必须配 V3。
- 没有 V2/V3 的“价值”一律标 `推测`，不得写进 deliverables。
- V3 不要求现在跑实验；要求**能设计**，且失败判据清楚。

## 4. 质量门（硬门，不过不进入下一 Phase）

| 门 | 要求 |
|---|---|
| G-E | 22/22 E3+；12 L3 E4；每篇有“第一个 sprint”答案 |
| G-A | 20/20 A3+；≥8 A4；每页有“改变哪个决策” |
| G-V | 所有 A3 有 V2；所有 A4 有 V3；无 V 的“价值”标推测 |
| G-X | **digest→topic 吸收矩阵**：22 篇 digest 的工程发现必须被相关 topic 吸收或在 frontier 说明不适用；每个 topic 核心判断有 digest 来源；orphan/unsupported 清零或解释 |
| G-T | 每个 topic 的 E/L 都能追到 digest；无 orphan claim |
| G-C | 跨页计数/术语/冲突一致；0 broken links |
| G-R | 独立 critic 全审 22+20；人类抽检 ≥5 digest + ≥5 topics；问题闭环 |

## 5. 全审流程

### Phase 0 · 校准（2–3 轮）

- 抽 3 篇 digest（MIOE、CAI、CASEL）+ 3 个 topic（action-gate、checker、feasibility）做 rubric 校准。
- 产出一份“什么叫 E3/E4、A3/A4”的样例；人类确认量表。
- 建 `digest-ledger.md`、`topics-ledger.md` 的表头；不填内容。
- **出口**：量表冻结；3+3 样例通过；人类 sign-off。

### Phase 1 · 22 篇 digest 全审（8–12 轮）

每轮 2–3 篇；每篇：

1. 读 `digest.md` + `paper.md` 关键节 + card；核 5 个数字。
2. 按 E0–E4 打分；写 `D-xx` 行：论文、E 级、工程缺口、修正、verdict。
3. 修 digest（不是只写评语）；补“第一个 sprint”“成本/stop condition/何时别用”。
4. 独立 critic（工程向）复审；不过则回修。

**出口**：22/22 E3+；12 L3 E4；每篇有 first sprint 段落；critic 闭环。

### Phase 2 · 20 个 topic 全审（7–10 轮）

每轮 2–3 个；每个：

1. 读 topic 的 `README/findings/frontier/mechanism` + 对应 digest。
2. 按 A0–A4 打分；写 `T-xx` 行：核心判断、吸收来源、决策改变、实施含义、缺口、verdict。
3. 修 topic：把“机制解释”改成“判断 + 实施含义 + 客户价值假设”；删复述。
4. 独立 critic（实施/产品向）复审。

**出口**：20/20 A3+；≥8 A4；每页有“改变哪个决策”。

### Phase 2.5 · digest→topic 吸收矩阵（3–5 轮）

- 建 `absorption-matrix.md`：每篇 digest 一行，列「工程发现（接口/参数/成本/stop/客户指标/边界）→ 被哪些 topic/findings/claims 吸收 → 状态（absorbed/partial/orphan）→ 动作」。
- 反向检查：每个 topic 的核心判断/实施段，必须能追到 digest；没有来源的 claim 标 unsupported。
- 修：把 digest 的工程发现写进 topic 的 mechanism/findings，或在该 topic frontier 说明「不适用/未采用」。
- 出口：22/22 absorbed 或 explained；0 orphan；0 unsupported。

### Phase 3 · 价值链与跨页（3–5 轮）

- 建 `value-trace.md`：V-01…；每个 A3/A4 一行。
- 检查：E/L → digest → topic → decision → V 的链条；找 orphan、过度概括、冲突。
- 重审 C-04、E-19、能力梯度、feasibility；不过则降级/改写。
- **出口**：G-V/G-T 通过；C-xx/E-xx 与 digest 一致。

### Phase 4 · 对抗复核（4–6 轮）

- 两个独立 critic：一个只挑工程/数字/条件，一个只挑“实施/客户价值”空话。
- 人类抽检：≥5 digest + ≥5 topics + 所有 V3。
- 反例：每个 A4 至少一条“为什么可能不成立/不划算”。
- **出口**：G-R 通过；问题闭环；未解决项进 frontier。

### Phase 5 · 报告与 go/no-go（2 轮）

- 写 `report.md`：通过项、未通过项、客户价值假设清单、实施优先级、下一步实验。
- 给出 go/no-go：哪些 topic 可进 deliverables，哪些只能留在研究层。

## 7. 评审与对抗

- **AI critic 全审**：22 digest + 20 topics 每个都过；不是抽样。
- **两个视角**：工程 critic（能复刻吗/数字对吗/失败模式全吗）；实施 critic（谁用/改变什么决策/客户指标是什么）。
- **人类抽检**：≥5 digest + ≥5 topics + 所有 V3；人类只判断“是否值得实施”，不替 AI 做全文校对。
- **反例要求**：每个 A4 至少一条反例/不成立条件；没有反例的“洞察”降级。

## 7.1 并发执行规则

- **一个 agent 只改一个子目录**：`topics/<派>/<子主题>/`；禁止跨目录写，避免冲突。
- **读-only 任务可全量并发**：吸收矩阵、A/E 评分、critic；最多 6 个同时跑。
- **写任务按批**：每批 3–5 个 topic；每个 agent 只追加 `## 实施与客户价值（A3/A4）` 到该 topic 的 `mechanism.md`（没有则建，并在 README 文件地图加一行链接由主控统一做）。
- **统一模板**：实施决策 / 数据接口 / 组织成本 / stop / first sprint / 客户指标+V3 / 反例；数字无出处标 `推测`。
- **批后验收**：链接检查 + A-critic 全批 + 失败回修；不通过不进下一批。
- **主控不做重复劳动**：agent 写内容，主控只做冲突检查、链接、critic 汇总、跨页回写。

## 9. 完成定义

- 22/22 E3+；12 L3 E4；每篇有 first sprint。
- 20/20 A3+；≥8 A4；每页有“改变哪个决策”。
- 所有 A3 有 V2；所有 A4 有 V3；无 V 的“价值”标推测。
- 每个 topic 的 E/L 可追到 digest；无 orphan；digest→topic 吸收矩阵 22/22 absorbed 或 explained。
- 0 broken links；计数/术语一致。
- 独立 critic 22+20 全审；人类抽检 ≥5+5；问题闭环。
- `report.md` 给出 go/no-go 与实施优先级。

## 10. 风险与对策

| 风险 | 对策 |
|---|---|
| digest 写得好，但 topics 不用 | G-T 价值链；T-xx 必须写“吸收来源/改变哪个决策” |
| topics 有洞察，但不可实施 | A3 硬门；必须写数据/接口/成本/风险/first sprint |
| “客户价值”编造 | V3 要求指标/反事实/实验；没有就标推测 |
| critic 同质化 | 工程 critic + 实施 critic 两个视角；人类抽检 |
| 全审变成无限打磨 | 量表 + 硬门 + 每 Phase 出口；不过就停，不无限循环 |
| 只改文字，不改判断 | 每个 D/T 行必须写“修正前/后判断”；没有判断变化不算通过 |

## 12. 第一轮怎么开

1. 人类确认 E/A/V 量表与“全审=22/22+20/20”。
2. Phase 0：MIOE、CAI、CASEL + action-gate、checker、feasibility 做样例；人类看一遍“什么叫 E4/A4”。
3. 建 ledger 表头；开始 Phase 1。
4. 每 Phase 结束写一页阶段报告；不通过不开下一 Phase。

---

**一句话验收**：给一个没读过论文的工程团队看 digest，他们能列出第一个 sprint；看 topic，他们能说出“这改变我们哪个决定、客户哪个指标会动、怎么验证”。做不到，就不算全审通过。
