# 论文消化计划：从摘要级卡片到工程级判断

> 本计划只管一件事：把 `src/papers/` 里的 22 篇从「摘要级卡片」推进到「可被 topics 引用的工程判断」，并把图、成本、使能条件一起留下。
> 它不改变 [AGENTS](../AGENTS.md) 的落点规则；与 AGENTS 冲突时，以 AGENTS 为准。

## 0. 一句话

**不平均用力。** 12 篇精读成「机制档案」，6 篇结构读，4 篇只留卡；先做 1 篇样板校准格式，再按「主干 → 机制 → 测量 → 行业/生产 → 横切综合」五波推进。每篇的交付不是更长的摘要，而是：**机制怎么执行、数字在什么条件下成立、落地要付什么成本、能解决什么操作问题、哪张图能一眼说清**。

---

## 1. 诊断：现在缺的不是「读」，是「可执行的细节」

现状（2026-11-07）：

- 22 篇 PDF、22 张论文卡 + 1 张材料卡；**全部 `reading: 摘要级`、`provenance: 原文摘要`**。
- `topics/` 六派已成型，E-01…E-13 有等级、有冲突；但 3 条仍是综述转述（E-09/10/11），C-04 靠一篇论文的边界解释。
- 全仓库没有一张图；没有「成本 / 使能条件 / 盈亏平衡」字段；部分细节数字只存在于 `frontier.md`，回查不到卡（例：CASEL 的 14.75%→7.02%、15.53%；APEX-MEM 的 88.88%）。
- 卡片擅长「做了什么 / 结果 / 没测什么」，不擅长「具体怎么做 / 参数是多少 / 为什么现在能做 / 复刻要花多少」。

三个例子，说明摘要级会漏掉什么：

1. **Narrow & Deep**：摘要只说「避坑率 +20pp」。正文的 H2（增益随模型容量上升）**未被支持**（Holm 校正 p=0.85）；9B 模型带投影的得分 0.737，高于最大模型不带投影的 0.672。这比「投影有效」更有工程含义：**投影不是强模型专属，也不是越强越受益**。
2. **CAI**：摘要说「结构化工件无准确率增益」。正文真正的干货是成本模型：**2% 盈亏平衡充分率、实测约 43%、平均 token −38%、证据不足时 +1.9%、决策门 140s→30s**。没有这些，「无增益」无法指导任何取舍。
3. **POLAR**：摘要说「18 个组合只有 8 个改善」。正文的机制是 T1–T5 五类可逆关系 + curator 权重 + 阈值 + tier ablation；不知道这些，就无法判断它能不能迁移到自己的工具集。

风险不是「读得不够多」，而是**抽象层的误差被下一层放大**：综述 → 卡 → topics → 交付物。仓库已经因综述转述失真修正过三处；同样的失真会在「摘要 → 精读」这一层重演。

## 2. 什么叫「值得消化」：五维判据 + 三级深度

五维，每维 0–2 分。不追求精确打分，只用来排序：

| 维度 | 问什么 | 2 分的样子 |
|---|---|---|
| 证据强度 | 有没有实现、评测、基线、消融、真实部署？ | 多数据集/多模型/真实环境，且有反例或消融 |
| 机制可迁移 | 去掉领域后，机制还能不能用？ | 能写成与域无关的判定/状态/编译结构 |
| 判断杠杆 | 会改变哪条 E/L/P，或填哪个开放问题？ | 直接支撑或推翻现有判断 |
| 工程细节 | 参数、阈值、接口、失败处理、成本写没写？ | 能照着重画一张流程图并估成本 |
| 图示可用 | 有没有一张图能承载机制或关键结果？ | 图本身能当讲解骨架 |

三级深度：

| 级 | 产出 | 判据 | 预算 |
|---|---|---|---|
| **L3 精读** | 机制档案（约 150–250 行）+ 2–3 张图 + 判断 delta | 杠杆=2，或证据/迁移/细节三项都强 | 每篇 1 次专注会话 |
| **L2 结构读** | 80–120 行：机制 + 关键数字 + 边界 + 1 张图 | 有证据但杠杆中等，或概念架构但承重 | 每篇 0.5–1 次会话 |
| **L1 只留卡** | 现有卡 + 一句「为什么不深读」 | 证据弱且杠杆低，或严格 off-thesis | 每篇 15 分钟 |

**质量 ≠ 相关性。** 一篇严谨但不在本仓库问题上的论文，仍然只配 L1；一篇概念架构但承重的论文（Commit Boundary）配 L2，但必须标「无实现、无实证」，不能当证据用。

证据类型也要标，防止类别错误：

`实证·部署` / `实证·基准` / `实证·模拟` / `概念架构` / `机制研究` / `立场或评测方法`

## 4. 消化单位：机制档案

L3 卡片按以下 12 节写；L2 可把 3+5+6 合并成三节。

1. `## 一句话` — 不用摘要句，说清它把什么判断从模型手里拿走了。
2. `## 证据类型与设定` — 任务/数据/模型/基线/n；一句话说清「这证据能证明什么、不能证明什么」。
3. `## 机制` — 本体在哪、变成什么、执行顺序、接口、参数/阈值；配图。
4. `## 关键数字` — 表：数字 | 条件 | 出处（页/表/图） | 核验状态。
5. `## 工程实践` — 复刻清单：schema 形状、阈值、评审点、日志、失败处理；「如果明天要在团队里做，第一步是什么」。
6. `## 成本与使能条件` — 建设/运行/维护/人审；一次性 vs 每次；盈亏平衡；依赖的技术条件；2022 年做会卡在哪。
7. `## 能解决的操作问题` — 2–4 条，写成 practitioner 认得出的问题；附「何时别用」。
8. `## 失效模式` — 作者自述 / 观察到 / 推断，三分，不混。
9. `## 不可迁移的部分` — 哪些结论只在这个域/这个数据/这个模型上成立。
10. `## 图与表` — 2–3 张，图注写「看什么」；出处 + 版权。
11. `## 对本仓库判断的影响` — E/L/P；没有影响就写「只作边界证据」。
12. `## 引用锚点` — 关键句原文 + 页码；定位不到的数字标 `存疑`，不进正文。

字段只动两个：`reading: 精读`、`provenance: 原文正文`。证据类型写在正文第一段，不新增 frontmatter 字段，避免 schema 膨胀。

**`已消化` 的定义**（建议写进 [conventions](./conventions.md)）：

> 卡片为 `精读` + `原文正文`，且至少有一个 topics 页面或 `claims.md` 被它改变；若判断未变，须在派 `sources.md` 写 `no delta` 及原因。只有卡、没有落点，不算已消化。

## 5. 落点：卡片 → 子主题 → 判断

1. **卡片是证据，子主题是判断。** 不把档案抄进 topics；topics 只写「跨论文之后我们信什么」。
2. **子主题页至少四张表**：机制步骤、证据（带条件）、成本/使能、失效；再加一张自绘图。
3. **`claims.md` 只记「改变了哪条判断」**；没改变就写 `no delta`，不硬造 `L-xx`。
4. **`E-xx` 只在跨派/交付物时改**；改前先查 `C-xx` / `Q-xx`，反例保留。
5. **home / subtopic 复查**：读完再定主效应。候选：CAI→03、Diagnose→06、SLB→06；改则同步原派的「双重身份」说明与 `updates:`。
6. **不轻易开子主题**：现有 23 个子主题对 22 篇已经偏碎。只有 ≥2 篇共享同一子机制，或原子主题过载时才拆/并。Wave 2 后做一次结构复盘。
7. **`frontier.md` 只放「下一步」**：把 frontier 里的细节数字搬回卡 / `claims.md`，frontier 留检索式与候选。

## 6. 图文并茂：两条图线

### A. 论文原图（证据图）

- 只选承载机制或关键结果的 2–3 张；不搬装饰图。
- 工具：PyMuPDF 定位 `Figure N` caption，裁上方图区，300 dpi PNG；人工目检。
- 存：`src/papers/figs/{arxiv_id}/fig-{n}-{slug}.png`。
- 卡片里写：原 caption（或缩短）+ 页码 + 「看什么」+ 出处/版权。
- 一张图配一句判断；没有判断的图不贴。

### B. 自绘图（综合图）

- 每个核心子主题 1 张，回答一个判断；≤9 个节点；中文标签。
- 工具：Graphviz `dot` → SVG + PNG（本机已验证）；Mermaid CLI 在本机超时，不用。
- 存：`topics/<派>/<子主题>/figs/fig-{slug}.svg` + `.png`；正文嵌 PNG，链 SVG。
- 图下写「这张图在说什么」，不重复 caption。

### C. 规则

- topics 可以嵌论文原图，但必须带出处/页码/「看什么」，且该子主题至少有一张自绘图。
- 版权：引用必要图，标 `arXiv:ID, p.X`，注明版权归作者、研究评论用途；优先自绘。
- 交付物复用图时，不改图、不新增判断。

## 7. 五波执行与 gate

### Wave 0 · 样板（1 篇）

**CAI**。产出：完整档案 + 3 张图 + `03-knowledge/compilation` 机制页 + `claims.md` / `sources.md` + 一页「样板复盘」（哪些节有用、哪些过重、单篇耗时）。

**Gate**：你验收一页；格式不对就先改模板，不铺开。

### Wave 1 · 主干（4 L3 + 1 L2）

POLAR、Narrow & Deep、Ontology Catch、Diagnose；OA-RAG 随 Ontology Catch。

产出：01/02/03/06 的四个机制页；两条综合草稿：

- **投影 vs 编译 vs 检索**（N&D + CAI；接 C-04）
- **能力梯度**初稿（POLAR + N&D：为什么一个随能力下降、一个不随能力上升）

**Gate**：C-04 是否要改写；Q-03 是否降级；E-13 是否要补限定。

### Wave 2a · 约束与状态（3 L3 + 3 L2）

CASEL、OntoAct、FIRME；Commit Boundary、多 agent 诊断、EvoMemState。

产出：01 的 action-gate / reasoning-gate / commit-gate 三页合看；04 memory 页；「闸门四形态」对比表（可逆性 / 后果-模式 / 符号验证 / 授权契约）。

**Gate**：01 的三个子主题是否该合并/重排；Commit Boundary 是否只能当规范。

### Wave 2b · 测量（2 L3 + 1 L2）

SLB、MIOE；Agents are Systems。

产出：06 的 trace / mechanism / metrics 三页；「度量的三种失败」（solver-like / 内部本体不可分 / 失败归工作流）+ 评测配置方差。

**Gate**：E-09/E-10 能否从推测升已核；06 是否要开 `feasibility`。

### Wave 3 · 行业与生产（2 L3 + 1 L2 + 4 L1 集群）

Grid Agents、OntoDoc；CASTON；Peeling / Evontree / SFE-O / ReX-GG 作 L1 集群。

产出：03/02 的工业约束页；05 的「本体生产成本」综合（手工 / LLM 生成 / 精化 / 编译 / 自演化）；`domains.md` 更新。

**Gate**：05 是否值得再加一个 L3；domains 是否需要新域。

### Wave 4 · 横切综合（不读新论文）

- **能力梯度**：哪些机制的收益随模型能力升/降/无关；写成可判定表。
- **落地经济学**：建设/运行/维护/人审成本 + 盈亏平衡 + 使能条件；候选新子主题 `06-measure/feasibility`。
- **问题 → 机制**目录：操作问题、对应机制、证据、成本、何时别用。
- 更新 `conclusions` / THESIS 候选假设；重抽 deliverables 大纲。

**Gate**：候选假设是否立；`feasibility` 是否立；deliverables 是否要改章。

## 8. 质量门与反幻觉

每篇的完成检查（建议并入 [checklist](./checklist.md)）：

- 每个数字有页码/表号；摘要数字标 `摘要`，正文核对后改 `正文`。
- 作者自述 vs 读者推断分开；推断句标 `推测`。
- 图目检过，caption 没裁掉，正文没混入。
- 成本/使能节填了；不适用要写为什么。
- 「不可迁移」节填了。
- 至少一条：新 `L-xx` / 改 `L-xx` / 明确 `no delta`。
- `sources.md`、`home/subtopic`、`updates:` 更新。
- 不把单篇结论直接升 `E-xx`。

反幻觉四招：

1. **引文锚点**：关键句原文 + 页码；定位不到就标 `存疑`，不写。
2. **两遍读**：先结构（节标题/图表/结论），再定点（数字/阈值/消融/局限）。
3. **图不看 caption 就下结论**：必须目检图；表格必须看单位与条件。
4. **反例检查**：每条新判断找一条反例或局限；找不到就降级。
