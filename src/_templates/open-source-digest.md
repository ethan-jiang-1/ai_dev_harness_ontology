# {org}/{repo}：{一句话判断}

> **自包含**：不假设读者读过 README、card 或论文。代码位置写到 `文件:符号`，不贴大段代码。
> **证据等级**（与全仓一致，四档，不造第五档）：
> - `已核`：读过代码，能指到文件/函数（代码就是一手原文）；或读过一手文档原文。
> - `已证`：不仅跑通，且能用 `EXP-xxx` 在本仓库外复现；「跑通官方示例」只证明代码能跑，不等于机制有效。
> - `推测`：只读 README / 文档 / issue，没有代码定位。
> - `存疑`：README 与代码/issue 冲突，或核心闭源、无法定位。
> `reading` 字段（未读 / 已读代码 / 已跑通）记「读到哪」，与证据等级是两件事。

## 0. 三句话

1. **它是什么**：
2. **本体怎么被用**（执行 / 上下文 / 都没有）：
3. **证据到哪**：

## 1. 项目与维护状态

定位、架构、license、维护活跃度（最后一次提交、issue 响应）、被谁用。不把 star 当质量。

## 2. 本体在哪

文件 / 目录 / 格式（OWL / SHACL / RDF / property graph schema / JSON schema / LinkML / prompt）；谁生成、谁加载、谁版本化；改一次要走什么流程。

## 3. 调用链

一条完整路径：输入 → 本体加载/编译 → 校验/推理/查询 → 输出或动作 → 失败处理。
每步写 `文件:符号`。没有调用链的，说明是离线批处理还是根本没接上。

## 4. 接缝判定

| 问题 | 回答 | 证据 |
|---|---|---|
| 有外部判据（判据来自本体，不是模型自评） | | |
| 有阻断能力（违反可剪动作/拒输出/阻落盘） | | |
| 位置明确（能指到回路某一时刻） | | |
| 对应六时刻或轴外位置（action-gate / evidence / checker / commit-gate / memory / determinism / read-path / supply / reasoning / training / 不是接缝） | | |
| 执行形态（engine / compiled / context / label / none） | | |

三者同时成立才算接缝；只有第一条是「知识注入」，只有第二条是「硬编码规则」。

## 5. 证据与最小复现

- 官方最小示例 / 测试：命令、环境、结果（失败也记原文报错）
- benchmark / issue / 生产案例：
- 这个证据能支撑什么、不能支撑什么

## 6. 不能证明什么

- README 营销句 ↔ 代码实际行为
- star / fork / 单测覆盖率 ≠ 效果
- 离线校验 ≠ 运行时 gate
- 某个示例跑通 ≠ 在生产规模下成立
