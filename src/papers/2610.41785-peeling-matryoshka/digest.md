# Peeling the Matryoshka：嵌入前缀里有没有分类法

> 这是一篇 L1 消化：它测的是「嵌入几何」，不是 agent 行为；对 harness 只提供旁证。

## 0. 三句话

1. **它问什么**：Matryoshka 表示学习（MRL）把信息压到前缀维度；这些前缀维度是否与金标分类法的粗→细粒度对齐？
2. **它怎么做**：在 3 个 MRL 架构/数据集上，用 98K 参数的 order-embedding 探针，从冻结嵌入的前缀解出分类 DAG；用维度打乱/逆序做对照。
3. **它发现什么**：Graph F1 **0.885 / 0.931**；前缀维度确实按粗→细组织。**但明确未测下游效用。**

## 1. 它解决什么问题

检索嵌入常被当成黑箱；如果前缀维度天然编码分类粒度，就能低成本抽 taxonomy、做层级检索、可解释检索。

## 2. 术语

| 术语 | 用大白话说 |
|---|---|
| **MRL** | Matryoshka Representation Learning；把嵌入做成可截断的前缀。 |
| **prefix dimension** | 前 k 维；越靠前越粗。 |
| **taxonomy** | 分类法/DAG；本文用金标。 |
| **probe** | 在冻结嵌入上训练的小模型；本文 98K 参数。 |
| **order embedding** | 用偏序约束学 taxonomy 的嵌入。 |
| **Graph F1** | 边级 F1；衡量抽出的 DAG。 |

## 3. 它怎么做

- 3 个 MRL 架构/数据集；冻结嵌入。
- 98K 参数 probe：从 prefix 解出 taxonomy DAG。
- 对照：打乱维度、逆序维度；看是否破坏对齐。

## 4. 结果：数字与条件

- Graph F1 **0.885 / 0.931**（两个设置）。
- 前缀维度与粗→细粒度对齐；打乱/逆序会破坏。
- 条件：特定 MRL 嵌入族；金标 taxonomy；无下游任务。

### 4.1 这些数字怎么读

- **Graph F1 是结构分数，不是语义真值。** 0.885/0.931 说明抽出的 DAG 与金标结构接近，不说明每个类定义正确。
- **只在 MRL 嵌入上。** 非 MRL/其他模型未测；前缀对齐是训练技巧的副作用，不是通用规律。
- **没有下游。** 抽出的 DAG 能否被判定器/agent 用，未测。

## 5. 这些数字不能说明什么

1. **不是「模型懂本体」。** 它测嵌入几何，不是 agent 行为/推理。
2. **不是通用。** 只在 MRL 嵌入上；非 MRL/其他模型未测。
3. **不是下游效用。** 抽出的 DAG 能否被判定器/agent 用，未测。
4. **不是深层迁移。** 零样本迁移只在「目标不比源域更深」时验证。

## 6. 工程上怎么用

- 需要从嵌入快速抽 taxonomy 时，可试 prefix + order-embedding 探针；成本低。
- 先确认目标本体不比源域更深；否则迁移会掉。
- 不要把它当「本体已内化」的证据；它只是「结构可解码」。

### 6.1 最小验证

1. 选目标嵌入与金标 taxonomy；先确认目标不比源域更深。
2. 用 prefix + order-embedding 探针抽 DAG；报 Graph F1 与人工抽查。
3. 加维度打乱/逆序对照；确认信号来自前缀顺序。
4. 做一次下游任务（检索/判定）；否则只能报结构保真。

## 7. 质量与边界

- **证据类型**：实证·嵌入分析（3 设置）。
- **强项**：探针小；有打乱/逆序对照；结论克制。
- **主要威胁**：只 MRL；无下游；金标域有限。
- **`quality: B`**：实验干净，但离开 harness 主线。

## 8. 与仓库判断的关系

- **E-11（已核）**：MRL 前缀维度与分类法粒度对齐；Graph F1 0.885/0.931。
- **05 生产/表征挖掘**：一条便宜的 taxonomy 抽取路线；不是运行时约束。
- **只作边界证据**：不能支撑「本体提升 agent 表现」。

## 9. 还没解决 / 下一步

- 抽出的 DAG 能否被下游判定器加载/验证？
- 非 MRL 嵌入是否还有前缀对齐？
- 更深的目标本体能否迁移？
