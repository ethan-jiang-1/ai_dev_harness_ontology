# POLAR · 消化

> 事实、数字、页码回 [card.md](./card.md)。这里只写**我们怎么用**、值不值得、哪里会坏。

## 工程思路

**要做「动作前可逆性门」，按这个顺序：**

1. **先列可逆性判据，不列危险动词。** 对每个 mutating tool，问「撤销它需要什么」：反向操作、有界可逆、补偿、不可逆消费、外部副作用。删除 `/tmp/x.log` 是否危险，取决于它是不是唯一副本，不取决于「删除」。
2. **把判据写成类型化关系，不写成 prompt。** T1–T5 的价值是**可审计**：每条 veto 能指回一条本体边。自由文本 rationale 不能。
3. **状态投影必须来自真实系统。** Layer B 从 DB + 已执行工具重建，不让 LLM 想象；否则门判的是模型以为的状态。
4. **反向搜索只做「是否存在可接受逆序列」。** 不要求执行逆操作，也不要求证明恢复一定成功；先把「有没有路」和「路好不好」分开。
5. **分数取最弱一步。** 一步不可逆就整条归零；bottleneck 就是审计理由。这比加权平均更符合安全语义。
6. **判定与执行分离。** 同一个 φ 可以驱动硬 veto、escalate、advisory；策略是可配置的，不是本体的一部分。
7. **阈值先按保留率/覆盖率校准，再按 reward 校准。** Table 4 显示 airline 在 0.80 只保留 36.6%，retail 100%；同一个阈值在不同域含义不同。
8. **上线前单独量 false-veto。** Reward 不告诉你「本可以做的合法动作被拦了多少」；必须有 harm/authorization 标签或人工审计。
9. **按能力分层部署。** 弱模型 + 高不可逆风险域：硬 veto；强模型：advisory 或动态门；强模型 + 合法用户意图域（retail）：不要用可逆性单独裁决。

## 实用意义

它解决的操作问题：

- **「删了唯一副本才发现没有备份，事后只能道歉。」** → 动作前问「有逆序列吗」，没有就拦。
- **「审计问为什么拦这次调用，系统只会说模型觉得危险。」** → 每条 veto 指回 T1–T5 本体边 + bottleneck。
- **「强模型本来能自己避开，硬护栏只剩代价。」** → 能力反向：弱模型收益大，强模型可能回退。
- **「retail 的退货/换货是合法用户请求，却被可逆性门拦了。」** → 可逆性不是唯一判据；需要 intent/authorization 层。
- **「门拦了很多，但不知道拦对没有。」** → 必须单独标注 false-veto / prevented harm；reward 不够。

**何时用**：动作不可逆且代价高；模型弱于域要求；域规则可查询成事实；有真实状态投影；能承担本体编写与维护。

**何时别用**：强模型 + 高基线；用户意图主导、动作本身合法（retail）；拿不到状态；本体没人维护；只用 reward 评估。

## 质量评估

- **证据类型**：实证·基准（`已核`，一手正文）。
- **样本与对照**：τ²-bench 3 域 × 6 模型 × 4 臂；每格 150 attempted runs；72 格；10,800 rollouts；用户模拟器与 judge 固定。
- **优点**：多模型、多域、多臂；有 tier ablation、阈值敏感性、block log；作者主动写清「reward 不是伤害度量」。
- **主要威胁**：单一合成基准；无 harm/authorization 标签；T1-only ≈ blanket veto，结构贡献未隔离；不模拟完整 s′、不验证逆执行；归档 provenance 不完整；对照臂是适配；retail 的失败可能是任务形态而非机制失败。
- **`quality: B` 理由**：内部对照和多模型覆盖不错，但外部效度、机制隔离、部署观测都不足；不能升 A。

## 洞察

1. **最尖锐的发现是「T1-only 接近 blanket veto，增益却不比 full 小」。** 这意味着测到的收益可能主要来自**保守拒绝**，而不是「结构反向组合」。作者自己写了这一点（p.7）。`已核`
2. **可逆性分数是「注释可恢复性」，不是「动作安全」或「用户授权」。** T5 的外部副作用可能在业务上完全合法；零售退货就是例子。把 φ 当安全总分，会误杀合法意图。`已核`
3. **收益与基线能力反向，但这是六点描述性拟合，不是部署阈值。** 斜率 −0.76/−0.67/−0.31、R² 0.92/0.98/0.65；作者明确说不能拿来做 zero-crossing 规则。`已核`
4. **False-veto 是护栏的隐性成本，而 reward 看不见它。** 1,745 条 blocked decisions 没有 harm/authorization 标签；retail 的 reward 损失是间接证据，不是 false-veto 率。`已核`
5. **「判定与执行分离」是可复用设计。** 同一个 φ 可以 veto/escalate/advisory；不要把它焊死在「硬拦」上。强模型场景可能只需要 advisory。`推测`（设计判断）
6. **可逆性门需要第二把尺：意图/授权。** 可逆性回答「能不能撤销」，不回答「该不该做」。retail 的失败说明两者不能互相替代。`推测`

## 成本与使能条件

| 成本 | 一次性 / 每次 | 说明 |
|---|---|---|
| Layer A 本体编写 | 每域一次性 | 人工 curator；工具/槽位/逆关系；本文未测工时 |
| Layer B 状态投影 | 集成一次性 | 接 DB + 工具执行记录；必须真实 |
| 反向搜索 | 每次候选调用 | 图遍历 + T2 bound 检查；轻量 |
| 阈值/策略校准 | 每域一次 | 保留率、reward、false-veto；本文只做了部分 |
| 审计/日志 | 每次 | bottleneck + 注释边；否则不可审计 |
| 维护 | 工具/本体变更时 | 新工具、槽位变更、注释修订 |

**使能条件**：工具 schema 类型化、能读真实状态、有可枚举的撤销操作；这些在 2026 年的工具调用生态里比 2022 年成熟。**但本体编写仍是人工成本**，这篇没有降低它。

**2022 年做会卡在哪**：工具调用 agent 还不普遍；没有 τ²-bench 这类多域工具基准；状态投影与工具 schema 不标准化；LLM 本身不足以稳定完成多步工具任务。

**反向条件**：强模型 + 高基线；用户意图主导域；拿不到状态；本体维护不起；只用 reward 评估。

## 不可迁移

- τ²-bench 的 airline/retail/telecom 是合成环境；真实业务的动作粒度、状态可见性、撤销成本都不同。
- 六个模型的结果不能外推到其他模型/版本；能力反向的斜率是描述性的。
- φ 是「注释可恢复性」，不是安全/授权；别拿它当合规判据。
- 本文不验证逆操作执行；「有逆序列」不等于「恢复会成功」。
- 本体编写成本、语义错误、对抗鲁棒性未测；不能把论文的工程可行性当成部署可行性。

## 开放问题

- T1-only 与 full 的差异能否用配对实验分开？需要同一 baseline、同一轨迹。
- False-veto 率怎么量？1,745 条 blocked decisions 能否人工标注出「本可合法执行」的比例？
- 动态/不确定性感知门（只在 token logprob / self-consistency 高时调用反向搜索）是否能在强模型上保留结构检查而不回退？
- 复合动作的可逆性怎么算？单步可逆、组合不可逆的情形，图搜索是否能覆盖？
- 意图/授权层怎么接？可逆性门 + 用户确认 + 策略引擎的组合，谁做最终裁决？
- 本体编写一个人天/域？工具变更后的维护成本是多少？
