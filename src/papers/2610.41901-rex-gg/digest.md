# ReX-GG：轻量集成 + 结构化输出 + 匿名互评

> 这是一篇 L1 消化：工程流水线有参考价值，但本体只当标签表，不是判定器。

## 0. 三句话

1. **它问什么**：从英语科普文章抽「因果关系」建图，怎么在不堆模块的前提下减少幻觉/单模型失效？
2. **它怎么做**：七个模型集成；每个输出 JSON（关系类型/强度/证据）；匿名互评排序；再生成交互式 HTML 因果图。
3. **它发现什么**：用户研究感知准确率 **0.778**；结构化输出 + 互评比堆模块更可控。**但本体只定义四种关系，不参与判定。**

## 1. 它解决什么问题

因果图构建：从文本抽事件 + 因果关系；常见失败是关系类型混乱、单模型幻觉、输出不可消费。

## 2. 术语

| 术语 | 用大白话说 |
|---|---|
| **relation extraction** | 从文本抽实体间关系。 |
| **ensemble** | 多模型集成。 |
| **structured output** | 强制 JSON schema。 |
| **anonymous peer review** | 模型匿名互评排序。 |
| **causal graph** | 事件/关系图。 |
| **ontology as label table** | 本体只提供关系类型，不做约束/推理。 |

## 3. 它怎么做

- 七个模型独立抽关系，输出 JSON。
- 匿名互评：把候选匿名，模型/规则排序。
- 聚合、去重、生成交互式 HTML 图。

## 4. 结果：数字与条件

- 用户研究感知准确率 **0.778**；n/任务/语言未在摘要级量化。
- 单一任务（英语科普文章）；本体四种关系（强因果/弱因果/对比/组合）。

### 4.1 这些数字怎么读

- **0.778 是用户研究感知准确率，不是金标 F1。**
- **结构化输出 + 匿名互评**降低单模型幻觉，但不提供形式保证。
- **本体只是标签表**（四种关系），不参与判定/推理。
- **没有下游 agent 使用**；图生成后是否可消费未测。

## 5. 这些数字不能说明什么

1. **不是本体机制。** 本体只定义标签；不判定、不约束、不推理。
2. **不是通用。** 单一任务/语言；用户研究样本有限。
3. **不是下游 agent 使用。** 图生成后有没有被 agent 消费，未测。
4. **不是可自动放行。** 互评排序仍需人审。

## 6. 工程上怎么用

- 多模型集成时，让每个模型输出 JSON，再做匿名互评排序；比 token/span 投票可控。
- 关系类型由本体定义，但本体不参与判定；它是**标签表**，不是判据。
- 输出交互式 HTML 图，便于人审；这是「可消费性」的工程细节。

### 6.1 最小验证

1. 定义关系 schema（四种关系足够做原型）。
2. 多模型输出 JSON；匿名互评排序；保留证据 span。
3. 人工抽 50–100 条，报 precision/recall；不要只报感知准确率。
4. 让下游 agent 用一次图；看是否真的可消费。

## 6.1 工程配方（E3）

### JSON schema

`{cause, effect, relation: strong|weak|contrast|composition, confidence: 0-1, evidence_span: {start,end,text}}`；关系类型由本体定义；没有 evidence_span 的条目丢弃。

### 匿名互评

- 每个候选关系由 k=3–5 个模型匿名评审，只给关系类型/证据，不给来源模型。
- 排序：每个 reviewer 给 1–5 分；聚合用中位数/Borda；分歧 >2 分或证据不一致 → 人工复核。
- 去偏：随机化顺序、隐藏模型名、同一模型不自评；位置偏差用双向顺序各跑一次。

### stop condition

- reviewer 一致性（Krippendorff α）<0.6 → 停，重写 rubric。
- 人工 100 条 precision <0.7 → 停，不自动放行。
- 七模型成本 > 单模型+人审的 2× → 退回单模型。
- 下游 agent 无法消费图 → 只做可视化，不做自动。

### 第一个 sprint

2 周、50 篇英语科普：

1. 七模型输出 JSON；丢弃无 evidence_span。
2. 匿名互评 k=3；聚合排序。
3. 人工标 100 条 precision/recall；算成本/延迟。
4. 让下游 agent 消费一次图，记录能否用。
5. 出口：precision ≥0.7、成本 ≤单模型 2×；否则停。

### 成本

- 七模型调用：按 token/篇；50 篇 × 7。
- 互评：k=3 × 候选数。
- 人工：100 条标注，约 1–2 人日（`推测`）。
- 维护：schema/ rubric 变更重跑。

### 替代方案

- 单模型 + 人审；传统关系抽取；不做图；商业 KG 工具。
- 论文无成本对照。

## 7. 质量与边界

- **证据类型**：工程流水线 + 用户研究（摘要级）。
- **强项**：结构化输出；匿名互评；可交互图。
- **主要威胁**：单任务/语言；本体仅标签；无下游；用户研究样本未量化。
- **`quality: B`**：工程样例有价值；证据不足以支撑通用结论。

## 8. 与仓库判断的关系

- **05 生成**：关系抽取路线之一；本体当标签表。
- **00 orchestration**：集成/互评是工程模式，不是本体机制。
- **只作边界证据**：不能支撑「本体提升 agent 表现」。

## 9. 还没解决 / 下一步

- 匿名互评的排序能否校准到自动放行？
- 多语言/多域是否稳定？
- 输出的图能否被下游 agent 直接消费？
