# ReX-GG · 消化（L1）

> 只到卡 + 一页判断；没有深读正文。事实回 [card.md](./card.md)。

## 为什么只到 L1

它是一条**轻量工程流水线**：七个模型集成 + JSON 结构化输出 + 匿名互评排序 + 交互式 HTML 因果图。工程味足，但本体只定义四种关系类型，不承担判定/约束；对 harness 主线的杠杆低。

## 一句话判断

不堆模块，而用**结构化输出约束格式** + **匿名互评压掉幻觉/单模型失效**；在英语科普文章的关系抽取上，用户研究感知准确率 0.778。

## 工程思路（如果有用）

- 多模型集成时，让每个模型输出 JSON，再做匿名互评排序；比 token/span 投票更可控。
- 关系类型由本体定义（强因果/弱因果/对比/组合），但本体不参与判定；它是**标签表**，不是判据。
- 输出交互式 HTML 图，便于人审；这是「可消费性」的工程细节。

## 质量与边界

- 用户研究 n 未在卡中量化；单一任务/语言；本体只四种关系。
- 没有下游 agent 使用；没有约束执行。
- 可作 05 生成/00 orchestration 的工程样例，不是核心证据。

## 洞察

1. **结构化输出 + 匿名互评比「更多模块」更有效。** 这是工程实践，不是本体机制。`推测`
2. **本体当标签表时，价值在一致性，不在约束。** 四种关系类型统一了输出，但不判断对错。`推测`

## 开放问题

- 匿名互评的排序能否校准到可自动放行？
- 多语言/多域是否稳定？
- 输出的图能否被下游 agent 直接消费？
