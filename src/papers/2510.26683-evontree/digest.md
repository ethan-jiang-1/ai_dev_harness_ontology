# Evontree：用本体规则驱动模型自演化

> 这是一篇 L1 消化：只到「它主张什么、边界在哪」，不假装有量化结论。

## 0. 三句话

1. **它问什么**：专业域模型常缺领域一致性；能不能用少量本体规则驱动「自检 → 修正 → 重训」的迭代，让模型在训练侧变好？
2. **它怎么做**：从少量人工选定的根概念出发，构建/扩展本体；用本体规则检查模型输出/训练样本的不一致；修正后继续训练。
3. **它发现什么**：报告了专业域表现提升；但摘要级无具体数字、无独立复现。**这是训练侧路线，不是推理时约束。**

## 1. 它解决什么问题

专业域数据少、标注贵；通用模型缺乏领域本体的一致性。推理时加约束（RAG/规则/检查器）需要每次调用都带；训练侧注入则可能「内化」一部分。

Evontree 的立场：**本体可以当训练信号**，而不只是推理时的判据。

## 2. 术语

| 术语 | 用大白话说 |
|---|---|
| **self-evolution** | 模型/数据/规则迭代改进，不依赖持续人工标注。 |
| **ontology rule** | 本体上的约束/关系，可用来检查不一致。 |
| **root concept** | 人工选定的种子概念；本体扩展的起点。 |
| **training-side** | 改模型参数/训练数据，不是在推理时加检查。 |
| **inference-time constraint** | 每次调用时执行的规则/检查器（本文不是）。 |

## 3. 它怎么做

1. 人工选定根概念（约 15 个）。
2. 从根概念扩展领域本体。
3. 用本体规则检查模型输出/训练样本的不一致。
4. 修正不一致样本，继续训练/迭代。

## 4. 结果：数字与条件

- 摘要级：报告专业域表现提升；**无具体数字、无跨域复现、无独立评测**。
- 条件：需要人工种子；规则覆盖决定能检出什么；训练成本未量化。

## 5. 这些数字不能说明什么

1. **不是推理时约束。** 它不改变 agent 的运行时回路；不能证明「本体在动作前被执行」。
2. **不是通用方法。** 单一/少数专业域；无跨域。
3. **不是无人工。** 15 个根概念是冷启动成本；规则也要人写。
4. **没有量化。** 不能引用为「提升 X%」。

## 6. 工程上怎么用

- 如果目标是**训练侧**注入领域一致性：可以把本体规则当弱标签/过滤器，而不是推理时约束。
- 需要人工种子；规则覆盖决定能检出的错误类型。
- 不适合需要审计/可解释的推理时闸门。

## 7. 质量与边界

- **证据类型**：概念/工程路线（摘要级）。
- **强项**：把本体当训练信号，而不是只当提示词。
- **主要威胁**：无量化、无复现、需人工种子、训练成本未知。
- **`quality: C`**：路线有价值，证据不足。

## 8. 与仓库判断的关系

- **05 生产**：生成/自演化路线之一；不是 01–04 的运行时约束。
- **P2**：训练侧与推理侧是两种 harness；本文只覆盖前者。
- **只作边界证据**：不能支撑「本体提升 agent 表现」。

## 9. 还没解决 / 下一步

- 规则种子能否自动扩展？
- 训练侧注入与推理时约束能否叠加？
- 在强模型上还有多少增益？
- 训练成本/数据效率？
