# SFE-O：一个超临界 CO₂ 萃取本体的工程账本

> 这是一篇 L1 消化：重点不是方法创新，而是它把「本体能表达什么、不能执行什么」写成了清单。

## 0. 三句话

1. **它问什么**：超临界 CO₂ 萃取过程的知识（物料/过程/产品、参数、拓扑）能不能用 OWL 本体组织，并在工程上可用？
2. **它怎么做**：建 SFE-O 域本体：Biomass/Process/Product 三维、过程拓扑、参数溯源；给出建模选择与局限清单。
3. **它发现什么**：OWL 2 表达力够，但**数值不在 OWL 里求解、约束还没变成可执行 SHACL、热物性/扩散系数仍是外部服务**。形式化不是瓶颈，执行/集成才是。

## 1. 它解决什么问题

超临界 CO₂ 萃取：温度/压力/流量、物料特性、产率/纯度；参数来源多、口径不一、数据矛盾。用本体组织，可以支持数据集成、溯源、复用。

## 2. 术语

| 术语 | 用大白话说 |
|---|---|
| **SFE** | 超临界流体萃取。 |
| **OWL 2** | 本体语言；能表达类/关系/约束，但不做数值计算。 |
| **过程拓扑** | 设备/单元操作怎么连。 |
| **参数溯源** | 这个值来自哪篇文献/哪次实验。 |
| **SHACL** | 对 RDF 数据做形状约束；可执行检查。 |
| **外部服务** | 热物性/扩散系数计算等 OWL 外的东西。 |

## 3. 它怎么做

- 三维：Biomass（原料）、Process（过程）、Product（产物）。
- 过程拓扑：单元操作/设备/流。
- 参数：值 + 单位 + 来源 + 条件。
- 数据矛盾：显式标记，不静默修正。

## 4. 结果：数字与条件

- 概念/域本体；**无量化结果、无 agent 评测**。
- 主要产出是建模经验与局限清单。

### 4.1 这些判断之间的逻辑

- **OWL 表达力够，但不做数值求解。** 热物性/扩散系数在 OWL 外；约束还没落成 SHACL。
- **数据矛盾是真实存在的。** 界面面积公式两处不一致、ChEBI 标识符被两种脂肪酸共用；作者选择显式标记。
- **域本体的价值在溯源/集成，不在推理。** 参数来源、过程拓扑、外部服务边界才是工程可用性核心。

## 5. 这些数字不能说明什么

1. **不是「本体能执行过程」。** OWL 不做数值求解；约束要落 SHACL/代码。
2. **不是通用域。** 单一萃取域。
3. **不是 agent 证据。** 没有下游/推理实验。
4. **数据矛盾未解决。** 作者选择显式标记，不是修正。

## 6. 工程上怎么用

- 建域本体时，先列「哪些数字必须由外部 solver/服务算」；不要假装 OWL 能算。
- 约束要落成 SHACL/代码，否则只是文档。
- 参数溯源/单位/条件要进本体；否则无法复用。
- 数据矛盾要显式标记，不要静默消解。

### 6.1 最小落地

1. 先列「哪些数字必须由 solver/外部服务算」；不要假装 OWL 能算。
2. 参数带单位/来源/条件；否则不可复用。
3. 约束落成 SHACL/代码；否则只是文档。
4. 数据矛盾显式标记，不静默消解。
5. 给外部服务建版本/审计边界。

## 7. 质量与边界

- **证据类型**：域本体工程（摘要级/概念）。
- **强项**：局限清单具体；参数溯源；矛盾显式化。
- **主要威胁**：无量化、单域、无 agent 评测。
- **`quality: C`**：工程经验有价值，证据不足。

## 8. 与仓库判断的关系

- **05-L4（已核）**：表示不是瓶颈，执行才是；OWL 表达力够，数值/约束/服务在 OWL 外。
- **P1**：域本体的价值在溯源/集成，不在推理。
- **只作边界证据**：不能证明本体提升 agent。
