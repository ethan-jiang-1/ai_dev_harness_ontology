# GB/T 35273-2020 信息安全技术 个人信息安全规范

> 本卡只核到**官方登记页**（全国标准信息公共服务平台，抓取 2026-11-10）：标准号、中英文名称、状态、发布/实施日期、CCS/ICS、主管与归口。**正文未取**——页面「在线预览」依赖浏览器渲染，`web_fetch` 只返回登记页源码；因此本卡不写任何条款号，正文层面的说法一律 `推测`/`待核`。同目录也没有 `gbt-35273.md` 原文存档，这条「原文 + 卡」的配对目前只有卡。

## 它主张什么

1. **定义两类对象，并区别对待**：个人信息、个人敏感信息；敏感信息触发更严的同意与处理要求（`推测`；条款 `待核`）。
2. **按处理环节给组织提要求**：收集（最小必要、告知同意）、保存（存储期限、去标识化）、使用（访问控制、展示限制）、共享/转让/公开披露、删除（`推测`；分章与条款 `待核`）。
3. **它是「组织应满足什么要求」的规范**，不是数据分级规则、不是策略语言，也不给 `级别 × 主体 × 动作` 的 allow/deny 表（`推测`，范围/时序推断；正文核对 `待核`）。

## 场景与 scope

- **发布 2020-03-06、实施 2020-10-01、状态「现行」**；`GB/T` 前缀 = 推荐性国家标准，不是强制标准。「推荐性」不等于无约束——常被法规、监管文件与行业实践当参考基线引用，但引用关系本身 `待核`；作为合规依据的法律地位 `待核`。
- **适用对象**：个人信息处理者（组织）对个人信息主体的处理活动，覆盖处理全流程 + 组织管理措施（适用范围原文 `待核`）。
- **不覆盖**：数据的机密性分级（核心/重要/一般）、策略语言（XACML/ODRL/Rego/ReBAC）、执行点（PEP/读路径）。本标准只从「个人信息」这一个维度切分，切出来的是**类别**与**处理要求**，不是**级别**。
- 「不含」是**范围与时序推断**：35273-2020 早于《数据安全法》（2021 年施行）与 GB/T 43697-2024，核心/重要/一般 三级不属于它的语汇（`推测`）。**未读正文，条款级核对 `待核`**，不要把这句写成结论。

## 证据强度

- **一手还是转述**：一手，但只到登记页（元数据级）；`provenance: 原文摘要` 指的就是这一层，不是标准正文摘要。
- **有数据吗**：无。标准是要求文本，不含测量、样本或效果数字。
- **数据规模与场景**：无统计口径；覆盖面 = 中国境内个人信息处理活动（适用范围原文 `待核`）。
- **可复现吗**：元数据可复现（同一 URL，抓取日 2026-11-10）；条款不可复现（在线预览需现代浏览器，`web_fetch` 与 `c.gb688.cn` 预览端点均取不到文本）。
- **证据等级**：登记页字段 `已核`（逐字读到）；「定义 PI/敏感 PI、按环节提要求」= `推测`（范围 + 公开常识，未核正文）；条款号、清单、是否给授权判定 = `待核`。
- **不能当**：不能当「中国监管要求全文」引用；不能当 04 C.2 的 level 来源；不能当「个人信息=个人敏感信息」的判据。

## 待核项

- [ ] **条款号**：个人信息/个人敏感信息的定义在第几章条、各处理环节要求分布在哪几章——需正文或官方在线预览（本次 `web_fetch` 只拿到登记页；预览需 Chrome/Edge 等浏览器）。不核到就永远不写条款号。
- [ ] **个人敏感信息清单**：是否以附录形式列清单、条目有哪些（身份证号、生物识别、健康、金融账户、行踪轨迹等是否在内）。清单决定它能不能当 tag 的类别来源，也决定 04 C.2 的 SSN/Phone 能不能指回标准。
- [ ] **是否给「授权」判定**：只要求「征得授权同意（含单独/明示同意）」，还是也要求访问控制的最小授权规则？若只到前者，它连「处置」都不算给全；若到后者，要看清是否到 principal 粒度——这是 F3 能否后退的关键。
- [ ] **与 GB/T 43697-2024 的衔接**：PI / 敏感 PI 两类与 核心/重要/一般 三级是什么关系，能否映射（两套分类的切口不同：一个按主体权益，一个按数据影响）。
- [ ] **发布单位**：登记页「发布单位」栏为空；发布主体（国家市场监督管理总局 / 国家标准化管理委员会）待核，勿在引用中写死。
- [ ] **原文存档**：补 `gbt-35273.md`（正文 markdown 或 PDF 路径），否则本卡无法升到 `原文正文`。
