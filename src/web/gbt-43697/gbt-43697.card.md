# GB/T 43697-2024《数据安全技术 数据分类分级规则》

> **读到哪**：只读到标准详情页的「标准摘要」栏与元数据，**全文未获取**。因此本卡不写任何条款号，凡涉及条文位置一律 `待核`；三级名称与定义取自央视报道（转述），非标准原文。

## 它主张什么

1. **它给的是「怎么定级」的规则，不是「谁能不能读」的规则**：标准规定数据分类分级的**原则、框架、方法和流程**，并给出**重要数据识别指南**；内容清单的落点全部是「把数据归到某个类别与某个级别」。
2. **级别是三级，从高到低为核心数据、重要数据、一般数据**：定级依据是数据在经济社会发展中的重要程度，加上一旦泄露/篡改/损毁/非法获取/非法使用/非法共享，对国家安全、经济运行、社会秩序、公共利益、组织权益、个人权益的危害程度；「重要数据」有专门识别指南，「一般数据」是两级之外的兜底。
3. **边界写在标准自己身上**：适用于行业领域主管（监管）部门参考制定本行业本领域标准规范、各地区各部门开展分类分级工作、数据处理者参考；**明确不适用于涉及国家秘密的数据和军事数据**。

## 场景与 scope

- **谁在用**：三类使用者——行业主管（监管）部门（据此定本行业规范）、各地区各部门（据此开展工作）、数据处理者（据此自查）。标准是**参考性上位框架**，不是可直接执行的配置。
- **管什么**：分类的维度与原则、分级的框架与流程、重要数据识别、由谁在哪个环节定级。
- **不管什么**（据摘要的内容清单判断，全文待核）：
  - **不定义策略语言**：没有 policy / rule / permission 一类的表达结构；
  - **不给出 principal / action → effect 的映射**：不回答「level 3 的列，analyst 能不能读」；
  - **不含国家秘密数据与军事数据**：这两块走其他规范体系，本标准明确排除；
  - 因此它能支撑的是**等级词表与定级流程**，不能支撑**访问控制判定**。
- **术语注意**：本标准的「一般数据」≠ 04 的 `level 1`；「核心数据」有行政评估成分（经国家有关部门评估确定），不是纯工程分类。

## 证据强度

- **一手还是转述**：摘要与元数据是一手（标准摘要原文，经 yzbzpt 第三方标准信息服务平台转载，非 openstd 官方原件）；三级名称与定义是**转述自央视新闻报道**（2024-04-08），**正文未读**，故 `provenance: 原文摘要`。
- **有数据吗**：无实验数据。标准类素材的证据力来自规范文本本身，不来自数据。
- **等级**：
  - 「规定了原则/框架/方法/流程，给出重要数据识别指南」「不适用于涉及国家秘密的数据和军事数据」「发布 2024-03-15、实施 2024-10-01、TC260 归口、SAMR 主管」——`已核`（摘要页与元数据可直接核）。
  - 「三级：核心/重要/一般」——转述来源明确（央视报道逐条给出三级定义），但**未核对标准原文**，记 `待核`；标准摘要页本身没有逐字列出三级名称。
  - 「不给 principal/action 映射」「不含策略语言」——`推测`（依据摘要所列内容范围推断；要升需全文逐章核对，目前只能写「没看到」，不能写「证明没有」）。
- **可复现吗**：摘要级可复现（任何人打开摘要页都能核到上述语句）；条款级不可复现（全文未获取）。

## 原文摘录

标准摘要（「标准摘要」栏，逐字）：

> 本文件规定了数据分类分级的原则、框架、方法和流程。给出了重要数据识别指南。

> 本文件适用于行业领域主管（监管）部门参考制定本行业本领域的数据分类分级标准规范。也适用于各地区、各部门开展数据分类分级工作，同时为数据处理者进行数据分类分级提供参考。

> 本文件不适用于涉及国家秘密的数据和军事数据。

三级与定级依据（**转述**自央视新闻报道 2024-04-08，非标准原文）：

> 根据数据在经济社会发展中的重要程度，以及一旦遭到泄露、篡改、损毁或者非法获取、非法使用、非法共享，对国家安全、经济运行、社会秩序、公共利益、组织权益、个人权益造成的危害程度，将数据从高到低分为核心数据、重要数据、一般数据三个级别。

> 重要数据是指特定领域、特定群体、特定区域或达到一定精度和规模的，一旦被泄露或篡改、损毁，可能直接危害国家安全、经济运行、社会稳定、公共健康和安全的数据。仅影响组织自身或公民个体的数据一般不作为重要数据。

> 一般数据是核心数据、重要数据之外的其他数据。
