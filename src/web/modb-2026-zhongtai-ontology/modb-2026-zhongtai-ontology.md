## 摘录

中泰证券以数据领域的知识管理实践为重点，围绕业务知识分散、指标口径难以准确调用等问题，将元数据、指标定义、数据标准和血缘关系组织为可检索、可追溯的数据治理知识，并通过自研 DataAgent 平台用于实际数据开发与业务分析。在此基础上，公司已启动业务本体演进探索，在信用业务经营分析场景中开展验证。

治理知识底座沿着资产采集、知识加工、语义组织和应用调用逐层建设。底层复用元数据、指标五要素、数据标准、血缘及质量规则；知识工程环节完成采集、语义补充、证据核验与索引构建；知识与语义层统一组织定义、关系、计算规则及约束，供上层智能体和开发工具调用。

中泰证券治理知识库已形成 9,137 份知识目录、6,503 个指标文档、2,622 张可检索表和 12 万余条物理血缘关系。在这些知识之上，中泰证券研发了元数据探查、治理问数 SQL、ODS 标准映射、元数据批量补全、敏感数据识别五项治理 Skill。

五项 Skill 均已部署于自研 DataAgent 数据智能分析平台，接入公司私有部署的大模型。开发人员可以用自然语言提出需求，由智能体选择工具并调用相关知识。平台提供 Agent、Skill、数据集及行列级权限管控，并记录意图识别、工具调用和数据返回过程。

中泰证券选择从现有治理资产逐步推进：先将指标定义整理为机器可执行的稳定口径，再识别客户、账户、产品等核心对象及其关系，围绕高价值场景按需实例化，逐步连接指标计算与应用调用。稳定的对象、身份和关系进入本体，多口径、变化较快的规则与事实证据继续由治理语义层维护。

知识载体采用开放知识格式（OKF），参考 Google Cloud 的开放知识格式和 Anthropic 的仓库化知识实践，以带有轻量结构化头部的 Markdown 文件保存知识。一份文档既能供人员阅读和审核，也能被检索系统定位，为智能体提供上下文，并支持后续 SQL 校验。采用开放文件形式，也便于版本比较、来源追踪和跨工具复用。

知识存储和维护也将随之完善。现有 OKF 文件继续作为权威源与交换格式，后续规划引入图数据库支持血缘穿透和对象关系计算，引入向量数据库支持经验性知识的语义检索，并通过知识管理平台支持业务人员审核与更新。

## 工作组背景（摘录）

工作组已成立本体工程、知识管理专家委员会，颁发首批专家证书，搭建本体和知识管理标准体系，已推动立项《本体建模技术要求》《本体智能平台技术要求》《知识管理能力成熟度模型》行业标准，启动《本体工程能力成熟度模型》标准研制，以及《本体智能研究报告（2.0）》《知识管理研究报告》撰写工作。
