# 中泰证券·本体与知识管理实践（CCSA TC601 WG15 案例分享）

> 这是行业社区对中泰证券在 CCSA TC601 WG15「本体与知识管理工作组」案例分享的报道。它比 QCon 议题页多出**治理知识库的规模数、平台部署、本体演进的边界**。

## 它主张什么

1. **先复用治理存量，不从零建本体**：把元数据、指标五要素、数据标准、血缘、质量规则组织成可检索、可追溯的治理知识；再向业务本体演进。
1b. **载体是 OKF**：知识用**开放知识格式（OKF）**组织——参考 Google Cloud 的 OKF 与 Anthropic 的仓库化知识实践，以**带轻量结构化头部的 Markdown** 保存；现有 OKF 文件继续作权威源/交换格式，后续再上“图数据库（血缘穿透/对象关系计算）+ 向量库 + 知识管理平台”。**OKF 是写模型/权威源，图与本体是读模型/派生位**，不是“OKF 被本体取代”。
2. **规模**：治理知识库已有 **9,137 份知识目录、6,503 个指标文档、2,622 张可检索表、12 万余条物理血缘关系**；五项治理 Skill 已部署在自研 DataAgent 平台，接入私有部署大模型，提供 Agent/Skill/数据集及行列级权限管控与过程审计。
3. **边界**：数据领域的“治理语义层”已在生产使用；**业务本体仍在信用业务经营分析场景验证**（“已启动业务本体演进探索”），不是全公司本体生产系统。
4. **失败/约束**：事实与解释分开（技术事实由程序整理，模型解释必须过来源证据核验）；检索依据不足继续查、口径不明向用户澄清、核心字段缺证据返回缺口清单、校验不通过不交付 SQL；模型处理失败时保留程序生成的事实文档，没有依据的语义内容剔除。

## 场景与 scope

- 中泰证券（单一券商）的数据治理/数据分析场景；案例在 CCSA TC601 WG15 分享，属于行业标准工作组的案例征集，不是第三方审计。
- 规模数是**知识库/指标文档/表/血缘**的数量，不是“本体实体数/查询量/用户数”；不能把它当成全公司本体覆盖。
- “本体”在这里分两层：治理语义层（指标/元数据/血缘，生产）与业务本体（客户/账户/产品/关系，验证）。两者不要混。

## 证据强度

- 一手/转述：行业社区对讲者分享的报道；讲者是中泰证券大数据中心经理。属于“公司生产系统报告”的二手文字化，但仍有一手讲者与标准工作组场景。
- 有数据吗：有规模数（9,137/6,503/2,622/120k+）；无成本（人月/金额）、无查询量、无准确率、无失败率。
- 可复现吗：不可；但“三泳道生产 + 检查门禁 + 证据不足不交付 SQL”是可对照的工程做法。
- 证据等级：作为“中泰报告了这些规模与做法”是 `已核`；作为“这套做法普遍有效”是 `推测`。

## 与已有判断的关系

| 结论编号 | 关系 | 说明 |
|---|---|---|
| E-28（平台承载） | 强支持 | 本体建设复用指标/元数据/血缘治理资产；先语义层、后业务本体 |
| E-29（失败模式） | 支持 | 事实/解释混淆、无依据语义、口径不明、权限/聚合泄露是主要风险 |
| E-30（成本拐点） | 旁证 | 6,503 指标文档、12 万血缘说明“治理存量”是重资产；LLM 只做摘要/别名/问法，事实仍由程序整理 |
