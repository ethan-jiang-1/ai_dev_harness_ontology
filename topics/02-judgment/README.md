# 02 判定派：怎么知道它做错了

## 核心主张

**判据必须外部、且必须可度量。**

「挂个本体就变准」是本派最想否掉的直觉。The Ontology Catch 把判定器本身当研究对象，结论是：判定器也是一个会犯错的法官——它会漏掉错误，也会把正确答案标错，并把 agent 推去「修复」本来没错的东西。

所以本派的工程问题不是「用不用本体」，而是**这条漏检/误报曲线在哪**。

## 三种判定形态

| 形态 | 判据 | 强 | 覆盖 | 备注 |
|---|---|---|---|---|
| 格式判定 | 语法 / schema | 强 | 窄 | 便宜，先做 |
| **语义判定** | 本体 / 业务规则 | 中 | 中 | 本派主战场 |
| 行为判定 | 测试 / 真实调用 | 强 | 窄 | 最贵，后做 |

三者是**串联**关系：格式不过关不该进语义判定，语义可疑不该触发行为判定。

## 两条硬结论

1. **curated 不等于可靠。** 在 UniProt 上，curated 本体误报的正确答案比数据派生的本体更多；在真实 agent 答案上，它的标记精确度**仅略优于随机**。按发布状态使用的 curated schema 甚至可能与自身数据矛盾。
2. **证据等级要显式化。** OA-RAG 让每个答案强制报告所用作证据的本体观察 + grounding 等级（entailed/supported/related/unrelated），在三个大规模本体、六个医学问答任务上整体最优。

## 误报比漏检更贵

漏检只是放过一个错误；误报会让 agent 去改对的东西。后者会产生**新的、更隐蔽的错误**——因为它带着「已修复」的外观。

这条推论目前是**推测**，但与本派的失败模式一致，值得做成实验（见 [EXP-002](../../experiments/README.md)）。

## 何时用 · 何时别用

**用**：产出可被结构性检查（有 schema、有约束、有可查的关系）；需要在不看全量人工复核的前提下筛出可疑项。

**别用**：判定器与生成器同源（自我审核几乎总失效）；没有标注集就无法知道曲线，此时判定器只是给人一种安全感。

## 开放问题

- 串联判定时，早期误报如何避免放大成下游大量无效工作？
