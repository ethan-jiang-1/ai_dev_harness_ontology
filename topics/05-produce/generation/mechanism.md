# 生成 · 机制

## 问题

多数本体文献默认本体已经存在；真实项目第一步往往是「造一个」。造法不止一种，来源决定它能被信到什么程度，也决定系统性偏向。

## 四条路线

| 路线 | 做法 | 代表 | 系统性偏向 |
|---|---|---|---|
| 专家手工 | 建模规范 + 评审 | SFE-O | 覆盖窄、维护贵、易过时 |
| LLM 生成 | 多 agent 流水线生成描述/关系 | OntoDoc、ReX-GG | 语义漂移、关系方向易错 |
| 表征挖掘 | 从冻结嵌入里抽层级 | Peeling | 只在特定嵌入族上成立；未测下游 |
| 规则引导自演化 | 用少量本体规则驱动自检/重训 | Evontree | 需要人工种子（15 个根概念） |

「数据挖掘」是第五种，但本仓库 22 篇里没有独立案例，暂并入「表征挖掘」。

## 证据

- **OntoDoc**：151 术语、3 知识图；completeness 3.43→3.84；模板 verbalizer 1.2–3.2；假设层 win 54–61%；11 人人工评估。**没有测下游任务。**
- **ReX-GG**：七模型集成 + JSON + 匿名互评；用户研究感知准确率 0.778（`摘要级`）。
- **Peeling**：98K 探针在冻结嵌入上抽分类，Graph F1 0.885/0.931；**明确未测下游**（`摘要级`）。
- **Evontree**：少量本体规则驱动自检/重训；需 15 个人工根概念（`摘要级`）。

## 核心判断

**生成产出的是候选，不是「完备本体」。** 能证明「能生成可读、部分正确的结构」，不能证明「能被下游判定器直接消费」。两者之间隔着「可消费性」评估，目前缺。

**OntoDoc 的可迁移设计**：先写 assumptions（reasoning + triple 引用）再写描述；DB context 权威、web 只补充；自适应 SPARQL 探索而非单跳查询。

## 失效模式

- **语义漂移。** 关系看似合理，方向/边界错。
- **把「常见」当「应然」。** 高频模式被写成约束。
- **只测完整性。** 说明更全 ≠ 下游任务更好。
- **无来源标记。** 判定器不知道约束是专家写的还是模型编的。
- **假设层信息损失。** OntoDoc 漏掉的关键细节后面拿不回来。

## 与本体 / 回路的关系

本体在生成阶段是 **产物**；约束强度取决于生成后的校验。被违反时通常没有即时信号，需要 checker/人审。
