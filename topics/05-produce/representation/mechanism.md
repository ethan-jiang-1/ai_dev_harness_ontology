# 表示 · 机制

> 机制判断与三档划分见 [README](./README.md)；本页补的是「消费位置 → 可执行产物」这一步与实施层，不重复论证。SFE-O 的事实引自其 [digest](../../../meta/audits/2026-11-11-source-purge.md#src-2610-37123)（单域、无量化、无 agent 评测、`quality: C`）。digest 的「工程配方（E3）」（5–10 条 shapes、字段、工时）是消化者建议，不是论文产物；论文明确说约束尚未成为可执行 SHACL shapes。凡标 `推测` 的是本页的实施建议、阈值或人日，不是论文数字。第三处数据矛盾 digest 未收，见 [findings/F1](./findings.md) 与 card。

## 机制速览：从消费位置到执行落点

| 消费位置 | 够用的表示 | 执行落点 | 过度的信号 |
|---|---|---|---|
| 上下文注入（弱） | 词表决 + 少量结构 | 投影文本 / 检索索引 | 形式化不产生约束，只占上下文预算 |
| 判定器（强） | 结构表（概念 + 关系 + 基数/范围） | SHACL / 代码检查 | 约束只写在注释或文档里，判定器看不见 |
| 记忆槽位（中） | 结构表（槽位与关系定义） | 槽位 schema + 更新校验 | 模式过重，状态更新成本高于收益 |
| 授权判据（最强） | 结构表（可由事实直接查询的谓词） | 事实查询，不依赖推理链 | 谓词要推理才成立，授权时延不可接受 |
| 需要隐含结论 | 逻辑表（类公理） | reasoner（例外路径） | 结论不可解释，推理成本不可预测 |

这张表不是 README 的复述：README 回答「需要什么能力」，这里回答「落到哪个可执行物、什么算过度」。这些映射仍是 `推测`——SFE-O 只能证明逻辑档不自动带来执行，不能证明结构表覆盖大多数判定场景。

## 实施与客户价值（A3/A4）

### 实施决策

1. **先写消费者契约，再选表示档位。** 立项时先填「谁在什么时刻读这份表示、要拒绝或回答什么」：消费者只把知识拼进上下文（prompt/检索），停在词表决 + 少量结构；有判定器加载约束或记忆槽位做状态校验，用结构表 + SHACL；只有必须从公理推出隐含分类/授权谓词、且能承担解释与推理成本时，才上逻辑表。SFE-O 反证的是「逻辑档自动带来可执行性」：OWL 2 表达力够，但数值、约束、外部服务都在 OWL 外；该文把约束落成可执行 SHACL 列为待办，没有交付 shape。**改变：选型评审的第一个问题是「消费者是谁」，不是「模型完不完备」。**

2. **约束必须有执行落点，否则按文档验收、不按本体验收。** 每条声明的约束配一个 shape（或代码检查）加一个已知能触发它的负例。digest 的 E3 建议是 5–10 条 shapes（单位必填、参数范围、source 必填、矛盾标记、单元操作连接），但这是待做清单：SFE-O 没有实现任何 shape，不能把 5–10 条当已验证的覆盖。负例用两处**确定**矛盾（界面面积公式、ChEBI 标识符共用），再加第三处**疑似**矛盾（床体积疑似缺几何因子）并单独标 `possible`——原文用 "possibly"，不能当 confirmed 错误。**改变：DoD 从「模型评审通过」改为「负例能标红、干净数据不误报、消费者能拿到报告」；预算先给 shapes，不先扩类层次。**

3. **参数按记录入库，不按裸值入库。** digest 的 E3 参数记录含 `{value, unit, source, condition, confidence, contradicts[]}`（字段是建议，不是论文 schema）；论文侧只给值/单位/来源/条件与显式矛盾标记。缺 unit/source 即拒收；矛盾显式标记、保留两侧来源，交人裁决，不静默选一个。SFE-O 报告三处数据层不一致：界面面积公式两处冲突、ChEBI 标识符被两种脂肪酸共用（确定），以及床体积表达式疑似缺一个几何因子（原文 "possibly"，未定论）；三处都在本体里 flag，不静默修正。这说明冲突要显式建模，不能假设一份数据只有一个真值（`推测`）。**注意：`confidence` 与 `contradicts[]` 怎么联动，digest 和论文都没有定义；论文只做显式标记，没有测矛盾是否该降下游置信度。`contradicts[]` 至少要有 `confirmed` / `possible` 两级状态。** **改变：数据接入校验与冲突处理流程；「以最新值为准」这类默认合并规则要废掉。**

4. **数值计算外置为带版本的服务，本体只存结果与边界。** 热物性/扩散系数这类量不在 OWL/SHACL 里算；服务契约记为 `{inputs, outputs, service_version, retrieved_at, audit_id}`，结果写回参数记录。**改变：架构上不把公式硬编码进本体；服务版本纳入本体版本与审计；没有服务 owner 就不启动这条。**

5. **人读视图与机读约束同源生成，禁止双份手工维护。** 从同一份结构表生成词表/文档与 shapes/查询；生成物只读，改动回源。README 把「两种表示并存且不同步」列为失效模式；SFE-O 没有验证同源生成是否可行，所以这是 `推测` 的工程约束，须在 sprint 里用一次再生成验证。**改变：仓库只留一份权威源，评审检查生成物是否落后于源。**

### 数据/接口

**最小结构（SFE-O 的三模块 + 参数；字段名是 digest E3 版本）**

- 类：`Biomass`、`Process`、`Product`、`Parameter`、`UnitOperation`、`Stream`。
- 关系：`hasParameter`、`unit`、`source`、`condition`、`confidence`、`contradicts`；过程拓扑用 `UnitOperation—Stream` 连接。
- 参数记录：`{value, unit, source, condition, confidence, contradicts[]}`；矛盾保留两侧的 value/source，不做「取平均」或「取最新」。
- 命名空间与版本：`sfeo:<version>`；本体定义与实例数据分开版本。

**SHACL / 检查接口（digest E3 建议，不是论文产物）**

- 5–10 条 shapes，至少覆盖：单位必填、参数范围、source 必填、矛盾标记存在、单元操作连接完整。这是 digest 的 E3 起始清单；SFE-O 的约束尚未成为可执行 shapes，所以覆盖与误报都没有论文数字。
- 校验输出本页建议为 `[{focus_node, path, constraint, severity, message, source}]`；`source` 指回参数记录，便于从「标红」追到「哪条来源」——报告字段是本页的接口建议（`推测`）；digest E3 只给 shape 类别，没有报告 schema，论文也没有实现。报告只说明「违反/未违反哪条 shape」，不回答「这批数据能不能用于决策」；判定器角色未测（[findings/F2](./findings.md)）。
- 数据接入闸门：缺 unit/source 直接拒收；范围检查交给 shape；矛盾写入 `contradicts[]`（元素带 `status: confirmed|possible`），不阻断入库但阻断下游判定（后一条是本页建议，`推测`）。

**外部服务边界（digest E3 契约；SFE-O 只把外部服务列为集成点）**

- 契约：`{inputs, outputs, service_version, retrieved_at, audit_id}`；调用前校验输入单位（本页建议），调用后把结果连同 `service_version/retrieved_at/audit_id` 写回参数记录。字段集是 digest E3 的建议，不是论文给出的接口。
- OWL 不求解数值：按 SFE-O 的边界，外部服务结果应作为「一次带版本的计算记录」写回参数，而不是当成本体公理（`推测` 的架构表述）。SFE-O 只把外部服务列为集成点，没有实现或测过调用成本。

**消费者接口（本页建议，`推测`）**

- `validate(graph) -> report[]`：判定器/CI 用；报告必须能定位到参数记录。
- `provenance(parameter_id) -> {value, unit, source, condition, confidence, contradicts[], service_version, retrieved_at, audit_id}`：审计/复用用。
- `to_text(scope)`：上下文注入用；从同一份源生成，可选，不承担约束职责。

**变更触发**

- 参数、单位、source、服务版本任一变更 → 重跑 shapes → 重生成文档/投影 → 递增版本。生成物被手工修改视为故障，不能当作热修复（`推测` 的工程约束）。

### 组织/成本

| 角色（owner） | 负责 | 工时 |
|---|---|---|
| 领域工程师 | 域本体/流程建模、参数与单位/来源/条件、三处数据不一致核对 | 2–4 人周 |
| 知识工程 / SHACL | 5–10 条 shapes、负例、报告格式 | 3–5 人日 |
| 平台/后端 | 外部服务契约与 mock、版本/audit_id 落库、接入校验 | 1–2 人周 |
| 数据 owner | 存量参数补 source/unit、矛盾裁决 | SFE-O 未给；本页 `推测` 与建模同量级或更高 |
| 维护 | 参数/服务版本变更后的重校验与再生成 | 持续；`推测` 0.5–1 人日/月/流程 |

**人日口径（`推测`）**：2–4 人周与 1–2 人周是 digest 自标 `推测` 的 E3 估算，论文没有成本数据；digest 把它们写在「2 周、一条 3–5 单元操作流程」的配方里，但没有绑定流程条数/团队规模，不能外推到任意流程规模。3–5 人日（SHACL）同样没有测量——论文并未实现 shapes。sprint 出口用预注册预算与实录工时，不拿这些数字当硬门。

**运行成本**

- 本页假设 SHACL 校验与查询的计算成本相对数据整备可忽略（`推测`，未测）；论文没有成本数字。大头是人工补来源、裁决矛盾、维护 shapes，不是推理。
- 外部服务通常按调用或按实例计费（本页 `推测`；SFE-O 未给单价）；旧版本服务若需保留以支持审计，运行成本会上升（`推测`）。
- SFE-O 没有 agent 评测，因此没有 token/上下文成本数据；若把表示投影进上下文，成本取决于投影体积，本页不估。

**build / buy / 不做**

- 替代方案：关系库 + 脚本；YAML/JSON schema；纯文档 + 人工核对；商业流程模拟器。SFE-O 列了这些方案但没有成本对照，sprint 必须把其中一个当基线测，否则无法判断本体是否划算。

### stop condition

开工前写死，命中即停：

1. **没有消费者 → 停。** 没有判定器、查询、授权或 agent 真的读这份表示，只做文档，不做「可执行本体」（SFE-O）。
2. **约束落不成 SHACL/代码，或找不到能触发它的负例 → 停。** 这时的「本体」只是文档（SFE-O）。
3. **参数缺 source/unit 且补不齐 → 停。** 先修数据；不可复用的参数不进本体（SFE-O）。
4. **数据矛盾未标记或未裁决 → 停。** 不把带冲突的表示交给下游判定；`possible` 不得自动当 `confirmed`，疑似矛盾要人裁（SFE-O + [findings/F1](./findings.md)）。
5. **需要数值求解但没有外部服务 owner/版本方案 → 停。** 不假装 OWL 能算（SFE-O）。
6. **消费者只是上下文注入 → 停在词表档。** 不建 OWL/SHACL；「形式化只占预算」是本页假设，未测（README 失效模式）。
7. **生成物被手工改、与源不一致 → 停并回源。** 双份不同步会让下游读到互相矛盾的规则（本页 `推测`，README 失效模式）。
8. **经济线：** 年省返工/集成工时 × 工时价 < 建模摊销 + shapes + 服务集成 + 年维护 → 停。没有工时价就先测分母，不拍板（`推测`）。

### 第一个 sprint

**范围**：2 周、一条 3–5 单元操作流程、一个真实消费者；只做结构表 + SHACL + 外部服务边界，不做全本体、不接 reasoner、不碰生产写路径。

| 天 | 做什么 | 产出 |
|---|---|---|
| D1–2 | 选流程与消费者；列参数与约束；盘点 unit/source 缺口 | 流程范围 + 消费者契约 + 约束清单 |
| D3–5 | 建三模块 + 参数记录；导入覆盖所有 shape 的一批真实记录 | schema v0 + 参数记录样本 |
| D6–7 | 写 5–10 条 shapes；用两处确定矛盾 + 一处疑似矛盾做负例（疑似单独标 possible） | shapes v0 + 负例集 |
| D8 | 外部服务 mock；落 `service_version/retrieved_at/audit_id` | 服务契约 + 审计字段样例 |
| D9 | 消费者跑 validate/provenance；统计干净记录误报 | 校验报告 + 误报统计 |
| D10 | 工时实录；对照方案（YAML/关系库）估算；写 go/no-go | 工时表 + go/no-go memo |

**交付物**：schema v0 与参数记录规范；5–10 条 shapes；三处数据矛盾的负例结果（两处确定 + 一处疑似）；外部服务契约 + mock + 审计字段样例；一个消费者接入并可读的报告；建模/shapes/集成工时实录；与 YAML/关系库基线的对照计划；一页 go/no-go。

**出口（全满足才进第二阶段）**：

- digest 建议的 5 类 shape 全覆盖（单位、范围、source、矛盾、单元操作连接）；这是 E3 清单，不是论文验证过的覆盖。
- 两处确定矛盾 2/2 被标红；第三处疑似矛盾至少标为 `possible`（不要求判成错误）；干净记录误报 ≤5%（本页建议阈值，`推测`）。
- 消费者能在真实或 shadow 路径上读到报告，而不是只跑通脚本。
- 实际工时对照立项时预注册的预算，而不是拿 digest 的 2–4 人周当验收线——那是 digest 自标 `推测` 的估算，且未绑定流程条数/团队规模；超支则降级为 YAML/关系库方案或只交付文档。
- 不满足 → 只交付参数整备 + 文档，不称「可执行本体」。

### 客户指标/V3

**受益者与痛点**

- 工艺/领域工程师：参数口径不一、单位缺失、复用前要重新核对。
- 数据/知识维护者：来源散在文献与记录里，矛盾靠人记。
- 判定器/agent owner：约束写在注释或文档里，加载不了。
- 审计/合规：答不出「这个值哪来的、哪个服务版本算的」。

指标定义与口径是本页建议（`推测`）；SFE-O 没有客户指标，digest 只给 shape 类别、论文未实现 shapes。

| 指标 | 定义 | 当前值怎么拿 |
|---|---|---|
| 参数记录完整率 | 有 unit + source + condition 的记录 / 总记录 | 对导入清单抽样 |
| 约束可执行覆盖率 | 有 shape + 负例的约束 / 声明的约束 | 约束清单 vs shapes |
| 已知矛盾检出率 | 被标红的已知矛盾 / 已知矛盾清单 | 负例集回放；区分 confirmed 与 possible |
| 误报率 | 干净记录被 shape 拒绝的比例 | 干净记录回放 |
| 溯源查询时间 | 从参数查到 source/condition/service_version 的耗时 | 人工计时或查询日志 |
| 数据接入返工工时 | 每次接入因单位/来源/冲突返工的工时 | 工单/工时记录 |
| 外部服务可审计率 | 带 `service_version/audit_id` 的调用 / 总调用 | 服务日志 |
| 下游判定错误/千次 | 消费者按错误参数做出的判定比例 | 只在 shadow 路径可取；SFE-O 无 agent 评测 |

**反事实**：同一流程、同一批记录上，用 YAML/JSON schema + 关系库约束 + 脚本，或纯文档 + 人工核对。SFE-O 明确列了这些替代方案，但没有成本对照；所以「不建本体」不是稻草人，是必须打败的基线。

**试点设计（V3）**：单流程、2 周（本页建议，`推测`）、两臂——A = 结构表 + SHACL + 外部服务边界；B = YAML/关系库约束 + 脚本（或纯文档人工核对）。同一批记录、预注册主指标（已知矛盾检出、干净记录误报、完整率、建模+维护工时），消费者在 shadow 路径使用报告。

**成功 / 失败 / 停止线**（全部 `推测`，客户价值尚未验证）：

- 成功：两处确定矛盾 2/2 检出、第三处疑似至少标 `possible`；干净记录误报 ≤5%；参数完整率 ≥90%；消费者在 shadow 决策中实际使用报告；维护 ≤1 人日/月/流程。
- 失败：两处确定矛盾任一漏检，或第三处疑似未标 `possible`；误报 >10%；消费者不采用报告；维护 >2 人日/月/流程。
- 停止线：`年省返工工时 × 工时价 + 年减少数据事故 × 单次成本 < 一次性建模 + shapes + 服务集成 + 年维护`。没有工时价/事故成本就先测分母，不立项。

**为什么只能标 `推测`**：SFE-O 无量化结果、无 agent 评测、单域、`quality: C`；从「shape 能标红」到「省多少返工/少多少事故」的换算没有来源，不能进 deliverables。

### 反例

1. **YAML/关系库就够，本体是过度工程。** SFE-O 自己列了替代方案且无成本对照；若同一批记录上 B 臂的检出/误报与 A 臂相当，而建模与维护更低，A 不划算。**反例成立的条件**：替代方案能表达跨表关系与参数溯源，且总成本更低；若表达不了，本体仍有理由。
2. **没有执行消费者，形式化退化为文档。** README 的失效模式；此时「覆盖率」是自证指标，行为没有改变。**反例成立的条件**：sprint 内没有真实或 shadow 路径加载 shapes；「以后会用」不算。已有消费者则这条不成立。
3. **数据整备成本可能吞掉收益。** 存量参数缺 source/unit，SFE-O 的 stop 要求先修数据；若补数据比建模更贵，项目会卡在数据上。这时表示层不是瓶颈，正确顺序是先做数据治理——这也是对「表示不是瓶颈」的反向限定。**反例成立的条件**：存量参数大面积缺来源/单位，补数据比建模更贵或无法在 sprint 内完成；数据本已可追溯则不成立。
4. **单域外部效度。** SFE-O 是一个萃取域、无量化、无 agent 评测；换到企业/API 域，「外部服务」是 schema 会变的 API，「来源」是 pipeline ID 而非文献，物性公式的边界不迁移。结论不能直接外推。**反例成立的条件**：目标域的外部服务/来源语义与萃取域差异大；若同样是「参数 + 文献来源 + 外部物性服务」，迁移性较好。
5. **结构表可能不够：授权谓词需要闭包/推理。** README 的默认是停在第二档，但授权判据若要求传递闭包或默认否定，SHACL + 结构表不直接表达，要靠 SPARQL 属性路径或代码外挂，已经不算「停在结构表」；两周 sprint 不会暴露。此时要么上逻辑档并承担解释成本，要么把谓词编译成代码（另一条成本）。**反例成立的条件**：判据需要闭包/默认否定且无法用代码谓词低成本实现；判据都是单跳事实查询则第二档够用。
