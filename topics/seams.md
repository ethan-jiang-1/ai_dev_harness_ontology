# 接缝：本体被执行的六个时刻

这是**时刻轴**，不是派轴。派轴（本体凭什么起作用）见 [01-06](./README.md)；部件轴（接在机器的哪里）见 [00-harness](./00-harness/README.md)。

## 什么算一个接缝

三条同时成立才算：

1. **有外部判据**——判定依据来自本体，而不是模型自评。
2. **有阻断能力**——违反时可以改变走向（剪掉动作、拒绝输出、阻止落盘），而不是只留一条日志。
3. **位置明确**——能指到回路的某一个时刻，而不是「整体上更懂业务」。

只有第 1 条的叫「知识注入」，只有第 2 条的叫「硬编码规则」。**接缝是二者相交。**

## 六个时刻

按时间轴排列，越往后约束越硬：

| # | 时刻 | 文档 | 本体角色 | 违反的后果 | 对应派 / 部件 |
|---|---|---|---|---|---|
| 1 | 动作执行**前** | [action-gate](./01-constraint/action-gate/README.md) | 可逆性分级、参数合法性 | 不可逆动作被执行 | 01 / tools |
| 2 | 输出**时** | [evidence](./02-judgment/evidence/README.md) | 强制附带依据与接地等级 | 无根据的结论流出 | 02 / observability |
| 3 | 输出**后** | [checker](./02-judgment/checker/README.md) | 判定器：查错与纠错 | 不合格产出被放行 | 02 / verification |
| 4 | 持久化**前** | [commit-gate](./01-constraint/commit-gate/README.md) | 授权判据：证据是否足够 | 错误变更落盘 | 01 / governance |
| 5 | 跨**轮** | [memory](./04-state/memory/README.md) | 状态结构：约束、失效、冲突 | 后续判断被污染 | 04 / memory |
| 6 | 跨**运行** | [determinism](./04-state/determinism/README.md) | 一致性锚点 | 同一输入得出不同结论 | 04 / memory |

## 轴外位置（可记录，但不是六时刻）

2026-11-09 起，`seam` 字段除六时刻外还接受四个**轴外位置**。它们对中心问题重要，但不满足「六时刻」的硬闸条件，或还没有第二个独立实现：

| 值 | 位置 | 是否硬闸 | 例子 | 为什么暂不列为第七时刻 |
|---|---|---|---|---|
| `read-path` | 检索结果返回前、进入上下文前 | 是（可阻断） | trustgraph 的 SHACL-AF 策略过滤 | 目前只有 1 个代码实现；等第二个独立实现再决定 |
| `supply` | 供给/编译内部执行 | 否 | ontop 的查询重写、CAI 的编译 | 它改变「给什么」，不直接拦模型动作 |
| `reasoning` | 推理期、动作前 | 是（条件验证） | OntoAct 的三值条件、reasoning-gate | 与 action-gate 的边界尚未稳定；先留在 01 派内 |
| `training` | 训练侧 | 否 | Evontree 的规则筛数据 | 不在推理回路内 |

`none` 只表示「不是上述任何位置」，**必须在 digest 里写清是“回路外”还是“尚未判定”**；不能再把两者混成一个值。

**扩轴规则**：轴外位置要升为第七/第八时刻，需要同时满足（1）≥2 个独立实现/论文；（2）有外部判据；（3）能阻断；（4）能指到回路的一个时刻。当前 `read-path` 只满足后三条，差一个独立实现。

## 三层强度谱，不要混

仓库里有三张「强度谱」，它们不是同一张图的不同详略，而是三种切法：

| 谱 | 切什么 | 在哪 |
|---|---|---|
| 派强度谱 | 机制类型（知识 → 状态 → 判定 → 约束） | [topics/README](./README.md#强度与覆盖率反向) |
| 部件强度谱 | 机器部件（context → memory → … → governance） | [00-harness/README](./00-harness/README.md#约束强度谱) |
| 时刻强度谱 | 介入时刻（上下文注入 → … → 落盘前） | 本页 |

**时刻强度谱**（旧 seams 页的版本，保留作历史对照）：

```
约束强度   弱 ────────────────────────────────▶ 强
覆盖率     广 ◀──────────────────────────────── 窄
位置     上下文注入   记忆   判定   证据   动作前   落盘前
```

这张谱把「上下文注入」和「时刻」混在一行；它只用于说明「越往后越硬」，不要拿它当分类表。分类以派轴/时刻轴为准。

## 六个时刻怎么选

不是都要做。选择依据是**错误的代价**：

- 错误可撤销 → 只需时刻 3（判定）
- 错误会扩散到下游 → 加时刻 2（证据）
- 错误会污染后续轮次 → 加时刻 5（记忆）
- 错误不可撤销 → 时刻 1 或 4（动作前 / 落盘前）
- 要求可复现 → 时刻 6（确定性）

## 与派轴的关系

- **01 约束** = 时刻 1 + 4（动作前 / 落盘前）
- **02 判定** = 时刻 2 + 3（输出时 / 输出后）
- **04 状态** = 时刻 5 + 6（跨轮 / 跨运行）
- **03 知识** = 供给（没有时刻；它不进控制）
- **05 生产** = 本体存在之前（没有时刻）
- **06 测量** = 旁路（没有时刻）

**01-04 是回路内的四个介入点；05 是回路前的来源；06 是回路外的尺子。** 所以「归派只问时刻」只适用于 01-04。

## 与部件轴的关系

| 时刻 | 主要部件 | 说明 |
|---|---|---|
| 1 动作前 | tools-and-sandbox | 动作尚未发生 |
| 2 输出时 | observability / context | 产出格式与证据 |
| 3 输出后 | verification | 判定器 |
| 4 落盘前 | governance | 授权 |
| 5 跨轮 | memory | 状态结构 |
| 6 跨运行 | memory / observability | 锚点与回放 |
