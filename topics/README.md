# topics：六派

流水线的第三个工位。材料在 `notes/` 里被读懂，在这里被综合成**可引用的判断**。

分类轴是**本体凭什么起作用**，不是主题。每一派回答一个工程问题，流派差异在目录名上就能看出来。

## 一句话地图

```
        05 生产          03 知识          01 约束        02 判定     04 状态
      本体尚未存在  ──▶   供给上下文  ──▶   动作前拦截  ──▶  输出后校验 ──▶ 跨轮一致
      来源/精化/演化       投影/编译         可逆性/前置条件    漏检/误报      槽位/冲突

      └──────────────────────── 06 测量：这一切到底有没有用 ────────────────────────┘
```

时间轴从左到右：本体先被造出来（05），再被喂进上下文（03），在执行前拦截动作（01），在产出后校验（02），在轮次之间维持一致（04）。06 是绕在整条链外侧的尺子。

## 六派对照

| 派 | 回答的问题 | 核心工程思想 | 介入时刻 | 约束强度 | 代表 |
|---|---|---|---|---|---|
| [05 生产](./05-produce/README.md) | 本体从哪来、怎么修 | 来源决定可信度；精化比新建常见 | 本体未存在时 | — | CASTON、SFE-O、OntoDoc |
| [03 知识](./03-knowledge/README.md) | 怎么让它知道得对 | **投影优于查询**；编译解决预算不解决准确率 | 供给时 | 弱 | Narrow & Deep、CAI、Grid Agents |
| [01 约束](./01-constraint/README.md) | 怎么不让它做错事 | 安全是**结构问题**：问「存在可逆序列吗」 | 动作前 / 落盘前 | **强** | POLAR、Commit Boundary、OntoAct |
| [02 判定](./02-judgment/README.md) | 怎么知道它做错了 | 判据必须外部且**可度量** | 输出时 / 输出后 | 强 | Ontology Catch、OA-RAG |
| [04 状态](./04-state/README.md) | 怎么让它记得对 | 记忆是**状态**不是集合；本体克制到只定槽位 | 跨轮 | 中 | EvoMemState、FIRME |
| [06 测量](./06-measure/README.md) | 它到底有没有用 | 答对≠内部有本体；失败多归工作流 | 旁路 | 元 | MIOE、Diagnose、SLB |

底座另置于 [00-harness](./00-harness/README.md)：控制回路的七个部件，六派都是往这七个部件上接。

## 强度与覆盖率反向

这是全仓库最重要的一张图，也是六派为什么必须分开的理由：

```
约束强度   弱 ────────────────────────────────────────▶ 强
覆盖率     广 ◀───────────────────────────────────────── 窄
          03 知识     04 状态      02 判定     01 约束
```

强度越高，能判定的范围越窄。上下文注入能覆盖一切，但什么都管不住；落盘前授权只覆盖极少数动作，但一旦触发不可绕过。

两条推论：

1. **「本体提升准确率」几乎都发生在弱端**（03 知识派）。强端改善的是「是否可用」，用准确率度量它必然得出「无增益」——这正是 [C-03](./conclusions.md#冲突) 记录的那条方法论问题。
2. **中间空档最缺研究**：大量中间产物（计划、草稿、中间结论）既没判定也没授权，直接流向下一步。

## 派与派的边界

分类要能用，边界必须能判。四条规则：

| 边界 | 判据 |
|---|---|
| 01 约束 vs 02 判定 | 前者问「动作能不能做」，后者问「产出对不对」 |
| 02 判定 vs 03 知识 | 前者是**外部判据**在事后把关，后者是**内部供给**在事前铺路 |
| 03 知识 vs 04 状态 | 前者管「这一轮看到什么」，后者管「下一轮还记得什么」 |
| 05 生产 vs 04 状态 | 前者造本体，后者用本体；本体来源与本体用法是两件事 |

跨派的工作（既提方案又做测量）**按主效应归派**，并在派内 README 标「双重身份」。例如 CAI 主效应在 03，同时是 06 最重要的尺子。

## 三种读法

- **找工程思路** → 01 → 02 → 03：哪里最硬、代价是什么。
- **找证据强度** → 06 → [conclusions](./conclusions.md)：哪些已核、哪些只是推测。
- **找落地路径** → 05 → 03 → 01：先有本体，再让它被看见，最后让它能拦住东西。

## 怎么增长

一篇新论文进库时，只问一句：**它改变了本体在哪个时刻的行为？** 答得出来就归派，答不出来说明它还没被消化。

派内正文只在被新证据**改变**时重写；新派不轻易开——先在 [conclusions](./conclusions.md) 记为「悬空结论」，累积三条以上再立派。

横切的领域差异集中在 [domains](./domains.md)，不单独成派。
