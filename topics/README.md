# topics：六派与四轴

流水线的第二个工位。材料在 `src/` 里被读懂，在这里被综合成**可引用的判断**。

分类轴是**本体凭什么起作用**，不是主题。每一派回答一个工程问题，流派差异在目录名上就能看出来。

## 四根轴

`topics/` 不是按一个维度切的。它有四条正交的轴：

| 轴 | 问什么 | 载体 |
|---|---|---|
| 派轴 | 本体凭什么起作用 | `01-06/` |
| 部件轴 | 本体接在机器的哪里 | [`00-harness/`](./00-harness/README.md) |
| 时刻轴 | 本体在哪个时刻介入 | [`seams.md`](./seams.md) |
| 形态轴 | 机器拿本体做了什么（引擎/编译/上下文/标签） | [`execution-forms.md`](./execution-forms.md) |

另有两条横切索引：[conclusions](./conclusions.md)（证据）与 [domains](./domains.md)（领域）。形态轴不是索引，是第四根轴。

派轴内部还可以再分**子主题**（`topics/<派>/<子主题>/README.md`）；那不是第四条轴，是派轴的第二层。派 README 只做地图，详细机制在子主题。

六派不是六个等价的桶，而是 **4+1+1**：

- `00-harness`：回路本身（七个部件）
- `01-04`：回路内的四个介入点（约束 / 判定 / 知识 / 状态）
- `05-produce`：回路前（本体从哪来、怎么修）
- `06-measure`：回路外（有没有用、用哪把尺）

所以归派一句话是：**01-04 问时刻，05 问来源，06 问尺子；跨派按主效应归派并标双重身份。**

## 一句话地图（时刻轴）

```
        05 生产          03 知识          01 约束        02 判定     04 状态
      本体尚未存在  ──▶   供给上下文  ──▶   动作前拦截  ──▶  输出后校验  ──▶ 跨轮一致
      来源/精化/演化       投影/编译         可逆性/前置条件    漏检/误报      槽位/冲突

      └──────────────────────── 06 测量：这一切到底有没有用 ────────────────────────┘
```

时间轴从左到右：本体先被造出来（05），再被喂进上下文（03），在执行前拦截动作（01），在产出后校验（02），在轮次之间维持一致（04）。06 是绕在整条链外侧的尺子。

**这是时间轴的读法，不是目录顺序。** 目录顺序是派轴 01-06；编号是稳定标识，不是时间顺序。

## 六派对照

| 派 | 回答的问题 | 核心工程思想 | 介入时刻 | 约束强度 | 代表 |
|---|---|---|---|---|---|
| [05 生产](./05-produce/README.md) | 本体从哪来、怎么修 | 来源影响可信度（推测）；精化比新建常见（推测） | 本体未存在时 | — | CASTON、SFE-O、OntoDoc |
| [03 知识](./03-knowledge/README.md) | 怎么让它知道得对 | **投影 pooled 最高但非普适**；编译只省预算、准确率 neutral | 供给时 | 弱 | Narrow & Deep、CAI、Grid Agents |
| [01 约束](./01-constraint/README.md) | 怎么不让它做错事 | 安全是**结构问题**：问「存在可逆序列吗」 | 动作前 / 落盘前 | **强** | POLAR、Commit Boundary、OntoAct |
| [02 判定](./02-judgment/README.md) | 怎么知道它做错了 | 判据必须外部且**可度量** | 输出时 / 输出后 | 强 | Ontology Catch、OA-RAG |
| [04 状态](./04-state/README.md) | 怎么让它记得对 | 记忆是**状态**不是集合；本体克制到只做对齐与印证 | 跨轮 | 中 | EvoMemState、FIRME |
| [06 测量](./06-measure/README.md) | 它到底有没有用 | 答对≠内部有本体；失败多归工作流 | 旁路 | 元 | MIOE、Diagnose、SLB |

底座另置于 [00-harness](./00-harness/README.md)：控制回路的七个部件，01-04 都是往这些部件上接。

### 派 × 时刻 × 部件

| 派 | 时刻 | 主要部件 |
|---|---|---|
| 01 约束 | 1 动作前 / 4 落盘前 | tools / governance |
| 02 判定 | 2 输出时 / 3 输出后 | verification / observability |
| 03 知识 | 供给（无时刻） | context |
| 04 状态 | 5 跨轮 / 6 跨运行 | memory |
| 05 生产 | 本体存在之前 | — |
| 06 测量 | 旁路 | — |

时刻表与选择规则见 [seams.md](./seams.md)；部件详情见 [00-harness/README.md](./00-harness/README.md)。

## 强度与覆盖率反向

**这是派强度谱**，不是时刻谱。时刻谱见 [seams.md](./seams.md)；部件谱见 [00-harness/README.md](./00-harness/README.md#约束强度谱)。三张谱不要混。

这是全仓库最重要的一张图，也是六派为什么必须分开的理由：

```
约束强度   弱 ────────────────────────────────────────▶ 强
覆盖率     广 ◀───────────────────────────────────────── 窄
          03 知识     04 状态      02 判定     01 约束
```

强度越高，能判定的范围越窄。上下文注入能覆盖一切，但什么都管不住；落盘前授权只覆盖极少数动作，但一旦触发不可绕过。

两条推论：

1. **「本体提升准确率」几乎都发生在弱端**（03 知识派）。强端改善的是「是否可用」，用准确率度量它必然得出「无增益」——这正是 [C-03](./conclusions.md#冲突) 记录的那条方法论问题。
2. **中间空档最缺研究**：大量中间产物（计划、草稿、中间结论）既没判定也没授权，直接流向下一步。

这张图目前是**组织假设**，不是 E 编号结论；它的证据分散在 E-01、E-04、E-12、E-13。把它当强结论引用前，先看 [conclusions](./conclusions.md) 的等级。

## 派与派的边界

分类要能用，边界必须能判。四条规则：

| 边界 | 判据 |
|---|---|
| 01 约束 vs 02 判定 | 前者问「动作能不能做」，后者问「产出对不对」 |
| 02 判定 vs 03 知识 | 前者是**外部判据**在事后把关，后者是**内部供给**在事前铺路 |
| 03 知识 vs 04 状态 | 前者管「这一轮看到什么」，后者管「下一轮还记得什么」 |
| 05 生产 vs 04 状态 | 前者造本体，后者用本体；本体来源与本体用法是两件事 |

跨派的工作（既提方案又做测量）**按主效应归派**，并在派内 README 标「双重身份」。例如 CAI 主效应在 03，同时是 06 最重要的尺子。

## 归派三问（新论文/新项目先答）

1. **它改变的是动作、产出、记忆，还是供给？** 动作前/落盘前 → 01；输出时/输出后 → 02；跨轮 → 04；只喂上下文 → 03；造/修本体 → 05；只量效果 → 06。
2. **它有外部判据、且能改变走向吗？** 只有判据、不能阻断 → 知识注入（03）或表示（05）；只有阻断、没有外部判据 → 硬编码规则，不是本体闸门。
3. **阻断发生在哪一格？** 动作前 → `action-gate`；输出后 → `checker`；落盘前 → `commit-gate`；检索结果返回前 → 轴外位置 `read-path`（暂记 01/commit-gate 的读路径）；推理期条件 → `reasoning-gate`。

例：一篇「用 SHACL 校验工具调用参数并在执行前阻断」的论文 → 01/action-gate；只校验产出 → 02/checker；只把 SHACL 当表示/编译产物、不阻断 → 05/representation；只过滤检索结果 → 01/commit-gate 的读路径 + `seam: read-path`。

## 七种读法

- **找工程思路** → 01 → 02 → 03：哪里最硬、代价是什么。
- **找证据强度** → 06 → [conclusions](./conclusions.md)：哪些已核、哪些只是推测。
- **找落地路径** → 05 → 03 → 01：先有本体，再让它被看见，最后让它能拦住东西。
- **找时刻** → [seams.md](./seams.md)：六个接缝、轴外位置、选择规则、到派与部件的 crosswalk。
- **找形态** → [execution-forms.md](./execution-forms.md)：引擎求值/编译/上下文/标签，以及 26 个来源的初判。
- **找前沿** → 各派 `frontier.md`：前沿问题、信号源、检索式、候选队列。
- **找局部判断** → 各派 [claims.md](./01-constraint/claims.md)：`L-xx`，尚未升到 E-xx。

## 论文进库的前置：低噪声三件套

新论文进 `src/papers/{arxiv_id}-{slug}/` 后，**先转换，再建卡，再消化**：

1. **PDF 完整转 MD**：`paper.md`（正文）+ `references.md`（参考文献）+ `appendix.md`（附录/补充材料）。正文保留 `<!-- page N -->` 页码标记。
2. **参考文献单独成文件**：默认**不读**。它最容易把检索/摘要带偏；只有核引文、查出处时才打开。
3. **附录单独成文件**：默认也不读。需要看额外表格、证明、提示词时再打开。

转换用 `pymupdf4llm`（逐页转，保留顺序）；公式/表格可能有版式噪声，引用前回 PDF 核。消化时默认读 `paper.md` + `card.md` + `digest.md`，不读 `references.md`；这是信噪比控制的第一步。目录与命名见 [src/README](../src/README.md)。

## 怎么增长

一篇新论文进库时，先按 4+1+1 判：

- 01-04：**它改变了本体在哪个时刻的行为？** 答得出来就归派。
- 05：**它改变的是本体的来源/精化方式吗？**
- 06：**它改变的是尺子吗？**

答不出来，说明它还没被消化。

每派根目录有四个文件：`README.md`（地图与硬证据，只在判断被改变时改写）、`frontier.md`（活页：前沿问题、信号源、检索式、候选队列、入档判据）、`claims.md`（本派局部结论 `L-xx`）、`sources.md`（本派卡片索引）。方法见 [meta/topic-research-protocol.md](../meta/topic-research-protocol.md)。

派内可以再有**子主题目录**：`topics/<派>/<子主题>/README.md`。派 README 只做地图与硬证据；子主题 README 放详细机制。子主题按子机制/子问题命名，不按来源类型；成立条件与素材类型规则见 [ADR 0003](../adr/0003-subtopics-and-source-types.md)。

**本页只做索引**：各派内部结构见各派 README 的「本目录怎么长」。新增子主题只改该派目录，不要求改本页；只有新派/跨派关系变化才动这里。

子主题的薄页合并门槛见 [ADR 0008](../adr/0008-thin-subtopics-merge-audit.md)。

新派不轻易开——先在 [conclusions](./conclusions.md#悬空结论未归派) 记为「悬空结论」，累积三条以上再立派。横切的领域差异集中在 [domains](./domains.md)，不单独成派。
