# 本体：语义层

本层不是研究重点，但它是接缝的另一半，必须被研究到「可被消费」的程度。

## 三个子问题

| 子问题 | 文档 | 一句话 |
|---|---|---|
| 语义如何被**表示** | [representation](./representation.md) | 形式化程度应按消费位置选择，而非按学术纯度 |
| 语义如何被**生产** | [modeling](./modeling.md) | 规范的价值在于压缩自由度，让不同人/不同次运行收敛 |
| 语义如何**存续** | [lifecycle](./lifecycle.md) | 本体的真正成本在维护，不在首建 |

## 三条与主流本体工程不同的立场

1. **完备性不是目标，可判定性才是。** 一个覆盖 80% 概念但能被机器判定的本体，胜过覆盖 99% 但只能被人读的图。
2. **窄而深优于大而全。** 单一工业域内分层展开，比跨域大一统本体更容易落到生产——反例是那些建了三年还在建模阶段的项目。
3. **本体的消费方是 harness，不是人。** 所以「图好看」没有价值，「能被判定」才有。这一条决定了后面所有取舍。

## 本层与接缝的分工

本层只描述**本体自身**：它长什么样、怎么生产、怎么修。至于它在哪一步被执行、强度如何、失效在哪，全部写在 [30-seams](../seams/README.md)。

判据：写「本体的 X 是什么」→ 本层；写「本体在 Y 环节如何生效」→ 接缝。
