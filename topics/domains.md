# 领域约束

横切单页。领域不是案例集，是**对机制的额外约束条件**——同一个做法换个域就不成立。

> **2026-11-11 撤源对账**：下表原代表工作中的 Grid Agents（2611.03534）、多 agent 差分诊断（2610.36325）、OA-RAG（2610.36335）、OntoDoc（2611.01276）均已移出（[黑名单](../meta/rules/excluded-sources.md)）。现役 admitted 仅 **Narrow & Deep**（E-12）与 **FIRME**（E-05）；其余仅作历史问题/三原则设计占位，原数值停用。

## 跨域的共同点

五个域里有四个反复出现同一条：**本体的作用是把「不能错的少数判断」钉住，而不是把知识铺满。**

电网钉住法规，金融钉住身份，工业钉住参数来源，医学钉住推理链。落点都少，但一旦触发不可绕过——这正是 [约束强度谱](./README.md#强度与覆盖率反向) 的经验形态。

## 两个值得单独记的域内工程判断

**电网**（`推测`，原 Grid Agents 已于 2026-11-11 移出，原数字停用）：三条原则作为设计结构仍清晰——答案必须引用证据、数字必须来自成熟求解器、人做最终决策，是「模型不下最终判断」的完整形态。**工具必须到达研究**：原报告的 PowerMCP 低调用率与 optimizer 加固降本只作历史问题线索（[tombstone](../meta/audits/2026-11-11-source-purge.md#src-2611-03534)），待过门新源复测。

**工业设备**：Narrow & Deep 的塔是 162 节点 / 217 边，投影约 45k 字符；K0→K1（命名+单位）+54.6pp，K1→K2（投影文本）+19.8pp；9B 带投影 0.737 > 750B 不带 0.672。作者自述局限：增益是在「答案基本就写在文本里」的任务上测得的。域内知识越像操作手册，投影越有效；越像需要现场推理，越不可靠。安全层必须独立于 agent：25/61 命令被拒，24–68% 事实主张无证据支持。
