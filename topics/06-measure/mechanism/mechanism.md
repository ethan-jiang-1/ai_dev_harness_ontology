# 机制尺子 · 机制

> 只写「它怎么测」。判断回 [findings](./findings.md)，边界/下一步回 [frontier](./frontier.md)。

## 问题

行为正确率不能证明模型内部在算本体关系；正确输出可能来自表面模式。MIOE 用因果抽象 / 互换干预来测这一步。

## 因果抽象

- 高维变量：subject 的 target taxonomic value + class-specific auxiliary attributes。
- 干预：`II(M,F,x_base,x_source)`：把 base 在低层特征 F 的值替换成 source 诱导的值。
- **Cause**：目标答案是否变成 source 的类。
- **Iso**：辅助属性是否保持 base。
- **Disentangle**：两者平均。

## 数据与模型

- `instance of`：54 classes / 1,099 subjects / 376 attrs / 4,288 个 prompt 模板。
- `subclass of`：39 / 1,113 / 160 / 2,095。
- Qwen3-8B、Qwen3-4B；36 层；subject token 的 block-output residual stream。
- 方法：SAE、DBM、MDBM、DAS、MDAS；单层 36 层全扫；多层 2/4 层连续窗口（256×4、512×2、512×4）。
- 切分：Entity（训练模板考未见 subject）/ Context（未见模板考训练 subject），不是两种 prompt 写法。

## 结果

> 下表是 **Qwen3-8B 单层 Disentangle**（Cause 与 Iso 的平均，不是准确率）。各方法按 **Entity** Disentangle 选最佳层/维度，**Context 复用同一配置**，不是对称切分；Dimension 定义不同（SAE latent width / DBM mask / DAS·MDAS rank），不是同容量对照（Table 2 caption）。

| 方法 | instance（Entity/Context） | subclass（Entity/Context） |
|---|---|---|
| SAE | 0.412 / 0.371 | 0.397 / 0.429 |
| DBM | 0.425 / 0.396 | 0.431 / 0.443 |
| MDBM | 0.443 / 0.408 | 0.440 / 0.450 |
| DAS | 0.584 / 0.547 | 0.496 / 0.535 |
| **MDAS** | **0.592 / 0.587** | **0.513 / 0.542** |

- **MDAS 不是 Cause/Iso 两项都优**：instance-of 的 Entity 上 MDAS Cause 0.527 / Iso 0.658，DAS Cause 0.589 / Iso 0.579；Disentangle 只差 0.008，且原文只报 seed 42、无 CI/方差，**不能当稳定排序**。
- 多任务（MDBM/MDAS）：**best-vs-best 配对差** Iso +0.081 / Cause −0.052（不是多任务整体平均）；Disentangle 仍升（Results, p.5）。
- 多层窗口（Qwen3-8B，instance-of）：DAS 512×4 0.667（+0.102，全表最高）；MDAS 256×4 0.666（+0.074）；MDAS 512×4 0.663（+0.070）；subclass-of 的 MDAS 512×4 0.565（+0.052）。0.667/0.666/0.663 的差距可能在小样本噪声内。
- **Δ 的基线**：相对**同方法、同总维**的单层结果。DAS 512×4 的基线是单层 DAS rank 2048 ≈0.565（由 0.667−0.102 反推），**不是** digest §4.1 的 DAS 0.584；subclass MDAS 的基线是 0.513（Table 3 caption）。
- 层剖面：Cause 中层/中后层最强；后层 Iso 高但 Cause 可能崩（Fig. 1）。
- 类级：具体/规则类（airport/country/currency/university）好，宽泛/异质类（body of water/geographical feature/food/biological process/material）差；同一类当 base 与当 source 也不同。**原文的类级结果是散点与类级均值/排名，没有可直接引用的类级区间**；类级切点必须按本域重算。

## 失效模式

- **部分分离**：0.59 不是「懂本体 59%」；没有方法到 1.0。
- **表示 vs 方法**：可能是表示纠缠，也可能是干预不够强；本文不能区分。
- **单模型族**：只 Qwen3；跨模型未测。
- **单任务类型**：只 entity typing/subsumption；更丰富公理未测。
- **单干预位置**：subject token；其他位置未测。
- **单 seed、无 CI**：只报 seed 42（`已核`）；0.592 vs 0.584 的排序与类级切点都可能被噪声推动（`推测`）。
- **聚合掩盖类级**：平均值可能由少数好类拉高。

## 与本体 / 回路的关系

本体在机制尺子里是 **被测试的对象**；它不进入运行时回路。测的是「内部有没有可干预的本体表征」，不是「输出对不对」。

## 实施与客户价值（A3/A4）

> 读者是要决定「能不能因为模型答对，就撤掉外部判定器 / 减人审」的人。机制与数字来自 [MIOE digest](../../../meta/audits/2026-11-11-source-purge.md#src-2610-38326) §4/§5（一手是 Table 2/3）；接口字段、成本、人日、排期与客户收益来自 digest §6.2/§6.5/§6.6 的**工程配方或本页推定**；训练超参（epoch/batch/seed）来自 Appendix Table 4。配方不是论文实测：字段名、2 人周 / 1–3 GPU 天 / 2–3 人日等一律 `推测`，逐条标等级；分档路线的证据（G5）未关，试点前不进 [deliverables](../../../deliverables/README.md)。

### 实施决策

1. **先问「撤判定器」这个决定是否还活着；不活就别做机制审计。** 若架构上已决定保留外部判定器，本页唯一能改变的就是「别用行为准确率当机制证据」这条禁止性判断——直接引用即可，不必再立项重测（重测约 2 人周是 digest 的估算，`推测`）。`已核`（F2 / E-10）→ 改变的是**审计立项条件**，不是方法选型。
2. **机制分数不进运行时判定链。** 它是条件性测量：只 Qwen3-4B/8B、只 entity typing / subsumption、只 subject token 位点、单 seed 无 CI（digest §4.1、§5）。做成在线 judge 会把「干预条件下的分离度」误读成「这条判断可放行」（误读风险是 `推测`，未见实测）。`已核`（边界）→ 预算归架构证据，不归运行时质量。
3. **先测数据可行性，再决定要不要 GPU。** 未干预 base 准确率与辅助属性准确率是前置门：base-correct 留存 <50% 或辅助属性 micro <50%，Iso 不可比，机制审计在本域直接不成立（digest §6.5 的工程门槛，阈值未验证，`推测`）。`已核`（门槛文本）→ 改变 sprint 顺序：基线先于训练；D3 先测基线（本页排期 1 天，`推测`）。
4. **验收看类级分布 + 随机子空间对照，不看全局均值。** 聚合分数会被少数好类拉高（F5）；类级中位 <0.40 **且**随机子空间对照达到学习子空间分数的 ≥70% 时，按 digest 的停手线判为本域尺子不可用（做法与 70% 阈值见 digest §6.2/§6.5，`已核`；阈值本身未验证、据此说「F 没有解释力」是 `推测`）。→ 改变验收表里必须有的两列。
5. **机制审计买的是「为什么」，不是「会不会」。** Entity split（新 subject）与 Context split（新模板）的行为 holdout 已经能测「答对能不能外推」；paraphrase 与扰动稳定性更便宜。机制审计多回答「内部是否可分离」，只有这个答案会改变修复路径（换模型 / 加判定器 / 改投影）时才值得买。`推测`（digest 明确没有与 DAS 的头对头成本-收益）→ 改变采购顺序。

### 组织/成本

- **owner（三缺一即失效，`推测`：角色划分是本页工程判断）**：
  - **机制 / 评测 owner**（1 人 × 2 周）：hook、训练、评测、一页 go/no-go；不能同时是「撤不撤判定器」的决定人，否则自评。
  - **域本体 owner**（0.2–0.5 人周，`推测`）：20–30 个类 + 每类 1 个辅助属性 + 值域；缺它只能借用论文类表（域外，结论不适用）。
  - **平台 / GPU owner**：单卡 A100、block-output hook 权限、checkpoint；挂不上 hook 就不要立项。
  - **决定人**（架构 / 质量）：读结论做撤 / 留；机制分不能替这个决定。
- **人日（`推测`）**：复用 RAVEL 约 2 人周（数据、pair、评测脚本）、自研另加 4–6 人周、类级结果与人审 2–3 人日——这三项来自 digest §6.5 的估算；域本体 0.2–0.5 人周是本页推定。
- **运行（`推测`）**：单卡 A100，9 个（层 × 方法）配置 1–3 GPU 天；跑 500 / 2,000 / 8,000 三档会按档放大机时，系数未测。论文未给单价，本页不填金额，按自有 A100 单价 × GPU 天折算。
- **维护（`推测`）**：类 / 属性变更要重跑对应类；换模型族整体重做；季度复核类表（频次未测——业务新增类会移动分档边界），人时未测。
- **隐性成本（`推测`：按 2 人周 + GPU 排期推）**：决策延迟——2 周 + GPU 之后才知道尺子能不能用。若「撤判定器」的决定两周内要拍，机制审计赶不上，只能先用行为 holdout。
- **成本自洽问题**：digest 的建设估算是 2 人周，价值停止线却是「年省人审 < 2 人周则不做」；按这两条，建设成本要靠一年节省才打平，且未计 GPU 与 2–3 人日 review。要么把停止线抬到「年省 > 建设 + 首年运行」，要么把建设压到 <1 人周（20 类、单层、复用实现）。`推测`（两项输入都是 digest 估算；成本口径同 [feasibility](../feasibility/README.md)：只给区间与公式，不给无出处的点估计）

### stop condition

> 规则文本来自 digest §6.5；阈值与 70% 停手线是该配方的工程判断，不是论文实测，阈值有效性 `推测`。

- **数据门（前置）**：base-correct 留存 <50%，或辅助属性 micro <50% → 不训，直接停（digest §6.5；阈值未验证）。
- **机制门**：类级中位 Disentangle <0.40，且随机子空间对照达到 ≥70% → 本域机制尺子不可用；停，转外部判定器 / 规则校验（digest §6.5）。
- **分档门**：0.40–0.55，**且**类间方差大于档间差 → 只做类级分档，不做全局门；不把结果写成「可用 / 不可用」二分。
- **下游门**：>0.55 才值得第二 sprint 做「机制分 vs 下游本体判断错误率」；试点若显示两档 false accept 无差异 → 停分档路线（G5）。
- **决定门**：若「撤判定器」决定已关闭，或审计不改变任何修复路径 → 停；本页只保留禁止性判断。`推测`（本页决策规则）
- **参数门（小 rank）**：单层只用 rank 1024/2048；不要用 256–512 的单层小 rank 去套上面的 0.40/0.55 阈值——小 rank 下 Cause 会掉，阈值作废，只认随机子空间对照（digest §6.2）。论文只给「维度增大会在部分配置提高 Cause、降低 Iso」的方向（Results, p.5；Fig. 2），阈值作废本身未做对照，`推测`。
- **报告门**：单 seed / 无 CI 时不得报 0.592 vs 0.584 的方法排序（digest §4.1）；500 对落在阈值边界时只能报 inconclusive，不得报 fail。`推测`（边界处理是本页要求）
- **价值门**：年省人审 < 建设 + 首年运行（GPU + review）→ 不做（本页把 digest 的 2 人周停止线按成本自洽改写，`推测`）。

### 第一个 sprint

**触发**：只有「撤 / 留外部判定器或人审预算」这个决定仍开放时才开跑；否则取消，直接引用 F2 的禁止性结论。

**范围**：一个域、20–30 个具体类、每类 1 个辅助属性、一个模型（就是准备撤判定器的那个；不是 Qwen3 则只借方法不借分数）、2–3 个中间层、单层 DAS/MDAS rank 1024/2048；4 层 256×4 窗口与 2,000 对拉伸臂二选一。离线，不接线上，不改 prompt。500 对为主。

| 天 | 做什么 | 产出 |
|---|---|---|
| D1–D2 | 定类表与辅助属性；写 base / source pair 规则；预登记阈值与分档规则 | 类表 + 属性表 + 预登记页 |
| D3 | 跑未干预基线：base 准确率、辅助属性 micro、Entity / Context 留存 | 数据可行性报告；不过门即停 |
| D4–D6 | 挂 hook；造 500 对；单层 DAS / MDAS 扫 2–3 层；随机子空间对照 | 干预跑通 + 对照结果 |
| D7–D9 | 补到 3 seeds（时间不够先砍可选项——层窗口 / 2,000 对，不砍 seeds）；有余额再加 2,000 对拉伸臂 | 稳定性与规模初值 |
| D10 | 出 Cause / Iso / Disentangle + 类级散点；写 go/no-go 一页 | 决策记录 |

**交付物**：① 数据可行性报告；② 机制结果表（含随机对照列与类级分布）；③ go/no-go 一页；④ 成本日志（GPU 小时 / 人日 / 复用还是自研）；⑤ 若结论是「保留判定器」，写明复核触发条件（类表变更、换模型、分数落边界）。

**出口**：
- **go（进第二 sprint）**：类级中位 ≥0.55，随机对照 <70%，类间方差小于档间差，数据门通过。
- **仅分档**：0.40–0.55 且类间方差大 → 只出类级分档，做 200–500 条判断的小试点，不做全局阈值。
- **stop**：数据门不过；或中位 <0.40 **且**随机对照 ≥70% → 本域尺子不可用，写回 [frontier](./frontier.md) 的 G4 / G5，转外部判定器。
- **inconclusive**：500 对与 2,000 对结论不一致，或 CI 跨阈值 → 只写「需要 8,000 对」，不写「失败」。

### 客户指标/V3

> 以下指标与试点设计是 `推测`（digest §6.6 的价值假设，不是论文结果）。

- **受益者**：
  - **架构 / 质量 owner**：决定能不能因「模型答对」撤掉外部判定器或减人审。撤早了是系统性 false accept，撤晚了是多付人审；痛点是缺一个区分「真用本体」与「表面模式」的证据。`推测`（决策场景）
  - **本体工程师 / 集成商**：决定人审预算往哪些类倾斜。现状是全类同等人审，或按行为准确率分档（会被表面正确骗）。`推测`
- **指标**：
  - 分档假设：高 Disentangle 档 vs 低档的 false accept 率之差；每千条判断 false accept；每千条 audit 工时；类级误判率。
  - 禁止性假设：撤判定器后被外部审计抓到的 false accept 数（应为 0 才谈撤）。
  - 尺子自身：同数据换人重算结论是否一致（本页提议的复核指标，未见来源）；CI 宽度；单次审计的 GPU 天 / 人日。
- **反事实**：不做 → 全量人审，或只用行为准确率决定撤 / 留；在「答对但内部纠缠」的域，后者会把系统性风险当成已解决。`推测`
- **V3 试点**：20–30 类、200–500 条判断；**先测基线**（当前全量人审工时 / 千条 + false accept 率），没有分母不做；预注册「高 Disentangle 档 false accept 率低于低档」；成功 = 相对下降 ≥30% 且 CI 不跨零；失败 = 无差异 / 反向；停止线 = 年省人审 < 建设 + 首年运行（见上，改写自 digest 的 2 人周线）。
- **如果试点只为回答「能不能撤判定器」**：成功判据是「机制分档对 false accept 有显著区分度」，不是「省了 30% 工时」；区分度不显著就直接保留判定器，不必等满 2 周。
- **边界**：下游 false accept 的测量归 [metrics](../metrics/README.md) 与 [failure-attribution](../failure-attribution/README.md)；本节只负责「机制档位」这一列。

### 反例

- **分档可能与下游错误无关（G5 未关）。** Disentangle 是干预下的内部分离度，不是输出正确率：高分档仍可能因上下文不足 / 属性歧义而 false accept，低分档也可能靠捷径一直对。若试点两档无差异，A4 的分档价值归零，只剩禁止性判断。`推测`
- **更便宜的替代可能已经够。** 行为 holdout（Entity 考新 subject、Context 考新模板）已能测「答对能不能外推」；paraphrase 与扰动稳定性 + 外部 judge 可能已足够回答「判定器能不能撤」。机制审计买的是「为什么」，除非这个「为什么」改变修复路径，否则是纯成本。`推测`（digest 无头对头成本）
- **本地小数据测不出 0.59。** 原文 5 万级 pair，20–30 类只有 1/20–1/50；500 对落在 0.40–0.55 时无法区分「域不行」与「数据不够」。第一 sprint 可能只买到「需要 8,000 对」这个结论。`已核`（数据量事实）+ `推测`（外推）
- **Iso 的条件偏差 + 单 seed。** Iso 池只含未干预模型答对辅助属性的例（8B instance-of 的辅助属性 micro 64.9%），所以 Iso 与 Cause 的池不同；单 seed、无 CI，0.592 vs 0.584 不是排序。拿它做类级切点会把噪声当信号。`已核`（池与 seed 事实）+ `推测`（分数偏乐观的方向）
- **本页最确定的产出可能是「省一次审计」。** 如果组织本来就不会撤判定器，这页的价值是「不要为了证明模型懂本体而做审计」——成本规避，不是收益。按 A4 的口径，它可能不该算客户价值。`推测`
