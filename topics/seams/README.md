# 接缝：本体被执行的六个时刻

本层是核心研究区。判据不是「本体有没有用」，而是「本体在哪个时刻介入」。

## 什么算一个接缝

三条同时成立才算：

1. **有外部判据** —— 判定依据来自本体，而不是模型自评。
2. **有阻断能力** —— 违反时可以改变走向（剪掉动作、拒绝输出、阻止落盘），而不是只留一条日志。
3. **位置明确** —— 能指到回路的某一个时刻，而不是「整体上更懂业务」。

只有第 1 条的叫「知识注入」，只有第 2 条的叫「硬编码规则」。**接缝是二者相交。**

## 六个时刻

按时间轴排列，越往后约束越硬：

| # | 时刻 | 文档 | 本体的角色 | 违反的后果 |
|---|---|---|---|---|
| 1 | 动作执行**前** | [tool-gate](./tool-gate.md) | 可逆性分级、参数合法性 | 不可逆动作被执行 |
| 2 | 输出**时** | [evidence-and-provenance](./evidence-and-provenance.md) | 强制附带依据与证据等级 | 无根据的结论流出 |
| 3 | 输出**后** | [ontology-as-checker](./ontology-as-checker.md) | 判定器：查错与纠错 | 不合格产出被放行 |
| 4 | 持久化**前** | [commit-boundary](./commit-boundary.md) | 授权判据：证据是否足够 | 错误变更落盘 |
| 5 | 跨**轮** | [memory-as-state](./memory-as-state.md) | 状态结构：约束、失效、冲突 | 后续判断被污染 |
| 6 | 跨**运行** | [determinism](./determinism.md) | 一致性锚点 | 同一输入得出不同结论 |

## 强度与覆盖率反向

这是本仓库最重要的一条结构判断：

```
约束强度   弱 ────────────────────────────────▶ 强
覆盖率     广 ◀──────────────────────────────── 窄
位置     上下文注入   记忆   判定   证据   动作前   落盘前
```

强度越高，能判定的范围越窄。上下文注入能覆盖一切，但什么都管不住；落盘前授权能管住极少数动作，但一旦触发不可绕过。

两条推论：

1. **「本体提升准确率」几乎都发生在弱端。** 强端改善的是「是否可用」，用准确率度量它，必然得出「无增益」——这可能解释了文献中正面与负面证据的冲突（推测）。
2. **中间空档是研究不足区。** 大量中间产物（计划、草稿、中间结论）既没有判定也没有授权，直接流向下一步。

## 六个时刻怎么选

不是都要做。选择依据是**错误的代价**：

- 错误可撤销 → 只需时刻 3（判定）
- 错误会扩散到下游 → 加时刻 2（证据）
- 错误会污染后续轮次 → 加时刻 5（记忆）
- 错误不可撤销 → 时刻 1 或 4（动作前 / 落盘前）
- 要求可复现 → 时刻 6（确定性）
