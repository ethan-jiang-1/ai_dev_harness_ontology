# cases：领域约束

同一个机制换一个领域，约束会变。领域不是案例集，是**对机制的额外约束条件**。

## 五个领域的约束差异

| 领域 | 决定性约束 | 对 harness 的要求 |
|---|---|---|
| 工业设备 | 知识窄而深，术语密集，错一个参数即事故 | 本体必须分层（本体塔），不能靠通用知识补 |
| 电网规划 | 法规与标准是硬约束，数字必须由成熟求解器算 | 模型不得直接产出数字；答案必须引用证据；人做最终决策 |
| 金融投研 | 实体跨期身份漂移，来源与时效必须保留 | 需要 registry 锚定 + 时间维度；本体只定义槽位 |
| 医学诊断 | 缺证据时需主动追问，推理需可审计 | 多 agent 分工 + 逐步可查 + 主动提问环节 |
| 生物医学 / 农业 KG | 资源描述缺失，术语与自然语言不匹配 | 需要面向 IRI 的说明生成流程 |

## 跨域的共同点

四个领域反复出现同一条：**本体的作用是把「不能错的少数判断」钉住，而不是把知识铺满。** 电网钉住法规，金融钉住身份，工业钉住参数来源，医学钉住推理链。

这与 [seams](../seams/README.md) 的约束强度谱一致：高处落点少而硬，低处覆盖广而软。

## 待办

- 每个领域一份约束清单（法规/标准/时效/责任人），格式待定。
- 至少一个领域的端到端拆解：从本体到判定器到闸门，看约束在哪一步被放弃。
