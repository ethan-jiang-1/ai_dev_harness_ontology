# 04 状态派：怎么让它记得对

## 核心主张

**记忆是状态，不是事实集合。**

把记忆当一堆独立条目会丢掉三样东西：事实之间的约束、失效条件、冲突记录。丢掉之后每轮都要重新做一次一致性推导，而每次结论可能不同。

这一派的工程思想是**克制**：本体只定义槽位与关系，不承担推理。

## 两种克制的做法

| 做法 | 本体做什么 | 代表 |
|---|---|---|
| 本体引导归纳 | 从多源记忆构建关系状态 | EvoMemState（关系状态 + 推理状态两层） |
| 本体只做对齐 | 跨期身份锚定、槽位定义 | FIRME（product–topic 本体 + registry） |

FIRME 的架构里有一个很值得抄的细节：**生命周期模型被实现为确定性状态机**——给定对账决策后，记忆强度与生命周期状态按固定规则更新；只有抽取与语义匹配仍依赖模型。

> **把不确定性赶进一个角落**，其余部分保持可复现。这是状态派最值钱的一条工程经验，比任何本体设计技巧都通用。

## 硬证据

- EvoMemState：长期对话与记忆使用基准上，检索完整性与 grounded 准确率均有提升，在偏好更新与证据冲突场景尤其明显（转述，待核数字）。
- FIRME：保留来源与时间；同实体跨期不碎裂。局限是私有语料不可复现。

## 与 00-harness 的分工

[00-harness/memory](../00-harness/memory.md) 讲控制回路的记忆机制（检查点、可恢复性、污染）；本派讲**本体在其中扮演什么角色**——这是「机制」与「用法」的区别。

## 何时用 · 何时别用

**用**：跨会话、跨期的实体知识；需要保留冲突与来源；下游判断依赖历史一致性。

**别用**：单轮任务；本体本身还在建设期（没有稳定槽位，状态结构会一直变）。

## 开放问题

- 状态结构能否由本体自动生成？若可以，本体必须先于任务存在——这是冷启动的硬约束。
- 冲突该阻塞推进，还是带着冲突推进并标注？对应两种产品语义。
- 记忆压缩与上下文压缩是同一问题吗？若是，可共用「判据保护」机制。
