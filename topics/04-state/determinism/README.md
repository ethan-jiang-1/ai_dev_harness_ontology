## 位置

不在单次执行内部的任何时刻，而在两次执行之间。它约束的不是某一步，而是「同一输入应得同一结论」这个性质。

## 问题

同一份需求，两次转换得到不同本体；同一个数据集，两次分析得到不同结论。这类不一致在人工流程里可以靠评审收敛（`推测`）；在 AI 辅助时代，它变成工程问题：

> **如何保证同一输入，每次运行都收敛到等价产物？**

本仓库把它归为 harness 问题（`推测`）：它需要运行后的**一致性与交叉验证**，而验证属于控制回路。

## 本体的两种用法（方向相反）

| 用法 | 方向 | 作用 |
|---|---|---|
| 本体作为**约束** | 生成时限制 | 缩小解空间，减少可选路径 |
| 本体作为**锚点** | 生成后比对 | 度量漂移，判定两次产物是否等价 |

常见讨论多讲前者；本页认为后者的价值被低估（`推测`）：**没有锚点就无法知道漂移发生了**，而漂移可能是缓慢且无声的。

## 漂移的可度量性

一个可操作的度量方式（设计提案，`推测`）：

1. 固定输入，跑 N 次（不同种子 / 不同温度 / 不同模型）。
2. 把每次产物投影到本体结构（概念集、关系集、约束集）。
3. 比较投影后的结构差异——不是比较自然语言文本。
4. 差异持续存在的部分，先按「输入未确定」处理，回到输入侧补信息；这是工作假设，不是已证结论。

第 4 步是关键：**一部分漂移是输入不完备的信号，而不是模型不稳。** 这是本页的操作假设（`推测`），不是 EvoMemState 的结论——EvoMemState 给的是状态结构与 stop 门，digest 没有报告跨运行重放。它与 E-06 同向：E-06 把本体接地任务的失败主因放在工作流（输入/接地/校验/修复），而不是只归给生成模型（`已核`，position paper、单案例）；把这一归因搬到跨运行仍是类比（`推测`）→ [E-06](../../conclusions.md)。

## 另一类不一致：冗余与错误继承

形式化求解中存在一种典型模式：模型在推理轨迹里已经把答案算出来了，程序里又重算一遍（冗余）；少数情况下，程序直接继承轨迹中的答案，包括错误答案（继承）。

> 一手数字（[SLB digest](../../../src/papers/2611.02395-solver-like-behavior/digest.md) §4.1–4.2；规模增长见原文 §1）：85% 轨迹含 SLB、24% 推理 token 是 SLB；但 77–89% 程序仍独立重算，只有 163/1,791（≈9.1%）继承轨迹答案（47 hardcoded / 88 partly fixed / 28 steered）。SLB token 在 Meeting Planning 上随实例规模增长（最小题→最大题近三倍），Calendar/BlocksWorld 不增长（原文 §1）；轨迹答案错时，继承会把错误带进输出，继承路径上的形式化保证随之失效。`已核` → [E-07](../../conclusions.md) / [E-09](../../conclusions.md)

工程含义（`推测`）：**「形式化 → 求解」这条链上，形式化产物的正确性必须被独立验证**，不能因为走了求解路径就默认可靠。

## 失效模式（本页归纳，`推测`）

- **把多样性当噪声。** 多次运行不一致被当作模型随机性接受，而不检查输入侧是否有缺口。
- **用文本相似度度量收敛。** 语义等价但表述不同的产物被判为不一致，反之亦然。
- **锚点本身漂移。** 本体升级后，历史产物无法与新版锚点比对。
- **无回滚。** 一次错误的约束收紧可能污染后续运行，且无法定位是哪一版引入的。
