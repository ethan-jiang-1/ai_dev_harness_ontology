# 时刻 6 · 跨运行

## 位置

不在单次执行内部的任何时刻，而在两次执行之间。它约束的不是某一步，而是「同一输入应得同一结论」这个性质。

## 问题

同一份需求，两次转换得到不同本体；同一个数据集，两次分析得到不同结论。这类不一致在人工时代靠评审收敛，在 AI 辅助时代变成工程问题：

> **如何保证同一输入，每次运行都收敛到等价产物？**

这个问题不是生成问题，是 harness 问题——它需要运行后的**一致性与交叉验证**，而验证属于控制回路。

## 本体的两种用法（方向相反）

| 用法 | 方向 | 作用 |
|---|---|---|
| 本体作为**约束** | 生成时限制 | 缩小解空间，减少可选路径 |
| 本体作为**锚点** | 生成后比对 | 度量漂移，判定两次产物是否等价 |

多数讨论只讲前者。后者的价值被低估：**没有锚点就无法知道漂移发生了**，而漂移往往是缓慢且无声的。

## 漂移的可度量性

一个可操作的度量方式：

1. 固定输入，跑 N 次（不同种子 / 不同温度 / 不同模型）。
2. 把每次产物投影到本体结构（概念集、关系集、约束集）。
3. 比较投影后的结构差异——不是比较自然语言文本。
4. 差异持续存在的部分，即为「输入未确定」的部分，应回到输入侧补信息。

第 4 步是关键：**漂移不是模型不稳，而是输入不完备的信号。** 这是一个仓库推断（`推测`）；它与失败归因研究的发现同向——反复出现的错误多来自输入不足、接地弱、校验弱，而非生成能力（E-06，`已核`）→ [E-06](../../conclusions.md)。

## 另一类不一致：冗余与错误继承

形式化求解中存在一种典型模式：模型在推理轨迹里已经把答案算出来了，程序里又重算一遍（冗余）；少数情况下，程序直接继承轨迹中的错误答案（继承）。

> 一手摘要：形式化器普遍在轨迹里把答案算出来，程序只做复述；成本随实例规模增长（Meeting Planning 上 token 近三倍），且形式化的保证随之失效（[SLB](../../../src_notes/cards/2611.02395-solver-like-behavior.md)）。错误继承比例 9% 一说来自综述转述，`待核` → [E-07](../../conclusions.md)

对设计的启示：**「形式化 → 求解」这条链上，形式化产物的正确性必须被独立验证**，不能因为走了求解路径就默认可靠。

## 失效模式

- **把多样性当噪声。** 多次运行不一致被当作模型随机性接受，而未回到输入侧找原因。
- **用文本相似度度量收敛。** 语义等价但表述不同的产物被判为不一致，反之亦然。
- **锚点本身漂移。** 本体升级后，历史产物无法与新版锚点比对。
- **无回滚。** 一次错误的约束收紧污染所有后续运行，且无法定位是哪一版引入的。

## 开放问题

- 结构比对能否自动化到可用？需要本体提供可比较的投影。
- 逐次运行的一致性，与单次的正确性，孰先优化？
- 本体能否作为「测试集」——一组必须成立 / 必须不成立的事实对？
