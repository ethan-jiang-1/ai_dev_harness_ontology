# 投影 · 机制

> 只写「它怎么跑」。判断回 [findings](./findings.md)，边界/下一步回 [frontier](./frontier.md)。

## 问题

本体是结构，模型吃文本。中间这一步决定本体能不能被使用，通常被当实现细节跳过。

## 同一份知识的四种交付形态（N&D）

| 形态 | 体积 | element score（pooled） | 关键条件 |
|---|---|---|---|
| 投影文本（prompt） | 约 45k 字符 | **0.777** | 四个模型都有效 |
| 整塔 JSON | 约 99k 字符 | 0.717 | 结构化但长 |
| 塔查询工具 | 按需 | 0.638 | 只在模型调用时有用（76/108 trials） |
| 文档检索 | 1.5M 字符语料 | 0.597 | 检索工具在 21/108 trials 才被调用 |

## 关键数字

- K0（地址级）→ K1（tag 名 + 单位）：避坑率 **+54.6 pp**。**命名和单位本身就是最大的一层知识。**
- K1 → K2（投影文本）：避坑率 **0.605 → 0.802（+19.8 pp，95% CI +3.0~+38.4）**，element score **0.566 → 0.777**，OR 5.45，Holm p=6.0×10⁻⁷。
- 四个模型（9B–750B）的 element gain：+0.235 / +0.178 / +0.213 / +0.219；H2（随容量上升）未支持（p=0.85）。
- **9B 带投影 0.737 > 最大模型不带投影 0.672**；但任务限定「答案基本写在文本里」。
- 打乱句序 0.685；JSON 0.717；文档检索 0.597；查询工具 0.638。

## 操作经验的三种处理

- 写进本体 → 被使用。
- 作为记录放进提示 → 也基本被使用。
- 留在原始日志 → **4/80 次诊断 trial 才被检索**；两个模型从未调用。

差别不在内容，在**是否已被提升为「结论形态」**，以及**由谁决定检索**：并入本体是抽取时（系统控制）；留在日志是查询时（agent 控制）。原始日志需要模型自己完成「从事件到教训」的归纳，而这一步它常常不做。

推论：**投影不只是换格式，是把归纳工作提前做掉。**

## 成本

| 成本 | 说明 |
|---|---|
| 塔构建 | 每系统一次性；42 tags / 34 assumptions / 24 knowledge / 16 derivations；人工 curator |
| 投影生成 | 约 45k 字符；从描述记录生成；自动化程度未量化 |
| 日志并入 | 持续；新教训写成 knowledge node，否则退回检索 |
| 维护 | 本体/投影/知识节点要同步；否则模型学到旧规则 |

## 失效模式

- **投影即答案，则基准偏慷慨。** 任务答案基本写在投影里，测的是「抄得准不准」，不是「理解得对不对」。
- **投影体积失控。** 45k 字符已接近中型上下文；多系统/多年日志会更大。
- **投影丢掉约束关系。** 只有概念/属性、没有「A 成立则 B 不成立」，等于给知识没给规则。
- **投影与本体不同步。** 本体改了、投影没重生成，模型学到旧规则。
- **投影不可追溯。** 文本陈述不能指回来源；查询工具能，但不是所有模型会用（9B/EXAONE 在查询工具下更差）。
- **把投影当约束。** 投影仍在上下文里，能被忽略；安全层必须独立（25/61 命令被拒；24–68% 事实主张无证据）。

## 与本体 / 回路的关系

本体在投影里以 **领域知识文本** 出现；约束强度弱（能被忽略），覆盖率取决于投影是否包含规则/约束。被违反时通常没有自动信号。
