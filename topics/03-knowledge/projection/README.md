## 当前判断

- **同一塔上投影文本的 pooled element score 最高（0.777 > JSON 0.717 > 查询工具 0.638 > 文档检索 0.597；N&D 单 plant、9 任务、4 模型），但这是事后描述性比较，不是普适排序。** GLM-5.2 的 JSON 0.900 反超其文本 0.891；Qwen 的工具 0.407 低于其文档检索 0.538。评分协议只报 primary-trap 的一致性：judge 间 κ=0.819（121 个抽样 trial）；作者与 judge κ=0.696（仅 7 个 trial，低于预注册 0.7）；element score 的一致性未报。`已核`（分数）/ `存疑`（普适排序）
- **已测得的最大一层增益是命名+单位（K0→K1 避坑率 +54.6 pp），大于投影文本（K1→K2 +19.8 pp）；塔的物理深度未测，不能与命名+单位排序。** 16 个推导量在塔里、不在投影里，9 个任务也不要求推导量。H2（随容量上升）未支持，p=0.85。`已核`（已测那两层）
- **运行教训在抽取时并入塔，比留在日志里更会被用。** K4 诊断 trial 中日志检索只 4/80 次被调用；移除已并入的教训 element score −0.20（SE 0.05）。预注册 H3（本事故记录提高诊断分）未支持：K4 0.644 vs K4x 0.645（差 <0.01，4 个诊断任务）；两臂只有「日志里有没有本事故记录」一处差别，投影相同（K4 仍是累积条件、带已并入的教训），所以这组只隔离「日志里的本事故记录」。由此推断「投影=把归纳提前做掉」是 `推测`——digest 的对照只支持「谁决定检索」，没有「agent 不做归纳」的因果检验。`已核`（现象）
- **投影不承担安全边界。** live run 故意不告知限值，25/61 条到达安全层的命令被拒；agent 自述不能作为控制依据，安全层必须独立于 agent。`已核`。「投影写了规则仍会被忽略」未做 prompt-vs-code 对照，`推测`。
