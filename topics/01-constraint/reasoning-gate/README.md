# 推理期约束：拦结论，不拦动作

## 位置

在动作之前、甚至在产出之前：模型正在推理，本体限制它**能用什么结论、能推到哪一步**。它不改变某个工具调用是否执行，而是改变「哪些结论有资格被取用」。

这是 01 派里最晚补进来的第三个位置。前两个是动作前（[action-gate](../action-gate/README.md)）与落盘前（[commit-gate](../commit-gate/README.md)）。

## 两种机制

| 机制 | 做法 | 代表 |
|---|---|---|
| 推理锚定 | 把推理限制在 curated KG 上，拆成可审计步骤；缺证据时主动追问 | 多 agent 差分诊断（2610.36325） |
| 符号验证 | 把动作空间压到本体概念层，用符号验证器检查条件是否满足 | OntoAct（2610.21983） |

两者的共同点：**判据来自本体，而不是模型自评**；区别是前者限制「从什么推」，后者限制「推出来的条件是否成立」。

## 证据

- **OntoAct（一手正文，`已核`）**：把继承记录抽象成 typed world knowledge；LLM 提议假设/动作，符号验证器用**三值条件**（⊤/⊥/?）检查；缺证据触发观察，不直接 block。Tacit-FLE 三个规模成功率 78.6/83.3/90.0%（IfR 64.3/66.7/65.0），spurious interventions 1.9/2.4/1.6（IfR 6.4/11.9/17.8）；Mars Score 15.92 vs 10.64；ALFWorld 98.5% vs 96.3%，LLM calls 13.7 vs 28.8。
- **多 agent 差分诊断（一手正文，`已核`）**：把推理限制在 curated KG（SYMP/DOID/HPO）上，LLM 只做抽取/提问/解释，排序全由确定性代码算；Q4DX 上 Top-1 18.7→21.2%、Top-3 25.8→27.3%。代价是**封顶**：本体没有的诊断（Jaundice/Vertigo 被本体归为症状）无法输出，准确率恒 0；作者明确写「caps benchmark performance」。
- **两者不矛盾，是两种约束形式**：OntoAct 验证「条件是否成立」，不限制「从什么推」；多 agent 诊断限制「只能用 curated KG」。前者是护栏，后者可能是天花板。

现有证据支持「推理期约束」作为 01 派的一个子位置；是否独立成派，仍看更多工作。

## 为什么这个位置值得单独记

- 它比动作闸门**更早**：能在模型形成错误结论时就限制，而不是等它要执行。
- 它比输出判定**更深**：判定器看产出，它看推理的依据链。
- 但它也最容易**过度限制**：curated KG 覆盖不到的地方，模型会被迫放弃正确答案；多 agent 诊断的「封顶基准表现」就是代价。**约束的形式决定它是天花板还是护栏**：验证条件（OntoAct）通常比限制知识源（curated KG）更少封顶。

## 失效模式

- **覆盖不足。** 本体只覆盖少数关系，推理被卡在 KG 边界。
- **封顶表现。** 限制越强，越可能把「本来能推对」的路径也剪掉。
- **阻断信号弱。** 推理被限制时，模型往往只是「换个说法」，而不是报错。
- **与动作闸门重复。** 同一份本体在推理期和动作期各判一次，可能重复收费。
- **schema 覆盖不足。** 没有适用 axiom 的动作/假设，验证器只能放行或 fallback；覆盖率决定它是不是「选择性护栏」。
- **把 unknown 当 block。** 缺证据应触发观察；直接拒绝会把「不知道」变成「不允许」。

## 开放问题

- 推理期约束与动作期约束是否该合为一派？判据来源相同，但介入位置不同。
- 验证条件的覆盖率：多少动作/假设没有适用 axiom？没有 axiom 时是放行还是 fallback？
- 三值条件在真实传感器噪声/缺失下是否仍可用？
- 如何度量「无依据结论」的比例，而不只是最终准确率？
- 推理期的阻断如何留下可审计的信号？
