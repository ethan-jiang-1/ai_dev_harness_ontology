## F1 · 条件闸门，不是安全保证

- **判断**：在动作执行前、推理进行中，本体限制「能用什么结论、哪些动作前提成立」。有适用 axiom 且条件/禁止被违反时，验证器 block 该动作；缺读数只报 unresolved、转观察。它只拦条件不成立的动作，不是覆盖所有动作的闸门，也不提供安全保证。
- **证据**：OntoAct 在共享资源条件下 70/70 违规候选在执行前被重定向、发出命令 0/136 违规（IfR 重定向 0/20、发出命令 20/107 违规）；Tacit-FLE 成功率 78.6/83.3/90.0% vs IfR 64.3/66.7/65.0%，SI 1.9/2.4/1.6 vs 6.4/11.9/17.8。多 agent 诊断把候选限制在 curated KG，Top-1 18.7→21.2%，但 KG 未覆盖的诊断恒 0。
- **边界**：模拟/小样本；无真实工厂/临床；多 agent 用模拟患者（可访问完整 profile，乐观估计）与单本体；schema 固定；作者明确 verifier 不是 safety guarantee。
- **来源**：OntoAct §3.4、§4.1、§4.3、§5；多 agent §IV。

## F2 · 形式决定天花板

- **判断**：验证条件（OntoAct）只检查条件是否成立，不限制模型从哪些知识推理，因而不一定封顶；限制知识源（curated KG）把候选锁在本体关系内，可能封顶。
- **数字**：OntoAct Tacit-FLE 78.6/83.3/90.0 vs IfR 64.3/66.7/65.0；多 agent Top-1 18.7→21.2，但 Jaundice/Vertigo 恒 0。
- **边界**：不同任务形态；不能直接说「验证条件一定更好」；elimination 上 IfR 匹配/超过 OntoAct。
- **来源**：OntoAct Table 1、§4.1；多 agent §IV-C、§5。

## F3 · 三值条件

- **判断**：⊤/⊥/?；? 只报 unresolved 并触发观察/追问，不直接 block；⊥ 才 refute 假设/拦相关动作。避免把「不知道」变成「不允许」。
- **证据**：OntoAct 的 condition report + hypothesis revision；多 agent 的 Yes/No/unsure 追问。
- **边界**：schema 固定；真实传感器噪声未测；? 过多会让闸门退化为观察循环（`推测`）。
- **来源**：OntoAct §3.4、§4；多 agent §3.3。

## F4 · 覆盖率

- **判断**：没有适用 axiom 的动作/假设只能放行/fallback；覆盖率决定它是不是「选择性护栏」。
- **等级**：`推测`（作者未给覆盖率数字；digest §9 把它列为未解决）。
- **边界**：需要统计每域 axiom 覆盖率；低覆盖时不要把它当全量安全门。
- **来源**：OntoAct §4.4、§9；digest §6.5。
