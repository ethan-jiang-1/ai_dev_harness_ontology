# 7. 决策：今天要上，先做什么、先问什么、什么时候停

> 本页只给**决策问题与验收数**，不给实施 recipe（那在 [02](../../02-engineering-playbook/README.md)）。目标：让你在 90 天内判断“这条路值不值得继续”，而不是先买三年平台。

## 7.1 先做三个“不”

1. **不从零建本体塔**：先把已有底座列出来——数仓/BI、dbt、图数据库、数据库内嵌、Wiki/OKF、自研数据平台。没有底座，先补底座，不要先造引擎。
2. **不把“本体”当项目**：它是一个有 owner 的语义资产；没有 owner、没有版本、没有退役机制，建完就是负债。
3. **不用厂商 demo 当验收**：demo 只证明“能演示”，不证明“你的数据/权限/口径能跑”。

> **底座不是单选题**：知识还散在 Wiki/文档里，可以先用 OKF/结构化 Markdown 统一概念、术语、来源、owner；也可以同时用数仓语义层、本体平台、图库或数据库内嵌——几种载体叠加是常态，不是“只能选一个”。用 [4b 的升级信号](./04b-okf-wiki.md#4b6-什么时候才值得上本体3-条信号设计判据推测) 判断要不要上本体；OKF 可以长期用，不是必经阶段，也别把“可以衔接”当“已经衔接”。

## 7.2 选底座前，问五个问题

| # | 问题 | 为什么问 | 不合格的信号 |
|---|---|---|---|
| 1 | **机器到底执行了什么语义？** | 查询重写/约束校验/策略求值/权限过滤，是不同能力；有引擎≠会拦 | 只会“把本体塞进 prompt”；说不清执行点 |
| 2 | **本体作用域多大、上限多少？** | 企业级本体与知识库级薄本体是两种东西 | 不告诉你类型/关系上限；或上限大到不真实 |
| 3 | **版本/证据/权限怎么做？** | 生产失败多在语义维护/权限，不在查询 | 没有版本、没有 evidence、权限靠人配 |
| 4 | **有没有具名生产参考（规模+失败）？** | 只有 logo 不够；要看它跑了多少、错过什么 | 只给“某大型集团”；不肯说失败/限制 |
| 5 | **退出/迁移怎么做？** | 语义资产不能被单一格式锁死 | 没有导出/开放格式；迁移要重买 |

> **加分项**：支持开放语义格式（如 Ossie/OSI 一类）、能把语义层当代码版本化、能把权限委托给已有 IAM/行列权限。

## 7.3 90 天试点：只看四个数

不要一上来全公司推广。选**一个高价值、口径争议最大、但边界清楚**的域（例如“客户资产层级”“理赔流程涉及部门”“设备故障根因”），做 90 天 shadow/小流量。

> **这一段是决策辅助，不是本份的实证结论**：四个数的量法与判据借自 [02 验收](../../02-engineering-playbook/02-sections/05-acceptance.md) 与 06-measure 的测量协议；公开材料里没有这套阈值的生产基准，10 不为它背书，也不把它写成“业界做法”。

开跑前三个前置，缺一个就别开：

- **基线要在第一天写下来**：现状下同一批问题的查数时长、由谁查、返工几次；否则 90 天后所有改善都是事后解释。
- **要有一个能签字的口径 owner**：定义冲突由他裁，不由模型裁。
- **要有一个能喊停的出资人**：否则四个数会被解释成大家想要的样子。

| 数 | 怎么量 | 用来判断 |
|---|---|---|
| **首次答对时间** | 从提问到业务方认可答案的中位时间（人工计时） | 有没有比现在快 |
| **同问跨界面一致性** | 同一问题在 BI/agent/报表上的答案是否同值同义 | 语义层有没有真的统一口径 |
| **需人工修的比例** | 100 个真实问题里，需要人改 SQL/改答案/补口径的数量 | 维护负担是否可承受 |
| **每周维护人时** | 口径/同义词/权限/版本维护的实际工时 | 能不能长期养 |

**辅助数**（有则更好）：查询量、用户数、延迟、权限拦截/误拦、影子实体数、退役口径数。

**四个数怎么一起读**（不要加权成一个总分）：

| 组合 | 读法 | 动作 |
|---|---|---|
| 首次答对时间降 + 一致性升 + 人工修降 + 维护人时平 | 语义层盖住了真实问法 | 继续，扩下一个域 |
| 首次答对时间降 + 一致性升 + 维护人时持续升 | 覆盖面换来了维护债 | 限流：只保留高频问题，冷门问法退回人工 |
| 首次答对时间不降 + 人工修比例高 | 问题多半不在语义层，在上游数据或口径源头 | 停语义层投入，先修源头 |
| 一致性升但首次答对时间不降 | 收益是“少吵架”，不是“更快” | 让业务方明确认这个价值，认不了就缩范围 |

> **不要用**“模型准确率”单独验收：没有业务口径的“准确”可能是另一个错。也不要用“命中率”代替“答案同源”。

## 7.4 什么时候停

| 信号 | 动作 |
|---|---|
| 出现**影子实体**（表→实体自动映射，源表一变全错） | 停自动映射；回到显式对象/关系建模 |
| **口径没有 owner**，或同一个指标两个“官方版本” | 停扩展；先定 owner/版本/退役 |
| **权限靠人特批**，或聚合结果能定位到个人 | 停上线；先做权限即计算/聚合屏障 |
| **每周维护人时**超过它省下的返工/事故价值 | 停/缩范围；回到“只做一个域” |
| 90 天拿不出上面四个数 | 不判成功；补测量，不靠感觉 |

## 7.5 一张决策卡（可抄）

```
场景：____________________
底座：____________________
本体厚度：知识库级 / 领域级 / 企业级
执行语义：查询 / 校验 / 策略 / 权限 / 无
owner：____________________
版本/证据/权限：有 / 无
具名生产参考（规模+失败）：有 / 无
90 天四个数：首次答对时间 / 跨界面一致性 / 人工修比例 / 每周维护人时
go / no-go：____________________
```

**判据**：四项里有两项明显优于现状，且维护人时在预算内 → 继续；否则缩范围或停。不要用“战略重要”替代数。

### 7.5b 一张填好的例子（示例值，不是任何一家公司的实测）

```
场景：某券商「信用业务经营分析的口径统一」
底座：既有指标/元数据/血缘治理资产 + OKF 作权威源
本体厚度：领域级（只做一个域，不做企业级）
执行语义：查询 + 权限
owner：数据产品应用部（具名角色，不是真人名）
版本/证据/权限：有
具名生产参考（规模+失败）：有 —— 中泰 CCSA（A 弱；9,137 知识目录 / 6,503 指标文档 / 12 万+ 血缘，业务本体仅在信用业务验证）
90 天四个数：首次答对时间 −30% / 跨界面一致性 ≥90% / 人工修比例 ≤20% / 每周维护人时 ≤8 人时/周
go / no-go：四项里两项达标且维护在预算内 → 继续
```

**这四个数是示例目标，不是中泰或任何公司的实测；用来示范怎么填，不能当基准**。

- **先照 7.5 的空表填一遍，再用 7.3 的四个数验收**；填不出来的格子，就是还没想清楚的地方。
- **示例值只示范格式**；真实阈值要用自己的基线（7.3 前置）定。

## 7.6 一句话

**先选底座，再做薄本体，先量四个数，再谈推广。** 本体不是买来的，也不是建一次就完的；它是“有人养”的语义资产。
