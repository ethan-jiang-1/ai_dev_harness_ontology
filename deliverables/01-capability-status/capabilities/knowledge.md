# 知识供给：K1 / 投影 / 编译

> **一句话**：先对齐名字/单位/别名，再决定要不要投影/编译。 ｜ **适用**：封闭域、命名/单位是主要歧义。 ｜ **证据**：E-12（单工厂/9 任务）。 ｜ **边界**：跨域、多设备未测。

## 3.1 K1 命名/单位/槽位：最先做，也最像「肯定没问题」

同一份工业知识，把地址级标签换成「tag 名 + 单位」，避坑率相对 K0 提高 54.6 个百分点；再把整座塔投影成文本，只再加 19.8 个百分点（E-12）。这是已测各层里最大的一层增益，而且不需要建整座本体塔。

**为什么先做**：它便宜、可回退、失败也不会造成伤害；它还是后面所有投影/编译/checker 的地基——名字和单位不对，后面的约束都建在沙上。

> 术语：K0 = 地址级标签；K1 = tag 名 + 单位；K2 = 把整座塔投影成文本。三者是 N&D 的三个知识层级，不是本仓库的证据等级。

**距离**：单工厂、9 个任务、答案基本写在文本里。换域要重测；但它仍然是当前最值得先做的一步。


## 3.2 领域知识投影：能试，但别把它当约束

同一座塔，投影成文本的 pooled element score 最高（0.777 > JSON 0.717 > 查询 0.638 > 检索 0.597），但不是普适排序：GLM-5.2 的 JSON 0.900 反超文本 0.891，Qwen 的工具 0.407 低于文档检索 0.538（E-12）。投影顺序本身是有效成分：打乱句序 0.777→0.685。

**能做什么**：让模型在封闭域、操作手册型知识上「知道得对」；9B 带投影 0.737 > 750B 不带 0.672，但区间约 0.3 宽，不能当普遍规律。

**不能做什么**：投影不承担拒绝逻辑。投影里写了规则，模型仍可能忽略；硬约束必须另进 01/02。强检索 harness 下，被测量的结构化工件没有可检出的准确率增益（E-01；但 ontology 在原文是 `not measured`，不能读成「本体无用」）。

**距离**：单工厂、9 任务、45k 字符；多设备/多站点、开放域检索、需要多跳推理的场景都未测。


## 3.3 证据编译：省的是预算，不是准确率

claim–leaf（主张-证据叶子）编译在证据充分时省 91% token，不充分时反而 +1.9%，平均 −38%；准确率 neutral；PageIndex 大纲在 FRAMES 规模实测为负（E-08/E-14）。盈亏平衡是条件性的：`p_h > 2% + c/(0.929Q)`；`c=10`、`Q=1000` 时门槛约 3.12%。

**能做什么**：语料大、重复检索多、token 是硬成本时，把「读整段」换成「读 claim + 逐字 span」。

**不能做什么**：不能拿平均 −38% 当上线依据；它不是准确率项目；证据替换用检索轮次换 token，配对子集时延约 3×（仅 7 题）。

**距离**：先量自己的 `p_h`、miss penalty、`c`、`Q`；`p_h < p_min` 就不做。
