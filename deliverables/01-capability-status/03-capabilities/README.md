## 3.1 点位语义：最先做，也最像「肯定没问题」

> **一句话**：先把 tag 名、单位、质量码对齐；工程上可再加别名/槽位。 ｜ **适用**：封闭域、命名/单位是主要歧义。 ｜ **证据**：E-12（单工厂/9 任务）。 ｜ **边界**：跨域、多设备未测。


同一份工业知识，把原始点位（PLC 地址 + 原始整数）换成「tag 名 + 单位 + 质量码」，避坑率相对原始点位提高 54.6 个百分点；再把塔的投影文本放进上下文，只再加 19.8 个百分点（E-12）。这是已测各层里最大的一层增益，而且不需要建整座本体塔。

**机制（解释，`推测`）**：塔有 162 节点/42 tags/9 个任务；K0 给 agent 的是 PLC 地址 + 原始整数，K1 补 tag 名、单位、质量码（N&D §3.1/§3.3）。primary trap 主要是单位/别名/槽位对不上——答案写在 45k 字符的描述记录里，失败发生在「读错了那个数」，不是「不知道」。K1 把这类失败从查找/换算降成阅读理解，所以 +54.6pp 最大、最便宜；代价是它不解决跨设备/多站点。

**为什么先做**：它便宜、可回退、失败也不会造成伤害；它还是后面所有投影/编译/checker 的地基——名字和单位不对，后面的约束都建在沙上。

> **K 是什么**：K0–K4 是 N&D 论文的实验条件编号，**不是术语，也不是行业标准**；正文用「点位语义 / 知识投影文本」。原文的 K1 只指 tag 名/单位/质量码，**不含别名/槽位**——别名/槽位对齐是本仓库的工程扩展（`推测`）。完整对照见 [K 页](../02-sections/92-k-ladder.md)。

**距离**：单工厂、9 个任务、答案基本写在文本里。换域要重测；但它仍然是当前最值得先做的一步。

## 3.2 知识投影文本：能试，但别把它当约束

同一座塔，投影成文本的 pooled element score 最高（0.777 > JSON 0.717 > 查询 0.638 > 检索 0.597），但不是普适排序：GLM-5.2 的 JSON 0.900 反超文本 0.891，Qwen 的工具 0.407 低于文档检索 0.538（E-12）。投影顺序本身是有效成分：打乱句序 0.777→0.685。

**机制（解释）**：投影是把塔的 45k 字符描述记录写成文本（原文说 prose + structured blocks）；它不含 16 个推导量（及假设）——那些在塔里、不在文本里。**固定分节是工程建议，不是论文的 K2 定义**；打乱句序会掉（见上），说明顺序本身是有效成分（N&D §3.2/§4）。

**能做什么**：让模型在封闭域、操作手册型知识上「知道得对」；9B 带投影 0.737 > 750B 不带 0.672，但区间约 0.3 宽，不能当普遍规律。

**不能做什么**：投影不承担拒绝逻辑。投影里写了规则，模型仍可能忽略；硬约束必须另进 01/02。强检索 harness 下，被测量的结构化工件没有可检出的准确率增益（E-01；但 ontology 在原文是 `not measured`，不能读成「本体无用」）。

**距离**：单工厂、9 任务、45k 字符；多设备/多站点、开放域检索、需要多跳推理的场景都未测。

## 3.3 证据编译：省的是预算，不是准确率

claim–leaf（主张-证据叶子）编译在证据充分时省 91% token，不充分时反而 +1.9%，平均 −38%；准确率 neutral；PageIndex 大纲在 FRAMES 规模实测为负（E-08/E-14）。盈亏平衡是条件性的：`p_h > 2% + c/(0.929Q)`；`c=10`、`Q=1000` 时门槛约 3.12%。

**机制**：claim–leaf 把「整段阅读」换成「claim + 逐字 span」：证据充分时，模型只读叶子，token 大降；证据不充分时，还要回退检索，反而更贵。所以平均是混合，不是「平均都能省」（E-08/E-14）。

**能做什么**：语料大、重复检索多、token 是硬成本时，把「读整段」换成「读 claim + 逐字 span」。

**不能做什么**：不能拿平均 −38% 当上线依据；它不是准确率项目；证据替换用检索轮次换 token，配对子集时延约 3×（仅 7 题）。

**距离**：先量自己的 `p_h`、miss penalty、`c`、`Q`；`p_h < p_min` 就不做。

## 3.4 输出证据契约：**撤回 / 待新源**（原为中端、可审计）

> **W-02**：原锚 E-03 撤回；机制保留、效应量不复述。能力判定见 [map §2.2b](../02-sections/02-map.md#22b-gap待新源4-行)。
>
> **一句话**：机制是「输出带依据 + 接地等级」；今天没有 admitted 效应量，不能判 B。 ｜ **适用**：愿意先做小样测量、且能接受「等级是模型自评」的团队。


做法是强制每个答案报告所用作证据的本体观察 + 接地等级（entailed/supported/related/unrelated）。

**机制（解释，`推测`）**：模型生成答案时，若不被要求带 observations，无法区分「没检索到/检索到但不够/检索到但无关」；契约把三态变成字段，让「无根据」可见；但接地（`local`：输出与本体证据的关系强度）是模型自评，不是形式证明。

**能做什么**：把「没有可用观察」「检索到但不足以定答案」「检索到但无关」三种情况分开；给答案一个可排序的可靠性字段。

**不能做什么**：等级是模型自评、未校准，不提供形式正确性保证；它不是闸门，不改变走向。

**重启前先量（协议，`工程建议`）**：

| 量什么 | 怎么量 | 停 |
|---|---|---|
| 检索是否够 | 200 题；gold evidence 检索率 ≥50%、引用率 ≥85% | 低于线先修检索，不上等级 |
| 等级是否可分 | 每级 100–200 条**独立标注**，报 precision/recall | 没有独立标注 → 只做提示 |
| 成本 | reasoner/SPARQL 调用 + 集成人日 | 量不出就只做只读 |

**距离**：等级校准、句级 span、多本体协调都未做；先修检索，再谈分级。

## 3.5 输出后 checker：**撤回 / 待新源**（原为「能抓结构错，抓不住语义错」）

> **W-01**：原锚 E-02 撤回；catch/FA、空结果重试基线、curated precision 不再作结论。能力判定见 [map §2.2b](../02-sections/02-map.md#22b-gap待新源4-行)。
>
> 本体当外部判据，检查查询/答案的类型、声明、domain/range、模式约束；机制在，效应量待重测。

**机制（代码 + 解释）**：checker 把答案/查询送进 reasoner 或 SPARQL，检查类型/声明/domain/range；结构错能变成可阻断信号，语义错（meaning change）抓不到。空结果重试是否为强基线，需要在本域重测（W-01）。

**能做什么**：在不看全量人工复核的前提下筛出可疑项；把「通过/违反/未检查完」三态显式化（E-20 的代码核对发现，第三态在 shell 退出码里会被折叠）。

**不能做什么**：结构检查对 changes of meaning 基本抓不到；不能证明「judge 一定更好」——旧观察提示它可能修坏多于修好，要自己测净修复。

**重启前先量（协议，`工程建议`）**：

| 量什么 | 怎么量 | 停 |
|---|---|---|
| 增量 catch | 200 题分层（类型/声明/语义各 ≥50）；相对空结果重试 | 增量 <+5pp → 停 |
| 误报 | FA 单独报，不并进 accuracy | FA >15% → 停 |
| 修坏 | flag 后 fixed − corrupted | ≤0 → 不用 judge 分支 |
| 成本 | per-flagged（token/时延）× flag_rate | 超过人工审核 1/3 → 停 |

**距离**：false-veto 未测；单 checker 实验；curated 需要先审计/补声明；没有标注集就不知道曲线。

## 3.6 动作前可逆性闸：**撤回 / 待新源**（原为「窄条件能试」）

> **W-03**：原锚 E-04/E-13 撤回；T1-only、能力梯度不再作结论。能力判定见 [map §2.2b](../02-sections/02-map.md#22b-gap待新源4-行)。CASEL（E-15）是非本体参照，不能补这一行。
>
> **一句话**：机制是「动作前按可逆性剪枝/审批」；今天没有 admitted 本体闸证据，不能判 B。 ｜ **适用**：愿意先做 shadow、且能标注 blocked 的团队。

> **词源**：「可逆性 / 动作闸」是 `local` 本仓库工作词，没有标准锚；ODRL 2.2 / XACML 3.0 只定策略表达与判定架构（`N: W3C ODRL 2.2` / `N: OASIS XACML 3.0`），不定「可逆」。


做法是用两层本体对工具调用打可逆性分、执行前剪枝。

**机制（代码 + 解释）**：POLAR 用 Layer A（T1–T5 类型化逆关系 + curator 权重）+ Layer B（每轮从 DB/工具记录重建的状态投影），对候选动作反向搜索 undo 序列；整条序列的分数是 `min φ(u)`，一步不可逆就把整条拉到 0；低于 τ 就 veto（τ 是论文参数，源已移出，只作机制示例）。

**能做什么**：在动作不可逆、代价高、模型能力弱于域要求、域规则可被查询成事实时，做 shadow 剪枝/审批。

**不能做什么**：不能证明「结构判据有效」；不能证明「护栏总是更好」；不能覆盖合法意图主导的场景；不能证明逆执行一定成功。

**重启前先量（协议，`工程建议`）**：

| 量什么 | 怎么量 | 停 |
|---|---|---|
| 误拦 | shadow 200–500 决策；100 条 blocked 人工标 harm/授权 | 标不出 harm → 只做只读 |
| 收益 | 同轨迹配对（上/不上闸）；task success 降幅 | 降 >2pp → 停 |
| 前沿 | 报 miss–false-block 前沿，**不设单点** | 只报单点 → 不接受 |
| 状态 | Layer B 投影准确率先测 | 投影不准 → 不做硬 veto |

**距离**：false-veto 标注、同轨迹配对、能力梯度阈值都没有；旧 E-13 的六点拟合与两份通用 guardrail 材料已移出，不能再引用。X5 的 false-veto 仍是 `unknown`。

## 3.7 跨轮身份/记忆：能试，但先锚身份

> **一句话**：先建 registry，再谈状态。 ｜ **适用**：跨期实体、冲突/失效要保留。 ｜ **证据**：E-05/E-17。 ｜ **边界**：专有数据；false merge 传播未测。


本体在记忆系统里克制到只做对齐与印证条件：alias memory 让 final-period CMR（跨期匹配率）+7.8–12.1pp（4 settings）、reattachment recall +22.5–29.0pp、human-audit CMR +9.0–16.5pp、semantic matching token −40.3%（E-05）。EvoMemState 把记忆分成 Persistent Facts + Relational State + Reasoning State：Complete Retrieval 85.6%（与最好 baseline 相当），但 Acc@complete（完整答案准确率）70.8/68.5（+11.5/+31.2）；去掉状态层掉点（E-17）。

**机制（解释，`推测`）**：跨期记忆的失败主要是实体对不上（同一设备不同 tag/别名）和状态被当成事实。registry 先给实体一个稳定 ID，再让状态挂在这个 ID 上；否则 alias/merge 会把两条历史缝错。CMR 看跨期匹配，Acc@complete 看完整答案；两者不是一回事。**所以**：先 registry，再谈内容/检索。

**能做什么**：跨会话、跨期实体知识；需要保留冲突/失效；下游判断依赖历史一致性。

**不能做什么**：不保证跨运行确定性；文本 only、需训练信号；false merge 的长期污染未测；未匹配 ≠ 关系结束。

**距离**：先建 registry，再谈内容/检索；merge precision 与 CMR 一起看；没有自动回滚。

## 3.8 读路径过滤/查询重写：有代码，但别扩大解释

> **一句话**：read-path/查询重写有代码，但别扩大解释。 ｜ **适用**：读侧可见性、OBDA。 ｜ **证据**：E-20（代码级）。 ｜ **边界**：fail-open/只删 subject；无 agent 集成。

> **词源**：「读路径过滤」是 `local` 工作词，没有标准锚；SHACL-AF 只定规则/扩展机制（`N: W3C SHACL-AF`），OWL 2 Profiles 只定 profile 语义（`N: W3C OWL 2 Profiles`）；「会不会拦住」是效应问题，回 E-20，不引标准。


trustgraph 在查询结果返回前跑 SHACL-AF 策略，命中 `tg-pol:blocks` 的节点，其 subject 侧三元组被删除；它是读路径 best-effort gate，不是动作前闸门：target/rule 异常时 fail-open，且只删 subject 侧（E-20）。ontop 在查询编译时做 TBox 饱和 + 查询重写，把 SPARQL 变成 SQL；它是供给层执行器，不是判定器（E-20）。

**机制（read-path）**：trustgraph 的 `PolicyFilter` 是查询结果后的 SHACL-AF 求值器；`_triple_blocked` 只查 `triple.s`，所以只删 subject 侧；target/rule 异常 → 不命中 → 放行；无策略 → passthrough。它被设计成**可用性优先的可见性过滤**，不是授权闸（trustgraph digest §3/§6）。**所以**：object 方向泄漏和 fail-open 是设计范围，不是可修的 bug；要用它做安全，必须补第二实现/两侧约束/异常注入。**反例**：`?s ex:worksFor ?o` 中 `?o` 被 block、`?s` 可见时，`_triple_blocked` 只查 `?s`，这条三元组仍返回。

**机制（OBDA）**：ontop 在查询编译时做 TBox 饱和 + 重写（rewrite → unfold → SQL）；本体不是「在运行时拦」，而是「把查询改写成 SQL」。边界可判：只支持 OWL 2 QL；需要 DL 推理/事务写入就不适合（E-20）。**所以**：OBDA 是 A（可先落地），因为边界能写成验收；它不是闸，不要拿它做授权。

**能做什么**：读侧可见性/信息屏障；OBDA（本体驱动的数据访问）式「本体+映射→SQL」的查询回答。

**不能做什么**：不能当写授权，不能当动作闸，不能证明对象方向也受控；ontop 只支持 OWL 2 QL，不做 DL 推理。

**距离**：read-path 只有 1 个独立实现；需要第二个实现才决定是否升第七时刻。

## 3.9 还不能承诺的三件事

> **一句话**：commit、跨运行确定性、多智能体共享本体还不能承诺。 ｜ **适用**：设计/边界讨论。 ｜ **证据**：E-20 + 设计提案。 ｜ **边界**：无实现、无度量。


- **落盘前授权（commit gate；`local` 工作词，没有标准锚）**：设计上要求证据齐、冲突清、版本有效三条全过；但只有概念架构，无实现、无 false-defer 数据；四个开源项目里没有一个是单次写授权（E-20）。**现在只能做只读/影子，不能声称已落地。**
- **跨运行确定性**：只有设计提案，未升 E；没有实现、没有度量。
- **多智能体共享本体**：`00-harness` 里唯一没有对应流派的部件；缺可判定设计与证据。**这是空白，不是遗漏。**

**为什么是这些档**：
- **commit 是 C 不是 B**：有三条设计契约，但没有 mutation class 实现、没有 false-defer 标签；只能设计，不能 shadow。
- **确定性是 C**：只有设计提案，没有实现/度量；跨轮记忆（E-17）不是跨运行重放，E-18 的 54% 是噪声地板，不是收敛度量。
- **多智能体是空白不是 C**：没有可判定设计，也没有一手证据；C 至少有机制/设计。
