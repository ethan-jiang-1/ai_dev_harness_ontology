# 术语与内码速查（01）

> 第一次读 01 先看这一页。这里只解释「读 01 会用到的词与码」；完整术语见仓库根 [GLOSSARY](../../../GLOSSARY.md)。

<a id="term-sources"></a>
## 0. 名词从哪来（N / local）

> **读法**：`N:` = 规范性锚（标准/权威本体），只定「这个词是什么意思、什么叫合格」，**不撑效果、不给阈值**；`local` = 本仓库工作词，没有标准锚，按本页解释读，不得写成行业共识。标准清单与「不能定义什么」见 [规范主干](../../../topics/trunk.md)；逐词判定见 [术语基线](../../../meta/term-baseline.md)。

| 词 | 来源 | 一句话（只到读懂 01） |
|---|---|---|
| 本体 | `N: ISO/IEC 21838-1`（本仓库义更宽，判 `broader`） | 领域概念、关系与约束的显式规范；标准只给 TLO 的合格性 |
| 顶层本体 / TLO | `N: ISO/IEC 21838-1/-2` | 小、通用、不含领域词的上层本体；BFO 是参考 TLO |
| 领域本体 | `local` | 面向一个领域的概念/关系/约束；标准不定义它 |
| 知识图谱 | `local` | 实例层事实图，区别于本体（概念层） |
| 语义层 | `local` | 把领域语义叠到数据/接口上的那一层 |
| 约束 / 校验 | `N: W3C SHACL` | 对 RDF 图的可检查条件与三态结果；只到图，不到动作授权 |
| 推理 / profile | `N: W3C OWL 2 Profiles` | profile 语义与规则表；不证明推理效果 |
| 策略表达 / 判定架构 | `N: W3C ODRL 2.2` / `N: OASIS XACML 3.0` | 许可/禁止/义务的表达，与 PDP/PEP 式判定架构；不含执行点 |
| 数据分级 | `N: GB/T 43697-2024` | 核心/重要/一般三级框架；不是策略语言 |
| 个人信息 | `N: GB/T 35273-2020` | 个人信息处理要求；不是机密性分级 |
| 数据契约 | `N: ODCS v3.1.0` | data contract 的结构/SLA/质量字段；不保证运行时执行 |
| 接地（grounding）/ 接地等级 | `local` | 输出与本体证据的关系强度；原锚 E-03 已撤回 |
| 动作闸 / 可逆性 | `local` | 动作前的放行点与逆序列判据；没有标准定义 |
| 落盘授权 / commit gate | `local` | 「可推理证据」与「有权落盘证据」的分界；没有标准定义 |
| 接缝 / 执行形态 | `local` | 本体在回路哪个时刻介入 / 机器拿它做了什么 |
| A/B/C/D、`gap`、`undetermined` | `local` | 交付层排序词，不是证据等级，也不是标准术语 |
| 证据等级（已核/推测/存疑） | `local` | 本仓库的置信度分级，定义见 [conventions](../../../meta/conventions.md#证据等级) |
| 论文条件 K0–K4 | `local`（论文 I 层条件，非术语） | N&D 的五个实验条件编号；不是行业层级/成熟度 |

> **只定词，不撑效果**：上表的 `N:` 行只回答「什么意思、什么叫合格」；「用了有没有用」只能引 E-xx（I 层）。下标不写 `N` 也不写 `local` 的专业名词，就是漏标。

## 1. 两套码，不再撞车

| 码 | 是什么 | 例子 | 不是 |
|---|---|---|---|
| **X1–X9** | 01 的 **9 条期待**（要量什么） | X1「点位语义相对原始点位 ≥+10pp（论文 K1 vs K0）」 | 不是证据编号 |
| **E-01–E-20** | 仓库的 **跨派结论**（已经形成的判断） | E-12「点位语义 +54.6pp（论文 K1）」 | 不是期待 |

> **X 是期待，E 是证据。** 2026-11-11 起期待改用 `X` 前缀，不再与 `E-xx` 共用字母。01 的 basis 是 E-01–E-20；仓库现在共 27 条 E，另 7 条（E-21–E-27）不在 01 的主路径里。
>
> 数据表文件名仍用 `e3`–`e8`（历史命名），与 X3–X8 一一对应；**文件名不是证据编号**。

## 2. 判定

| 词 | 含义 | 注意 |
|---|---|---|
| **A 可先落地** | 有实现/公式/已测操作 + 边界能写成验收 + 可回退；源仍 admitted | 不是「已证」 |
| **B 可试点** | 有一手证据且源仍 admitted，但边界不能完全写进验收 | 先量 1–3 个数 |
| **C 只能设计** | 有机制/设计，但只有模拟/概念架构/无实现；**从未有 E 的设计提案也走 C** | 不是「不值得研究」；也不是「没有证据」 |
| **D 反向** | 在已测且源仍 admitted 的条件下会错/负收益 | 不是「永远不能用」 |
| **gap / 待新源** | **曾有 E，但原锚 withdrawn/移出**，且没有替代的 admitted 源 | 不进 A/B/C/D；不是「只能设计」，也不是「从没证据」 |
| **非本体（参照）** | 机器没在「执行本体」（例：CASEL 的审批分配） | 不进 A/B/C/D |
| **undetermined** | 只有方向，没有机制/设计/证据 | 不是 C；不伪装成「只能设计」 |
| **A+** | 不存在 | 本仓库无独立复现，最高 `已核` |

## 3. 证据等级与状态

| 词 | 含义 |
|---|---|
| **已核** | 一手原文/代码核对过 |
| **已核（代码）** | 读代码核对过，不是效应量 |
| **推测** | 从一手材料推的，或工程估算 |
| **存疑 / contested** | 主结论可站，某个读法被削弱 |
| **not measured** | 原文没测（例：E-01 的 ontology） |
| **unknown** | 还没有一手证据；不是「无效」 |
| **gap** | 缺数据/缺来源，不进验收 |

## 4. 知识条件（K）与指标

> **K0–K4 是论文 N&D 的五个累积实验条件，不是行业标准，也不是成熟度等级。** 完整来源、原文对照、K3/K4 与「论文 vs 工程」的三处差异，见 [K0–K4 来源说明](./k-ladder.md)。

| 码 | 含义 | 坑 |
|---|---|---|
| **K0** | 原始点位：PLC 地址 + 原始整数 | 没有 tag 名；不要叫「地址级标签」 |
| **K1** | 点位语义：tag 名 + 单位 + 质量码；工程上常再加别名/槽位（我们的扩展） | 先 K1，再投影/编译；别把扩展当成论文测到的 |
| **K2** | 知识投影文本：从塔投影出的约 45k 字符文本，**不含推导量** | 不是「整塔」；固定分节是工程建议 |
| **K3** | 流程摘要：六个操作流程的摘要（塔外） | 不进 01 能力矩阵；不是「K2 的升级版」 |
| **K4** | 运行记录检索：日志/调查文档的检索工具（塔外） | 不进 01 能力矩阵；诊断 trial 只查了 4/80 |
| **primary-trap avoidance / 避坑率** | 预注册任务中「主要陷阱」被避开的比例；trap = 单位/别名/槽位等主要坑，分母是任务数 | 不是「所有错误」；E-12 是单工厂 9 任务 |
| **p_h** | 命中率：回答所需证据在上下文里的比例 | 不是「检索到没有」 |
| **p_min** | 编译盈亏平衡：`2% + c/(0.929Q)` | 自己的 `c`/`Q` 没量就不能套 |
| **FA** | false alarm：checker 把对的判错 | 与 catch 分开报 |
| **false-defer** | 本可直接执行、却被转人工/审批的比例 | 与 false-veto 不同：一个是拖，一个是拦 |
| **curated** | 人工整理的本体/schema | 相对 data-derived / masked LLM；不是「权威」 |
| **SHACL-AF / OWL 2 QL** | SHACL 高级特性（规则/目标）/ OBDA 支持的轻量 OWL profile | 前者不是「会拦」，后者不是「完整 OWL」 |
| **CMR** | 跨期匹配率：同一实体跨会话能否对上 | 与 `Acc@complete` 不是一回事 |
| **pp** | 百分点（percentage point） | +54.6pp ≠ +54.6% |

### 4.1 K0–K4 的来源与边界

**一句话**：K0–K4 是 N&D 一篇论文的五个累积实验条件，不是行业标准，也不是本体成熟度模型；01 常把 K1 写成「tag 名/单位/质量码 + 别名/槽位」，其中**别名/槽位是工程扩展**。完整来源、原文对照与「论文 vs 工程」的三处差异见 [K0–K4 来源说明](./k-ladder.md)。`已核`（论文 Table 1/§2.8）；「没有第二来源」是 `推测`（检索非穷尽）。

> **用法**：K 只作回查标签；正文用人话「原始点位 / 点位语义 / 知识投影文本」，不要读成行业标准层。

## 5. 执行形态

| 词 | 机器拿本体做了什么 |
|---|---|
| **context** | 把本体/知识放进上下文，不改动作 |
| **compiled** | 编译成约束/查询/策略，再执行 |
| **engine** | 引擎执行（查询重写、SHACL 校验等） |
| **label** | 给数据打标，不直接执行 |
| **none** | 没有落在机器执行上 |

> 定义与五种形态的选法见 [02 §2.4](../../02-engineering-playbook/sections/map.md#24-选形态五种别把-context-当低配-engine)。**不要把 `context` 当 `engine` 的低配。**
