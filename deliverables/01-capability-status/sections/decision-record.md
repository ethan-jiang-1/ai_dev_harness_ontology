# 决策记录：把 A/B/C/D 走一遍

> **这是什么**：用 [map §2.1](./map.md#21-判定口径) 的有序规则，把两行能力从证据走到判定，再附一个对照。
>
> **不是什么**：不是新结论；每个判断都落回已有的 E 与 [boundaries](./boundaries.md)。判定只解释「为什么是 A/B」，不改 14 行的标签。
>
> **K 代号**：K0–K4 是 N&D 论文的实验条件编号，不是行业标准；本页保留 K 只为回查 E-12。定义见 [K 页](./k-ladder.md)。

## 记录 1 · 点位语义（K1）→ **A**

| 项 | 内容 |
|---|---|
| 要决定什么 | 目标域要不要先做点位语义（tag 名 + 单位 + 质量码；工程上可再加别名/槽位），还是直接上投影？ |
| 证据 | E-12：原始点位→点位语义（K0→K1）primary-trap avoidance **+54.6pp**；单工厂、9 任务、答案基本写在文本里。`已核`（E-12） |
| 条件 | 目标域有 tag/单位混用；能拿到 K0/K1 回放；同一模型。 |
| 门槛 | 目标域 K1−K0 **≥ +10pp**（本域工程门；E-12 实测 +54.6pp，工程门取保守值，`推测`）；低于就停。 |
| 判定路径 | D？否 → 本体机制？是 → A？**有已测操作**（对齐 tag 名/单位/质量码）+ **边界能写成验收**（「目标域 ≥+10pp」可量）+ **可回退**（不过是改数据字典）→ **A**。 |
| 缺什么 | 跨域；目标域 trap 标注；点位语义的维护人日。 |
| 停在哪 | 若目标域 < +10pp：停在点位语义，不做投影；先查单位/别名覆盖。 |
| 什么会改变判定 | 目标域 < +10pp，或强检索 harness 下增益消失 → 降 B；若连 K0 都不稳 → C。 |

**为什么不是 B**：B 要求「边界不能完全写进验收」。点位语义（K1）的边界（单工厂、需本地复测）能写成一条可执行的验收：`目标域 K1−K0 ≥ +10pp`。所以是 A。

## 记录 2 · 读路径过滤 → **B**（当授权用 → **越界**）

| 项 | 内容 |
|---|---|
| 要决定什么 | 能不能用读路径过滤（检索返回前删 subject 侧三元组）防敏感数据泄漏？ |
| 证据 | E-20：trustgraph 在 pin commit 上加载 SHACL-AF，命中 `tg-pol:blocks` 的 subject 侧三元组从结果删除；**异常 fail-open；只删 subject 侧；只有 1 个独立实现**。`已核（代码）`（E-20） |
| 条件 | 只读检索；有 `urn:graph:policy`；principal/clearance 可传。 |
| 门槛（当闸） | object 方向 **0 泄漏**；异常 **fail-closed**；第二实现存在。三条缺一条就不能当闸。**当过滤器**：subject 侧按 policy 删除、异常 fail-open 必须标出；误拦率**未测**，不能写「可接受」。 |
| 判定路径 | D？**看用法**：当「可见性过滤」否；当「授权」是**越界**（不是 A/B/C/D）——读路径 ≠ 写授权（E-20；03 R07），不要把可见性当授权。本体机制？是 → A？有实现，但 **fail-open + object 未测**，边界写不成验收 → 不是 A。C？有实现，不是模拟 → 不是 C。B？有代码级阻断证据，边界不能完全写进验收 → **B**。 |
| 缺什么 | 第二个独立实现；object 方向用例；异常 fail-closed；阻断测试。 |
| 停在哪 | 若 object 方向泄漏，或异常 fail-open 未修：只当可见性，不当授权；不上写路径。 |
| 什么会改变判定 | 第二实现 + object 受控 + fail-closed → 可升 A；只当授权用 → 越界，不进 A/B/C。 |

**为什么不是 A**：A 要求「边界能写成一条你能执行的验收」。读路径的边界是「object 方向也不泄漏」，但 object 方向没有用例、异常还是 fail-open，所以这条验收现在写不出来。

> **2026-11-11 复查**：sparql-guard（rewrite）76/76 tests 复跑通过；10 用例实跑 7 pass、1 alias leak、0 false-block（EXP-002）；holosdb（scan）是第三个执行点。它们不改变本记录的 **B**：粒度不同、无 harness 集成、无独立泄漏率；read-path 的「单实现」限定只指 post-filter。见 [read-path §3/§7](../../../topics/01-constraint/commit-gate/read-path.md)。

## 记录 3 · 离线/CI 的 SHACL 校验 → **A**

| 项 | 内容 |
|---|---|
| 要决定什么 | 要不要把 SHACL 校验放进 CI？ |
| 证据 | E-20：semantica 派生 SHACL + pyshacl；open-ontologies 的 `--verified` 走 `oo-shacl`（0/2/3，3=undetermined）。`已核（代码）` |
| 条件 | 有 TBox/shapes；有负例；CI 能读到 JSON 三态。 |
| 门槛 | 负例 100% 检出；干净误报 ≤5%；三态可报。 |
| 判定路径 | D？否 → 本体机制？是（SHACL 被执行）→ A？有实现 + 边界（三态/targetClass）能写成验收 + 可回退（CI 失败可修）→ **A**。 |
| 缺什么 | 派生 shapes 的质量；跨 validator 一致性；CI 集成。 |
| 停在哪 | 若三态被折叠成 exit code：**不能只看退出码**——open-ontologies 把 `conforms:null` 映射成 exit 2，与「违反」不可分；要读 JSON 的 0/2/3。 |
| 什么会改变判定 | 三态报不出，或负例检出 <100% → 降 B/C。 |

## 这张记录怎么用

1. 拿你关心的能力，按 [map §2.1](./map.md#21-判定口径) 的七步（含第 0 步「源是否撤回」）走一遍；每一步写「是/否 + 依据」。
2. 走到 `undetermined` 不是失败：写清缺哪一条，回 [acceptance §5.2](./acceptance.md#52-期待与数据需求验收规格) 找要量的数。
3. 判定变了，先改 `topics/` 的证据或本派 `claims.md`，再改这一页；**不要在记录里改标签**。

> 与 04 的 `decision` 页同形：都是「证据 → 门槛 → 判定 → 缺什么 → 停在哪」；04 的判的是「这条链能不能上线」，01 的判的是「这项能力现在能不能做」。
