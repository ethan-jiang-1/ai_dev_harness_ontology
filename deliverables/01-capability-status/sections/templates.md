# 可填模板：决策记录、能力行、期待行

> 三张空表，复制到你的项目文档里填。**填不出就写「不知道」或「未测」，不要编。**
>
> 模板不是验收；填完只说明字段齐，能不能立项看 [acceptance](./acceptance.md) 与 [canonical](./canonical.md)。

## DR-1 决策记录（照 [decision-record](./decision-record.md) 填）

| 项 | 填什么 | 判据 |
|---|---|---|
| 要决定什么 | 一句话：这项能力现在能不能做 | 有主语、有场景 |
| 证据 | E-xx + 条件 | 至少一条一手证据；没有就写 `gap` |
| 条件 | 在什么域/模型/数据上成立 | 单域/跨域、模拟/实测 |
| 门槛 | 过了算 pass 的数 | 可量；没有就写「未定」 |
| 判定路径 | 按 [map §2.1](./map.md#21-判定口径) 七步走（含第 0 步「源是否撤回」） | 每步写「是/否 + 依据」 |
| 缺什么 | 还差的数据/实现 | 能指到 acceptance 的期待行 |
| 停在哪 | 不过时做什么 | 不是「再试试」 |
| 什么会改变 | 看到什么就改判 | 可证伪 |
| 等级 | 已核 / 已核（代码）/ 推测 / 存疑 / gap | 四选一 + 限定 |
| 日期 | 判定日期 | 便于回看 |

## 怎么用

1. **先填 DR-1 的「证据/条件/门槛」**：填不出，说明还没到判定，回 [acceptance](./acceptance.md) 找要量的数。
2. **再按七步走 DR-1 的「判定路径」**；走到 `gap`/`undetermined` 就停，不要硬塞 A/B/C/D。
3. **最后填 DR-2/DR-3**：它们是 DR-1 的摘要，不是另一套判断。
4. 改判定：先改 `topics/` 或本派 `claims.md`，再改模板实例；**不要在表里改标签**。
