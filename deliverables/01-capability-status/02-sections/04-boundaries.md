# 4. 边界与反例

> 本章回答：哪些能当工作前提、哪些不能。 ｜ 读完你应该能：说出反例、反向清单和证据边界。

### 4.1 在已测条件下，可以当工作前提（只列源仍 admitted 的）

1. **薄语义层先起量。** 命名+单位 +54.6pp > 深度结构 +19.8pp（E-12；单工厂；N&D `admitted (probation)`）。
2. **强检索 harness 会吃掉结构化上下文的准确率增益。** 被测量的摘要树/大纲/wiki/实体图在 FRAMES 上无可检出增益；PageIndex 大纲退化（E-01；ontology not measured）。
3. **执行 ≠ 健全 ≠ 授权。** 四个开源项目给出四种语义；trustgraph fail-open、只删 subject；open-ontologies 只做影响报告/CI 门（E-20）。

### 4.2 还不能当工作前提

1. **「上本体能稳定提准确率」。** E-01 的 ontology 是 `not measured`；E-12 是单工厂、答案写在文本里；没有跨域复现。
2. **「结构判据有效」。** 原锚撤回（W-03/W-04）；T1-only ≈ full 的旧观察不能再用，重启按 W-03 做同轨迹配对。
3. **「空结果重试是 checker 的强基线」。** 原锚撤回（W-01）；旧 catch/FA 数字不再引用，重启按 W-01 的 200 题协议重测。
4. **「护栏的收益大于误拦成本」。** 审批量有模拟数，false-veto 没有标注；`γ_m` 是假设（E-15；非本体、模拟）。
5. **「写路径能授权」。** 没有实现；E-20 只有否定性证据。
6. **「本体越完备越好」。** [Q-01](../../../topics/conclusions.md) 与 E-01 冲突；完备性与可判定性在工程上反向。

<a id="43-反向在已测条件下不要做"></a>
### 4.3 反向：在已测且源仍 admitted 的条件下不要做

1. **在强检索 harness 下为「提准确率」买结构化工件。** 被测量的摘要树/大纲/wiki/实体图没有可检出增益；PageIndex 大纲退化（E-01）。要买的是治理/预算/审计，不是准确率。
2. **把 commit gate 的概念架构当已落地机制。** 没有实现、没有 false-defer 数据；四个开源项目里没有单次写授权（E-20）。

**原锚撤回、暂不能当“已测反向”的三条**（保留作待新源清单，不作为 D）：
- 「curated 本体当权威 checker」——原锚撤回（W-01）；旧 precision/FA 数字停用。
- 「用 reward 或单一 accuracy 证明护栏有效」——原锚撤回（W-03）；C-03 的这条也要随新源重写。
- 「把 T1-only 当结构判据」「把 grounding level 当形式保证」——原锚撤回（W-01/W-03）；旧观察停用。


<a id="7-证据边界"></a>
### 4.4 证据边界

这份交付物的判断都来自 [conclusions](../../../topics/conclusions.md) 的 E-01…E-20 与 C-01…C-04。引用时注意：

- E-01/E-08/E-14/E-15/E-18 是 harness/度量证据，不是本体专属；不要把「结构化上下文」读成「本体」。
- **换词检查（历史，`推测`）**：早期统计过「把本体换成任意结构化上下文后仍成立」的比例（W-08）；参与源已按 §4 重置，计数停用；要重算等新源。见 [execution-forms](../../../topics/execution-forms.md)。
- **E-02/E-03/E-04/E-13/E-16 已 `withdrawn`**；本页不再把它们的旧数字当边界。E-15 是 `contested`（模拟、非本体）；E-12 的分数级是已核、排序级是存疑。
- E-20 是代码级核对（4 个项目、pin commit、只读代码、未做对照实验），不是效应量。
- 本仓库没有独立复现；「已核」只表示原文/代码读对了，不表示命题被验证。

更细的边界见 [03 机制参考](../../03-mechanism-reference/README.md) 与 [附录 §3.7](../../03-mechanism-reference/05-appendix-constraint-spectrum.md#37-本章不能证明什么)。
