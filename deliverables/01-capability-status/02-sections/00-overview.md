# 0. 现状摘要：案例、判断与计数

> 本页是 01 的正文第 0 章。索引与阅读顺序见 [README](../README.md)；判定规则见 [地图 §2.1](./02-map.md#21-判定口径)。

## 0.1 案例：一个工厂的 9 个任务

某工厂的 9 个任务里，agent 最初只看到「PLC 地址 + 原始整数」；把点位换成「tag 名 + 单位 + 质量码」后，避坑率相对原始点位提高 **54.6 个百分点**。再把设备本体的知识写成约 45k 字符的文本放进上下文，避坑率从 0.605 升到 0.802，只再提高 **19.8 个百分点**（E-12；单工厂、9 任务、答案基本写在文本里）。

论文（Joo & Kim, arXiv:2610.11768）把这两种条件叫 **K1** 与 **K2**，把只有地址和裸值的基线叫 **K0**。**K0–K4 是论文的实验条件编号，不是术语，也不是行业标准/成熟度**；正文只用「原始点位 / 点位语义 / 知识投影文本」，K 只在出处与回查里出现，见 [K0–K4 来源说明](./92-k-ladder.md)。

**由此得到的第一个决定**不是「建什么本体」，而是：先对齐点位语义（tag 名/单位/质量码），还是先做知识投影文本？01 的答案是：先点位语义；它不过，不做投影。

<a id="1-三句话"></a>
## 0.2 三条判断

1. **最确定的角色是「可求值的约束/查询对象」，不是「更懂业务的提示词」。** 四个开源项目在 pin commit 上给出四种执行语义：OWL 2 QL 查询重写、SHACL-AF 策略求值、SHACL 校验、SHACL→SPARQL/verified Core（E-20）。「有引擎」不等于「会拦」，更不等于「有授权」。
2. **今天能拿到的最大知识增益来自薄语义层，不是深度结构。** 点位语义（K0→K1）避坑率 +54.6pp；把塔投影成文本（K1→K2）再加 +19.8pp，且只在单工厂、9 个任务、答案基本写在文本里的条件下测过（E-12）。强检索 harness 下，被测量的结构化工件没有可检出的准确率增益；原文的 ontology 还是 `not measured`（E-01）。
3. **约束/判定这条线今天不能承诺。** 原锚 E-04/E-13（可逆性闸）与 E-02（checker）已撤回；只剩 CASEL 的审批/分配模拟（E-15，非本体）。「护栏能改变走向」不再是本仓库的结论；今天能说的是：**落盘写路径的授权仍然没有实现**（E-20）。

如果只记一句：**今天能拿到的，不是「让模型更准」，而是「在少数供给/读路径接缝上有可验收的实现」；动作前的「拦」还缺 admitted 证据，不能先承诺。**

## 0.3 判定与计数

> **计数：A=3 / B=4 / C=2 / 非本体=1 / gap=4。**

| 判定 | 清单 | 一句话 |
|---|---|---|
| **A 可先落地** | 点位语义（K1）；离线/CI SHACL；OBDA 查询重写 | 有实现或可复算公式，失败可回退；仍需本地复测 |
| **B 可试点** | 知识投影文本（K2）、编译、记忆、读路径过滤 | 有一手效应量、源仍 admitted，限定强；先量 1–3 个数再决定 |
| **C 只能设计** | 落盘授权、跨运行确定性 | 有机制/设计，但只有模拟或无实现；不能承诺 |
| **非本体（参照）** | 审批/多模式分配（CASEL） | 没有本体变量；只作参照，不进 A/B/C |
| **gap / 待新源** | 证据契约、checker、动作闸、推理期条件验证 | **原锚 E-02/E-03/E-04/E-13/E-16 已撤回**；不判 A/B/C，等新源 |
| **D 反向** | 见 [§4.3](./04-boundaries.md#43-反向在已测条件下不要做)：强 RAG 下为准确率买工件、commit 概念架构当落地；curated/reward 两条原锚撤回→待新源 | 在已测且源仍 admitted 的条件下会得出错误结论或负收益 |

> **多智能体共享本体**：只有方向，没有机制/设计/一手证据，标 **`undetermined`**。**本体自动生成/精化**是 source（[05 生产](../../../topics/05-produce/README.md)），不在本表；不要硬塞进 A/B/C。判定规则见 [map §2.1](./02-map.md#21-判定口径)。

**最像「可以先做」的只有一件：先把点位语义对齐——tag 名、单位、质量码（论文的 K1）。** 工程上常再加别名/槽位，但那是工程扩展，不在论文的 K1 里。其余都是「有条件能试」或「还差得远」；点位语义也只在单工厂、9 任务里测过，换域要重测。

**第一轮 verdict（2026-11-09；2026-11-11 证据重置后修订）**：9 条期待里，X1/X2/X6/X7 仍有 `supported（限定）` 半边，X3 仍 `conditional`；**X4/X5 因 E-02/E-04/E-13 撤回，改为 `unknown/待新源`**；X8/X9 仍 `unknown`。没有 9/9 supported；X4/X5 的旧 supported 已撤回。详见 [§2.4](./02-map.md#24-x1x9-verdict2026-11-09-第一轮) 与 [`09-data/`](../09-data/)。

<a id="6-如果只做一件事"></a>
## 0.4 第一个动作

**先做点位语义（K1），再建账本。**

- 点位语义（tag 名/单位/质量码；论文 K1）是已测最大增益、最便宜、最可回退；不需要先建整座本体塔。
- 账本（per-query 或 per-decision 的 token、时延、审批、决策、回滚）是所有 go/no-go 的前提；没有它，`p_h`、false-veto、审批成本都算不出来。
- 然后只选**一个**接缝做 shadow：今天优先在供给或读路径里选（投影、编译、读路径）；判定/动作线（checker、动作闸）等新源，不要拿 gap 行当试点。

**不要先做的**：整座本体塔（一台设备的窄而深本体，不是整座企业本体）、自动生成本体、commit gate、跨运行确定性、多智能体共享本体。它们要么没有实现，要么没有下游证据。
