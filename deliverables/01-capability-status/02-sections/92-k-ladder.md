# K0–K4 到底是什么：来源、定义与边界

> **你不需要先记住 K。** 先记住四件人话：**原始点位 → 点位语义 → 知识投影文本 → 流程摘要 / 运行记录**。K0–K4 只是 N&D（Narrow and Deep）论文给「agent 多拿到什么」编的条件号。
>
> **一句话结论**：**K0–K4 不是行业标准，也不是本体成熟度模型。** 它是一篇论文自己的五个累积实验条件；01 保留它只为回查 E-12。
>
> **先对齐一个词**：下文 K2 里的「塔」= **本体塔**，一台设备的窄而深知识结构（tag、绑定、假设、推导、运行教训），不是整座企业本体。定义见根 [GLOSSARY](../../../GLOSSARY.md#结构)。

## 1. 谁定义的，有没有共识

| 问题 | 答案 | 依据 |
|---|---|---|
| 谁定义的 | Younghwan Joo、Sung-il Kim（韩国能源研究院 / UST） | 论文作者与机构 |
| 在哪 | *Narrow and Deep: An Ontology Tower as the Knowledge of an LLM Agent for an Industrial Equipment System*，arXiv:2610.11768，2026-10-08，Table 1 + §2.8 | 原文 |
| K 是什么 | 论文的**累积知识条件**编号（K 是条件号；论文称这一组为 knowledge conditions，未单独解释字母缩写） | 原文 "five cumulative conditions, K0 to K4" |
| 是标准吗 | **不是。** 没有标准组织维护；论文自己称其为 evaluation conditions | 原文 |
| 有共识吗 | **没有。** 截至 2026-11-11：预印本、未见到同行评议版本、OpenAlex 引用 0；没有第二来源采用同一套 K0–K4 | [OpenAlex 记录](https://api.openalex.org/works/https://doi.org/10.48550/arXiv.2610.11768)；检索判断 |
| 会撞名吗 | **会。** 另一篇 2026 preprint 用 **K0–K6** 表示七种「知识操作原型」（检索/定界/解释/组合/计算/遍历/编排），与这里的「供给条件」不是一回事 | [Knowledge Operations](https://zenodo.org/records/20083456) |

> **不要把「有数字」当成「有共识」。** +54.6pp / +19.8pp 是这篇论文在单工厂、9 任务里测到的效应；K 是它的条件标签。**效应属于实验，标签不属于行业。**
>
> **本仓库的准入状态**：N&D 卡是 `admitted (probation)`（单站点，2027-05-11 前补第二独立信号）。所以 E-12 可用，但只到 `已核`，不能写成 `已证`；probation 到期补不到信号就移出。
>
> **按 [ADR 0011](../../../adr/0011-source-standing-and-term-baseline.md) 的源位阶**：K0–K4 判 `local`（`local`：论文条件，不是 normative 源）；anchor 是论文 Table 1/§2.8；scope 只到 N&D 的五个条件，不能外推成行业层级或成熟度。

## 2. 五个条件：原文、人话、测到什么

> **本表读法**：每一行是**论文条件**（`local`，I 层），不是术语定义；「人话名字」是本仓库的描述性工作词，不是标准术语。效应量只对 N&D 的单工厂、9 任务成立。

| 论文代号 | 人话名字（01 正文用） | agent 多拿到什么 | 知识在哪 | 已测效应（原文） | 01 怎么用 |
|---|---|---|---|---|---|
| **K0** address level | **原始点位** | 只有 PLC 地址 + 原始整数；**没有 tag 名** | 绑定，但没有名字 | 基线 | 只作基线，不算能力 |
| **K1** tag level | **点位语义** | tag 名、单位、质量码（按现场显示） | tag | K0→K1 避坑率 **+54.6pp** | **A，最先做** |
| **K2** structured knowledge | **知识投影文本** | 从塔投影出的约 45k 字符文本：tag 属性、连接、包络、已并入的教训；**不含 16 个推导量与假设** | 塔 | K1→K2 避坑率 **+19.8pp**（0.605→0.802）；element score 0.566→0.777 | **B，K1 过了再做** |
| **K3** procedural | **流程摘要** | 六个操作流程的摘要（K3-sub：完整流程文本） | 塔外 | K3 相对 K2 的 element score 变化 **−0.025**（探索性） | 不进 01 主路径 |
| **K4** experiential | **运行记录检索** | 日志/调查文档的检索工具（K4x：去掉本事故记录） | 塔外 | element score +0.014（相对前一层）；避坑率 +6.9pp（95% CI [3.3, 10.7]）；但日志检索只被调用 **4/80** 次；K4 vs K4x 0.644/0.645（element score，4 个诊断任务） | 不进 01 主路径 |

> **K3 不是「K2 的升级版」。** 它加的是流程文本，不是本体；element score 还略低。**K4 也不是「更成熟」**——它把「要不要查日志」交给 agent，结果 80 个诊断 trial 里只查了 4 次；K4 去掉本事故记录（K4x）几乎没有差别。
>
> **两个增益都是条件差，不是单因素拆解。** K0→K1 同时换了 tag 名、单位、质量码，+54.6pp 是这一整包的效应；K1→K2 多了整段约 45k 字符投影，+19.8pp 也不能全归给「结构化」。要拆因子，得自己做消融。
>
> **这些中文名也是描述性的，不是标准术语。** 「点位语义」对应 OPC UA/IEC 61360 里的点位元数据字段；「知识投影文本」对应论文的 projected text。它们的作用是让读者不先背 K，**不是另一个行业分级**。

## 3. 论文原文 vs 我们的工程说法

这三处最容易把「我们的建议」误当成「论文测到的 K」：

| 01/02 里常见的说法 | 论文原文 | 关系 | 怎么写才不误导 |
|---|---|---|---|
| K1 = tag 名 + 单位 + **别名 + 槽位对齐** | K1 = tag names, units, quality flags | 前三个是原文；**别名/槽位是我们的工程扩展**，不在 +54.6pp 的操纵里 | 「tag 名/单位/质量码（论文 K1）；工程上常再加别名/槽位，但那是我们的扩展」 |
| K2 = **整座塔**投影 / **固定分节**文本 | 从塔投影出的文本（prose + structured blocks），**不含推导量** | 「整塔」错（推导量不在里面）；「固定分节」是我们的建议，原文只说散文 + 结构化块 | 「知识投影文本（不含推导量）；固定模板是工程建议」 |
| K0 = **地址级标签：tag 名、点位、原始字段** | PLC addresses and raw integer values only | 自相矛盾：K0 没有 tag 名；tag 名是 K1 的东西 | 「原始点位：PLC 地址 + 原始整数，没有 tag 名」 |

> **判断规则**：写 K 之前先问一句——**这是论文的操纵，还是我们的工程建议？** 论文操纵只有 Table 1 那五行；其余都标 `推测` 或「工程建议」。

## 4. 为什么 01 只讲 K0–K2

1. **只有 K0–K2 还落在「知识供给」这一格。** K3 是流程文本、K4 是检索工具；它们不改变「本体在 harness 的哪个时刻被执行」，所以不该硬塞进 01 的能力矩阵。
2. **只有 K1、K2 有可行动的增益。** K1 +54.6pp、K2 +19.8pp；K3 的 element score 略低，K4 的 +6.9pp 建立在「agent 会去查」上，而实际只查了 4/80。
3. **论文没有说 K3 > K2。** 五个条件是累积实验条件，不是成熟度等级；不要把「K 编号更大」读成「更好」。
4. **01 的 A/B/C/D 问的是「本体能做什么」，不是「知识栈全不全」。** K3/K4 不进矩阵，不等于它们没价值；它们只是不在 01 的问题里。

## 5. 这张梯子不是什么

| 不要读成 | 实际 |
|---|---|
| 行业标准 / ISO / W3C / ISA 分级 | 一篇论文的实验条件编号；没有标准组织维护 |
| 本体成熟度模型 | 不量组织、治理、流程；只量「agent 多拿到什么」 |
| DIKW（数据→信息→知识→智慧） | DIKW 是概念层级，没有工程判据；K 是实验操纵 |
| 本仓库的证据等级 | 证据等级是 `已证/已核/推测/存疑`；K 不是 |
| A/B/C/D 判定 | A/B/C/D 是交付层排序；K 是论文条件 |
| L1/L2/L0 深度层 | L 是 01 的写作深度；K 是知识条件；两者无关 |
| 「K 越大越好」 | K3 的 element score 比 K2 低；K4 的检索几乎没被调用 |
| 「K1 级本体」 | K1 不是本体的等级；它是一组点位字段。对外请说「点位语义」 |

## 6. 相邻的框架有哪些，为什么不能直接替代

| 框架 | 它量什么 | 为什么不能替代 K |
|---|---|---|
| **DIKW**（data → information → knowledge → wisdom） | 抽象程度 | 概念层级，没有工程判据；常被批评为不可操作（[Frické 2009](https://doi.org/10.1177/0165551508094050)） |
| **Ontology Maturity Model**（[Obrst 2009](http://ontolog.cim3.net/file/work/OntologySummit2011/reference/ontologyMaturityModel-obrst-2009.pdf)） | 组织从术语表/词表迁移到本体驱动企业的过程，仿 CMM；学术提案，非标准 | 组织/流程成熟度，不是单次任务的知识供给 |
| **EKG Maturity**（[EKGF](https://maturity.ekgf.org/intro/structure/levels/)） | 企业知识图谱采纳的 5 级：试点 → 企业平台 → 战略基础设施 | 组织能力/治理，不是 agent 输入；EKGF 是 OMG 社区工作产品，**不是标准**，本仓库审计判 `excluded` |
| **Ontology Spectrum**（[Uschold & Grüninger 1996](https://doi.org/10.1017/S0269888900007797)） | 表示形式：词表 → 弱/强本体 → 逻辑约束；学术提案 | 表示形式，不是知识内容多少 |
| **Semantic Web layer cake** | 表示语言栈：RDF → RDFS → OWL → logic | 语言栈，不是供给形态 |
| **ISA-95 Levels 0–4**（[OPC UA 规范页](https://reference.opcfoundation.org/specs/OPC-10030/4.2.3)） | 制造活动层级：物理过程 → 传感器/执行器 → PLC → MOM → ERP | 数字像，轴完全不同；最容易被误读 |
| **OPC UA / IEC 61360 / AAS**（[OPC UA 过程值示例](https://reference.opcfoundation.org/specs/OPC-40001-2/v1.00/b-1)、[IEC 61360 数据规范](https://industrialdigitaltwin.org/en/wp-content/uploads/sites/2/2025/06/IDTA_01003a-25-01_AAS-Specification_Part3a_Data-Specification_IEC61360.pdf)） | 点位元数据：信号名、工程单位、量程、质量码、语义 ID | **外部规范，本仓库尚未入卡（无 `standing`）**；只作对照，不作本仓库的术语定义依据；它不定义 K 阶梯，也不含 K2–K4 |

> **表中除 OPC UA/IEC 61360 外，都是学术/社区框架，不是本仓库的 normative 源。** 它们只用来回答「为什么不能直接拿一个现成阶梯替代 K」，不构成对任何框架的背书。
>
> **所以：有共识的是「点位元数据字段」，不是「K0–K4 阶梯」。** 作为外部对照，说「K1 的内容对应 OPC UA/IEC 61360 的信号名/单位/质量码」是稳的；但**要写进本仓库的术语定义，得先按 [CHARTER §4.4](../../../CHARTER.md#44-三个窄例外) 入卡并标 `standing: normative`**。说「K1 是行业知识层级」是不稳的。

## 7. 在 01 里怎么用（五条）

1. **正文先写人话名字，K 放括号**：点位语义（K1）、知识投影文本（K2）。
2. **每个数字带来源条件**：「N&D 的 K0→K1，单工厂 9 任务」；不要写「K1 一般能 +54.6pp」。
3. **不写「K1 级本体」「K2 成熟度」「升到 K3」**：K 不是本体等级，也不是路线图。
4. **换域要重定义条件**：别处的 K1 未必是 tag 名/单位/质量码；先写清「你的 K0/K1 各是什么」，再谈增益。
5. **对外沟通不用裸 K**：写「点位语义（论文 K1）」或「N&D 的 K1」；单独一个 K1，别人不知道你在说什么。

## 8. 一页自测：你的 agent 现在拿到什么

> 这是**描述现状**，不是打分；一个系统可以同时有下面多项，不必逐级升。

| 你的 agent 现在能看到 | 对应人话 | 论文代号 |
|---|---|---|
| 只有 PLC 地址/原始整数，没有 tag 名 | 原始点位 | K0 |
| tag 名、单位、质量码（可能还有别名/槽位） | 点位语义 | K1 |
| 从设备本体投影出的说明文本（不含推导量） | 知识投影文本 | K2 |
| 操作流程/SOP 摘要 | 流程摘要 | K3 |
| 能检索日志、工单、事故报告 | 运行记录检索 | K4 |
