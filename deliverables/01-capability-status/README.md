# 01 · 现状：本体接进 harness，今天能完成什么

> **读者**：决策者 / 工程负责人 ｜ **回答**：今天能做成什么、不能承诺什么 ｜ **不回答**：具体怎么做（去 02）、为什么是这些位置（去 03）。


> 这份交付物回答三个问题：**现在能确定做成什么、哪些只是能试点、哪些还差得远。** 它不介绍本体，也不教怎么建；它只把 `topics/` 里的判断摆成一张可决策的地图。
>
> **怎么用**：本页只做索引；先读本份 [GUIDE.md](./GUIDE.md)。
>
> **证据等级**：本仓库没有独立复现，最高等级是 `已核`。所以下文「能落地」只表示「有实现/有公式 + 一手证据 + 边界可写进验收」，**不表示「已证」**。`推测` 的工程建议会单独标出。
>
> **A/B/C/D 是交付层的排序，不是新的 E。** 它只把 E 的限定读成「工程上能不能先做」；排序依据写在 [§2.1](./sections/map.md#21-判定口径)，改变排序要回到 `topics/` 改证据，不是在交付物里改标签。




## 0. 一页结论

| 判定 | 清单 | 一句话 |
|---|---|---|
| **A 可先落地** | K1 命名/单位；离线/CI SHACL；OBDA 查询重写 | 有实现或可复算公式，失败可回退；但仍需本地复测 |
| **B 可试点** | 投影、编译、证据契约、checker、动作闸、记忆、读路径过滤 | 有一手效应量，限定强；先量 1–3 个数再决定 |
| **C 只能设计** | 落盘授权、跨运行确定性、多智能体共享本体 | 机制在，效果没被独立测；不能承诺 |
| **D 反向** | 见 [§4.3](./sections/boundaries.md#43-反向在已测条件下不要做)：强 RAG 下为准确率买工件、curated 当权威、reward 证明护栏…… | 在已测条件下会得出错误结论或负收益 |

**最像「肯定没问题」的只有一件：先把名字、单位、槽位对齐（K1）。** 其余都是「有条件能试」或「还差得远」。

> 还有一类方向尚未形成 E（例如本体自动生成/精化到可消费），只在派内判断里，本表不把它们当结论；见 [05 生产](../../topics/05-produce/README.md)。


<a id="1-三句话"></a>
### 0.1 三句话

1. **最确定的角色是「可求值的约束/查询对象」，不是「更懂业务的提示词」。** 四个开源项目在 pin commit 上给出四种不同的执行语义：OWL 2 QL 查询重写、SHACL-AF 策略求值、SHACL 校验、SHACL→SPARQL/verified Core（E-20）。「有引擎」不等于「会拦」，更不等于「有授权」。
2. **今天能拿到的最大知识增益来自薄语义层，不是深度结构。** 命名+单位（K0→K1）避坑率 +54.6pp；把整座本体塔投影成文本（K1→K2）再加 +19.8pp，且只在单工厂、9 个任务、答案基本写在文本里的条件下测过（E-12）。强检索 harness 下，被测量的结构化工件没有可检出的准确率增益；原文的 ontology 还是 `not measured`（E-01）。
3. **约束类机制能改变走向，但收益不普遍、随模型能力下降，误拦还没有测。** 可逆性闸在 τ²-bench 的 18 个模型-域组合里只有 8 个整体改善，retail 和更强模型常回退；T1-only 接近 blanket veto，结构贡献没有被隔离（E-04）。**落盘写路径的授权仍然没有实现**（E-20）。

如果只记一句：**本体+harness 今天能做的，不是「让模型更准」，而是「在少数接缝上让某些事不发生」；而且要先证明它没有把对的事拦掉。**

补充一条：**很多证据不是本体专属。** 在当时的 26 个来源里，15 个的结论把「本体」换成「任意结构化上下文」仍成立（`推测`，分类判断）；只有 3 个依赖 OWL/DL 语义。读下面的「本体证据」时，先把这条放在旁边。

**第一轮 verdict（2026-11-09）**：9 条期待里，5 条 `supported（限定）`（E1/E2/E4/E6/E7 的存在性），1 条 `conditional`（E3），3 条 `unknown`（E5 false-veto、E8 写路径、E9 确定性）。**没有 9/9 supported；这不是失败，是 D1 要展示的现状。** 详见 [§2.4](./sections/map.md#24-e1e9-verdict2026-11-09-第一轮) 与 [`data/`](./data/)。


<a id="6-如果只做一件事"></a>
### 0.2 如果只做一件事

**先做 K1，再建账本。**

- K1（命名/单位/槽位）是已测最大增益、最便宜、最可回退；它不需要先建整座本体塔。
- 账本（per-query 或 per-decision 的 token、时延、审批、决策、回滚）是所有 go/no-go 的前提；没有它，`p_h`、false-veto、审批成本都算不出来。
- 然后只选**一个**接缝做 shadow：知识供给选投影、判定选 checker、动作选可逆性闸；不要同时上三个。

**不要先做的**：整座本体塔、自动生成本体、commit gate、跨运行确定性、多智能体共享本体。它们要么没有实现，要么没有下游证据。
