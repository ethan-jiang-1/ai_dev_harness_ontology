# 01 · 现状：本体接进 harness，今天能完成什么

> 这份交付物回答三个问题：**现在能确定做成什么、哪些只是能试点、哪些还差得远。** 它不介绍本体，也不教怎么建；它只把 `topics/` 里的判断摆成一张可决策的地图。
>
> **读法**：先看 §0 的一页结论；再看 §1 的三句话与 §2 的能力地图；需要细节跳到 §3；要知道「还差什么」看 §5。
>
> **证据等级**：本仓库没有独立复现，最高等级是 `已核`。所以下文「能落地」只表示「有实现/有公式 + 一手证据 + 边界可写进验收」，**不表示「已证」**。`推测` 的工程建议会单独标出。
>
> **A/B/C/D 是交付层的排序，不是新的 E。** 它只把 E 的限定读成「工程上能不能先做」；排序依据写在 §2.1，改变排序要回到 `topics/` 改证据，不是在交付物里改标签。

## 0. 一页结论

| 判定 | 清单 | 一句话 |
|---|---|---|
| **A 可先落地** | K1 命名/单位；离线/CI SHACL；OBDA 查询重写 | 有实现或可复算公式，失败可回退；但仍需本地复测 |
| **B 可试点** | 投影、编译、证据契约、checker、动作闸、记忆、读路径过滤 | 有一手效应量，限定强；先量 1–3 个数再决定 |
| **C 只能设计** | 落盘授权、跨运行确定性、多智能体共享本体 | 机制在，效果没被独立测；不能承诺 |
| **D 反向** | 见 §4.3：强 RAG 下为准确率买工件、curated 当权威、reward 证明护栏…… | 在已测条件下会得出错误结论或负收益 |

**最像「肯定没问题」的只有一件：先把名字、单位、槽位对齐（K1）。** 其余都是「有条件能试」或「还差得远」。

> 还有一类方向尚未形成 E（例如本体自动生成/精化到可消费），只在派内判断里，本表不把它们当结论；见 [05 生产](../../topics/05-produce/README.md)。

## 1. 三句话

1. **最确定的角色是「可求值的约束/查询对象」，不是「更懂业务的提示词」。** 四个开源项目在 pin commit 上给出四种不同的执行语义：OWL 2 QL 查询重写、SHACL-AF 策略求值、SHACL 校验、SHACL→SPARQL/verified Core（E-20）。「有引擎」不等于「会拦」，更不等于「有授权」。
2. **今天能拿到的最大知识增益来自薄语义层，不是深度结构。** 命名+单位（K0→K1）避坑率 +54.6pp；把整座本体塔投影成文本（K1→K2）再加 +19.8pp，且只在单工厂、9 个任务、答案基本写在文本里的条件下测过（E-12）。强检索 harness 下，被测量的结构化工件没有可检出的准确率增益；原文的 ontology 还是 `not measured`（E-01）。
3. **约束类机制能改变走向，但收益不普遍、随模型能力下降，误拦还没有测。** 可逆性闸在 τ²-bench 的 18 个模型-域组合里只有 8 个整体改善，retail 和更强模型常回退；T1-only 接近 blanket veto，结构贡献没有被隔离（E-04）。**落盘写路径的授权仍然没有实现**（E-20）。

如果只记一句：**本体+harness 今天能做的，不是「让模型更准」，而是「在少数接缝上让某些事不发生」；而且要先证明它没有把对的事拦掉。**

补充一条：**很多证据不是本体专属。** 26 个来源里 15 个的结论把「本体」换成「任意结构化上下文」仍成立（`推测`，分类判断）；只有 3 个依赖 OWL/DL 语义。读下面的「本体证据」时，先把这条放在旁边。

## 2. 能力地图

### 2.1 判定口径

| 判定 | 含义 | 不等于 |
|---|---|---|
| **A 可先落地** | 有可运行实现或可复算公式，边界能写进验收；仍需本地复测 | 已证 / 跨域有效 |
| **B 可试点** | 有一手效应量，但限定强；先量 1–3 个数再决定 | 可以直接上线 |
| **C 只能设计** | 模拟、概念或没有实现；不能承诺效果 | 不值得研究 |
| **D 反向** | 在已测条件下会得出错误结论或负收益 | 永远不能用 |

> **没有 A+。** 本仓库没有独立复现，任何一项都升不到「已证」。A 是「工程上可以先做、失败也能回退」，不是「肯定没问题」。

| 1 | 命名/单位/槽位（K1） | 供给 | context | E-12：+54.6pp | **A** | 单工厂；先做这个 |

### 2.3 怎么读这张表

- **A 不是「更好」，是「更可验收」。** 离线 SHACL 校验不会让 agent 变准，但它能在 CI 里给出一个可复算的通过/违反/未检查完；OBDA 不会拦动作，但它能把本体+映射编译成 SQL。
- **B 的共同点是「有效应量，但限定强」。** 它们都值得做一次 shadow，而不是直接上线。
- **C 的共同点是「机制在，效果没被独立测」。** 可以设计，不能承诺。

## 3. 逐项：哪些能确定，哪些只是能试

### 3.1 K1 命名/单位/槽位：最先做，也最像「肯定没问题」

同一份工业知识，把地址级标签换成「tag 名 + 单位」，避坑率相对 K0 提高 54.6 个百分点；再把整座塔投影成文本，只再加 19.8 个百分点（E-12）。这是已测各层里最大的一层增益，而且不需要建整座本体塔。

**为什么先做**：它便宜、可回退、失败也不会造成伤害；它还是后面所有投影/编译/checker 的地基——名字和单位不对，后面的约束都建在沙上。

> 术语：K0 = 地址级标签；K1 = tag 名 + 单位；K2 = 把整座塔投影成文本。三者是 N&D 的三个知识层级，不是本仓库的证据等级。

**距离**：单工厂、9 个任务、答案基本写在文本里。换域要重测；但它仍然是当前最值得先做的一步。

### 3.2 领域知识投影：能试，但别把它当约束

同一座塔，投影成文本的 pooled element score 最高（0.777 > JSON 0.717 > 查询 0.638 > 检索 0.597），但不是普适排序：GLM-5.2 的 JSON 0.900 反超文本 0.891，Qwen 的工具 0.407 低于文档检索 0.538（E-12）。投影顺序本身是有效成分：打乱句序 0.777→0.685。

**能做什么**：让模型在封闭域、操作手册型知识上「知道得对」；9B 带投影 0.737 > 750B 不带 0.672，但区间约 0.3 宽，不能当普遍规律。

**不能做什么**：投影不承担拒绝逻辑。投影里写了规则，模型仍可能忽略；硬约束必须另进 01/02。强检索 harness 下，被测量的结构化工件没有可检出的准确率增益（E-01；但 ontology 在原文是 `not measured`，不能读成「本体无用」）。

**距离**：单工厂、9 任务、45k 字符；多设备/多站点、开放域检索、需要多跳推理的场景都未测。

### 3.3 证据编译：省的是预算，不是准确率

claim–leaf（主张-证据叶子）编译在证据充分时省 91% token，不充分时反而 +1.9%，平均 −38%；准确率 neutral；PageIndex 大纲在 FRAMES 规模实测为负（E-08/E-14）。盈亏平衡是条件性的：`p_h > 2% + c/(0.929Q)`；`c=10`、`Q=1000` 时门槛约 3.12%。

**能做什么**：语料大、重复检索多、token 是硬成本时，把「读整段」换成「读 claim + 逐字 span」。

**不能做什么**：不能拿平均 −38% 当上线依据；它不是准确率项目；证据替换用检索轮次换 token，配对子集时延约 3×（仅 7 题）。

**距离**：先量自己的 `p_h`、miss penalty、`c`、`Q`；`p_h < p_min` 就不做。

### 3.4 输出证据契约：中端、可审计、但不是形式保证

强制每个答案报告所用作证据的本体观察 + 接地等级（entailed/supported/related/unrelated），在三个大本体、六个医学 QA 任务、2 个 backbone 上整体最优：平均 50.5%/68.1%；Tests 1–2 +10–15pp；Test 3 同 8k 预算 84.9% vs 66.7%（E-03）。

**能做什么**：把「没有可用观察」「检索到但不足以定答案」「检索到但无关」三种情况分开；给答案一个可排序的可靠性字段。

**不能做什么**：等级是模型自评、未校准，作者明确不提供形式正确性保证；检索是主瓶颈（gold evidence 完整检索 MCQ 61.7% vs OQ 23.6%）。它不是闸门，不改变走向。

**距离**：等级校准、句级 span、多本体协调都未做；先修检索，再谈分级。

### 3.5 输出后 checker：能抓结构错，抓不住语义错

本体当外部判据，检查查询/答案的类型、声明、domain/range、模式约束。三种来源各有偏向：curated catch/FA 18.9/16.8、data-derived 8.2/3.5、masked LLM 5.0/1.8；precision（人工故障、25% 错答案假设）57.1/72.3/93.7；curated 精确度仅略优于随机（+1.6 点，CI 跨零）（E-02）。

**能做什么**：在不看全量人工复核的前提下筛出可疑项；把「通过/违反/未检查完」三态显式化（E-20 的代码核对发现，第三态在 shell 退出码里会被折叠）。

**不能做什么**：结构检查对 changes of meaning 基本抓不到（0%）；LLM judge 检错更多（catch 40.3%/FA 16.2%），但 40 条修好 / 83 条修坏；空结果重试是必须超过的基线（人工 fault 上 catch 79.2%、FA 0%）。

**距离**：false-veto 未测；单 checker 实验；curated 需要先审计/补声明；没有标注集就不知道曲线。

### 3.6 动作前可逆性闸：窄条件能试，不能承诺「安全」

用两层本体对工具调用打可逆性分、执行前剪枝：τ²-bench 上六个模型中四个在 airline 域提升 0.11–0.18；但 18 个模型-域组合只有 8 个整体改善，retail 与更强模型常回退；T1-only 接近 blanket veto，增益却不比 full 小；false-veto 未测；作者声明 reward 不是防止伤害的直接度量（E-04）。

**能做什么**：在动作不可逆、代价高、模型能力弱于域要求、域规则可被查询成事实时，做 shadow 剪枝/审批。

**不能做什么**：不能证明「结构判据有效」；不能证明「护栏总是更好」；不能覆盖合法意图主导的场景（retail 退货/换货）；不能证明逆执行一定成功。

**距离**：false-veto 标注、同轨迹配对、能力梯度阈值都没有；强模型下可能只剩代价（E-13 是六点描述性拟合，给不出零交叉阈值）。

### 3.7 跨轮身份/记忆：能试，但先锚身份

本体在记忆系统里克制到只做对齐与印证条件：alias memory 让 final-period CMR（跨期匹配率）+7.8–12.1pp（4 settings）、human-audit recall +22.5–29.0pp、semantic matching token −40.3%（E-05）。EvoMemState 把记忆分成 Persistent Facts + Relational State + Reasoning State：Complete Retrieval 85.6%（与最好 baseline 相当），但 Acc@complete（完整答案准确率）70.8/68.5（+11.5/+31.2）；去掉状态层掉点（E-17）。

**能做什么**：跨会话、跨期实体知识；需要保留冲突/失效；下游判断依赖历史一致性。

**不能做什么**：不保证跨运行确定性；文本 only、需训练信号；false merge 的长期污染未测；未匹配 ≠ 关系结束。

**距离**：先建 registry，再谈内容/检索；merge precision 与 CMR 一起看；没有自动回滚。

### 3.8 读路径过滤/查询重写：有代码，但别扩大解释

trustgraph 在查询结果返回前跑 SHACL-AF 策略，命中 `tg-pol:blocks` 的节点，其 subject 侧三元组被删除；它是读路径 best-effort gate，不是动作前闸门：target/rule 异常时 fail-open，且只删 subject 侧（E-20）。ontop 在查询编译时做 TBox 饱和 + 查询重写，把 SPARQL 变成 SQL；它是供给层执行器，不是判定器（E-20）。

**能做什么**：读侧可见性/信息屏障；OBDA（本体驱动的数据访问）式「本体+映射→SQL」的查询回答。

**不能做什么**：不能当写授权，不能当动作闸，不能证明对象方向也受控；ontop 只支持 OWL 2 QL，不做 DL 推理。

**距离**：read-path 只有 1 个独立实现；需要第二个实现才决定是否升第七时刻。

### 3.9 还不能承诺的三件事

- **落盘前授权（commit gate）**：设计上要求证据齐、冲突清、版本有效三条全过；但只有概念架构，无实现、无 false-defer 数据；四个开源项目里没有一个是单次写授权（E-20）。**现在只能做只读/影子，不能声称已落地。**
- **跨运行确定性**：只有设计提案，未升 E；没有实现、没有度量。
- **多智能体共享本体**：`00-harness` 里唯一没有对应流派的部件；缺可判定设计与证据。**这是空白，不是遗漏。**

## 4. 哪些能当工作前提，哪些不能

### 4.1 在已测条件下，可以当工作前提

1. **薄语义层先起量。** 命名+单位 +54.6pp > 深度结构 +19.8pp（E-12；单工厂）。
2. **强检索 harness 会吃掉结构化上下文的准确率增益。** 被测量的摘要树/大纲/wiki/实体图在 FRAMES 上无可检出增益；PageIndex 大纲退化（E-01；ontology not measured）。
3. **约束类收益随基线能力下降。** airline/retail/telecom 斜率约 −0.76/−0.67/−0.31，但只是六点描述性拟合（E-13）；强模型/retail 回退（E-04）。
4. **空结果重试是 checker 的强基线。** 人工 fault 上 catch 79.2%、FA 0%（E-02）；新 checker 必须先超过它。
5. **执行 ≠ 健全 ≠ 授权。** 四个开源项目给出四种语义；trustgraph fail-open、只删 subject；open-ontologies 只做影响报告/CI 门（E-20）。

### 4.2 还不能当工作前提

1. **「上本体能稳定提准确率」。** E-01 的 ontology 是 `not measured`；E-12 是单工厂、答案写在文本里；没有跨域复现。
2. **「结构判据有效」。** T1-only ≈ full，结构贡献未隔离；false-veto 未测（E-04）。
3. **「护栏的收益大于误拦成本」。** 审批量有模拟数，false-veto 没有标注；`γ_m` 是假设（E-15）。
4. **「写路径能授权」。** 没有实现；E-20 只有否定性证据。
5. **「本体越完备越好」。** Q-01 与 E-01 冲突；完备性与可判定性在工程上反向。

### 4.3 反向：在已测条件下不要做

1. **在强检索 harness 下为「提准确率」买结构化工件。** 被测量的摘要树/大纲/wiki/实体图没有可检出增益；PageIndex 大纲退化（E-01）。要买的是治理/预算/审计，不是准确率。
2. **把 curated 本体当权威 checker，不做审计/补声明。** curated 的 precision 仅略优于随机；FA 主源是缺声明/闭世界，不是「与数据矛盾」（E-02）。
3. **用 reward 或单一 accuracy 证明护栏有效。** 任务账看不见「被拦住的伤害」和「被误拦的正确动作」（C-03/E-04）。
4. **把 T1-only 当「结构判据有效」。** T1-only 接近 blanket veto，增益却不比 full 小；结构贡献未隔离（E-04）。
5. **把 grounding level 当形式保证。** 等级是模型自评、未校准（E-03）。
6. **把 commit gate 的概念架构当已落地机制。** 没有实现、没有 false-defer 数据；四个开源项目里没有单次写授权（E-20）。

## 6. 如果只做一件事

**先做 K1，再建账本。**

- K1（命名/单位/槽位）是已测最大增益、最便宜、最可回退；它不需要先建整座本体塔。
- 账本（per-query 或 per-decision 的 token、时延、审批、决策、回滚）是所有 go/no-go 的前提；没有它，`p_h`、false-veto、审批成本都算不出来。
- 然后只选**一个**接缝做 shadow：知识供给选投影、判定选 checker、动作选可逆性闸；不要同时上三个。

**不要先做的**：整座本体塔、自动生成本体、commit gate、跨运行确定性、多智能体共享本体。它们要么没有实现，要么没有下游证据。

## 7. 证据边界

这份交付物的判断都来自 [conclusions](../../topics/conclusions.md) 的 E-01…E-20 与 C-01…C-04。引用时注意：

- E-01/E-08/E-14/E-15/E-18 是 harness/度量证据，不是本体专属；不要把「结构化上下文」读成「本体」。
- **换词检查（`推测`，分类判断）**：26 个来源里 15 个的结论把「本体」换成「任意结构化上下文」仍然成立；只有 3 个（MIOE、Ontology Catch、OA-RAG）的结论依赖 OWL/DL 语义。也就是说，仓库过去测的更多是「结构化上下文 + harness 位置」，不是「本体形态」。这不是说本体没用，而是说不要把前者的证据当成后者专属的证据。见 [execution-forms](../../topics/execution-forms.md)。
- E-04/E-15 是 `contested`：主结论可站，某个读法被削弱；E-12 的分数级是已核、排序级是存疑。
- E-20 是代码级核对（4 个项目、pin commit、只读代码、未做对照实验），不是效应量。
- 本仓库没有独立复现；「已核」只表示原文/代码读对了，不表示命题被验证。

更细的边界见 [03 机制参考](../03-mechanism-reference/README.md) 与 [附录 §3.7](../03-mechanism-reference/appendix-constraint-spectrum.md#37-本章不能证明什么)。
