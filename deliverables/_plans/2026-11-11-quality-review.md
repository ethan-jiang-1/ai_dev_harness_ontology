### 红旗（必须先修，不能只写在分维里）

1. **04 把 Glyph 的规模写小了约 490×/680×。** `sections/decision.md:164`、`:172`、`:264`、`example/data.md:9`、`body/consume.md:9`、`example/README.md:10`、`sections/acceptance.md:78` 七处写「200 表 / 5,000 列 = Glyph 量级参照」；E-22 与 Glyph digest 是 **~98,000 表 / ~3.4M 列**。这一列正是 04 用来讨论「规模先断在哪」的，读者会低估两个数量级。**同一个量级也出现在 `src/web/oasis-xacml-3.0` 卡:76（作为 04 的场景规模）**——修的时候要回查上游，别只改 04 一处。
2. **03 把 E-15 的判断写反了，还标 `已核`。** `positions/action.md:40`、`appendix-constraint-spectrum.md:349`：「CASEL 少约 31% 审批…但 HSR 高 1.2pp；**不是「相近 harm」**」。E-15 的原话是「约 30% 更少审批达到**相近 harm**」。这是交付物新增判断，不是 E-15 的结论。
3. **03 把两个分母拼进了一句。** `positions/checker.md:13`：「curated FA 16.8%、precision 57.2%」；同页 `:40` 写 57.1，`:72` 明令「precision 不能与真实答案 catch/FA 拼成一个准确率」。57.2 是 O-F08 用 FA **15.0** 复算的 PPV，13 行却把它与真实答案 FA **16.8** 并排。

### 四句话回答原始问题

1. **有没有干货？有，高于多数同类报告。** 不是「叙事半天没东西」，是反过来：02 每条 recipe 有数据契约/成本/停线/失效模式，04 有能解析的 fixture 与 9 件产物。真正的风险是**读者接不住**，不是内容空。
2. **叙事对不对？半对。** 单页有叙事（02 §2.1 五步法、03 claim 走查、04 A.1–A.5、03 附录 §3.0），但**入口没有叙事**：四份 README 的第一屏都是「读者卡 + 分类/索引」。
3. **结构对不对？大结构对，小结构过度。** 「判断/操作/依据/生命周期」的 3+1 分法成立；但 110 个文件、中文字符中位数 765、1,044 条链接，读者是在**逛索引**。
4. **专业性够不够？底子够，细节有两处硬伤。** 证据纪律（逐条等级、限定、作者主张 vs 观测）是全仓最强资产；但「两个数量级」和「判断写反还标已核」这两类错误，会在外部评审里一击致命。

## 4. 三个共性问题（比单份短板更值得改）

### 4.1 没有「5 分钟入门坡道」

- 四份 README 的第一屏都是「读者卡 + 分类/索引」，没有一份用**具体场景**开场。
- 「本体」只在 `04/sections/glossary.md:15` 有人话定义；「harness」在四份里都没有定义，但它是 01/02 标题里的词。
- 结果是：越需要被说服的人（决策者），越要先学一套词。

**这不是写作能力问题**：02 §2.1、03 claim 走查、04 A.1、03 附录 §3.0 都证明作者会写叙事。问题是入口被「索引契约」占了。

### 4.2 私有编号系统成了阅读门槛

| 冲突 | 例子 | 读者要付的代价 |
|---|---|---|
| `E1–E9` vs `E-01–E-20` | `01/sections/glossary.md:13-18` 专门解释「差一个字符」 | 每次看到 E 都要先判是不是带横杠 |
| `R0–R12`（recipe）vs `R01–R12`（反例） | 02 全篇 vs `03/evidence/boundaries.md:17` | 跨份阅读会串；`R6` 与 `R06` 是两个东西 |
| `D1`（底稿编号）vs `D`（反向判定） | `01/sections/glossary.md:70` 专门声明 | 读者以为 D1 是 D 类 |
| `M1–M5`（研究期待） | `03/sections/acceptance.md:17-21` | 又一套要记的码 |

**判断**：编号对追溯有用，但现在是「给 Agent 的索引键」直接暴露给人。人读层应只保留 `E-xx` 一种码，其余改中文名或括号出处。

### 4.3 过度分片，读者在逛索引

- 110 个 md，中文字符中位数 **765**；48 个文件 <600 字，20 个 <300 字（最小的 `02/sections/README.md` 只有 69 字）。
- 1,044 条链接（793 条内部、250 条外部）；每千中文字符：01 6.1、02 4.3、03 4.7、04 **16.9**。
- 四份各有一套 `README + GUIDE + glossary + canonical + templates + acceptance + relations`：对「只读一份」友好，对「读整个 corpus」是四倍导航开销。
- 4 个孤儿索引页 + 9 个 0 出链正文页（6 个在 01 的 capabilities）。

**判断**：分片本身不是错，错在**没有一条连续的 3–5 页主路径**。现在是「每页都短、每页都链」，读者必须自己拼。

## 5. 只做三件事
