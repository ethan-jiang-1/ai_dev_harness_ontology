# 基线整改计划：先把源立对，再换内容

> 依据 [ADR 0011](../../adr/0011-source-standing-and-term-baseline.md)。一句话：**结构不动，内容置换**——六派、子主题、`E`/`L` 编号、四个交付目录都留；换的是定义、锚点，以及被标准推翻的局部判断。
>
> 起点是坏的：先让 agent 自己找、自己起名，标准基线没进 `src`，于是「本体」「成熟度」「知识层级」各说各话。现在补次序。

## 0. 目标与不变量

**目标**：每个术语的义要么指到 `normative` 源，要么明确标 `local`；每条定义的锚可查。

**不变量**：
- 不改六派结构、不改子主题、不改 `E-xx` / `L-xx` 编号（只改内容与等级）。
- 不新造词汇来命名这套整改（沿用 normative / informative）。
- 不在并行整改动 `deliverables/` 时双写。

## 1. 阶段

### S0 定调（本轮）

- `adr/0011`：源位阶与术语基线规则。
- `meta/conventions.md`：`standing` 字段 + 三条规矩。
- 产出：本计划。

**验收**：规则可在 `conventions` 一处查到；标准卡有 `standing`。

### S1 主干入库（A 批，3 张卡）

| 卡 | 定什么 | 锚 |
|---|---|---|
| ISO/IEC 21838 系列 | 顶层本体的要求与合格性；BFO 为参考 | iso.org/standard/74572（-2）、78927（-3）；-1 见 cssn 记录 |
| OMG ODM 1.1 | 本体与 UML/ER/OWL 的映射元模型 | omg.org/spec/ODM/1.1 |
| OMG Commons 1.3 | 通用概念（时间、组织、事件等）的规范本体 | omg.org/spec/Commons/1.3 |

每张卡记：`standing: normative`、`gate: standard-in-force`、现行版本、2026-06 后维护活动、≥2 活跃实现、范围（管什么 / 不管什么）。

**为什么先这三张**：它们定义「本体 / 顶层本体 / 通用本体」这三个我们天天用、却从没锚过的词。

### S2 领域入库（B 批，5 张卡）

GB/T 42131-2022、FIBO、HL7 FHIR、GS1 EPCIS、IOF。

**只收被产业强制或半强制使用的**；不收「某公司本体白皮书」。每张卡同样记范围与在役证据。

### S3 术语差异表（30 词）

对 `GLOSSARY.md` 每个词给一行（v0 十词已落 [term-baseline.md](../../meta/term-baseline.md)；本表是工作稿，不新增 E/L）：

| 词 | 我们的定义 | 标准锚 | 判定 | 动作 |
|---|---|---|---|---|
| 本体 | 「领域概念、关系与约束的显式规范」 | ISO/IEC 21838-1 §3（待核条款号） | `narrower` | 保留，注明只覆盖 TLO 视角 |
| 成熟度 | 「组织能力分级」 | 无标准 | `local` | 标 local，禁止写成行业标准 |
| 知识条件（K0–K4） | 论文的五个累积实验条件；K 不是知识层级 | arXiv:2610.11768 Table 1 / §2.8 | `local` | 保留 K 作回查；正文用人话名；不写成层级/成熟度；01 线已落地（[K 页](../01-capability-status/02-sections/92-k-ladder.md)） |

判定五类：`aligned`（换锚）/ `narrower`（标范围）/ `broader`（拆开）/ `divergent`（改名或限定）/ `local`（标自造）。

**偏移阈值**：`divergent` + 冒充行业词的 `local` > 1/3 → 停，重定基调。

**预判**：框架词（六派、执行形态、本体塔、k-ladder）必为 `local`；借词（本体、知识图谱、SHACL、OWL）多为 `aligned` / `narrower`。风险不在框架本身，在**把框架说成行业共识**。

### S4 判断回改（试点 06-measure）

- 逐条 `L` / `E` 检查术语用法；冲突的换锚、降级或撤回。
- 记录 `meta/audits/2026-11-11-term-baseline.md`：改了什么、为什么、影响谁。
- 跑通后扫其余五派。

**为什么是 06**：`成熟度`、`层级`、`覆盖率`、`p_h` 都在这，术语最容易被当成行业词；改动半径小（17 条 L），且 K 阶梯事故的教训就在隔壁。

### S5 交付物置换（等并行整改落地）

只动三处：定义段、首现术语、引用锚点。结构、叙事、目录不动。每篇加一行「术语基线：ADR 0011 / 2026-11」。

## 2. 差异判定标准

| 判定 | 判据 | 动作 |
|---|---|---|
| `aligned` | 与标准定义一致，或只差措辞 | 定义改为引用条款 |
| `narrower` | 我们只取标准的一个子集 | 保留，标「本标准只覆盖 X」 |
| `broader` | 我们把标准没涵盖的塞进来 | 拆：标准部分归 N，扩展标 local |
| `divergent` | 同词不同义 | 改名，或明确写「本仓库限定义」 |
| `local` | 标准无此词 | 标 local，禁止外推 |

## 3. 验收

- `GLOSSARY` 无裸词：每词有 `origin` + `anchor`（local 的 anchor 写 `—`）。
- A/B 批卡片有 `standing`、`gate: standard-in-force`、活动证据。
- 06 试点：所有术语用法与基线一致；冲突项有裁决记录。
- 差异表公开：五类计数可查。
- `check_repo` 通过（字段检查本轮不加，避免和并行整改撞）。

## 4. 风险与不做的

| 风险 | 处置 |
|---|---|
| 与并行整改撞车 | S1/S3 只动 `src/`、`meta/`、`GLOSSARY`；`deliverables/` 等对方落地 |
| 标准卡膨胀成标准百科 | 只收「定义了我们正在用的词」的标准 |
| 过度对齐，消灭分析框架 | `local` 是合法类别；规则是标清楚，不是消灭 |
| 拿标准卡撑效应量 | 明令禁止；效应量只认论文/实验 |
| 付费墙核不到条款 | 降为 `academic` 或 `local`，不硬挂 N |
