# 内容审计：干货、锐度与水分（2026-11-11）

> 这次**不评流程、不评数据、不评 10 维可核对性**；只评「内容本身有没有硬货、够不够鲜明、哪里是四平八稳」。
>
> 方法：把内容页的句子分三类——**硬句**（数 + 单位 + 条件/机制）、**锐句**（不要/停/只有/必须/否则/不是…是）、**水句**（框架复述/程序/目录指针）。按千字计；`data/` 与 `evidence/` 的证据表不算散文，单独看。

## 0. 一句话

**不是没有干货，是干货被「框架税、程序税、边界税」稀释了；而且稀释页正好在门口和出口，所以第一眼和最后一眼都像手册，不像判断。**

## 1. 总览

| 交付物 | 硬句/千字 | 锐句/千字 | 零硬页（散文） | 最硬页 | 最水页 | 内容判断 |
|---|---:|---:|---|---|---|---|
| 01 | **1.7** | 3.2 | 0（glossary 除外） | decision-record 3.4 / knowledge 3.2 | capability 摘要、`data/` 表 | **短而硬**；观点最清楚，体量最薄 |
| 02 | 1.3 | **4.0** | 2（ledger、README） | canonical 3.5 / cost 2.8 / domains 2.6 | ledger 0.0（4.3k）、interfaces 0.3、offline 0.2 | **手册体**；操作多、判断少；34 次 shadow |
| 03 | **1.1** | 3.1 | 5（placement/acceptance/README/positions-README/execution-forms） | action 3.7 / ledger 3.3 / context 2.2 | execution-forms 0.0、placement 0.0、acceptance 0.0 | **概念最锐，数字最薄**；61 次「本页」 |

> 硬句密度 04≈01>02>03；锐句密度 02>01≈03>04。**03 的硬密度最低，不是因为它没观点，而是它的观点是概念型的，不靠数字。**

## 2. 01：短而硬，但只有三分之一是「判断」

**最硬的三个**：
1. 「**本体+harness 今天能做的，不是让模型更准，而是让某些事不发生**；而且要先证明它没有把对的事拦掉。」（README §0.1）
2. 「**A 不是更好，是更可验收**；没有 A+。」（map §2.3）
3. E-04 的「18 格只有 8 格改善、retail/强模型回退、T1-only≈blanket veto」——这是全份最反直觉的一组数。

**最水的三个**：
1. 6 个 `capabilities/*` 页把地图表又说一遍；体量小，重复感强。
2. `data/e3–e8` 是「数+表」，但缺一句「所以呢」；按散文算，硬密度只有 0.4–0.5/k。
3. `GUIDE` 的「三种读法 / 推荐顺序 / 不要先读」是导航，不是内容。

**判断**：**观点最鲜明的一份**（「让某些事不发生」是可被反对的），但**体量撑不住**；读完记住的是三句话，不是 23 个文件。

## 3. 02：最像「工程手册」，干货集中在 4 页

**最硬的三个**：
1. 「**false-veto 不设单点，报 miss–false-block 前沿**；5% 只作示例。」（R6/canonical）——这是全份最反行业习惯的一条。
2. 「**R8 只做可见性，不当授权**；fail-open、只删 subject、单实现。」（R8）——把「有过滤器」和「有授权」切开。
3. 「**先超过空结果重试**；curated precision 近随机；−38% 是 −91% 与 +1.9% 的混合，不能当上线依据。」（R5/R3）

**最水的三个**：
1. `operations/ledger` 4.3k 字，硬句 0.0/k；它是 schema，不是判断。
2. `appendices/interfaces` 3.8k 字，硬句 0.3/k；字段清单。
3. 13 条 recipe × 10 个字段，很多字段是「未测 / 工程建议 / 待填」；**34 次 shadow**，读起来像咨询模板。

**判断**：**操作层最有用，但最不「鲜明」**。它回答了「怎么做」，没回答「哪一条最值得做、哪一条最容易被做错」；后者只在 R6/R8/R3 三页。

## 4. 03：概念最锐，框架税最重

**最硬的三个**：
1. 「**强端不是更好，是更窄**；用错尺子会得出『无增益』。」（map §2.4）
2. 「**有引擎 ≠ 会拦 ≠ 有授权**；四种执行语义。」（E-20/execution-forms）
3. 「**直线不成立，矩阵才是操作定义**；越强越窄只是 H，不是 E。」（map §2.4/coverage）

**最水的三个**：
1. `execution-forms` 是核心页，硬句 **0.0/k**；它靠分类和代码锚，不靠数。
2. `placement`、`acceptance`、`positions/README`、`README` 都是 0.0/k；**61 次「本页」**，读者一直在被告诉「本页回答什么」。
3. 六张位置卡的 §1–§2（机制/触发/输入/输出）是 taxonomy；真正的判断在 §3–§7。

**判断**：**观点最反常识的一份**（「强端更窄」「引擎不等于拦」），但**被框架税埋了**；第一页是目录，不是论点。

## 5. 04：闭环最硬，但最窄

**最硬的三个**：
1. 「**T9 保持 undetermined**；policy 有冲突就承认冲突。」（govern C.2）
2. 「**当前 fixture 的默认结论是 conditional，不是可上线**；C3 的 object 泄漏不在 04 内修。」（acceptance）
3. 9 件产物 + 5 组门槛 + 决策顺序，闭环。

**最水的三个**：
1. 「fixture」出现 111 次；同一件事反复指认，读多了像咒语。
2. 部分小节是 checklist（A.1/A.5/C.4），信息密度靠表，不靠论证。
3. 单域、单 fixture；**深度够，广度不够**。

**判断**：**不是四平八稳，是单点深**；它的问题是「只有一条链」，不是「没有观点」。

## 6. 「四平八稳」的三个来源

| 税 | 表现 | 数据 | 修法 |
|---|---|---|---|
| **框架税** | 每页重述 0–6 / 四轴 / 六位置 | 03「本页」61 次；01 六个能力页重复矩阵 | 框架只留一页；其余页直接从「判断」开头 |
| **程序税** | 13 recipe × 10 字段、步骤/成本/验收 | 02「shadow」34 次；ledger/interfaces 0.0–0.3/k | 步骤压成「if X → Y，否则 Z」；schema 并进一个附录 |
| **边界税** | 每条判断后跟 3 条 caveat | 03 卡的 §4/§6 常比 §3 长；02 的「工程建议/未测」满页 | 每页一个「边界」盒；正文只留主张与条件 |

## 7. 门口的悖论

- 01 的 README 有硬数；02 的 README 0.0/k；03 的 README 0.0/k、acceptance 0.0/k。
- 读者第一眼看到的是「本页回答什么 / 读完你能 / 目录」，最后一眼看到的是「验收/关系/维护」。
- **核心页（02 R6/R8、03 action/coverage、01 decision-record）在中间，门口没有把它们的主张提上来。**

## 8. 如果目标是「鲜明」，只做四件事

1. **每份加一页「你可以反对的 5 句话」**：01 的「让某些事不发生」、02 的「false-veto 不设单点」、03 的「强端更窄」、04 的「T9 不可判」——放在 README §0，不放在附录。
2. **砍 0 硬页**：02 的 ledger/interfaces/offline 并成一个 schema 附录；03 的 placement/acceptance/README 框架压成一页；01 的 6 个 capability 摘要并进地图表。
3. **把 caveat 收进一个盒子**：每页只留「主张 + 条件 + 一条反例」，其余移到 boundaries。
4. **把「怎么做」改成「什么时候别做」**：02 的 recipe 开头先写「这条不适用时」，比写 10 个字段更鲜明。
