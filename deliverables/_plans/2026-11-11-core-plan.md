## 1. 这个仓库是什么（给新会话的最小背景）

### 1.1 它是什么

- 一个**研究档案**：材料进来 → 精读成卡 → 沉淀成主题 → 抽成交付物。
- 三层信息流：
  - `src/`：给 Agent 的原料（论文/标准/开源/网页的卡与 digest）。
  - `topics/`：给 Agent + 人的判断（六派、E/L、机制、边界）。
  - `deliverables/`：给人的成品（01 现状、02 工程、03 机制、04 落地）。
- 唯一的代码例外：`meta/tools/check_repo.py`（只读自检，不承载研究逻辑）。

### 1.2 它不是什么

- 不是软件项目、不是产品、不是 demo；不建代码目录、不 vendor 代码、不部署、不做实验。
- 不把“示例能跑”当交付标准；TTL/JSON/SPARQL 只是说明材料。
- 不自行设置要求用户提供资产/人/价/签核的 gate。

### 1.3 必须知道的四个内部词

| 词 | 人话 |
|---|---|
| **E-xx** | 跨主题结论（仓库级判断），定义在 `topics/conclusions.md`；有证据等级（已核/推测/存疑/withdrawn）。 |
| **L-xx** | 派内局部判断（六派各自的 `claims.md`）；不是交付物结论。 |

### 2.3 为什么先讲 K0–K4

- 现在的规则：**K0–K4 只在出处/回查出现，正文用「原始点位 / 点位语义 / 知识投影文本」**。

## 3. 三条来源线：N / I / S

清掉噪声之后，剩下的来源要分层。正式名字是：

| 层 | 是什么 | 能做什么 | 不能做什么 |
|---|---|---|---|
| **N 规范性（normative）** | 标准、规范、权威本体 | 定义术语、定合格性、写边界 | **不能证明效果、不能给阈值** |
| **I 资料性（informative）** | 论文、工程报告、开源代码 | 给效应量、数据、代码锚、失败模式 | **不能定义术语**（定义必须回 N 或标 local） |
| **S 线索（signal）** | 只进 `frontier.md` 候选队列 | 提示“有人在说” | **不能进 claims/README/交付物；不能当证据** |

> 口头说的“主干 / 支持补充 / 线索”，对应的就是 **N / I / S**；正式文件用 N/I/S，避免再造私词。

### 3.1 主干上有哪些标准

已入 `src/`、`admission: admitted`、`standing: normative` 的 10 张标准卡：

| 标准 | 能定义什么 | 不能定义什么 |
|---|---|---|
| ISO/IEC 21838-1/-2 | 顶层本体（TLO）的要求与合格性；BFO 是参考 TLO | 不定义领域本体；不给成熟度；不证明效果 |
| OMG Commons 1.3 | 可复用本体模块、最小承诺 | 不是 TLO；不定义领域语义 |
| W3C SHACL | RDF 图约束、校验、三态语义 | 不是动作授权；不保证语义正确 |
| W3C SHACL-AF | 规则、target、扩展机制 | 不是执行点；不保证“会拦” |
| W3C OWL 2 Profiles | profile 语义、RL 规则 | 不定义实现；不证明推理效果 |
| W3C ODRL 2.2 | 策略表达 | 不定义身份/认证、默认结论、执行点 |
| OASIS XACML 3.0 | 访问控制策略/判定架构 | 不定义 obligation 语义、审计字段 |
| GB/T 43697-2024 | 数据分类分级框架 | 不是策略语言；无 principal×action 映射 |
| GB/T 35273-2020 | 个人信息处理要求 | 不是机密性分级；不是策略语言 |
| ODCS v3.1.0 | data contract 结构、SLA、质量字段 | 不是本体 schema；不保证运行时执行 |

> 主干索引在 `topics/trunk.md`。**标准只定词与合格性，不撑效果量。**

### 3.2 现在的主干缺口

这些词没有 normative 锚，只能标 `local`：

- 知识图谱（实例层）
- 语义层
- 成熟度
- 知识层级 / K0–K4（论文条件，不是术语）
- 接地（grounding）/ 接地等级
- 动作可逆性 / 动作闸
- commit gate / 落盘授权
- agent 记忆 / 跨轮状态

> “没有 N”不是“永远没有标准”，是**今天没有入卡的 normative 源**。要用，先按 CHARTER §4 找标准/权威本体；找不到就继续标 local。

## 4. 核心思想（接手人必须认同的六条）

1. **判断跟着源走。** 源被撤回，判断不能靠“以前引用过”继续活着。
2. **“不知道”是合法状态。** 没有合格证据时标 gap，不要硬塞进 B/C。
3. **术语必须有出处。** 专业术语只能来自 N；论文只给证据/条件编号，不能定义术语；K0–K4 不是术语。
4. **标准不撑效果。** 标准只能定义词与合格性；效果只能引 I 层论文/代码/数据。
5. **先清后补。** 先扫描清掉旧噪声，确认干净，再补新信息；不在脏底上叠新层。
6. **先收口，再美化。** 不重写结构、不新造框架；先让证据和定义站得住，再谈文笔与评分。

### 4.1 六条红线

1. 源没合格，判断不能留；唯一支撑被撤回 → 撤回或 gap。
2. 把 gap 伪装成 B/C 是失败；“暂时不知道”不是失败。
3. 标准卡不能撑效果。
4. 自造词必须标 `local`；不得写成“行业共识”。
5. 论文条件编号（K0–K4）不能进标题/主列/判定名，只能作出处/回查。
6. 每批跑 `check_repo`；失败不往下走。

## 12. 已知坑

1. **并发编辑**：可能有其他 agent/会话改同一仓库。每次编辑前重读；遇到 `file changed since it was read` 先重读。
2. **旧数字还在 data/_plans**：它们已标历史，不要再引用；不要为了“看起来完整”恢复。
3. **标准卡不是效果证据**：不要用 ISO/SHACL/ODRL 证明“用了本体 agent 更准”。
4. **K 页是来源说明**：`deliverables/01-capability-status/sections/k-ladder.md` 专门解释 K 为什么不是术语；不要把它当术语表。
5. **不要擅自 commit**：本轮最终 checkpoint 已按用户「一口气做完」的授权提交（见 §13）；**下一轮改动仍需用户点头**再 commit。
6. **不要新增代码/实验**：唯一例外是 `meta/tools/check_repo.py`。
7. **不要重写六派/交付结构**：这次只改证据、定义、首现、锚点。
