# 03 · 机制参考：六个位置、三条轴与证据边界

> **这不是一本手册，也不是教程。** 它是交付物的「依据层」：解释为什么把本体接在六个位置、三条轴怎么分、每条判断的证据边界在哪。
>
> 原《本体在 harness 里如何被执行》7 章、4–6 万字的书稿计划已废弃，**也没有保留独立的 handbook**。唯一值得留的是第三章的论证，现在作为本目录的长版附录 [appendix-constraint-spectrum.md](./appendix-constraint-spectrum.md)（约 0.97 万字）；原大纲与规划已删除，git 历史保留。理由：书稿没有独立角色、后四章缺证据、主线过强。见 [deliverables/README](../README.md#handbook-的去留2026-11-09)。

## 1. 三份交付物的分工

| 交付物 | 回答 | 读者 | 形态 |
|---|---|---|---|
| [01 现状](../01-capability-status/README.md) | 今天能做成什么、不能承诺什么 | 决策者/工程负责人 | 判断 + 矩阵 |
| [02 工程实施](../02-engineering-playbook/README.md) | 拿本体做某件事，具体怎么做 | 工程负责人/架构师 | 步骤 + 接口 + 验收 |
| **03（本份）** | 为什么是这些位置/形态，证据边界在哪 | 架构师/研究者 | 参考 + 边界 |

**一句话**：01 告诉你「值不值得做」，02 告诉你「怎么做」，03 告诉你「凭什么这么说、说到哪为止」。

## 2. 三条轴，不要混

| 轴 | 问什么 | 载体 | 典型误用 |
|---|---|---|---|
| 派轴 | 本体凭什么起作用 | `01-06` | 把「知识注入」当「约束」 |
| 时刻轴 | 本体在哪个时刻介入 | 六个 seams + 轴外 | 把「读路径」当「动作前」 |
| 形态轴 | 机器拿本体做了什么 | engine/compiled/context/label/none | 把「有引擎」当「会拦/有授权」 |

> 三条轴正交：同一份本体可以在不同时刻、以不同形态被执行；「强度」是时刻轴的排序，「形态」不是强度的刻度。

## 3. 六个位置一页表

| 位置 | 问什么 | 本体角色 | 能阻断 | 主证据 | 主要代价 | 不能证明 |
|---|---|---|---|---|---|---|
| context | 模型看到什么 | 投影/编译 | 否 | E-01/E-12/E-14 | token/编译 | 规则被执行 |
| memory | 下一轮记得什么 | 状态/对齐 | 否 | E-05/E-17 | 维护/训练信号 | 跨运行确定性 |
| evidence | 产出带什么依据 | 证据契约 | 否 | E-03 | token/集成 | 形式保证 |
| checker | 产出对不对 | 外部判据 | 是 | E-02/E-20 | 每条判定/维护 | 语义正确 |
| action | 动作能不能做 | 可逆性/条件 | 是 | E-04/E-13/E-15/E-16 | 审批/误拦 | 结构有效/安全 |
| commit | 证据够不够授权 | 授权判据 | 是（设计） | E-20 + gap | 无实现 | 已落地 |

> 这不是「六个都该做」；是「六个位置问的问题不同」。选择规则见 02 §2。

## 4. 强度–覆盖率反向：组织假设，不是 E

```
约束强度   弱 ──────────────────────────────▶ 强
覆盖率     广 ◀────────────────────────────── 窄
位置      context   memory   evidence  checker  action  commit
```

**这是组织假设（非 E）。** 它把六派/六位置排成一个「越强越窄」的次序，但没有被任何一条 E 直接测量；E-01/E-04 只作边界证据，不作证明。

**什么会推翻它**：强端机制在广覆盖上稳定有效，或弱端机制在高覆盖下仍能改变走向，且不是单案例。

> 如果你只想要一个可操作的结论：**强端不是更好，是更窄；用错尺子会得出「无增益」。**（组织假设，非 E）

## 5. 证据边界 15 条

1. 强度/覆盖率反向没有被直接测量；图是组织假设。
2. E-01 的 ontology 是 `not measured`；不能写「本体无增益」。
3. E-04 的结构贡献未隔离、false-veto 未测；不能写「结构判据有效」。
4. E-13 是六点描述性拟合；不能当预测曲线/零交叉阈值。
5. E-12 是单工厂、9 任务、答案基本写在文本里；排序非普适。
6. E-15 是模拟、无本体变量；不是本体增益。
7. E-16 是模拟、固定 schema、无真实工厂；不是安全保证。
8. E-20 是代码级、4 个项目、未做对照实验；不是效应量。
9. E-02 是单 checker 实验；precision 是 25% 错答案假设；false-veto 未测。
10. E-03 的等级是模型自评、未校准；不是形式保证。
11. E-05 是专有数据、3 period；未匹配 ≠ 关系结束。
12. E-17 是文本 only、需训练信号；跨模态未测。
13. commit 写路径无实现；E-20 只给否定性证据。
14. 单来源为主、无独立复现；没有同一本体跨 harness 的对照。
15. C-03 不是新证据；它是方法论冲突，不是评分卡。

> 更细的逐条解释见 [附录 §3.7](./appendix-constraint-spectrum.md#37-本章不能证明什么)；每条 E 的限定见 [conclusions](../../topics/conclusions.md)。

## 6. 读法

- 想知道「这个机制能不能用」→ 01 §2 的能力地图。
- 想知道「拿本体做 X 怎么做」→ 02 §4 的 R1–R9。
- 想知道「为什么是这六个位置」→ 本页 §3 + [附录 §3.4](./appendix-constraint-spectrum.md#34-六个位置)。
- 想知道「这条判断的边界」→ 本页 §5 + [附录 §3.7/§3.8](./appendix-constraint-spectrum.md#37-本章不能证明什么)。
- 想知道「下一步研究什么」→ 各派 `frontier.md`；本页不复制候选。

## 8. 期待与数据需求（验收规格）

> 这一节不是结论，是**这份参考要成立需要什么证据**。它把「什么会改变判断」写成可检验的句子；缺的数据回 `frontier` 找，不在交付物里补。这是验收规格（非 E）。

| # | 期待（可证伪） | 支持它需要的数据 | 现在的证据 | 缺口 |
|---|---|---|---|---|
| M1 | 同一份本体换位置/形态，效应量不同且大于 run-to-run 噪声 | 同一本体 ≥2 位置/形态；同一度量；重复运行 | 只有跨来源弱对照；E-18 噪声基线 | 对照实验 |
| M2 | 强度越高、覆盖率越窄（反向关系） | 每个位置的覆盖率测量 + 效应量 | 组织假设；E-01/E-04 边界 | 覆盖率定义与测量 |
| M3 | 「有引擎」不等于「会拦/有授权」 | 代码级调用链 + 阻断测试 + 授权测试 | E-20 4 个项目 | 更多实现；对照 |
| M4 | C-03 的度量错配是文献冲突主因 | 同一机制用任务账/风险账两把尺子测 | E-01/E-04 的间接证据 | 配对度量实验 |
| M5 | 每条 E 的限定在跨域/独立复现后仍成立 | 跨域/独立复现；同一 E 的重复测量 | 单来源为主；无已证 | 独立复现 |

**怎么用**：M1/M2 是这份参考的「承重墙」；它们不成立，六位置表仍可作分类，但「强度–覆盖率反向」只能当组织假设。M3/M4/M5 是边界检查，不是新结论。
