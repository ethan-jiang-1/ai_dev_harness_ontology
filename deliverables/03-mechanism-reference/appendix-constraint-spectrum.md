## 3.0 本章一页话

- **强度不是好坏。** 强度问的是「违反时能不能改变走向」；覆盖率问的是「能碰到多少种失效」。强端管得硬，但管得少。
- **越强越窄是组织假设。** 它有边界证据，但没有被任何一条 E 直接测量；图上的「广/窄」是定性排序，不是刻度。
- **尺子要跟机制走。** 不改变走向的供给/契约位置，准确率、token 仍可用（校准是缺口；E-03、E-12、E-14）；能改变走向的判定/动作/落盘位置，用单一准确率或 reward 会错配（C-03、E-02、E-04、E-15）。
- **六个位置各有代价。** `context → memory → evidence → checker → action → commit`；每节写能拦什么、拦不住什么、代价、证据等级。
- **本章不能证明「强端更好」，也不能证明「本体无用」。** 它只能把「本体有没有用」改写成「在哪个位置、量什么、付什么代价」。

**怎么读**：架构师读 §3.1–3.2 再跳到 §3.6；平台/评测 owner 先读 §3.1.4、§3.7、§3.8；被「本体有用/无用」争论困住的人先读 §3.1.3、§3.5。本章不按章号顺序读也成立。

**与前后章的关系**：第一章把「差距不在模型」讲成现象；第二章给七个部件；本章给强度谱与六个位置；第四章用反例填六个时刻；第六章补「按机制类型分派指标」的表。本章只负责把「位置」讲清，不替前后章下结论。

三个最常见的误读，先放在前面：

| 误读 | 为什么不对 | 该读成 |
|---|---|---|
| 强端一定更好 | E-04 的 18 格仅 8 改善、retail/强模型回退；E-13 给不出阈值 | 强端更窄，要算代价 |
| 本体没有增益 | E-01 的 ontology 是 `not measured` | 被测量的结构化工件在强 harness 下无准确率增益 |
| 有引擎就是执行 | E-20：同一个 `engine` 至少四种语义 | 先问机器到底做了什么 |

## 3.1 先拆一个混淆：强度 ≠ 好坏

### 3.1.1 两个词的定义

**强度**：违反时能否改变走向——剪掉动作、拒绝输出、阻止落盘、要求授权。加上一条：后果是否可撤销。它不是「本体多完整」，也不是「模型多聪明」。

**覆盖率**：这个位置能碰到的失效类型/产出类型，占全部失效的比例。本章只用「广/窄」定性，没有测量。

两个定义带来三个推论：

1. **强弱不按时间顺序排。** 同一位置上，不同动作的强弱仍会变：一次转账比读一个文件强，一次发信比写草稿强。图上的顺序是讨论顺序，不是因果顺序。
2. **强弱不按「是否用本体」排。** 不用本体的硬编码规则也可以很强；用了本体的上下文注入仍然很弱。
3. **「强」不等于「好」。** 强端可能误拦、可能只剩代价；弱端可能覆盖广、可能被忽略。好坏取决于错误性质、代价、审批量（§3.6）。

> **三个词别混**：**派**是「本体凭什么起作用」（01–06）；**时刻**是「本体在哪个时刻介入」（seams 的六个位置）；**执行形态**是「机器拿本体做了什么」（engine/compiled/context/label/none）。「接缝」是「有外部判据 + 能阻断 + 位置明确」的概念，不是一个位置的名字。本章的「六个位置」是强度谱上的展开刻度，不是第四张分类表。

### 3.1.2 为什么准确率在强端失效

强端机制的目标不是「答得更对」，而是「不让某些事发生」：不让不可逆动作执行、不让不合格产出流出、不让错误变更落盘。用最终答案准确率量它，会同时漏掉两件事：

- 被拦住的错误没有出现在最终答案里；
- 被误拦的正确动作也没有出现在最终答案里。

E-04 把这件事说得很直接：作者声明 **reward 不是防止伤害的直接度量**。18 个模型-域组合里只有 8 个 reward 改善，不能读成「护栏无效」——它可能是「reward 看不见护栏在防什么」。`已核`（E-04；限定：τ²-bench、单 gate、6 模型）

这不是两个相反结论，而是同一个方法论问题。C-03 把它记成「度量尺不一致」：**用准确率/reward 量控制类机制，会得出错误结论；应按机制类型选尺。**

换一个说法：强端机制有两本账。

- **任务账**：答对/答错、token、时延。它记录「做成了什么」。
- **风险账**：被拦住的伤害、被误拦的正确动作、审批量。它记录「没发生什么」。

用任务账验收风险机制，会把「没发生的伤害」记成 0，把「误拦」记成「没做成」。这不是说任务账没用，而是说它只回答任务问题，不回答风险问题。`推测`（C-03 的展开，不是新 E）

### 3.1.3 E-01 与 E-04 的精确读法

这两条最容易被读过头，先把边界钉住。

**E-01：被测量的结构化工件，在强检索 harness 上无准确率增益。**

- 被测量的是摘要树、PageIndex 大纲、wiki、entity graph 这类**结构化工件**；PageIndex 式大纲在同规模下反而退化。
- **ontology、timeline、mind map、session memory 在原文 Table 1 是 `not measured`**，不能算进这个结论。
- 限定：单基准 FRAMES、单 compiler/answer model、无 CI。
- 不能写成「本体无增益」。它能支持的是：在足够强的检索 harness 下，**被测量的那几类结构化上下文**没有可检出的准确率增益；本体的效果在原文里没有被测。`已核`（E-01）

**E-04：可逆性分级 + 执行前剪枝，收益不普遍。**

- τ²-bench 上六个模型里四个在 airline 域提升 0.11–0.18；但 **18 个模型-域组合只有 8 个整体改善**，retail 与更强模型常回退。
- **T1-only 接近 blanket veto，增益却不比 full 小**——结构反向组合的贡献没有被隔离。
- **false-veto 未测**；作者声明 reward 不是防伤害度量。
- 不能写成「结构判据有效」。它能支持的是：护栏收益不普遍、强模型/retail 会回退、结构贡献尚未被证明。`已核`（E-04；状态 contested）

> 另外记住 E 层的证据类型：E-01/E-14/E-15 是 harness/度量证据，不是本体专属；E-20 是代码级形态分类。引用时不要把「结构化上下文」读成「本体」。

### 3.1.4 尺子跟机制走

把 C-03 展开成一张最小的对照：

| 机制是否改变走向 | 可用主指标 | 本章证据 | 不能用的尺子 |
|---|---|---|---|
| 不改变走向：供给/输出契约 | 任务准确率、token；校准是缺口 | E-03、E-12、E-14 | 伤害率、审批量——机制不产生这些量 |
| 改变走向：判定/动作/落盘 | 漏检/误报、伤害、审批、false-veto、授权正确率 | E-02、E-04、E-15；E-20 只证「执行 ≠ 授权」 | 单一 accuracy 或 reward |

> 这是 C-03 的展开（`推测` 的框架，不是新 E）；完整的分派表是第六章的缺口，本章只给判据，不给评分卡。

这里要修正一个过粗的说法：**「准确率说法集中在弱端」不够准。** E-03 是输出时的证据契约——中端、不阻断——恰恰用准确率量出了增益（平均 50.5%/68.1%，Tests 1–2 +10–15pp）。更准确的表述是：

> 准确率作为主指标，适用于**不改变走向**的供给/契约位置（E-03、E-12）；用于**能改变走向**的判定/动作/落盘位置会错配（C-03、E-02、E-04、E-15）。

这句是本章的方法论主轴，后面六节都按它读。

## 3.2 强度–覆盖率反向图

### 3.2.1 图

```
约束强度   弱 ──────────────────────────────────────────────▶ 强
覆盖率     广 ◀────────────────────────────────────────────── 窄
派         03 知识          04 状态        02 判定          01 约束
本章位置   context         memory         evidence  checker  action  commit
能否阻断   否              否*            否**      是       是      是***
典型失效   被忽略          状态失真        自评未校准 漏检/误报 误拦/回退 无实现

* 只改状态；** 只约束输出；*** 授权
```

**图注：组织假设（非 E）。** 强度/覆盖是定性排序，不是测量值；「能否阻断」是机制属性，不是效果。E-01/E-04 只作边界证据，不作图的证明。

### 3.2.2 读图三条

1. **按这张图的假设，越往右，能碰到的失效类型越少；一旦触发，越接近「改变走向」。** 弱端覆盖广，但什么都管不住；强端管得硬，但只管极少数动作/产出。
2. **弱端不是强端的低配。** `context` 不执行，只供给；把 `context` 当成 `engine` 的低配版，会得出「本体没被执行所以没用」的假结论。E-20 会说明：即使都叫 `engine`，语义也不止一种（§3.3）。
3. **中间空档最缺研究。** 计划、草稿、中间结论既没有判定、也没有授权，直接流向下一步。这是 `推测`/开放问题，不是 E；详见 §3.5.2。

### 3.2.3 这张图为什么仍然值得画

它不证明「强端更好」，只把问题换掉：

- 从「本体有没有用」换成「本体在哪个位置、以什么形态被用」；
- 从「准确率涨没涨」换成「这个位置该量什么」；
- 从「要不要上本体」换成「这个错误值不值得为它加一道闸」。

图的合法性来自**派谱**（[topics/README.md](../../topics/README.md#强度与覆盖率反向)），不是新建第四张分类谱。六个位置是派谱下的展开刻度：`context` 对应 03 知识的供给面，`memory` 对应 04 状态，`evidence`/`checker` 对应 02 判定的两个时刻，`action`/`commit` 对应 01 约束的两个时刻。分类仍以派轴/时刻轴为准；反向关系本身仍是组织假设，不是 E。

也要说清**六个位置不是 seams 的六个时刻**：`determinism`（跨运行一致性）不在这条强度谱上；`orchestration`（分工）是唯一没有对应流派的部件，本章不单列。它们重要，但不属于「约束强度」这条线。见 [seams.md](../../topics/seams.md)。

### 3.2.4 什么会推翻它

- 找到强端机制在广覆盖上稳定有效，且不是单案例；
- 或找到弱端机制在高覆盖下仍能改变走向，且效应稳定；
- 或「强度」与「覆盖率」被同一组实验测出同向变化。

目前没有这类证据。所以它是组织假设，不是 E。

## 3.3 同一位置，不同执行形态

### 3.3.1 强度谱不够用

同一份本体放在同一个位置，机器拿它做的事也可能不同。E-20 在四个开源项目的 pin commit 上做了代码级核对：**同一个 `engine` 至少覆盖四种语义**。

| 项目（commit） | 位置 | 形态 | 机器实际做什么 | 不做什么 |
|---|---|---|---|---|
| trustgraph `184f622` | `read-path` | `engine` | 从 `urn:graph:policy` 加载 SHACL-AF NodeShape，跑 `sh:SPARQLTarget` + `sh:SPARQLRule`；被 block 的 subject 侧三元组从查询结果删除 | 不是动作前 gate；不做 OWL 推理；异常 fail-open；只删 subject 侧 |
| semantica `39cf721` | `checker` | `compiled` | `OntologyEngine.to_shacl` 派生 SHACL；`validate_graph`/`run_shacl_validation` 调 pyshacl，`inference="none"`；CLI `validate shacl` | 不在 agent loop 内自动调用；不做 OWL 推理；无 catch/FA 测量 |
| ontop `964dbb7` | `supply` | `engine` | TBox 饱和 + 查询重写（rewrite → unfold → SQL）；`QuestStatement` 执行 | 不是 gate；不校验输出；不是 LLM agent |
| open-ontologies `375fbc4` | `none`（工具面；CI 规则门） | `engine` | 默认 `ShaclValidator` 把 SHACL 编译成 SPARQL 交 Oxigraph；`--verified` 走 `oo-shacl`（0/2/3，3=undetermined） | 不授权单次写/落盘；`enforce` 是 CI 规则门；外层 CLI 把 `conforms:null` 映射为 exit 2 |

强度谱回答「在哪一格」，形态轴回答「机器拿它做了什么」。形态不改变位置，但会改变同一位置内的语义：同样是 `checker`，semantica 是离线 CLI 校验，不是回路内的自动判定；同样是 `engine`，ontop 做查询重写，trustgraph 做策略过滤。所以读强度谱时，位置和形态要分开看。

### 3.3.2 三条代码级判断

1. **`engine` 不是一种语义。** ontop 是 OWL 2 QL 的 TBox 饱和 + 查询重写；semantica 是 SHACL 校验且 `inference="none"`；trustgraph 是 SHACL-AF 策略求值；open-ontologies 是 SHACL→SPARQL 或 verified Core。四者都叫「执行」，只有 ontop 动 TBox 蕴含。
2. **执行 ≠ 健全。** trustgraph 在 target/rule 异常时返回 False/None，无策略直接放行；且只查 subject 侧。read-path 是 best-effort gate，不是强闸门。
3. **执行 ≠ 授权。** open-ontologies 有真求值器、影响报告与 `enforce` CI 规则门，但没有单次写授权/commit gate；semantica 是 CLI 校验，不在回路内。唯一 read-path gate 仍是 trustgraph，不够第二个独立实现。

### 3.3.3 形态轴五档，别把 `context` 当低配 `engine`

`engine` / `compiled` / `context` / `label` / `none` 回答的是不同问题：

- `engine`：机器直接求值，输出随本体变化；
- `compiled`：本体先被编译成约束/规则/状态结构，再由代码执行；
- `context`：进入 prompt/上下文，模型自行使用；没有外部求值；
- `label`：只当标签表/schema/分类，不参与判定；
- `none`：没有执行，或本体不是被测变量。

`compiled` 与 `engine` 的差别是「有没有一个显式的编译步骤」；`context` 不是「弱执行」，是「不执行，只供给」。形态轴见 [execution-forms.md](../../topics/execution-forms.md)。

### 3.3.4 限定与用法

- 这是 **4 个开源项目、pin commit、只读代码、未跑测试**的核对；不是效应量，不能证明「形态改变行为」。
- 它的用处是给强度谱加一个警告：**读图时先问「机器到底做了什么」**。同一格内可能是策略求值、校验、查询重写或 CI 门，不能合成一个「强执行」。
- 一个旁证：仓库对 26 个来源的换词检查是 `推测`（分类判断，不是元分析）——15 个来源的结论把「本体」换成「任意结构化上下文」仍然成立。这提醒读者：本章很多证据其实是「结构化上下文 + harness 位置」，不是 OWL/DL 本体专属。

## 3.4 六个位置

先给读法：

- 六个位置按**强度**排，不按时间排。时间顺序见 [seams.md](../../topics/seams.md)：动作前 → 输出时 → 输出后 → 落盘前 → 跨轮 → 跨运行。`context` 没有对应时刻（它是供给），所以不在这条时间线上。
- 每节一张位置卡 + 解释 + 「什么会改变这条判断」。位置卡里的「能否阻断」是机制属性，不代表已经实现。
- 六节不是六篇综述：能拦/拦不住/代价/证据等级四件事写清，就够了；写不动的地方留显式 gap。

一张表先看全貌（详表见各节）：

| 位置 | 本体角色 | 能否阻断 | 主要失效 | 代价 | 主证据 |
|---|---|---|---|---|---|
| context | 投影/编译进上下文 | 否 | 被忽略、强 harness 下无准确率增益 | token/编译 | E-01/E-12/E-14 |
| memory | 状态结构/对齐 | 否（只改状态） | 状态失真、长期污染未测 | 维护/训练信号 | E-05/E-17 |
| evidence | 输出契约/接地等级 | 否（只约束） | 自评未校准、检索瓶颈 | token/集成 | E-03 |
| checker | 外部判据 | 是 | 漏检/误报、修坏多于修好 | 每条调用/维护 | E-02/E-20 |
| action | 可逆性/前置条件 | 是 | 误拦/回退、结构未隔离 | 审批/误拦 | E-04/E-13/E-15/E-16 |
| commit | 授权判据 | 是（授权） | 无实现、false-defer 未测 | 无数据 | E-20 + gap |

### 3.4.1 context：最广，也最容易被忽略

| 项 | 内容 |
|---|---|
| 本体角色 | 投影/编译成文本或结构化上下文；模型自行使用；不阻断 |
| 能改什么 | 输出知识；答案基本写在知识里时改变答案；编译省 token |
| 拦不住什么 | 写了规则仍可能被忽略（未做 prompt-vs-code 对照，`推测`）；强检索 harness 下被测量的结构化工件无准确率增益（E-01，ontology not measured）；投影排序非普适（E-12）；PageIndex 大纲在同规模退化（E-01） |
| 代价 | token/编译；E-14 的平均 −38% 是 hit/miss 混合，不充分时 +1.9%；先量 `p_h`；配对子集时延约 3× |
| 证据 | E-12 `已核`（分数）/`存疑`（排序）；E-14 `已核`（条件性）；E-01 `已核`（边界，ontology not measured） |
| 什么会改变 | 同一本体在强/弱 harness 下的对照；投影 vs 代码执行的对照；跨域复现 |

E-12 是这一格最具体的证据：同一份知识，投影成文本的 pooled element score 最高（0.777 > JSON 0.717 > 查询 0.638 > 检索 0.597），但**不是普适排序**——GLM-5.2 的 JSON 0.900 反超其文本 0.891；Qwen 的工具 0.407 低于文档检索 0.538。避坑率 0.605→0.802（+19.8pp，OR 5.45，p=6.0×10⁻⁷），但 **K0→K1（命名+单位）已有 +54.6pp**，塔只再加 +19.8pp；物理深度未测。限定：n=1 工厂、9 任务、答案基本写在文本里。`已核`（数字）/`存疑`（排序）

这组数字的正确读法是「薄语义层先起量」，不是「深度本体没用」，也不是「文本永远最好」。E-12 原文也把 JSON/工具当**事后描述性条件**，不是受控对照。

E-14 补上代价：编译的盈亏平衡是条件性的——无限视野 `p_h > 2%`，有限视野 `p_min = 2% + c/(0.929Q)`；平均 −38% 是 hit/miss 混合，不能当上线依据；证据替换用检索轮次换 token，配对子集时延约 3×。`已核`（E-14）

E-01 是这一格的边界证据：在足够强的检索 harness 下，**被测量的**结构化工件（摘要树、PageIndex 大纲、wiki、entity graph）在 FRAMES 上无可检出的准确率增益；PageIndex 式大纲在同规模下反而退化；ontology 等是 `not measured`。所以不能说「本体无增益」，只能说「被测量的那几类结构化上下文，在强检索 harness 下没有可检出的准确率增益」。`已核`（E-01；单基准、单 compiler/answer model、无 CI）

E-01 与 E-12 不矛盾：一个是强检索 harness 下的证据工件，一个是把领域知识投影成文本。差别不只在「答案是否写在知识里」，还在**投影什么**——证据 vs 领域知识。这是 C-04 记录的冲突，本章不重新裁决。`推测`（分析框架）

**何时用**：封闭域、操作手册型知识、答案基本写在文本里；需要模型照着规则做时，硬执行另进 01/02。

**何时别用**：开放域检索、多跳问答——如果目标是准确率增益，此时该投资的是检索 harness 本身，而不是工件；编译只在算过 `p_h > p_min` 后才买；投影不承担拒绝逻辑。

供给形态不止一种；选错形态，会把「知识问题」误当成「检索问题」：

| 形态 | 做法 | 何时 |
|---|---|---|
| 投影 | 把本体成段写成文本/记录 | 知识小而深、就是答案 |
| 编译 | 预整理成 claim–leaf/树/图/wiki | 语料大、需要反复检索 |
| 集成 | 知识并入既有系统（法规库、工单） | 有存量系统、需要治理（暂无专文） |

> 这是 03 知识派的供给形态分类，不是本章新判断；「集成」目前没有专文，是显式 gap。见 [03-knowledge](../../topics/03-knowledge/README.md)。

### 3.4.2 memory：状态，不是事实集合

| 项 | 内容 |
|---|---|
| 本体角色 | 状态结构/对齐与印证条件；不是自由推理 |
| 能改什么 | 跨轮一致、身份、冲突/失效；alias memory 让 final-period CMR +7.8–12.1pp；human-audit recall +22.5–29.0pp；semantic matching token −40.3%；EvoMem Acc@complete +11.5/+31.2 |
| 拦不住什么 | 不保证跨运行确定性；长期污染未测；文本 only；需训练信号；未匹配 ≠ 关系结束 |
| 代价 | 维护、抽取保真、训练信号；E-05 专有数据/3 period；E-17 需训练信号 |
| 证据 | E-05/E-17 `已核`；长期污染/本体改动不扩散 `推测` |
| 什么会改变 | 无训练信号的 reasoning state；跨来源/跨模态；false merge 的长期影响 |

E-05 的机制是「本体克制到只做对齐与印证」：product–topic 本体把 topic 讨论关联到 product，跨期身份由 registry 负责；本体只供给槽位、关系与印证条件，不做自由推理。alias memory 让 final-period CMR +7.8–12.1pp（4 settings），human-audit recall +22.5–29.0pp，semantic matching token −40.3%。限定：专有数据、3 period、无年度周期；未匹配 ≠ 关系结束。`已核`（E-05）

E-17 把「记忆是状态」说得更完整：Persistent Facts + Relational State（有效性/scope/更新/冲突）+ Reasoning State（当前请求怎么用）。EvoMemState 四基准上，Complete Retrieval 85.6%（与最好 baseline 相当），但 Acc@complete 70.8/68.5（+11.5/+31.2）；去掉 Relational −8.9/−6.4，去掉 Reasoning −8.0/−15.0，去掉 RL −7.9/−16.4；reasoning state 跨 6 系统 +0.2–4.9。限定：文本 only、需训练信号。`已核`（E-17）

这组数字的读法是：**增益在「会不会用」，不在「检索更多」**。Complete Retrieval 与最好 baseline 相当，但 Acc@complete 更高；去掉状态层，掉得更多。`已核`（数字）/`推测`（表述）

**拦不住**：跨轮一致不等于跨运行确定性；后者是另一个时刻（determinism），本章不把它塞进 memory。false merge 会把后续同名观察路由到错误 anchor，但「长期污染」是机制推断，论文未测量。`推测`

**何时用**：多会话、身份/别名、状态会变、冲突要留痕。**何时别用**：单轮任务、没有训练信号、不能接受文本 only。

### 3.4.3 evidence：输出时的证据契约

| 项 | 内容 |
|---|---|
| 本体角色 | 强制输出附带依据 + 接地等级（entailed/supported/related/unrelated）；是输出契约，不是判定器 |
| 能改什么 | 输出可审计；平均 50.5%/68.1%；Tests 1–2 +10–15pp；Test 3 8k 预算 84.9% vs 66.7% |
| 拦不住什么 | 等级是模型自评、未校准；检索是主瓶颈（gold evidence 完整检索 MCQ 61.7% vs OQ 23.6%）；不是形式保证；无句级 span |
| 代价 | token（9.7k vs 96.7k 是不同预算口径）；reasoner/SPARQL 集成；工程估算未测 |
| 证据 | E-03 `已核`；等级校准/检索瓶颈未解 |
| 什么会改变 | 等级校准；gold evidence 完整检索下的对照；代码级/结构化输出的接地 |

E-03 是这一格的主证据：强制每个答案报告所用作证据的本体观察 + 接地等级，在三个大本体、六个医学 QA 任务、2 backbone 上整体最优：平均 50.5%/68.1%；Tests 1–2 +10–15pp；Test 3 同 8k 预算 84.9% vs 66.7%，9.7k vs 96.7k tokens/问。限定：等级是**模型自评**、未校准；检索是主瓶颈（gold evidence 完整检索 MCQ 61.7% vs OQ 23.6%）。`已核`（E-03）

为什么这一格是中端而不是弱端：它约束了输出的格式与证据声明，但不阻断；模型仍可以输出一个错答案，只要附上一个等级。它是**契约**，不是闸门。也正因为它不改变走向，准确率在这里仍然是一把可用的尺子——这正是 §3.1.4 修正「准确率说法集中在弱端」的原因。

四个接地等级的含义（按 E-03 的接地等级定义，不是本仓库的证据等级）：

| 等级 | 含义 | 对读者的用法 |
|---|---|---|
| `entailed` | 答案可由观察中的事实逻辑推出 | 最强，但仍不是形式证明 |
| `supported` | 可由观察 + 参数知识合理推断，不是严格逻辑后承 | 可审计的支持关系 |
| `related` | 观察相关，但不足以确定答案 | 只能当线索 |
| `unrelated` | 观察与问题/答案无关 | 不是「没检索到」 |

> 这四个词是**接地等级**，不是本章的 `已核/推测/存疑`。两者不要混。见 [GLOSSARY](../../GLOSSARY.md#证据)。

**拦不住**：不是形式保证；不解决检索覆盖；没有句级 span（观察是整卡/ASK 结论/查询绑定级别的引用）；`unrelated` 只表示「有观察但与问题/答案无关」，不是「没检索到」。`已核`

**何时用**：医学/生物本体问答、需要可审计依据、术语歧义、检索失败与推理失败要分开。**何时别用**：没有 OWL reasoner/SPARQL endpoint、问题超出本体覆盖、答案主要靠文本阅读/计算、需要形式正确性保证。

**代价**：token 与集成；9.7k vs 96.7k 是不同预算口径，不能直接比；8,192 是论文全方法统一口径，96.7k 是 i-MedRAGdoc 在 262k 下的加报。工程集成成本未测；digest 有估算，但本章不把它当证据。`已核`（口径）/`推测`（成本）

### 3.4.4 checker：输出后的判定器

| 项 | 内容 |
|---|---|
| 本体角色 | 外部判据：查错/纠错；可阻断/退回/仅标注（策略层） |
| 能改什么 | 漏检/误报可见；三来源各有偏向；空结果重试基线；LLM judge 能抓语义变化 |
| 拦不住什么 | 语义反向/边界错抓不到（结构检查对 changes of meaning 是 0%）；LLM judge 修坏多于修好；false-veto 未测；同源检查 catch 下降是探索性 |
| 代价 | 每条答案一次模型调用（judge），成本/稳定性未测；curated 维护；覆盖与保证不可兼得（E-20：默认支持 `sh:sparql` 但会 skip；verified 覆盖 Core 但拒绝 `sh:sparql` 22/120） |
| 证据 | E-02 `已核`；E-20 `已核（代码）`；同源 `推测` |
| 什么会改变 | false-veto 标注；跨域复现；部署成本 |

E-02 的核心不是「有没有本体」，而是「哪种来源、什么代价、漏检/误报怎么换」：

- 真实答案上 catch/FA：curated 18.9/16.8、data-derived 8.2/3.5、masked LLM 5.0/1.8；
- precision（**人工故障 + 25% 错答案假设**）：curated 57.1、data-derived 72.3、LLM masked 93.7；curated 的精确度仅略优于随机（+1.6 点，CI 跨零）；
- 空结果重试在人工 fault 上 catch 79.2%、FA 0%，是关键基线；
- LLM judge 检错更多（catch 40.3%/FA 16.2%），但 40 修好 / 83 修坏；每条答案一次模型调用，成本/稳定性未测。

curated 的 FA 主源是 declaration/domain-range，不是「与数据矛盾」：盲审 32 个 FA 的双标注一致项中，undeclared term 17、closed-world 11、data clash 0。Table 5 的矛盾是另一类观察，不能拿来解释 FA。`已核`（E-02）

限定：单 checker 实验；precision 与真实答案 catch/FA 不是同一组，不能拼成一个「准确率」；false-veto 未测。`已核`（E-02）

**三态是接口问题，不只是指标问题。** 判定器要报「通过/违反/未检查完」；把「没检查完」合并进 pass，会污染 catch/FA 的分母。E-20 的代码核对里，`oo-shacl` 的 exit 3（undetermined）进入 wrapper 后变成 `conforms: null`，外层再把 null 映射为 exit 2，与解析失败同码；JSON 保留第三态，shell 退出码不保留。`已核（代码）`（E-20）

**覆盖与保证不可兼得。** 同一 SHACL 引擎的两条路径：默认支持 `sh:sparql` 但会 skip；verified 覆盖 Core 但拒绝 `sh:sparql`（22/120）。选型时要说明用哪条、拒了什么。`已核（代码）`（E-20）

**同源检查**：同一 artifact 既做 context 又做 checker 时 catch 下降，是探索性观察；机制（确认偏差 vs 信息冗余）未定，不能写成「必须不同源」的部署规则。`推测`

**何时用**：语义/结构检查、产出已形成、错误代价高。**何时别用**：格式/行为检查、类型都对但关系方向反/边界错、没有标注故障、需要形式保证。

### 3.4.5 action：动作前的闸

| 项 | 内容 |
|---|---|
| 本体角色 | 可逆性分级/参数合法性；动作前剪枝/审批 |
| 能改什么 | 拦不可逆动作；分配审批；airline 四模型 +0.11–0.18；CASEL HSR 14.75→7.02%；OntoAct 成功率/SI |
| 拦不住什么 | 18 格仅 8 改善；retail/强模型回退；T1-only ≈ blanket veto；结构贡献未隔离；false-veto 未测；E-13 六点拟合无阈值；E-15 模拟无本体变量；E-16 模拟固定 schema |
| 代价 | 审批量（8.7%/13.8%/12.6%，三种方法）；误拦；维护；强模型下可能只剩代价 |
| 证据 | E-04 `已核`/contested；E-13 `已核`（描述性）；E-15 `已核`（模拟）；E-16 `已核`（模拟） |
| 什么会改变 | false-veto 标注；同一本体不同 harness 的对照；能力梯度阈值 |

E-04 在这一节是该位置的主证据（在图上是边界证据，不作图的证明）：用两层本体对工具调用打可逆性分、执行前剪枝，τ²-bench 上六个模型中四个在 airline 域提升 0.11–0.18；但 **18 个组合仅 8 个改善**，retail 与更强模型常回退；T1-only 接近 blanket veto，增益却不比 full 小——结构反向组合的贡献未被隔离；false-veto 未测；作者声明 reward 不是防止伤害的直接度量。`已核`（E-04；状态 contested）

E-13 把「收益与基线能力反向」量化了一点：airline/retail/telecom 斜率约 −0.76/−0.67/−0.31（R² 0.92/0.98/0.65），但这是**六点描述性拟合**，给不出零交叉的部署阈值。不能当预测曲线。`已核`（E-13）

E-15 是审批/分配的证据，不是本体增益：CASEL 模拟（20 seeds、120k actions）HSR 14.75%→7.02%、审批 8.7%；最低 HSR 是 Consequence-Menu 4.38%（审批 13.8%），Risk-Menu 5.82%（审批 12.6%）；CASEL 用约 30% 更少审批达到相近 harm。主表在 τ=∞（阈值关闭）下；不是所有方法同 menu/cost；审批疲劳未建模；**无本体变量**。`已核`（E-15；状态 contested）

E-16 说「约束形式决定它是天花板还是护栏」：限制知识源（curated KG）可能封顶；验证条件（三值 ⊤/⊥/?）+ 假设 revision 可同时提高成功率与减少无效干预（Tacit-FLE 78.6/83.3/90.0% vs IfR 64.3/66.7/65.0%；SI 1.6–2.4 vs 6.4–17.8；Mars 15.92 vs 10.64；ALFWorld 98.5% vs 96.3%）。限定：模拟、固定 schema、无真实工厂；不是安全保证。`已核`（E-16）

这一格其实有三种子机制，别混：

- **可逆性/审批**（action-gate）：问「有没有可接受的逆序列/该分配多少审查」；E-04/E-15 在这里。
- **条件验证**（reasoning-gate）：问「结论/动作的前提条件成不成立」；E-16 在这里。
- **落盘授权**（commit-gate）：问「什么证据才有权推动持久化」；见 §3.4.6。

三者都在动作前/落盘前，但判据不同；本章按强度把它们合在「action/commit」两节，不表示它们是同一个机制。

**何时用**：动作不可逆且代价高（对外发送、资金、删除唯一数据）；模型能力弱于域要求；域规则可被查询成事实。**何时别用**：强模型 + 高基线（POLAR 已观察到回退）；动作的复合可逆性无法计算；判定所需事实依赖运行时状态而系统拿不到；合法意图主导（retail 退货/换货）且没有意图/授权层。

**代价**：审批量、误拦、本体维护；强模型下可能只剩代价（E-04/E-13）。这不是「强端一定更好」的反面，而是「强端要算账」。

### 3.4.6 commit：落盘前的授权

| 项 | 内容 |
|---|---|
| 本体角色 | 授权判据：证据是否足够、scope/version 是否有效、冲突是否清；不是「能不能推理」 |
| 能改什么（设计上） | 三条件全过才 commit；claim-specific promotion；不跨 mutation 继承；同源检索不算独立确认 |
| 拦不住/现状 | 写路径只有概念架构，无实现、无实证；E-20 代码级：四个项目里没有一个是单次写授权；open-ontologies 只做影响报告 + CI 规则门；semantica 是 CLI 校验；trustgraph 是读路径过滤（fail-open，只删 subject 侧） |
| 代价 | false-defer 未测；审批粒度/橡皮图章；无实现成本数据 |
| 证据 | E-20 `已核（代码）`；设计提案是概念架构，非 E |
| 什么会改变 | 写路径实现；false-defer 率；scope/version 失效的实测 |

落盘前是变更真的发生的那一刻：前面都是推理/预览，这里是持久化或写入外部系统。按 [commit-gate](../../topics/01-constraint/commit-gate/README.md) 的定义，这里问的不是「结论能不能推出来」，而是「什么证据才有权推动持久化」。

这一节必须诚实：**它是六个位置里证据最薄的一格。**

- 设计上，它要求证据齐、冲突清、版本有效三条全过才 commit；`P_auth` 按命题/观察域/policy version 绑定，commit 时再验 scope/version；批准不跨 mutation 继承；同源检索不算独立确认。这些是概念架构，**无实现、无实证**；commit-gate 主题页把它们标为 `已核（概念架构）`，不是 E。
- 代码上，E-20 只给出否定性证据：四个项目里没有一个是单次写授权——open-ontologies 有真求值器、影响报告与 `enforce` CI 规则门，但那是 CI 规则门，不是单次写授权；semantica 是 CLI 校验，不在回路内；trustgraph 是读路径过滤，拦的是「看到什么」，不是「写什么」，而且 fail-open、只删 subject 侧；ontop 是供给重写。`已核（代码）`（E-20）
- 所以本节给的是**设计问题清单**，不是已验证机制：false-defer 未测，审批粒度/橡皮图章风险未测，scope/version 失效未测。

**何时用**：持久化/外部写入、错误变更代价高。**何时别用**：没有实现时，不要把它说成已落地；可以先做读路径/CI 检查，但要标明那不是 commit gate。

### 3.4.7 六个位置之外

本章的六个位置不是全集。至少还有四类，故意不放进强度谱：

| 位置 | 为什么不放进谱 | 去哪看 |
|---|---|---|
| `determinism` | 跨运行一致性，不是单次路径上的施力点 | [seams](../../topics/seams.md) · [04-state/determinism](../../topics/04-state/determinism/README.md) |
| `orchestration` | 唯一没有对应流派的部件；多智能体共享本体缺可判定设计 | [00-harness](../../topics/00-harness/README.md) |
| `reasoning-gate` | 与 action-gate 的边界未稳定；同一时刻的另一种判据 | [reasoning-gate](../../topics/01-constraint/reasoning-gate/README.md) |
| `read-path` / `supply` | 轴外位置；read-path 只有 1 个独立实现，supply 是供给内部执行 | [execution-forms](../../topics/execution-forms.md) · [seams](../../topics/seams.md) |

这四类重要，但把它们塞进强度谱会让「强度」变成「所有东西」；本章按「能否改变走向 + 覆盖」只收六个。`推测`（分类边界，不是 E）

## 3.5 两条推论

### 3.5.1 尺子跟机制走，不是「强弱跟好坏走」

把 §3.1.4 再收一句：

- **不改变走向**的位置（context、evidence），准确率/token 仍可用（校准是缺口）；E-03 的输出契约、E-12 的知识投影、E-14 的编译经济学都在这一侧。
- **改变走向**的位置（checker、action、commit），单一准确率/reward 会错配；E-02 的 catch/FA、E-04 的 harm/approval、E-15 的 harm–approval–cost 都在这一侧。
- 这不是「弱端有用、强端没用」，也不是「强端更好」。它是 **C-03**：量控制类机制，要用能看见「被拦住/被误拦」的尺子。

文献里「本体有用」与「本体无用」的冲突，至少有三层来源：度量错配（C-03）、任务形态（E-12 的排序非普适）、检索强度（E-01 的强 harness 边界）。本章不裁决哪一层最重要；它只把三层分开。`推测`（分析框架）

### 3.5.2 中间产物是空档

计划、草稿、中间结论——它们既没有判定，也没有授权，直接流向下一步。这是本章最值得记住的工程观察，也是**没有 E 支撑的开放问题**。`推测`

为什么它是空档：强端（action/commit）只管最终动作/落盘；弱端（context/memory）只管「看到什么/记得什么」；中间那层「这一步的结论能不能当下一步的输入」没有对应的闸。E-02 的 checker 管产出，但通常只管最终答案；E-03 的证据契约管输出，但不阻断；E-04 的 action gate 管工具调用，不管计划文本。

01 派有一个子主题叫 `reasoning-gate`（推理期条件验证），但它与 action-gate 的边界尚未稳定，本章不把它单列。见 [reasoning-gate](../../topics/01-constraint/reasoning-gate/README.md)。要补这个空档，需要 case-level 的失败数据；本章没有，也不新开实验。

## 3.6 选择规则

### 3.6.1 先问三个问题

1. **这个错误可逆吗？** 可撤销 → 先判定；不可撤销 → 动作前/落盘前。
2. **代价多大？** 错了会扩散到下游、污染后续轮次、还是只影响这一次？
3. **审批量能承受吗？** 强端不是免费；E-15 的 8.7%/13.8%/12.6%（三种方法）是审批量，不是「零成本」。

### 3.6.2 决策表

| 错误性质 | 优先位置 | 为什么 | 证据/限定 |
|---|---|---|---|
| 可撤销、会扩散 | evidence + checker | 先判定再放行；输出契约让判定有依据 | E-02/E-03；false-veto 未测；等级自评 |
| 会污染后续轮次 | memory | 状态结构先对齐；跨轮一致 | E-05/E-17；文本/训练信号限定 |
| 不可撤销、对外 | action | 动作前剪枝/审批；可逆性结构判据 | E-04/E-15/E-16；回退/模拟限定 |
| 不可撤销、持久化 | commit | 授权判据；scope/version；不跨 mutation 继承 | E-20 仅代码级；写路径无实现 |
| 要求可复现 | determinism | 跨运行锚点 | 不在本章；见 [seams](../../topics/seams.md) |

> **这是组织建议（非 E）**，依据 E-02/E-03/E-04/E-05/E-15/E-16/E-17/E-20 + seams；不是已验证的决策模型。

### 3.6.3 不要合成一个分数

- 每个位置量的是不同的东西：token、catch/FA、审批量、false-defer、伤害率。合成一个分数会丢掉「代价/误拦/审批」。
- 同一场景可能要叠加多个位置；表里的「优先」不是优先级排序，是**错误传播路径**上的先后。
- 强端不是默认答案：E-04 的 retail/强模型回退、E-13 的能力梯度都说明，强端在高基线下可能只剩代价。
- 成本数据不全：本章不给单价、不给阈值；可行性页有公式，但单位价格/审批基线仍是空的（`推测`/gap）。见 [feasibility](../../topics/06-measure/feasibility/README.md)。

成本横向看（只列 E 里已有的口径；没有数字的写 gap）：

| 位置 | 主要成本 | 有数字吗 | 缺口 |
|---|---|---|---|
| context | token/编译 | E-14：平均 −38% 是混合，配对子集时延约 3× | 每个部署的 `p_h` 要自己量 |
| memory | 维护/抽取保真/训练信号 | E-05：semantic matching token −40.3% | 维护成本未测 |
| evidence | token/集成 | E-03：9.7k vs 96.7k 是不同预算口径 | 集成成本未测 |
| checker（judge 分支） | 每条答案一次模型调用 | E-02：judge 每答案一次调用 | 成本/稳定性未测 |
| action | 审批/误拦 | E-15：审批 8.7%/13.8%/12.6%（三种方法） | false-veto 未测 |
| commit | false-defer/审批粒度 | 无 | 无实现 |

> 这张表是组织建议（非 E）：它只把各节已经写过的代价并排，不新增数字，也不合成总成本。

### 3.6.4 一页工作表

给一个具体场景，按顺序填；填不满的地方就是 gap，不要用「通用经验」补。

| 问题 | 填什么 | 填不出来意味着 |
|---|---|---|
| 错误是什么？可逆吗？ | 一句话 + 可撤销/不可撤销 | 还没定义失效形态，别选机制 |
| 错误会扩散/污染/只影响这一次？ | 下游影响、跨轮影响 | 选不准位置 |
| 这个位置现在有实现吗？ | 有/无；有的话在哪一段代码/流程 | 没有实现就先写 gap，不要假装有闸 |
| 该量什么？ | 按 §3.1.4 选主指标 + 过程指标 | 尺子没选对，结论会反向 |
| 代价是什么？ | token/审批/误拦/维护，哪一项是硬约束 | 成本没算，不要上线 |
| 什么会推翻这个选择？ | 一条可观测的反例 | 没有反例，说明判断不可证伪 |

这不是评分卡，是**把「要不要上本体」问成「在哪个位置、量什么、付什么代价」的最小清单**。它是组织建议（非 E）。

### 3.6.5 两个场景，说明怎么用

| 场景 | 先上哪个位置 | 用什么尺 | 不要做什么 |
|---|---|---|---|
| 可撤销的内容生成/文档草稿 | evidence + checker | 准确率、catch/FA、token | 不要用 action gate 的 harm 指标；不要把 reward 当唯一尺 |
| 不可逆的对外动作/资金/删除 | action + commit | harm、审批、false-veto、授权正确率 | 不要用 reward 证明有效；不要把「有引擎」当授权 |

> 示例只用于说明选择顺序，不是客户案例；两个场景都可能需要多个位置叠加。

## 3.7 本章不能证明什么

1. **强度/覆盖率反向没有被直接测量。** 图是组织假设（非 E）；E-01/E-04 对这张图只作边界证据。
2. **E-01 的 ontology 是 `not measured`。** 不能写「本体无增益」；它测的是几类结构化工件。
3. **E-04 的结构贡献未隔离、false-veto 未测。** retail/强模型回退是真的；不能写「结构判据有效」。
4. **E-13 是六点描述性拟合。** 不能当预测曲线，不能给零交叉阈值。
5. **E-12 是单工厂、9 任务、答案基本写在文本里。** 排序非普适；不能当跨域规律。
6. **E-15 是模拟、无本体变量。** 它是 harness/审批证据，不是本体增益。
7. **E-16 是模拟、固定 schema、无真实工厂。** 不是安全保证。
8. **E-20 是代码级、4 个项目、只读未跑测试。** 不是效应量；不能证明「形态改变行为」。
9. **E-02 是单 checker 实验。** precision 是 25% 错答案假设；不能当部署估计；false-veto 未测。
10. **E-03 的等级是模型自评、未校准。** 检索是主瓶颈；不是形式保证。
11. **E-05 是专有数据、3 period。** 未匹配 ≠ 关系结束；无年度周期。
12. **E-17 是文本 only、需训练信号。** 跨模态未测。
13. **commit 写路径无实现。** E-20 只给「执行 ≠ 授权」的否定性证据。
14. **单来源为主、无独立复现。** 证据以英文论文/单基准为主；没有同一本体跨 harness 的对照。
15. **C-03 不是一条新证据。** 它是方法论冲突；本章把它展开成「按机制选尺」，但没有独立检验这个分派框架。

如果读者只带走一句话：**强端不是更好，是更窄；用错尺子会得出「无增益」；选位置按错误性质，不按本体质量。**（组织假设，非 E）
