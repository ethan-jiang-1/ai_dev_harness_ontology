# 决策支持：该不该试、做到哪一步、什么时候停

> **给谁**：要为这条链拍板的人——负责人、评审、立项/预算、治理与安全。
> **回答**：这条链现在是 `go` / `conditional` / `no-go` 的哪一种；要花什么；规模先断在哪；`conditional` 怎么处置；怎么给负责人一页 memo。
> **不回答**：值不值得做本体（去 [01](../../01-capability-status/README.md)）、接哪个缝（去 [02](../../02-engineering-playbook/README.md)）、为什么是这些位置（去 [03](../../03-mechanism-reference/README.md)）。
>
> 一句话：**04 能决定「这条链能否试点」，不能决定「本体是否值得」；没有单价与 owner，就不出点估计。**

## 0. 一页结论

| 问题 | 04 的答案 | 依据 / 限制 |
|---|---|---|
| 这张 fixture 能上线吗 | **不能**；它是 `conditional`，不是「可上线」 | C3 object 泄漏、T9 未定、写授权无实现（[acceptance](./acceptance.md)） |
| 这张 fixture 能试点吗 | 可以，但要收窄范围 + 补条件 | 见 §5；不是所有团队都适合 `conditional` |
| 要花多少 | `推测`：建模 2–4 人周 + shapes 3–5 人日 + 集成 1–2 人周；打标/审计/执行层**未估** | §2；**不是报价**（缺打标/审计/执行层三项，且无单价） |
| 多久 | 4 个阶段：3–5 天 / 3–5 周 / 1 周 / shadow 2–4 周（`推测`） | §3；按 5 表小域、1 个 owner 假设 |
| 什么时候停 | 契约填不出 / `targeted=0` / object 泄漏未修 / 无 owner / 无回滚 | §5、§6 |
| 什么会改变判断 | 第二实现、真数据误报率、单价、规模测试 | §7；缺这些只能 `conditional` 或 `not enough data` |

> 要给负责人一句话，直接抄 [§5.3](#53-给负责人的一句话)。
>
> 如果你的决策规则是「要么全量上线、要么不做」：04 的答案是「现在不做全量，先做收窄试点」；不能接受 `conditional`，就按 `no-go` 处理，不要用「先上线再说」绕过 C3。

## 1. 决策边界：04 回答什么、不回答什么

| 问题 | 04 | 去哪 |
|---|---|---|
| 这个能力今天能不能用、先做哪个 | 不回答 | [01](../../01-capability-status/README.md) |
| 接哪个位置、用哪条 recipe、怎么上线 | 不回答；只借 02 的 R0/R8/R10/R11 | [02](../../02-engineering-playbook/README.md) |
| 为什么是这些位置、边界在哪 | 不回答 | [03](../../03-mechanism-reference/README.md) |
| 这条链的 9 件产物、5 组门槛、停在哪 | **回答** | 本页 + [acceptance](./acceptance.md) |
| 这条链能不能试点、`conditional` 怎么处置 | **回答** | §5 |
| 这条链要花什么、规模先断在哪 | **回答到「成本驱动项 + 量级」**；不出报价 | §2、§4 |

**三个选项**（借 [02 operations/cost](../../02-engineering-playbook/04-operations/03-cost.md#6-build--buy--do-nothing)）：

- **build pilot**：有稳定域、复用高、能维护；04 只给这一项的产物与门槛。
- **buy**：有成熟产品、能 RFQ、集成可控；04 的验收表可当 RFQ 的检查项。
- **do nothing**：复用低、风险低、基线够用；反事实必须是 do nothing，不是「换个更好的机制」。

> 04 不比较 build/buy；只把 build pilot 的成本项与门槛摆出来，让比较有分母。

## 2. 成本：先算分母

### 2.1 五个成本维度（借 02）

| 维度 | 问什么 | 04 里常漏的 |
|---|---|---|
| 建设 | 一次性投入多少？谁维护？ | 建模 + shapes + 查询/集成 + policy 表 |
| 运行 | 每次查询多少 token/时延/调用？ | 04 的 fixture 是本地 rdflib，不是生产 endpoint |
| 维护 | 源/标签/策略/形状变更后怎么更新？ | `policy_version` / `tag_version` / 形状回归 |
| 人审 | 多少比例需要人看？看的成本？ | 审计/例外/审批队列；04 只给 3 条样例 |
| 失败 | 机制失效时的代价？ | object 方向泄漏、`skip` 被当 allow、T9 平局 |

**不要只算 token**：打标、执行层修复、审计/人审常是大头（`推测`）。

>

### 2.3 TCO 与「缺项」规则

```text
TCO_12m =
  建设（建模 + shapes + 集成 + policy/audit）
+ 运行（查询/时延/调用）
+ 人审（审批分钟 × 单价 + 抽检工时）
+ 维护（标签/策略/形状/版本对账）
+ 失败（object 泄漏、误拦、审计返工）
```

- **缺项 >2 不出 build/buy 点估计**；只出公式与敏感性（借 02 cost）。
- **如果只能填 3 个数**：建模人日、打标覆盖率/人日、执行层修复人日。这三项决定成本能不能算清；算不清就是 `not enough data`，不要硬给 `go`（`推测`）。
- **四个常见漏算**：打标、执行层、审计/人审、维护。

### 2.4 收益侧：04 不证明，但 memo 要写假设

| 收益 | 04 能说什么 | 不能说什么 |
|---|---|---|
| 防泄漏 / 审计 | object 探针、per-subject audit、`skip` 单列；这些是合规能力 | 泄漏率下降多少、审计省多少工时 |
| 查询效率 | 3 条固定 CQ 可对照；0 行能分因 | 比手工 SQL 快多少；自由问句的准确率 |
| 复用 | TBox/shape/policy/audit 共用标识，改一处能回填 | 复用带来的维护节省 |
| 决策质量 | 门槛与停显式，能区分 `go/conditional/no-go/not enough data` | ROI、NPV |

> 如果收益不能货币化，memo 写「合规/风险」而不是 ROI；不要编收益数（`未测`）。TCO 公式在 §2.3，收益公式借 02 cost。

### 2.5 把三个未估项变成可测的数

> 不发明单价；只给公式 + 最小测量。参数填不出 = `not enough data`。

| 缺口 | 公式 | 最小测量 | 输出 |
|---|---|---|---|
| 打标 | `N_col × t_label × (1 + r_review)` | 50 列分层样本，含未标列；记分钟/列、复核率 | 人日 |
| 执行层修复 | `spike + fix + test + rollout` | 3–5 天（`推测`）spike：单侧修复 vs 第二实现；object 探针 + 4 用例 + 回滚 | 人日 / 风险 |
| 审计运营 | `records/day = QPS × 86400`；`storage = records × bytes × retention`；`review = sample × minutes` | 1 周 shadow | GB/月 + 人时/月 |
| 维护 | `changes/month × hours` | policy/tag/形状变更记录 | 人日/月 |
| `conditional` 修复 | 执行层 spike + T9 优先级 + 写授权设计 | 修复清单 + 回滚演练 | 人日 / 风险 |

**打标的算术示例**（`推测`；不含 taxonomy / 工具 / 返工）：

| 列数 | 1 min/列 | 3 min/列 | 5 min/列 |
|---|---:|---:|---:|
| 13 | 0.03 | 0.08 | 0.14 |
| 50 | 0.10 | 0.31 | 0.52 |
| 200 | 0.42 | 1.25 | 2.08 |

> 人日 = 列数 × 分钟 / 480；复核按 ×1.5 另乘。打标时间不等于标签源建设时间；taxonomy / 工具 / 返工另算。
> 如果 50 列样本的 `t_label` / `r_review` 量不出，或执行层 spike 没做，就写 `not enough data`，不要用「大概 2–4 人周」蒙混。

## 3. 工期：按产物分四个阶段

> 时间是量级（`推测`），不是承诺；按 5 表小域、1 名熟悉该域的人、数据已可读假设。数据清洗/打标另加；多人协作不线性。
>
> 与 [transfer §7](./transfer.md) 的 5 个检查点对应：P0=检查点 0；P1=检查点 1–2；P2=检查点 3；P3=检查点 4 + 试点。

| 阶段 | 入口 | 产物 | 出口 | 停 | 量级（`推测`） |
|---|---|---|---|---|---|
| **P0 契约** | 3 个 owner（UI/数据/治理） | 契约 6 项 + principal/多标签决策 + 3 条 CQ 草稿 | 3 条 CQ 写得出；每行有拒绝条件或明确 `—` | 填不出 → 不建 | 3–5 天 |
| **P1 最小链** | P0 | TBox/ABox + 2 shapes + `build_report` + 3 CQ raw | 三关；0 行分因 | `targeted=0` 当 pass → 停 | 3–5 周（建模 2–4 周 + shapes 3–5 天） |
| **P2 治理链** | P1 | policy 表 + 测试（fixture 8/11）+ audit schema + 3 条记录 | 10/11 唯一；T9 显式；object 探针 | object 泄漏未修 → `conditional` | 1 周 |
| **P3 试点** | P2 | shadow 2–4 周；账本（借 02）；误报/延迟/审计 | 能按查询出分布；有回滚 | 无 owner/无回滚 → 不 enforce | 2–4 周 |

> 集成（endpoint/agent）1–2 周不含在 P1/P2；放在 P3 前，按你的栈另加。

**三条纪律**：

1. **不要并行**：契约 → TBox → CQ → shape → policy → audit；跳步会把问题推到下一段。
2. **不要从 shadow 直接 enforce**：至少一个完整周期的 advisory（2–4 周；借 02 rollout）。
3. **时间不是承诺**：3–5 天/3–5 周是范围，不是 deadline；数据清洗和打标会改它。

## 4. 规模：先断在哪

| 轴 | fixture | 先撞什么（`推测`） | 现在有什么 | 你要测 |
|---|---|---|---|---|
| 表 / 列 | 5 / 13 | 建模 + 打标先于查询 | 5 / 13 | 你的 schema 规模；列级标签覆盖率 |
| 标签 | 9 正常 + 2 坏 | 多标签/覆盖率；策略组合 | 9（Glyph 275 叶是参照） | 你的 tag 数、多标签率 |
| shapes | 2 | 每条约束 1 shape；变更要回归 | 2 | 你的约束数 / 变更频率 |
| policy | 8 规则 / 11 测试 | 规则 × principal × kind 组合；T9 平局 | 8 / 11 | 你的角色/动作/资源种类 |
| 查询 | 3 条 CQ | 每条要 expected + 0 行分因；自由问句不覆盖 | 3 | 你的查询量；是否固定 CQ |
| audit | 3 条样例 | 每 query × 每 subject 一条；存储/保留期 | 3 | 你的 QPS / 保留期 |
| 组织 | 单团队 | 标签/策略/执行层/审计四个 owner | 单团队 | 谁维护哪一层 |

**读法**：

- 5 表/13 列是 **fixture**；200 表/5,000 列是**本文假设的「中型目录」规模**（`推测`），**不是 Glyph 的量级参照**——Glyph 是 ~98,000 表 / ~3.4M 列（E-22），比这里大两个数量级。三者不要混：fixture 跑通、假设规模、生产参照。
- 「先断在哪」是结构推断（`推测`），没有规模实测；先量标签覆盖、策略组合、审计量，再判断。
**规模带（`推测`，不是阈值）**：

| 量级 | 表 / 列 | 能说什么 | 不能说什么 |
|---|---|---|---|
| 1× | 5 / 13 | fixture 已跑通 | 不是你的域 |
| 10× | ~50 / 130 | 未测；先量标签覆盖率与策略组合数 | 不能说结构不变 |
| 40× 表 / ~385× 列（假设） | 200 / 5,000 | 本文假设的「中型目录」，只用于讨论先断在哪 | 不是 Glyph，也不是你的域 |
| Glyph 参照 | ~98,000 / ~3.4M | 生产目录的量级（E-22；Apple 单企业） | 不能当本 fixture 的容量证明 |

- **什么时候不要用 04 起步**：如果你的应用需要自由问句、多租户、行级/值级控制、写授权，04 的 3 条 CQ + 列级读策略不覆盖；先看 02 的对应 recipe 或 01 的能力边界。
- 规模测试在仓库外；需要时用 `EXP-xxx` 回链，不在仓库内做实验。

## 5. `conditional`：不是失败，是未决项

**定义**：接口、产物、验收表都在，但至少一条门槛没过。`conditional` 的意思是「可以按收窄范围试点，不能按全量上线」。

> `conditional` 不是「先放着」：必须有 owner、修复清单、到期日；三样缺一，就是 `no-go` 的软化版。

**当前 fixture 的 `conditional` 来自**：

- **C3 object 方向**：trustgraph 只删 subject、fail-open；表页探针会返回 `col_ssn`（E-23）。
- **T9 平局**：steward 读 table 同时命中 R4 allow / R5 skip，优先级未写（C.2）。
- **写授权无实现**：04 只到读路径；写路径是设计（E-20）。

> `targeted=0` 是**风险检查项**，不是当前 fixture 的现状（它 `targeted=2`）；但你的项目里一旦出现，就按「空转」处理。
>
> 严格 replay（hash/parser）不是 5 组门槛之一；它是不升 stable 的额外限制，见 §5.2。

### 5.1 你的处境 → 建议

> 下面是工程建议（`推测`），不是效果承诺；监管/合同/风险约束更高时，以你的约束为准。

| 你的处境 | 建议 | 必须补 | 不该做 |
|---|---|---|---|
| 内部、steward-only、只读 | **可试点（conditional）** | 收窄范围写进契约；audit；object 探针；版本；T9 显式 | 不要对 analyst/外部用户开放 |
| 有外部用户 / 监管 / 多租户 | **停 / 换执行层** | 第二实现或修执行层；fail-closed；object 双向；写授权 | 不要用 trustgraph 单实现上线 |
| 没有标签来源 / 没有 owner | **停在 A.1** | [label-source](./label-source.md) 的准入清单；等级、owner | 不要先建 TBox |
| 只要 demo / 评审 | **演示** | 标 `conditional` + 未修清单 | 不要说「可上线」 |

### 5.2 升到 stable 的条件

| 条件 | 证据 | 谁 |
|---|---|---|
| object 方向不返回敏感列 | LEAK-T1 + 4 条一致性用例 | 平台/安全 |
| 第二实现或修好的执行层 | 双实现差分 / 修法记录 | 平台/安全 |
| T9 有显式优先级，或 `undetermined` 时执行层按 deny/withhold 处理（不能放行） | policy 测试 + 执行记录 | 治理 |
| `targeted>0` 且坏样本被抓住 | `build_report` | 数据/本体 |
| 写授权有设计/实现边界 | 设计文档 + 测试 | 平台/安全 |
| 严格 replay 有 hash + parser 版本 | audit 记录 | 治理/平台 |

> **如果只能修一件**：object 方向（安全洞）。**如果只能买一件**：第二执行层/执行器（把 `conditional` 变 `go` 的最短路径）。两条都是工程建议（`推测`），不是效果承诺；修复成本怎么算见 §2.5。

### 5.3 给负责人的一句话

> 「现在不是『可上线』，是『可试点』：契约、产物、验收表齐了，但执行层 object 方向已知会返回敏感列，T9 优先级未定，写授权没有实现。试点范围收窄到内部 steward-only、只读、带审计；要全量上线，先补第二实现/修执行层和写授权。不能接受这个条件，就停在这里。」

## 6. `go / conditional / no-go` 与决策 memo

### 6.1 四类结论（借 02 evaluation）

| 结论 | 条件 | 下一步 |
|---|---|---|
| **go（pilot）** | 5 组门槛全过；成本可接受；有 owner/回滚 | 进 shadow/advisory |
| **conditional** | 至少 1 条门槛未过，但可修、可收窄范围、有 owner | 收窄试点 + 修复清单 |
| **no-go** | 契约填不出 / 没标签来源 / 没执行层 owner / 成本 > 价值 | 停；回 01/02 |
| **not enough data** | 没有基线、单价、规模测试、误报率 | 先量数；不要用「通用经验」补 |

> 「不出结论」不是失败；它防止把噪声写成结论（借 02 evaluation）。

### 6.2 一页决策 memo（8 项）

1. **问题与消费者**：谁、在什么时刻、要答什么/拒什么。
2. **链路范围**：9 件产物里哪些做、哪些不做（读/写、列/表/数据集、内部/外部）。
3. **5 组门槛现状**：过/未过/未测；`conditional` 的未过项写清。
4. **成本与收益假设**：建设/运行/维护/人审/失败五维；至少 3 个数（建模/打标/执行层）；公式见 §2.5，工作纸见 [TPL-9](./templates.md#tpl-9-成本工作纸)；收益写防泄漏/审计/效率/复用，哪些能货币化。
5. **缺口与风险**：object 泄漏、T9、写授权、规模、单价。
6. **选项**：build pilot / buy / do nothing；各自的代价与反事实。
7. **建议**：`go` / `conditional` / `no-go` / `not enough data`；一句话理由。
8. **止损线**：什么条件出现就停/回滚；谁有权停。

### 6.3 RACI 简版（工程建议）

| 决策/维护 | 拍板 | 给证据 | 维护 |
|---|---|---|---|
| 要不要做 | sponsor + 01 | 01 | — |
| 建什么（TBox/CQ） | 数据/本体 | A.1–A.5 | 数据/本体 |
| 查询路线 | 应用 | B.0 资产表 | 应用 |
| 标签 / 等级 | 治理/安全 | C.1 + 标准 | 治理 |
| policy / 测试 | 治理/安全 | C.2 + 测试 | 治理 |
| 执行层 / 探针 | 平台/安全 | C.3 + 差分 | 平台/安全 |
| audit / replay | 治理 + 平台 | C.4 + schema | 治理/平台 |
| 上线 / conditional | 负责人 | 5 组门槛 | 全员 |

> **没有 owner 的项 = 不能上线**；没有回滚 = 不能 enforce（借 02 rollout）。

## 7. 五个常见误判

| 误判 | 正确说法 |
|---|---|
| 「fixture 5 表跑通，说明 200 表也能跑」 | 200/5k 是本文假设的中型目录，不是 Glyph 参照（Glyph ~98k 表/3.4M 列，E-22），也不是本 fixture 的容量证明；规模未测 |
| 「`conditional` 就是失败」 | `conditional` 是未决项：可收窄试点，不是可上线，也不是永久标签 |
| 「2–4 人周就是报价」 | 是工程假设（`推测`；原 SFE-O 估算已移出），未绑定流程条数/团队规模；不是报价 |
| 「04 说这条路值得做」 | 04 只给链的产物/门槛/停；值不值得去 01 |
| 「一条 CQ 跑通就是有效果」 | 只证明这条链在该 fixture 上自洽；效果要自域对照/配对 |

## 8. 证据与边界

> 成本与工期是工程建议（`推测`）；04 没有做实验，也没有单价。

- **成本口径**：[02 cost](../../02-engineering-playbook/04-operations/03-cost.md)（五维、TCO、单价表空、缺项规则）；§2.5 公式；[TPL-9](./templates.md#tpl-9-成本工作纸) 工作纸。
- **上线节奏**：[02 rollout](../../02-engineering-playbook/04-operations/04-rollout.md)（shadow → advisory → enforce；回滚；RACI）。
- **go/no-go**：[02 evaluation](../../02-engineering-playbook/04-operations/02-evaluation.md)（go / no-go / not enough data）。
- **量级估算**：工程假设（`推测`；原 SFE-O 估算已移出，只作历史）；[representation mechanism](../../../topics/05-produce/representation/mechanism.md)（1–2 人周集成，`推测`）；policy 2–4 人日借 [02 cost](../../02-engineering-playbook/04-operations/03-cost.md) R9（commit gate 的 policy 部分，04 读路径按同类量级类比）。
- **条件项**：E-22（标签单企业）、E-23（读路径单实现/fail-open）、E-20（写授权无实现）。
- **不证明**：ROI、真数据误报率、延迟、规模、第二实现、严格 replay。
- **停**：没有单价/owner/第二实现，只出 `conditional` 清单，不出 `go`。
