# 边界与反例

> **一句话**：04 能证明「这条链在 fixture 上能跑」，不能证明「在你的域/规模/生产上有效」。能否落地看位置×成本（推测）；外部 signal 不作依据。
>
> 读者只需要记住三条：① 建没有域内评估；② 用没有头对头；③ 治是单企业+单实现。细节见下表。
>
> **另一个切法（README 移入）**：不证明效果（建/用/治各自单设置）、不证明跨域/规模（fixture 5/13）、不证明生产（无真实误报率/延迟/replay）。两套是同一件事的不同切法，不要当两组独立结论。

## 读者版三条

| 不能证明 | 一句话 | 什么会改变它 |
|---|---|---|
| 建的效果 | 没有 in-scope 建本体评估；只有 fixture 三关与 10 个坏样本 | 独立复现的建模基准 |
| 用的排序 | 三条路线各单设置、无头对头；98.33/89.9/64.6 不可比 | 同 KG/同题/同指标的头对头 |
| 治的通用性 | Glyph 单企业；trustgraph 单实现；对象方向无已测修法 | 第二实现 + 领域策略来源 |

## 十七条边界

| 边界 | 影响段 | 什么会改变它 |
|---|---|---|
| 建无 in-scope 评估，只到候选+人审 | 建 | 独立复现的建模基准 |
| checker 的 catch/FA 同源，precision 随错答案基率变 | 建 | 换基率仍成立 |
| 薄层优先：单工厂、9 任务、答案在文本 | 建 | 跨域、深结构 |
| 三路线各单设置、无头对头；Match 允 superset | 用 | 跨域对照 |
| execution accuracy ≠ 业务正确；空结果不分因 | 用 | 自域配对 |
| OBDA 是本体+映射→SQL，不是 NL→SPARQL | 用 | 同查询集对比 |
| 三层不可互推：标签有、策略语义有但领域映射无、执行单实现 | 治 | 领域策略来源、第二实现 |
| 读路径过滤≠写授权；fail-open、只删 subject；sparql-guard 不够第二实现，Jena 已退役 | 治 | object 受控且 fail-closed、合格第二实现 |
| 策略 11 条里 T9 无唯一期望；`clearance` 未消费；`skip` 是第 4 种效果 | 治 | 补优先级声明、消费 clearance |
| 可消费性 10 个坏样本只稳定抓住 2 个；`violations=2` ≠ 干净 | 建 | 契约 schema、target 必填、跨 validator |
| 失败跨段传播（推测）：单点准确率看不见 | 治 | 端到端注入实验 |
| 成本/组织无实测，厂商 token 说法只是 signal | 全 | 你的单价数据 |
| CQ3 是 dataset 级治理查询，用 R8；analyst 不适用；没有 subject 的聚合不在列策略内 | 治 | 查询级 guard / 数据集策略 |
| `skip` 是未判定，不是安全声明；执行层可返回或 withhold；leak 断言敏感 object 不出现 | 治 | 执行层双向过滤 |
| 策略语义只到 T9 未定；R7 是 fallback；`clearance` 未消费 | 治 | 补优先级声明、消费 clearance |

| 版本 replay 不严格：snapshot 是日期标签，tag/contract 是 fixture 约定，parser 未记 | 治 | 内容 hash + parser 版本 |


## 反模式

1. 先建整座本体再找消费者：无 CQ/负例，无法验收。
2. LLM 生成的类/公理直接当结论；读路径过滤当写授权。
3. 只做输入侧约束（闸门），不做输出校验：输入 gate 只在单 benchmark 上部分改善。


## 未测与缺口

四处仍是未测：① 输出校验只有六类骨架，生产误报与 `targeted=0` 未测；② 端到端访问控制缺领域策略来源与合格第二实现；③ 失败传播无跨段注入实验（工作流归因只到流派）；④ 可消费性只到 fixture 三关，没有真数据/跨域。04 给接口、测试与停，不给效果；成本/工期见 [decision](./decision.md)（量级，不是报价）。
