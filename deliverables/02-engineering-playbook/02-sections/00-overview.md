# 0. 工程摘要：案例、主线与判断

> 本页是 02 的正文第 0 章。索引与阅读顺序见 [README](../README.md)；配方总表见 [03-recipes/README.md](../03-recipes/README.md)。

## 0.1 案例：一次参数写回

某产线的一次参数写回：agent 读到 `P-101 = 0.42`，但没看到单位是 **bar**，按 **MPa** 写回；下游按 MPa 执行。错误不可逆、会扩散。问题不在「模型不够强」，而在名字/单位没对齐、写路径没有授权。（示意，不是真实事故；单位/别名失败见 E-12 的 K1 实验）

这类失败决定了 02 的顺序：先问**错可逆吗？会扩散吗？判定所需事实拿得到吗？** 再选配方，而不是先建本体。

## 0.2 主线

**先定错 → 过 R0 → 选一个位置 → 选形态 → 定尺子 → 做完一份产物包。** R1–R12 是这条线上的分支，不是并列目录。

今天能直接走的是 R1（点位语义）、R2（投影）、R3（编译）、R7（记忆）、R8（读路径）、R10/R11（离线/OBDA）；R9（落盘授权）只有设计。**R4/R5/R6/R12 的原锚已撤回，先标 gap，不要拿旧配方上线**（W 表见 [91-canonical §1.1](./91-canonical.md#w-table)）。

<a id="1-三条判断"></a>
## 0.3 三条判断

1. **点位语义是最大单层增益。** 原始点位→点位语义 +54.6pp；知识投影文本只再加 +19.8pp（E-12；单工厂、9 任务、答案基本写在文本里）。先做点位语义，不要先建塔。
2. **R0 是准入，不是效果证明。** 名字/单位、声明、覆盖、执行落点四项检查不过，后面的配方都是沙上；过了也只证明「值得进下一轮」。
3. **约束/判定配方今天不能承诺。** R4/R5/R6 的原锚已撤回；旧格数/改善数、catch/FA、T1-only 都不再用。R9（落盘授权）仍只有设计、没有实现（E-20）。

## 0.4 一页结论

**这份交付物只回答「怎么做」，不回答「做了有没有用」。**

> **计数：A=3（R1/R10/R11）/ B=4（R2/R3/R7/R8）/ C=1（R9）/ gap=4（R4/R5/R6/R12，不含 R0）。**

1. **先做准入体检（R0）**：四项检查不过，后面的配方都是沙上。
2. **只选一条主配方**：按错误类型选 R1–R12；先 shadow，不要同时上三个。
3. **每条配方十字段**：目标与适用 / 前提 / 接缝与形态 / 数据契约 / 步骤 / 证据 / 成本 / 验收与 stop / 失效模式 / 可抄锚点；填不满的字段就是上游任务。
4. **证据只到 E-xx**：recipe 是工程配方，不是新结论；效应量仍看 E-xx 的限定。
5. **做完长什么样**：一份填好的 R2/R3 或 R8 产物包；[附录 D 产物包](../05-appendices/04-artifact-pack.md) 的 R4 包只作字段模板（E-03 已撤回，不是验收依据）。
6. **如果只做一件事**：准入体检（R0）+ 账本 + 名字/单位（K1）；不要先建整座塔。

<a id="6-如果只做一件事"></a>
## 0.5 第一个动作

- 先过 R0：名字/单位、声明、覆盖、执行落点；任何一项 `unknown` 都不当 pass。
- 建账本：per-query / per-decision 的 token、时延、审批、回滚；没有它，false-veto 与成本都算不出。
- 只选一条 recipe 做 shadow；不要同时上三条，也不要把 gap 行当试点。
