# 02 · engineering-playbook — SCOPE（定位契约）

> **改/建本交付物前必读。** 本页是 02 定位的唯一权威；四份的总索引与共用规矩见 [meta/deliverable-scope](../../meta/deliverables/scope.md)。

## 初心（为什么有这份）
让工程负责人照着把本体接进 harness，知道接口 / 步骤 / 验收 / 停线，不靠"行业通常"补位。

## 定性
**做法**（规定性 recipe）。回答"怎么做"，不回答"做了有没有用"。

## 回答的问题（一句话）
拿本体做某件事，具体怎么做？

## 读者拿到什么
R0–R12 可照做的配方：数据契约 / 步骤 / 验收 / stop / 成本量级。

## in-scope（该干的）
配方、接口、数据契约、验收 / 停线、成本量级、账本 / 评测 / 上线。

## out-of-scope（不该干的，去哪）
- 值不值得 → 01；为什么是这些位置 → 03；业界落地现状 → 10。

## 红线（绝不能）
- recipe 不是 E、不证明"做了有效"；效应量回 E-xx。
- gap 配方（R4/R5/R6/R12）不冒充可上线。
- 填不满的字段是上游任务，不用"行业通常"补。

## 发挥空间（scope 内你可以）
把 admitted 证据组织成可照做的步骤 / 接口 / 验收；可以写工程建议（标 `推测`）。**不能编效应量、不能把 gap 写成可落地。**

## 答不了怎么办
admitted 证据答不了 → 标 gap + frontier 写"关闭它需要什么"；**禁止偷换成更容易的问题**。
