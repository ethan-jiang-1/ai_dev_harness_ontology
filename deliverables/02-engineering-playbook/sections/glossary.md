# 术语与内码速查（02）

> 第一次读 02 先看这一页。这里只解释「读 02 会用到的词与码」；完整术语见仓库根 [GLOSSARY](../../../GLOSSARY.md)。
>
> `E-xx` = 跨派结论（证据），不是 recipe；`F/G` = 派内 finding/gap 编号（不是 E）；见 [conclusions](../../../topics/conclusions.md)。
>
> **术语基线**：ADR 0011 / 2026-11；K0–K4 标 `local`（论文条件，非 normative 源）。
>
> 内码：`R0–R12` = recipe；`K0–K2` = N&D 实验条件（非标准）；`O-xx` = 对象地址（公式/代码/表）；`T1–T5` = 逆关系类型；`p_h`/`p_min` = 命中率与盈亏平衡；`FA` = false alarm；`CMR` = 跨期匹配率。

## 1. 两个总开关

| 词 | 一句话 | 在哪 |
|---|---|---|
| **接缝（seam）** | 本体在回路的哪个时刻介入：供给 / 输出时 / 输出后 / 动作前 / 跨轮 / 落盘前 / 检索返回前 | [03 §2.2.1](../../03-mechanism-reference/sections/map.md#221-位置--时刻--派--部件--形态) |
| **形态（execution form）** | 机器拿本体做了什么：`context`（进上下文）/ `compiled`（编译成约束/查询）/ `engine`（引擎执行）/ `label`（打标）/ `none`（不执行） | [map §2.4](./map.md#24-选形态五种别把-context-当低配-engine) |

> **不要把 `context` 当 `engine` 的低配。** 供给是「给什么」，engine 是「执行什么」；前者不拦动作。

## 2. 知识条件（K）

| 码 | 含义 | 判据 |
|---|---|---|
| **K0** | 原始点位：PLC 地址 + 原始整数 | 没有 tag 名；不要叫「地址级标签」 |
| **K1** | 点位语义：tag 名 + 单位 + 质量码；工程上常再加别名/槽位（扩展） | 同一实体在不同表能对上；单位统一；别把扩展当成论文测到的 |
| **K2** | 知识投影文本：从塔投影出的文本，**不含推导量** | 有节模板/字符数预算/维护成本是工程建议，不是论文的 K2 定义 |

> K1 是「先对齐 tag 名/单位/质量码」，K2 是「再把知识写成文本」。**先 K1 再 K2**；K1 不过，投影只会放大错误。
>
> K0–K4 是 N&D 单篇论文的实验条件，不是行业标准；02 常把 K1 写成「tag 名/单位/质量码 + 别名/槽位」，其中**别名/槽位是工程扩展**。完整来源、K3/K4 与「论文 vs 工程」的差异见 [01 的 K0–K4 来源](../../01-capability-status/sections/k-ladder.md)。

## 3. Recipe（R0–R12）

| 码 | 一句话 | 接缝/形态 |
|---|---|---|
| **R0** | 先证明本体能被执行：名字/单位、声明、覆盖、落点 | 准入 |
| **R1** | 先对齐 tag 名/单位/质量码（可加别名/槽位）；K1 够就停 | 供给 / context |
| **R2** | 知识投影文本；固定分节是工程建议；先 K1 再投影 | 供给 / context |
| **R3** | 只买 claim + 逐字 span；先算 `p_min` | 供给 / compiled |
| **R4** | 输出带观察与 grounding；等级要校准 | 输出时 / compiled |
| **R5** | 先超过空结果重试；catch/FA 分开 | 输出后 / compiled |
| **R6** | 只在不可逆/高代价/弱模型时试；先 shadow | 动作前 / compiled |
| **R7** | 先 registry，再状态；CMR 与 precision 同看 | 跨轮 / compiled |
| **R8** | 只做可见性，不当授权；单实现/fail-open 未修 | read-path / engine |
| **R9** | 只能设计，不能声称落地 | 落盘前 / 无实现 |
| **R10** | 离线/CI SHACL；三态不可折叠 | 离线/CI / compiled |
| **R11** | 查询时编译；不是闸/判定器 | supply / engine |
| **R12** | 证据 + solver + 人签核；不是准确率项目 | 供给+输出+人 |

## 4. 数字与指标

| 词 | 含义 | 坑 |
|---|---|---|
| `p_h` | 命中率：回答所需证据在上下文里的比例 | 不是「检索到没有」 |
| `p_min` | 编译的盈亏平衡命中率：`2% + c/(0.929Q)` | 自己的 `c`/`Q` 没量就不能套 |
| `φ` | R6 的可逆性分数（0–1）；整条序列取 min φ | 不是 accepted query 答错率 |
| `err_rate` | accepted query 中答错的比例（false-accept） | 不是 `p_h`；p_h 是放行率 |
| `FA` | false alarm：checker 把对的判错的比例 | 与 catch 分开报，不能只报净修复 |
| `HSR` | harm success rate：有害轨迹比例 | 不是 task success；CASEL 的主指标 |
| **false-veto** | 本可合法执行、却被闸拦掉的比例 | 没有 blocked 的 harm/授权标签就写 `unknown` |
| **false-defer** | 本可直接执行、却被转人工/审批的比例 | 与 false-veto 不同：一个是拦，一个是拖 |
| `CMR` | 跨期匹配率：同一实体跨会话能否对上 | 与 `Acc@complete` 不是一回事 |
| `Acc@complete` | 完整答案准确率 | 别和检索命中率混 |
| **curated / data-derived** | checker 的两种来源：人工整理 vs 从数据派生 | 两者 catch/FA 不可直接比 |
| **shadow** | 只记录、不拦截的试运行 | 不是「已经上线」 |

> 阈值统一在 [canonical](./canonical.md)；本页只解释词，不重复数。

## 5. 对象地址（O）

`O-xx` 是「这个数/公式/代码在哪」的地址，不是结论。

| 码 | 指向 |
|---|---|
| `O-T01`–`O-T13` | 13 行停线表对应的数/公式（[acceptance](./acceptance.md#51-验收与-stop按机制选尺)） |
| `O-F01` | 编译盈亏平衡公式（`p_min`） |
| `O-C01`–`O-C15` | 代码锚（trustgraph / semantica / ontop / open-ontologies / OPA） |

> 规则：O 只回答「在哪」，主句仍落 `E-xx`（[ADR 0009](../../../adr/0009-object-layer.md)）。

## 6. 证据等级

| 词 | 含义 | 用法 |
|---|---|---|
| **已核** | 一手原文/代码核对过 | 可以写「已测」 |
| **推测** | 从一手材料推的，或工程估算 | 必须带「推测」 |
| **工程建议** | 我们的口味/经验，不是论文结论 | 不能当「已验证」 |
| **untested** | 没跑/没量 | 不能写成「通过」 |
| **gap** | 缺数据/缺来源 | 不进验收，只作方向 |

> 这张表是 02 的「诚实开关」：`工程建议` 与 `untested` 不许伪装成 `已核`。

## 7. 常见误读

| 误读 | 实际 |
|---|---|
| 「有引擎 = 会拦」 | 执行 ≠ 健全 ≠ 授权（E-20） |
| 「检索到 = 有证据」 | 检索到还要看是否支持结论 |
| 「平均 −38% = 都能省」 | 是 −91% 与 +1.9% 的混合（R3） |
| 「R4 有引用率 = 引用对」 | 只测有没有，不测对不对 |
| 「R6 的 5% 是停线」 | 不设单点；报 miss–false-block 前沿 |
