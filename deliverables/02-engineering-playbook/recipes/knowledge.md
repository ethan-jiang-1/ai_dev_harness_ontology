# R1–R3 · 知识供给：先 K1，再决定要不要投影/编译

> 三条 recipe 都发生在「供给」层：本体不改变走向，只改变模型看到什么。它们回答的是**知道得对/省预算**，不是「拦住错」。
>
> 顺序不是并列：**R1 是地基；R2/R3 是两种不同的加法**。R1 没做，R2 的投影会把错单位抄得更权威；R3 的编译只省 token，不修正内容。

## 0. 先选哪一条

| 你的问题 | 先做 | 不要先做 |
|---|---|---|
| 模型答错是因为叫错名字、用错单位、槽位对不上 | R1 | R2/R3 |
| 领域知识是封闭的、像操作手册，模型「不知道」而不是「查不到」 | R1 → R2 | R3 |
| 语料大、重复检索多、token 是硬成本，准确率不是主诉求 | R3（先量 `p_h`） | R2 |
| 答案在法规/标准里，需要引用与人签核 | R1 → R3 的受监管支线 → [R12](regulated.md) | 只做 R2 |
| 你只有一个 taxonomy/ERD | R1 + R5 data-derived | R2/R9 |

## R1 · K1 语义层：先把名字和单位对齐

### 目标

用最低成本拿到已测最大的一层知识增益；在决定要不要建塔/投影之前，先证明「薄语义层」够不够。


> **为什么（机制）**：K0 是 PLC 地址+原始整数；K1 补 tag 名/单位/质量标志；primary trap 是单位/别名/槽位对不上；K1 把失败从查找/换算降成阅读理解。

### 适用 / 不适用

| 适用 | 不适用 |
|---|---|
| 有历史误判、值班记录、工单，能抽出 3 个代表性任务 | 没有任何任务样本，只有「本体文件」 |
| 命名/单位/别名是主要歧义源 | 答案需要物理推导/多跳检索，命名不是瓶颈 |
| 愿意用同一模型做 K0/K1 回放 | 不能固定模型/提示/评分口径 |

### 前提

- 能拿到 3 个任务的 ground truth 与 primary trap 标注。
- 能固定同一模型、同一提示框架、同一评分 rubric。
- 有 tag/单位/别名的权威来源（设备台账、字段字典、SOP）。

### 接缝 / 形态

供给 / `context`。这里的「执行」是**上下文供给**，不是约束；不要把它当闸门。

### 最小数据契约

```text
tag_registry: {label, unit, quality_flag, aliases[], source}
slot_map:     {entity_type, slot, unit}
task_card:    {task_id, question, ground_truth_elements[], primary_trap, rubric_version}
run_record:   {task_id, arm: K0|K1, model, prompt_version, answer, trap_hit, element_score, tokens}
```

### 做法（2 周内）

1. **选 3 个任务**：2 个读数解释 + 1 个事故诊断（或你域里的等价组合）；每个任务标一个 primary trap。
2. **建 K0 基线**：地址级标签、原始单位、原始别名；同一模型回放。
3. **做 K1**：统一 tag 名、单位、别名；补换算；不改结构、不加推理规则。
4. **回放 K1**：同一模型、同一提示、同一 rubric；报 primary-trap avoidance 与 element score，分开报。
5. **算差值**：K1−K0 的 primary-trap avoidance；若剩余 trap 与深知识无关，停在 K1，不建塔。

### 证据

- K0→K1 避坑率 **+54.6pp**；这是 N&D 已测各层里最大的一层（E-12）。
- 条件：**单工厂、9 任务、答案基本写在文本里**；换域要重测。
- 9B 带投影 0.737 > 750B 不带 0.672，但区间约 0.3 宽，不能当普遍规律（E-12）。

### 成本

| 项 | 量级 | 等级 |
|---|---|---|
| 3 任务标注 + rubric | 1–2 人日 | 推测 |
| tag/单位/别名审计 | 2–5 人日/域（按实体数伸缩） | 推测 |
| 回放（3 任务 × 2 臂 × 模型） | 1–2 人日 + 推理成本 | 推测 |
| 维护 | 0.5 人日/月 | 推测 |

### 验收 / 停

| 指标 | 通过线（工程建议） | 停 |
|---|---|---|
| primary-trap avoidance | 3 任务 ≥ 0.90 | 仍 <0.90 且 trap 与深知识无关 → 先修 K1，不建塔 |
| 剩余 trap | 不由命名/单位/别名造成 | 仍由它们造成 → 继续 K1 |
| 跨模型 | 至少 2 个模型同向 | 单模型反转 → 先别推广 |

**不要**用 element score 总分掩盖 trap 没动；R1 的验收是 trap，不是平均分。

### 失效模式

- **K1 被当成「改 prompt」。** 它是数据契约变更：tag/单位/别名要有唯一来源与版本。
- **单位换算只做一半。** 同一量在不同系统有不同单位，换错比不换更危险。
- **别名写成自由文本。** 别名要能回指 canonical tag，否则无法审计。
- **单工厂结论外推。** E-12 是单 plant；跨域先重测。

### 可抄锚点

- [projection 机制](../../../topics/03-knowledge/projection/mechanism.md) 的「关键数字」「实施决策 1」「数据/接口」。
- N&D 的任务构造法、primary-trap 标注、judge κ 记录方式；不要抄它的 45k 投影规模。

## R2 · 知识投影：把领域知识写成固定分节的文本

### 目标

让模型在**封闭域、操作手册型知识**上「知道得对」，而不是「查得到」；把归纳工作提前到入库时，而不是让 agent 查询时自己归纳。

> **为什么（机制）**：投影把 45k 字符描述记录写成固定分节文本；不含 16 个推导量；顺序是有效成分；增益小于 K1，因为 K1 先解决了最硬的歧义。

### 适用 / 不适用

| 适用 | 不适用 |
|---|---|
| 领域知识窄而深、答案基本写在文本里 | 答案主要靠开放检索/多跳推理 |
| 有稳定的描述记录（tag/binding/assumption/derivation/knowledge） | 没有 curator，投影无法维护 |
| 模型上下文能放下约 45k 字符 | 上下文预算紧、时延敏感 |
| 需要可追溯的陈述→节点映射 | 需要形式保证/拒绝逻辑（那是 R5/R6） |

### 前提

- 先做 R1；K1 不够再投影。
- 有本体/描述记录的稳定版本；能自动生成，不靠手工排版。
- 有一个能回放的 9 任务集（5 读数 + 4 诊断，或域内等价）。

### 接缝 / 形态

供给 / `context`。投影是**知识供给**，不承担拒绝逻辑；硬约束另进 R5/R6。

### 最小数据契约

**投影头（必填）**：

```text
{system_id, tower_version, projection_version, generated_at,
 covered_sections, projection_chars, rubric_version}
```

**投影体（固定分节顺序）**：

1. 头部
2. 设备/流程概览
3. tags/bindings（按 level 排序，同级按名字）
4. assumptions（按影响面）
5. derivations（按 level）
6. knowledge nodes（日期倒序）
7. 安全边界（仅提示；拒绝逻辑在代码里）

每条陈述末尾带 `[node_id]`；另出 `statement_id → node_id` 映射表（与投影同版本）。

**写接口（独立安全层，不是投影功能）**：

```text
propose_setpoint(tag, value, reason, actor, idempotency_key)
  → {accepted|rejected, checks[], readback}
```

检查顺序：tag 在允许列表 → 值在范围 → 最近无人工写入 → plant guard（绝对限、步长、每小时/累计变化、等待时间）；通过才写，写后读回并记录，拒绝也记录。投影里可写允许列表/限值作提示，但**拒绝逻辑必须在代码里**。

### 做法

1. 先做 R1；用 3 任务判断 K1 是否够。K1 已解决 primary trap → 停，不建塔。
2. 从描述记录生成投影；**冻结分节顺序**。顺序变更按行为变更处理（打乱句序 0.777→0.685）。
3. 本体/投影/知识节点同步；tag/单位/假设/推导任一变更 → 重生成 + 递增 `projection_version`。
4. 运行教训在抽取时并入 knowledge node，不要让 agent 查询时自己查日志（日志检索 4/80 次被调用）。
5. 投影只做供给；写路径另做安全层，不要把「投影里写了规则」当约束。

### 证据

- K1→K2 避坑率 **0.605→0.802（+19.8pp，95% CI +3.0~+38.4）**；element score **0.566→0.777**；OR 5.45（E-12）。
- 四种形态 pooled：文本 0.777 > JSON 0.717 > 查询 0.638 > 检索 0.597；但排序非普适：GLM-5.2 的 JSON 0.900 > 文本 0.891；Qwen 工具 0.407 < 文档 0.538。
- 打乱句序 0.777→0.685；顺序本身是有效成分。
- 9B 带投影 0.737 > 750B 不带 0.672；区间约 0.3 宽。
- 条件：单工厂、9 任务、答案基本写在文本里；**不能外推**到开放域/多设备。

### 成本

| 项 | 量级 | 等级 |
|---|---|---|
| 建塔（162 节点） | 2–4 人周；按 `(节点数/162)^0.7` 伸缩 | 推测 |
| 投影生成器 | 2–3 人日 + 0.5 人日/额外 10k 字符 | 推测 |
| curator 维护 | 0.5–1 人日/月 | 推测 |
| 运行 | 约 1.1–1.5 万 token/轮（45k 字符粗估） | 推测 |
| 评测 | 1–2 人周 + GPU | 推测 |

### 验收 / 停

| 指标 | 通过线（工程建议） | 停 |
|---|---|---|
| K2−K1 primary-trap | ≥ +5pp | <5pp → 停，只交付 K1 |
| 投影字符数 | ≤ 60k | >60k 或遵守率下降 → 拆域/转工具，不截断 |
| 维护 | ≤ 2 人周/月 | 超过 → 冻结为静态投影或回文档检索 |
| 映射覆盖 | 100% 陈述可回指 node_id（抽 10 条） | 不能 → 不发布 |
| 工具调用率 | ≥20% 才把审计寄托在工具上 | <20% → 用 statement→node_id 映射做审计 |

### 失效模式

- **投影即答案，基准偏慷慨。** 任务答案写在投影里，测的是「抄得准不准」（E-12 的条件）。
- **投影体积失控。** 45k 已接近中型上下文；多系统/多年日志更大。
- **投影丢掉约束关系。** 只有概念/属性、没有「A 成立则 B 不成立」，等于给知识没给规则。
- **投影与本体不同步。** 本体改了、投影没重生成，模型学到旧规则。
- **投影不可追溯。** 文本陈述不能指回来源；靠 `statement→node_id` 映射补。
- **把投影当约束。** 25/61 条到达命令被拒；投影写了规则仍可能被忽略（N&D；prompt-vs-code 对照未做，`推测`）。
- **工具路线更便宜但未测。** N&D 没有成本对照；「更便宜」只是可能性。

### 可抄锚点

- [projection 机制](../../../topics/03-knowledge/projection/mechanism.md) 的「数据/接口」「组织/成本」「stop」「第一个 sprint」。
- N&D 的固定分节顺序、`statement→node_id`、写接口检查顺序；不要抄「文本一定优于 JSON」的排序。

## R3 · 证据编译：只买 claim + 逐字 span

### 目标

在**重复检索多、语料大、token 是硬成本**的场景，把「读整段」换成「读 claim + 逐字 span」；不承诺准确率提升。


> **为什么（机制）**：claim+span 把整段阅读换成叶子；证据充分时只读叶子，不充分时要回退检索；所以平均是混合，不是无条件省。
### 适用 / 不适用

| 适用 | 不适用 |
|---|---|
| 语料大、查询重复、token/预算是硬约束 | 一次性任务、复用次数低 |
| 证据充分率 `p_h` 高于 `p_min` | `p_h < p_min`；或 p95 时延是硬约束 |
| 有稳定文档源、能保留 offset/版本 | 表格/扫描/行话导致 span 抽不出 |
| 能接受用检索轮次换 token | 要求「省 token 且不加时延」 |

### 前提

- 同一语料、同一 harness 的能量基线（准确率、token/问、p95、轮次）。
- 能算 `c`（编译总 token ÷ 平均每问 token = query-equivalent）与 `Q`（查询量）。
- 有原词法检索器可保留；树只做 carrier，不做 router。

### 接缝 / 形态

供给 / `compiled`。编译发生在检索前；它改变「给什么」，不直接拦模型动作。

### 最小数据契约

```text
claim_index: {claim_id, text, span_start, span_end, chunk_id,
              source_version, extractor_version, acl}
tool_policy: {tool: off | compiled-only | compiled-first}
eval_table:  {query_id, arm, hit/miss, token_in/out, latency, rounds,
              gate_verdict, citations}
```

**claim–leaf = 主张 + 逐字证据 span 的叶子节点**；不是摘要，也不是整段 chunk。

### 做法

1. **先跑基线**：同语料、同 harness 的准确率、token/问、p95、轮次；不可比就写明不可比。
2. **compiler v0**：只抽 claim + span；span 对不上就丢，不让模型修。
3. **保留原词法检索器**；树只做 carrier；默认 E2 substitution + raw chunk fallback。
4. **量 `p_h`、miss penalty、`c`、`Q`**；算 `p_min = 2% + c/(0.929Q)`。
5. **A/B 分桶**：按 collection hash 分桶；主指标预登记；报 hit/miss 分布，不报平均 −38%。

### 证据

- 证据充分时查询 token **−91%**；不充分时 **+1.9%**；平均 **−38%**（E-08）。
- 准确率 neutral；PageIndex 在 FRAMES 规模实测为负；不要写成 neutral（E-08）。
- 盈亏平衡：无限视野 `p_h > 2%`；有限视野 `p_min = 2% + c/(0.929Q)`（E-14）。
- 证据替换用检索轮次换 token；配对子集时延约 **3×**（仅 7 题，E-14）。
- 平均 −38% 是 −91% 与 +1.9% 的混合，**不能当上线依据**。

### 成本

| 项 | 量级 | 等级 |
|---|---|---|
| parse+chunk+enrich+validate+register | 约 20 人日（2 人 × 2 周） | 推测 |
| 评测表/分桶/计算器 | 约 5 人日 | 推测 |
| φ 审计 | 100 条约 0.5–1 人日；400 条约 2–4 人日 | 推测 |
| 运行 | 论文无金额；按 token 与相对时延折算 | 已核（相对） |

### 验收 / 停

| 门 | 通过 | 停 |
|---|---|---|
| `p_h` | ≥ `p_min`（用自有 `c`、`Q`） | `p_h < p_min` → 停，转 harness 侧：收紧读预算、改停策略、缓存、并行检索 |
| p95 | 不超预算 | 超预算 → 只在 token 是硬成本的小片流量灰度 |
| span 覆盖 | ≥50%（工程门） | <50% → 不买 |
| 准确率 | 不下降 | 下降 → 停 |
| 时延 | 可接受 | 3× 不可接受 → 不买 E2 的 token 节省 |

**φ（false-accept）**：`p_h` 只说放行多少，不说放对没有；必须另抽 100–400 条 accepted query 人工审计，报区间（E-14；工程门）。

### 失效模式

- **平均掩盖两端。** −38% 是混合；先量自己的 `p_h` 与 miss。
- **省 token 换时延。** 3× 只在 7 题配对观测，不是 p95；交互式 agent 可能不可接受。
- **接受率当正确率。** `p_h` 不是 φ。
- **编译产物被当事实。** span 有误差，进入后续对话后不再被质疑。
- **树被当检索器。** 树是 carrier；路由用树会多一跳且可能带偏。
- **部署价值被当已证。** CAI Table 2 部署 ledger 无一行达标；引用时标「作者主张，未量化」。

### 可抄锚点

- [compilation 机制](../../../topics/03-knowledge/compilation/mechanism.md) 的「机制一/二」「数据/接口」「stop」「第一个 sprint」。
- CAI 的 parse→chunk→enrich→validate→assemble→register；只抄流程，不抄规模。
- 受监管语料不要共用这条预算；走 [R12](regulated.md)。

## 三条的共用反模式

1. **用平均收益立项。** R1 的 +54.6pp、R3 的 −38% 都是条件值；先量自己的基线。
2. **把 context 当约束。** R1/R2 不改变走向；硬约束另进 R5/R6。
3. **跳过 R1 直接建塔。** K1 是已测最大的一层；塔只再加 +19.8pp（单工厂）。
4. **把「结构化」当「本体专属」。** E-01 的 ontology 是 `not measured`；E-08/E-12 是工件/供给证据。
5. **不记版本。** 投影/编译/知识节点不同步，模型会学到旧规则。
