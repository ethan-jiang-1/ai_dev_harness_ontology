# 领域适配：同一机制，换域先换约束

> **证据重置**：E-02/E-03/E-04/E-13 等原锚已撤回（W 表见 [canonical §1.1](../sections/canonical.md#w-table)）；本页保留机制与换域约束，数值按 W 协议重测。


> 领域不是案例集，是**对机制的额外约束**。同一份 recipe 换域，阈值、覆盖率、标签、审批都变；不能把单域数字当跨域常数。

## 1. 五个域，五种「不能错」

| 域 | 决定性约束 | 主要 R | 代表证据 | 换域先改什么 |
|---|---|---|---|---|
| 工业设备 | 知识窄而深，参数来源必须可追 | R0/R1/R2/R5 | N&D：K1 +54.6pp、K2 +19.8pp；单 plant | tag/单位/别名；投影字符上限；primary trap |
| 电网规划 | 法规/标准硬约束，数字必须由 solver 算 | R12/R3/R10 | Grid 移出（W-05）：只留「证据+solver+人签核」架构 | citation/拒答阈值；solver 版本；人签核 SLA |
| 金融投研 | 实体跨期身份漂移，来源/时效必须保留 | R7/R9 | FIRME：CMR +7.8–12.1pp、merge precision 85.6–97.5% | 匹配阈值 0.8；五态；alias 回滚；周期口径 |
| 医学诊断 | 缺证据要追问，推理可审计 | R4/R5/R6（均 gap） | OA-RAG 移出（W-02）；只留机制读法 | 检索率门槛；grounding 校准；追问上限 |
| 生物医学/农业 KG | 资源描述缺失，术语与自然语言不匹配 | R0/R1/R5 | OntoDoc：completeness 3.43→3.84；无下游 | 术语表；描述补全；不要自动生成后直接执行 |

## 2. 工业设备

**不能错**：参数单位/来源/工况；误设点可能造成物理后果。

**怎么做**：

- 先 R0 检查 tag/单位/别名、参数 source/condition、约束是否有 SHACL 落点。
- R1 用 3 个任务（2 读数 + 1 诊断）测 primary trap；K1 够就停。
- R2 投影固定分节；不把投影当安全边界；写路径另做 R6。
- R5 只查结构/声明；语义错用人工/ judge，先测净修复。

**不要**：把 45k 字符/9 任务的 +19.8pp 外推到多设备；把投影里的限值当拒绝逻辑。

## 3. 电网规划/受监管工程

**不能错**：法规引用、solver 数字、人签核；错了是合规/责任问题。

**怎么做**：

- 先立三原则：证据先行、solver 算数字、人决策（R12）。
- citation 必须带 `{doc_id, version, page, span, clause_id}`；不能引用就拒答。
- study 工具记录 `state_hash`/`solver_version`；strict pass 重放。
- 人签核是架构一部分；未签核不继续。
- 不要用 LLM 手算替代 solver；不要承诺形式安全保证。

**数字边界（Grid 移出后，只作定性）**：相对最强 agent baseline 的增益可能很小；工具多数时候没被调用；benchmark 规模有限。换域必须按 W-05 重测。

## 4. 金融投研/CRM

**不能错**：同一客户/产品跨源跨期身份；false merge 会长期污染。

**怎么做**：

- 先 R7：registry + alias + 五态；CMR 与 merge precision 同看。
- merge/split 写侧走 R9（设计）；`UNVERIFIED` 只进推理。
- 阈值 0.8 按域重标；alias 回滚预案先演练。
- 补任务级指标（引用正确率/调研工时），不要只报 CMR。

**不要**：单看 CMR；把未匹配当关系结束；一次 false merge 后不回溯。

## 5. 医学诊断/问答

**不能错**：证据不足要追问；推理链可审计；不能把模型自评当保证。

**怎么做**：

- 先 R0 检查本体覆盖/未知 IRI；检索率 <50% 先修检索。
- R4 的 grounding 必须独立校准；没有标注只做提示。
- R5 先超过空结果重试；语义错用 judge/人工，先测净修复。
- 多 agent 诊断的 curated KG 覆盖会封顶：本体没有的诊断恒 0；先扩覆盖，再谈排序。

**不要**：把已移出的医学 benchmark 当临床验证；把多 agent 的聚合增益当个案改善（W-02）。

## 6. 生物医学/农业 KG

**不能错**：术语与自然语言不匹配；资源描述缺失；生成物不能直接执行。

**怎么做**：

- 先 R0：术语表、描述完整性、约束落点。
- R1 做术语/单位对齐；R5 用 data-derived 低 FA 检查。
- 生成/精化（OntoDoc/CASTON）只当候选；没有下游可消费性证据，不直接进执行路径。
- 需要数值/外部服务时，把边界外置、不塞进 OWL（工程经验；原 SFE-O 已移出，只作历史）。

**不要**：把「文档变好」当「可执行」；把生成物直接当权威本体。

## 7. 跨域的共同点

- 本体的作用是把**少数不能错的判断**钉住，不是把知识铺满。
- 落点都少，但一旦触发不可绕过；这正是强度–覆盖率反向的经验形态。
- 每个域都要重标：阈值、覆盖率、审批率、标签口径。
- 没有跨域对照；任何「跨域有效」都是 `推测`。

## 8. 换域检查表

1. 这个域「不能错」的是什么？对应哪个 R？
2. 现有证据是单域/单基准吗？哪些阈值不能搬？
3. 标签/审批/责任谁提供？没有的话，是否只能 shadow？
4. 本体覆盖/术语/单位够吗？先 R0。
5. 失败代价是否可逆？不可逆 → R6/R9，不要只做 R4/R5。
