# 成本与立项：先算分母，再谈收益

> **证据重置**：E-03/E-04/E-13 等来源已撤回/移出（W 表见 [canonical §1.1](../sections/canonical.md#w-table)）；这些机制的**成本项仍可算**（人日/调用/审批分钟），只是效应量不再引用。


> 本页不给单价。单价是业务输入，不是研究结论；填不出来时只给公式与敏感性，不给 build/buy 结论。

## 1. 五个成本维度

| 维度 | 问什么 | 常见漏算 |
|---|---|---|
| 建设 | 一次性投入多少？谁维护？ | 本体/投影/registry 的人工建模 |
| 运行 | 每次查询/动作多少 token、时延、调用？ | 检索轮次、审批、重试 |
| 维护 | 源/工具/法规变更后怎么更新？ | 增量重抽、版本对账、回归测试 |
| 人审 | 多少比例需要人看？看的成本？ | 审批疲劳、false alarm 的信任损失 |
| 失败 | 机制失效时的代价？ | false-veto、错误合并、漏检 |

**不要只算 token。** 投影/记忆/护栏的主要成本常在人审与维护，不在推理。

## 2. 三个可算的盈亏平衡

### 2.1 编译

```text
p_h > 2% + c / (0.929 Q)
```

- `c` = 编译总 token ÷ 平均每问 token（query-equivalent）；`Q` = 查询量。
- `p_h` = 证据充分、可替换的查询比例。
- 示例：`c=10`、`Q=1,000` → 3.12%；`p_h=2.5%` 仍亏。
- **平均 −38% 不能当上线依据**；先量 miss penalty。

### 2.2 动作分配

- 没有单一 HSR 最小；按 **harm–approval–cost** 前沿选点。
- CASEL 模拟：8.7% approvals / 7.02% HSR；Risk-Menu 12.6% / 5.82%；Consequence 13.8% / 4.38%。
- **“审批少 30% 是否值得多 1.2 点 HSR”是业务问题**，不是论文结论。
- 主表在 `τ̂=∞`（阈值关闭）下；不能当开了阈值的成绩。

### 2.3 能力梯度

- **E-13 撤回（W-03）**：收益随能力下降的方向可作假设，具体斜率按 W-03 重测。
- 知识投影增益不随容量上升（E-12，H2 p=0.85 是「未检出」，不是「证明无效应」）。
- 9B 带投影 > 750B 不带，但区间约 0.3 宽。
- **没有一条适用于所有机制的能力曲线。**

其余机制只有成本项与定性边界，没有 break-even 公式；不要把 3 条可算门槛和 9 条定性边界合成一个总分。

## 3. TCO 模板

```text
TCO_12m =
  建设（建模/集成/评测）
+ 运行（token/算力/调用）
+ 人审（审批分钟 × 单价 + 抽检工时）
+ 维护（重抽/重标/版本对账）
+ 失败（误拦/误合并/漏检的返工/事故）
```

**收益**：

```text
收益 =
  prevented_harm × cost_per_incident
+ task_success_gain × value_per_success
+ 工时节省 × hourly_rate
+ 返工/审计发现减少
```

**决策线**：

```text
NPV_build = Σ(收益 − 成本)/(1+r)^t − TCO
NPV_buy   = 同口径（RFQ + 集成 + 迁移/退出）
NPV_do_nothing = 0
取 argmax；硬约束：task success 下降 ≤2pp；false-veto 报前沿，不设单点（见 [canonical](../sections/canonical.md)）
```

| 参数 | 值 | 来源 | 备注 |
|---|---|---|---|
| 人周价 | 待填 | 财务 | 没有就不出点估计 |

## 5. 各 R 的成本起点（全部 `推测`，不能相加当 TCO）

| R | 建设 | 运行/人审 | 维护 |
|---|---|---|---|
| R0 | 30–60 分钟 + 修数据 | — | 随本体变更 |
| R1 | 2–5 人日/域 | 回放 1–2 人日 | 0.5 人日/月 |
| R2 | 塔 2–4 人周 + 生成器 2–3 人日 | 1.1–1.5 万 token/轮 | 0.5–1 人日/月 |
| R3 | 约 20 人日 + 评测 5 人日 | err_rate 审计 0.5–4 人日 | 增量重抽/对账 |
| R4 **gap** | 卡片 1–2 人日/本体 + 集成 1–2 人周（工程估算） | 按 W-02 记 per-answer 调用/token | 新源前不设门槛 |
| R5 **gap** | 200 题标注 + 50 抽检（测量项） | per-flagged 成本按 W-01 记账 | 告警处置 0.5–1 人日/月 |
| R6 | Layer A 2–5 人日 + Layer B 1–2 人周 | 审批分钟；false-veto 标注 3–5 人日 | 工具/槽位变更 |
| R7 | registry 1–2 人周 + 本体 1–2 人周 | 人审 0.5–1 人日/200 条 | 0.5 人日/月 |
| R8 | 策略图/形状；未测 | 每批×每节点查询 | 策略版本/缓存 |
| R9 | policy 2–4 人日 + 状态机 2–3 人周 | false-defer 20–50 样本 | 持续审计 |
| R10 | shapes + CI；未测 | 校验随图规模 | 本体/shapes 变更 |
| R11 | 映射/本体维护；未测 | 查询重写+SQL | schema/映射变更 |

**这些是量级，不是报价。** 每一项都要用第一个 sprint 的实录工时校准。

## 6. build / buy / do nothing

| 选项 | 什么时候 | 代价 |
|---|---|---|
| build | 有稳定域、复用高、能维护 | 建设/维护/人审 |
| buy | 有成熟产品、能 RFQ、集成可控 | 报价+集成+迁移/退出 |
| do nothing | 复用低、风险低、基线够用 | 不省伤害/不省工时 |

**反事实必须是 do nothing**，不是「换个更好的机制」。CASEL 的 do-nothing 模拟是 HSR 32.76%、审批 0%、task success 29.48%；这是模拟基线，不是你的基线。

## 7. 立项 memo 最小结构

1. 问题与错误类型；2. 机制与接缝；3. 基线（可重跑）；4. `p_h`/false-veto/审批率；5. TCO 与敏感性；6. stop line；7. 缺口（单价/标签）。

## 8. 反模式

1. **用平均收益立项。** −38%/+54.6pp 都是条件值。
2. **只算 token。** 人审/维护常是大头。
3. **没有单价就拍板。** 只给公式/敏感性。
4. **把模拟当部署。** CASEL 的数字有明确条件；Grid 移出（W-05），其数值不再引用。
5. **把 build 当默认。** buy/do nothing 也是选项。
