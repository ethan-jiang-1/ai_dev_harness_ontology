## 1.2 四个词，先说清

| 词 | 人话 | 不是什么 |
|---|---|---|
| **本体（ontology）** | 领域概念、关系、约束的显式规范；能被人和机器共同引用 | 不是知识图谱（那是实例层），不是词表/分类法 |
| **语义层（semantic layer）** | 把表/字段翻译成业务指标、维度、同义词、口径的中间层；让 BI 和 agent 用同一套定义 | 不一定是 OWL/RDF；很多生产语义层就是 SQL/YAML |
| **知识图谱（KG）** | 按本体/ schema 抽出来的实体-关系实例；图数据库是存它的容器 | 不是本体本身；有图库不等于有本体 |
| **底座（platform）** | 承载本体/语义层的已有系统：数仓、dbt、图数据库、本体平台、数据库内嵌、Wiki/OKF | 不是“中台”口号；本文指可指名的产品/系统 |

> 本份把“重型本体塔”（Palantir 式）与“LLM 辅助薄语义层”（Snowflake/Sigma/dbt 式）放在同一谱系的两端；中间是行业平台（阿里 PolarDB/Context0、中泰 DataAgent）。三者不是谁替代谁，是不同底座上的不同厚度。

### 1.2b 内码与缩写（第一次见时查这里）

| 记号 | 意思 |
|---|---|
| **A / B / C** | A = 一手生产复盘（规模 + 成本或失败/限制 + 独立信号）；B = 具名采用、有独立信号但缺规模/失败；C = 厂商页/白皮书/赞助调查/二手转述。完整定义见 [02 §2.5](./02-map.md#25-什么叫生产落地四件套) |
| **A（弱）/ A（probation）** | A（弱）= 有规模 + 失败，但缺独立复核或成本（中泰）；A（probation）= 单公司自述、6 个月内补第二信号（Snowflake / Sigma） |
| **signal** | 未过门、但有规模或失败实质披露的线索；比厂商页强，仍不撑结论 |
| **E-28–E-32** | 上游结论编号（平台承载 / 失败主诉 / 证据不对称 / 成本拐点 / OKF 底座）；正文都给了要点，想看原文见 [conclusions](../../../topics/conclusions.md) |
| **G1（时效门）** | 素材首次公开 ≥ 2026-06-01；“G1 失败/超窗”指不满足这条，只作背景 |
| **I1–I5** | 准入的五个独立信号：制度背书 / 多主体 / 独立采用 / 社区讨论 / 公开资产 |
| **OWL、RDF、SHACL、SPARQL** | 本体语言、图数据模型、约束校验、图查询四种 W3C 技术；Netflix 用的是这一套 |
| **TCO / POC** | 全生命周期总拥有成本 / 概念验证 |
| **指标五要素** | 名称、口径、单位、来源、owner（中泰的指标定义格式） |
| **HN** | Hacker News；本份只把它的讨论条数当弱信号，不把点赞数当证据 |
| **CCSA / WG15** | 中国通信标准化协会 / 其“本体与知识管理工作组” |

## 1.3 证据怎么读：三步

1. **先看等级**：A（一手生产复盘）/ B（具名采用）/ C（厂商材料）；另有 **signal** = 有规模或失败披露、但未过门的线索（见 [02 §2.5](./02-map.md#25-什么叫生产落地四件套)）。C 类再权威也不撑结论。
2. **再看日期**：本份只把 2026-06-01 后的材料当现役；更早的（腾讯 Topbase 2025-12、Palantir 2020 案例）只作背景。
3. **再看独立信号**：同一机构自说自话不算；要有客户侧、标准组织、社区、独立报道中的至少一个。

**一个快速判断**：如果一条材料删掉作者自己的宣传，还剩什么？
- 只剩“我们很强” → C，别用。
- 剩“某具名组织在用/某会议在讲/某标准在立项” → B，能说明“有人在投”。
- 剩“规模数 + 失败/限制 + 独立印证” → A，能说明“这种形态在这个规模下跑过”。
