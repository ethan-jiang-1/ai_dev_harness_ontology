# 8. 边界：这份东西不能证明什么，什么会改变它

> 本页回答：05 的证据到哪为止；哪些结论是“公开证据的选择”，哪些是“推测”；反例在哪；什么新证据会推翻它。

## 8.1 不能回答的四个问题

| 问题 | 为什么不能 | 需要什么才能答 |
|---|---|---|
| **哪家平台最好？** | 没有同场景/同数据集对照；Palantir、Snowflake、阿里不是同一形态 | 同域、同任务、同预算的并排试点 |
| **ROI 多少、几年回本？** | 没有全生命周期账本；只有价目/合同额/运行费锚点与工作量代理 | 人月 + 年维护 + 回收期的生产账本 |
| **成功率多少？** | 只有 Atlan 的“<15%”二手综述，原始统计未核 | 可核样本框、分母、年份、失败定义 |
| **跨行业能不能复制？** | 中泰是券商、Snowflake/Sigma 是数据平台公司；域差异大 | 金融/制造/医疗/政府的多案例对照 |

> 答不了就标 gap，不偷换成“那我说说怎么建”。怎么建在 [04](../../04-worked-example/README.md)/[02](../../02-engineering-playbook/README.md)。

## 8.2 证据缺口（按重要性）

| # | 缺口 | 现状 | 关闭它需要什么 |
|---|---|---|---|
| G1 | **没有“规模+成本+失败+独立印证”四项齐全的 A 类案例** | 5 条 admitted/probation 各缺一项：中泰缺成本/失败率；Snowflake/Sigma 缺外部采用/成本；Netflix 缺成本/收益/独立复核 | 一条带账本/预算/失败复盘的企业案例，且有独立印证 |
| G2 | **中国大厂缺 2026-06 后外部采用/成本/失败** | 阿里有产品文档（C）；蚂蚁 TuGraph 2026-05 后无 push；腾讯 Topbase 2025-12 | 客户侧工程博客/会议 talk/采购公告，至少带规模或失败 |
| G3 | **无全生命周期 TCO/ROI** | 有价目、项目合同额（¥49.4–178.8 万）、组件月费、POC 运行费；没有「人月 + 年维护 + 回收期」账本 | 一份 12 个月以上的生产账本，或续费/采购合同 + 团队规模 |
| G4 | **无失败率/成功率** | 只有失败形态（影子实体/口径漂移/权限旁路），没有分母 | 项目样本框 + 失败定义 + 统计 |
| G5 | **无同数据集对照** | 没有“本体 vs 无本体”“厚 vs 薄”的生产级 A/B | 预注册对照或 shadow 实验（仓库外） |

## 8.3 反例与冲突（不要调和）

| 冲突 | 一边 | 另一边 | 本份怎么处理 |
|---|---|---|---|
| “本体很有用” vs “KG 项目大多失败” | 厂商案例/中泰/ Snowflake 的生产写作 | Atlan 引用的“<15% 过 pilot”**不可核**：追到 Improvado 2025-09-29，原文只有一句没有 survey 名/样本/日期的 “industry surveys suggest”；且 Improvado 页面 G1 不过 | 不把 <15% 当分母，也不当结论。更可核的替代线索是 VentureBeat VB Pulse（2026-10/11，n=107/100，自选样本：39% 生产用语义层；采用者 78% vs 未采用 37% 报告上下文失败，原文自认不能定因果）——C 类调查，只作“失败常见”的弱信号，仍不给成功率 |
| “LLM 让本体便宜了” vs “维护更贵了” | 阿里 Context0 自动发现/中泰 LLM 解释 | 中泰 7,000+ 同义词/6,503 指标文档；Snowflake/Sigma 的版本/CI/job | 拆成“启动成本”与“维护成本”两段；前者降，后者没降（E-31，`推测`） |
| “美国领先” vs “中国有大厂平台” | Snowflake/Sigma 的公开规模/失败 | 阿里 2026-09/10 产品文档、中泰案例、CCSA 标准 | 改成“公开证据不对称”，不是能力排序（E-30） |
| “上了语义层 = agent 会用” | VB Pulse：39% 生产中使用 governed semantic layer | 其中仅 28% 说它是 agent 的主要上下文源（全体仅 13%） | 采用率≠使用率；不要把 adoption 当 effect；这是自选样本调查，不能推因果 |
| “有图库就是有本体” | 厂商把图数据库/GraphRAG 叫本体平台 | 图库只存实例；本体要 schema/约束/版本/权限 | 本份把“图库”与“本体平台”分列；选型先问执行语义（E-20） |
| “22 亿三元组 vs 100 个类型，谁更强” | 腾讯 Topbase 的图谱规模 | 阿里 Context0 的产品规格（类型≤100） | 量纲不同，不能拼成趋势；一个说实例规模，一个说 schema 上限 |
| “客户 logo 就是落地” | Palantir 2026 公告/厂商案例页 | 公告无规模/成本/失败 | 只作 C/B 线索；案例台账单列“不能证明” |

## 8.4 什么会改变结论

| 新证据 | 会改变哪条 | 怎么改变 |
|---|---|---|
| 中国大厂（阿里/蚂蚁/腾讯）带规模+成本+失败的一手复盘 | E-30（证据不对称） | 中国侧从“平台存在”升级为“生产证据”；不对称减弱 |
| 一条从零自建本体塔的公开成功案例 | E-28（平台承载） | “没有公开成功案例”被推翻；需要重写形态判断 |
| 同数据集/同任务的“本体 vs 无本体”对照 | E-31、05 的成本/收益 | 从“无 ROI”变成“有条件 ROI”；结论可量化 |
| 失败率/成功率的可核统计 | E-29、08 的成功率问题 | 从“失败形态”升级为“失败概率”；但要能核分母 |
| Palantir 客户侧工程复盘（规模+成本+失败） | E-28/E-30 | 重型平台从“客户名单”升级为“生产证据” |
| 阿里 PolarDB/Context0 的具名客户+规模 | E-30、04 中国 | 从“产品文档”升级为“采用证据” |

> **可证伪性**：如果上述任一证据出现，05 的对应判断应改；不改就是叙事，不是研究。

## 8.5 三个“不要”

1. **不要把 C 类厂商材料拼成“行业现状”**：客户 logo + 产品页 + 白皮书，不等于生产证据。
2. **不要把“没公开”读成“没做”**：中国大厂的材料受公开意愿/语言/渠道影响；本份只说“公开证据缺”，不说“产业没做”。
3. **不要把“单公司自述”读成“跨组织规律”**：Snowflake/Sigma/中泰都是单公司；它们的规模/失败可以借鉴，不能直接外推。

## 8.6 一句话

**05 能给你一张“谁在跑、什么形态、坑在哪、证据到哪”的地图；不能给你“哪家最好、ROI 多少”的答案。** 后者需要你自己的 90 天试点（[07](./07-decision.md)）。
