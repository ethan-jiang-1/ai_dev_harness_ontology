# 04 · worked-example — SCOPE（定位契约）

> **改/建本交付物前必读。** 本页是 04 定位的唯一权威；五份的总索引与共用规矩见 [meta/deliverable-scope](../../meta/deliverables/scope.md)。
> **本份曾名 ontology-in-production，名实不符已改**：它是合成示例，不是生产现状。"业界落地现状"之问归 [05](../05-production-landscape/SCOPE.md)。

## 初心（为什么有这份）
给要建小型本体查询应用的团队，一条可走查的最小建用治链，看清要哪些产物 / 字段 / 门槛。

## 定性
**示例**（规定性 · **合成**）。fixture 是编的对照例子，**不是生产现实**。

## 回答的问题（一句话）
如果要建一个小型本体查询应用，一条最小建用治链长什么样？

## 读者拿到什么
合成 fixture 的契约 → TBox → shapes → CQ → policy → audit 走查 + 三关记录。

## in-scope（该干的）
合成示例的建 / 用 / 治链、产物模板、三关记录、fixture 边界。

## out-of-scope（不该干的，去哪）
- **业界真实落地现状 / 生产证据 → 05**；值不值得 → 01；接缝选择 → 02；机制 → 03。

## 红线（绝不能）
- **不声称代表生产现实 / 业界现状**；fixture 数字是期望值、非实测。
- 不证明效果 / 跨域 / 生产。
- 不拿合成例子冒充"落地现状"（这正是本份曾经跑偏的地方）。

## 发挥空间（scope 内你可以）
把合成链的产物 / 字段 / 门槛 / 失败模式讲清楚，供读者对照。**不能把示例写成生产证据、不能越界报现状。**

## 答不了怎么办
本份只负责"示例走查"；凡涉及"真实落地如何"一律转 05，**不在本份编现状**。
