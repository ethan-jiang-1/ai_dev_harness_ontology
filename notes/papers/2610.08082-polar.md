# POLAR

## 做了什么

面向小型工具调用 agent 的护栏：用**两层本体**给每个动作打**分级可逆性分数**。

打分方式不是给动作贴标签，而是**推导一个候选的逆操作序列**——能推出逆操作，说明可逆。分数低于阈值的调用在执行前被剪掉，并给出可审计的结构化判定。

## 结果

τ²-bench，六个 agent 模型：

- airline 域上，六个模型中有四个的平均任务奖励提升 0.11–0.18。
- **但 18 个模型-域组合里只有 8 个整体改善。**
- retail 域与更强的模型经常**回退**。

## 没测什么

**作者自述**：
- 「奖励不是防止伤害的直接度量」——被剪掉的风险动作不会体现在 reward 里。
- 定位是小型 agent。

**读者补充**：未报告「本会发生的不可逆错误被阻止了多少」这一真正的目标指标。

## 对本仓库的意义

| 关联 | 关系 |
|---|---|
| P3（判定是权衡） | **直接支持**：剪枝有真实的任务效用代价，且与模型强弱相关 |
| P1 | **削弱弱版本**：不能声称「护栏总是更好」 |
| E-04 | 本卡是其一手依据，且**修正了综述的转述** |
| [tool-gate](../../topics/01-constraint/tool-gate.md) | 核心文献 |

**两处必须记住**：
1. 能力越强的模型，越容易被护栏拖累——因为它本可以自己避免那些错误。护栏的收益与模型能力反向。
2. 目标指标（防住多少伤害）与代理指标（任务奖励）不是一回事。用后者评估前者会得出错误结论。
