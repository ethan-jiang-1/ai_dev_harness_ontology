# Solver-Like Behavior

## 做了什么

研究「形式化器」——先写长推理轨迹、再写程序交给求解器的模型。提出并刻画 **solver-like behavior (SLB)**：在写程序之前，轨迹里已经在赋值、试算、排除变量的取值，常常一路算到最终答案。

于是程序不再是在搜索，只是在**复述一个已经算出来的答案**。

## 结果

两种伤害：

1. **昂贵。** 约束满足是 NP 完全的；在 token 里求解，成本随实例规模增长——在 Meeting Planning 上，solver-like token 从最小实例到更大实例**接近三倍**。
2. **使形式化失效。** 求解器本应提供 LLM 自身推理所缺的保证；若程序只复述轨迹答案，这层保证就不存在了。

综述转述的补充数字（`待核`）：SLB 出现在 85% 的轨迹、占 24% 推理 token；9% 的程序继承了轨迹中的错误答案；隐藏输入数值可消除 97% 的 SLB。

## 没测什么

**作者自述**：未在摘要列出。
**读者补充**：只按「程序输出是否正确」评估会完全看不见 SLB——这正是作者指出的评测缺口。
