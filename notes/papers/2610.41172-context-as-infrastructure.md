# Context as Infrastructure

## 做了什么

把「检索」重述为**知识编译**：在检索之前，用 LLM 把源文档加工成不含于任何单一片段的结构化工件——导航层级（叶子是「原子主张 + 逐字证据」对）、实体图、时间线、心智图、本体、wiki、记忆。

然后**测量这些工件是否值得**。这是本仓库最看重的一点：作者在提出方案的同时给出了它的反证。

## 结果

**基线本身就很强**：一个只用 BM25 与 grep 的 harness（MiniMax M3 作答）在 BrowseComp-Plus 上达 85%，多跳 FRAMES 上达 91%（作者自己声明两个基准的数字不可比）。

**结构化工件没有准确率增益**：
- 在 FRAMES 上，结构化工件**无可检出的准确率增益**。
- PageIndex 式大纲在 FRAMES 规模上**反而退化**。

**有增益的是「主张-证据叶子的导航树」**：
- 证据充分时，总查询 token 减少 91%；不充分时增加 1.9%；平均减少 38%。
- 由此推出 2% 的盈亏平衡充分率，实测约 43%。
- 一个决策门把时延从 140s 降到 30s（但替代带来的 token 节省是用检索轮次换的，自带时延代价）。

**作者对本体/图谱价值的最终定位**：
> 本体、图、wiki、时间线、心智图、记忆这些工件，**在部署层面**（治理、跨源集成、上手、时序定向、连续性）产生回报，而**准确率基准看不见这些回报**。

## 没测什么

**作者自述**：无增益结论限定在 FRAMES；两个基准分数不可比。
**读者补充**：未量化「部署层面回报」——这是全文最关键的断言，却只有定性描述。

## 对本仓库的意义

| 关联 | 关系 |
|---|---|
| P1（价值在约束） | **最强支持**：作者自己把价值从准确率迁到治理与集成 |
| P2 | 支持：收益依赖 harness 的成熟度（强 harness 下工件无用） |
| E-01 | 本卡是其一手依据，**且需补上「范围」与「作者的价值定位」** |
| [context](../../topics/harness/context.md) | 核心文献 |

**两条推论**：
1. 编译解决的是**上下文预算**与**部署语义**，不是检索准确率。用准确率评估它，等于用错的尺子。
2. 「强 harness 下工件无用」这个结论**不能反向推出**「工件无用」——它依赖 harness 强到能自己跑完检索。这正好是 P2 的证据：同一个工件在不同 harness 下价值不同。
