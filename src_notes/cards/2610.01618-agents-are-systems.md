# Agents Are Systems, Not Models

## 做了什么

把 agent 当作**可配置系统**来评测，而不是固定模型。作者在四个科学任务上让 coding agent 找到并正确操作一个已发表的 specialist model，系统改变五个配置：

1. 任务信息（task information）
2. 推理（reasoning）
3. 自我验证（self-verification）
4. 时间预算（time budget）
5. 骨干模型（backbone model）

另发布 benchmark 与 18,000+ 条 agent trajectories。

## 结果

- **约 54% 的结果方差来自「重复同一配置」**，而不是改变配置。
- 跨配置比较：**给 agent 的信息**影响最大，超过时间预算与模型规模；信息还降低 cost、改善 calibration。
- 配置间有交互：时间只有在信息足够或模型足够强时才有用。
- 轨迹分类：**提示 agent「去验证」几乎不改变验证行为；给一个专用验证工具才会实质改变**。

## 没测什么

**作者自述**（摘要层面）：四个科学任务、一个 coding agent benchmark；不是通用 agent 评测。

**读者补充**：这里的「信息」是任务信息，不是本体；不能直接外推到「本体投影」。但它是目前最直接支持「harness/配置比模型大小更重要」的量化证据之一。

## 对本仓库的意义

| 关联 | 关系 |
|---|---|
| P2（harness 是不可分离的一半） | **强支持**：配置/信息的效果超过模型规模 |
| C-03（尺子错配） | **强支持**：把 agent 当固定模型评，会把配置方差误记成模型能力 |
| P1（结构优于措辞） | 支持：「给验证工具」>「提示去验证」 |
| [06 测量](../../topics/06-measure/README.md) | 核心文献：评测对象应是 system，不是 model |

**两条可直接用的判断**：

1. 做「本体有没有用」的实验时，必须把 harness 配置（信息、工具、时间、模型）当作变量，否则 54% 的重复运行方差会把效应吞掉。
2. 「提示它要验证」不是验证；「给它一个验证工具」才是。这与本仓库「约束优于措辞」同向。
