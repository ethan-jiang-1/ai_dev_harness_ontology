# ai_dev_harness_ontology

**研究 harness。本体是研究它的切口，不是目的。**

这个仓库不是一次性成文的文档，而是一条**持续运转的消化流水线**：不断吸纳新文章，消化成结构化认知，成熟后抽取为可对外的交付物（手册、Deck、图）。

---

## 1. 研究什么

模型能力外溢之后，同一模型在同一任务上仍然拉开差距——差距不在模型，在模型外围那一圈工程：上下文怎么给、状态怎么存、动作怎么放行、结果怎么验、过程怎么看得见。这一圈就是 **harness**。

本体在这个语境里反复被提起，但多停在「把业务语义注入提示词」。本仓库追问更靠工程的一层：

> **本体在 harness 的控制回路里，究竟以什么形式被执行？**

本体若只是上下文里的知识，随时可被忽略、压缩掉或幻觉覆盖；只有当它成为判定器、闸门、证据要求或状态结构，才开始真正约束行为。

三条工作假设（细节与反驳条件见 [THESIS](./THESIS.md)）：

| # | 假设 | 若成立意味着 |
|---|---|---|
| P1 | 本体的价值在**约束与控制**，不在语义注入的准确率 | 「上本体提准确率」类论证应被降权 |
| P2 | harness 是本体得以「被执行」的那一半 | 本体工程不能脱离 harness 单独立项 |
| P3 | 判定质量是**权衡**——漏检与误报此消彼长 | 不存在「好本体」这种单一量 |

## 2. 根目录 = 流水线的四个工位

一级目录不套 `docs/`：**目录名即地图**。根下有七个目录，前四个是流水线，后三个是支撑。

```
   材料入库            精读单元            主题沉淀            对外抽取
 ┌──────────┐      ┌──────────┐      ┌──────────┐      ┌──────────────┐
 │ source/  │ ───▶ │  notes/  │ ───▶ │ topics/  │ ───▶ │ deliverables/│
 │   吸纳   │      │   精读   │      │   沉淀   │      │     交付     │
 └──────────┘      └──────────┘      └──────────┘      └──────────────┘
   只读存档          一篇一卡         结论可被引用       只抽取不新增
```

| 工位 | 职责 | 增长方式 | 完成信号 |
|---|---|---|---|
| [`source/`](./source/) | 一手材料原样存档 | 随时往里加，不改写原文 | 材料落盘 + 在台账登记 |
| [`notes/`](./notes/) | 一篇材料一张卡：它说了什么、可信度多少 | 卡片可互不关联地累积 | 卡片标了证据等级与 `待核` 项 |
| [`topics/`](./topics/) | 按主题成文，跨材料综合 | 新卡触发相关主题的修订 | 结论带等级，冲突显式保留 |
| [`deliverables/`](./deliverables/) | 手册、Deck、图等对外物 | 定期从 topics 抽取重排 | 每条可反查回 topics |

支撑目录：

| 目录 | 职责 |
|---|---|
| [`experiments/`](./experiments/) | 实验设计。实现产物在仓库外，靠编号回链 |
| [`adr/`](./adr/) | 结构性决策：为什么这样组织 |
| [`meta/`](./meta/) | 写作约定与模板 |

四个根文件各司其职：[README](./README.md) 门厅、[THESIS](./THESIS.md) 纲领、[GLOSSARY](./GLOSSARY.md) 术语、[AGENTS](./AGENTS.md) 落点规则。

### 流水线的三条规矩

1. **单向、可越级但不可反向。** `deliverables` 只能从 `topics` 抽取，不能直接引 `source`——否则未经消化的材料会以成品面貌流出。反向修订（发现材料有误）走回溯：改 `notes` → 改 `topics` → 重抽交付物。
2. **上游可以领先下游。** `source` 堆积未读、`notes` 堆积未成主题，都是健康状态；要求每一层同步才是负债。
3. **每级都自带台账。** `source` 记什么已入库，`notes` 记哪张卡喂了哪个主题，`topics` 记结论等级，`deliverables` 记依据哪几条结论。台账让流水线可盘点。

## 3. 为什么 topics 只有三层

`topics/` 下是 `harness/`、`ontology/`、`seams/`、`cases/`。三层论点而非更多，因为研究对象只有两半——本体与 harness——而价值产生在二者的交集：

```
              ┌─────────────────────────────┐
              │  seams ★  接缝（核心）       │  本体在此被 harness 执行
              └─────────────────────────────┘
                    ▲                 ▲
        ┌───────────┘                 └───────────┐
   ┌──────────────┐                    ┌──────────────┐
   │  harness ★   │                    │  ontology    │
   │  控制层      │                    │  语义层      │
   └──────────────┘                    └──────────────┘
```

上层不依赖下层，上层是下层的**交集**。`cases/` 是领域侧：同一个机制在工业、电网、金融、医学里受不同约束。

## 4. 源文献的四个方向怎么归位

起点材料是一份 2026-11 的本体×智能体综述（[原文](source/weixin-laoliu/otology.md)），把 20 篇工作分为四类。四类**没有**变成四个平行目录——方向是文献的组织方式，工位与层才是研究的组织方式：

| 原文方向 | 归位 | 理由 |
|---|---|---|
| 本体当判定器 / 约束层 | [`topics/seams/`](./topics/seams/) | 表面是本体，实质是「放在回路哪一格」 |
| 本体构建与生成 | [`topics/ontology/lifecycle.md`](./topics/ontology/lifecycle.md) | 语义层的生产流程 |
| 机制、评测与反例 | [`topics/conclusions.md`](./topics/conclusions.md) | 证据形态，不是知识形态 |
| 本体当记忆 / 自演化骨架 | [`topics/seams/memory-as-state.md`](./topics/seams/memory-as-state.md) | 记忆是 harness 机制，本体在此当状态结构 |

归位判据：**这份材料在回答「语义是什么」，还是「语义在哪一步生效」？** 前者进 `topics/ontology/`，后者进 `topics/seams/`。

## 5. 四种读法

- **要结论** → [topics/conclusions](./topics/conclusions.md)：三栏，含反例与冲突。
- **要机制** → [topics/harness](./topics/harness/README.md)：七环节 + 约束强度谱。
- **要台账** → [notes](./notes/README.md)：哪篇读了、哪篇没读、喂了哪个主题。
- **要交付** → [deliverables](./deliverables/README.md)：手册大纲与抽取规则。

## 6. 现状

骨架与机制地图成型，四个工位都有可用样板：

- `source/` — 20 篇论文原文 PDF（全部下载成功并核对标题）+ 1 篇综述
- `notes/` — 综述卡 1 张 + 论文卡 8 张（摘要级）
- `topics/` — 8 条已核结论，6 个接缝位置成文
- `deliverables/` — 手册大纲 7 章

**最大空缺是没有一条结论被独立复现。** 三个实验待做，见 [experiments](./experiments/README.md)。
