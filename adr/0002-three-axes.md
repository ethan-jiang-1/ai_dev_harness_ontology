# 以派为主轴，时刻与部件作为横切索引

> **2026-11-09 增补**：第四根横切轴「执行形态」见 [ADR 0006](./0006-execution-form-axis.md)。本 ADR 的派/时刻/部件三轴仍成立。

## 背景

仓库的核心问题不是「本体有没有用」，而是「本体在 harness 的哪个时刻被执行」。但 `topics/` 的目录是按「本体凭什么起作用」分的六派。两者不是同一个维度：

- **派**：机制类型（约束 / 判定 / 知识 / 状态 / 生产 / 测量）。
- **部件**：harness 的组成（context / memory / orchestration / tools / verification / observability / governance）。
- **时刻**：介入时间（动作前 / 输出时 / 输出后 / 落盘前 / 跨轮 / 跨运行）。

三套都用了「六」左右的数字，容易被误认为一一对应。11:38 的重排把旧 `topics/seams/` 页删掉后，时刻轴失去了自己的主页，只剩散落在 01/02/04 正文里的「时刻 N」标题。

## 决策

1. **派轴作为 `topics/` 的主目录**（`01-06`）。理由：交付物是手册，手册按机制组织；派也是稳定、可写的综合单元。
2. **部件轴保留在 `00-harness/`**，并在其 README 增加「对应时刻」列。
3. **时刻轴不建目录，建一页横切索引** [`topics/seams.md`](../topics/seams.md)。理由：时刻是序列，不是容器；同一时刻的文档已经按派存放，复制成目录会产生两套权威。
4. **六派明确为 4+1+1**：`01-04` 是回路内的四个介入点，`05` 是回路前（来源），`06` 是回路外（尺子）。
5. **验证回路不在仓内**；`experiments/` 已于 2026-11-09 删除，若未来需要验证，放在仓库外并只留指针。

## 后果

- 新增 `topics/seams.md` 与每派 `frontier.md`；不移动现有文档。
- 三张强度谱（派 / 部件 / 时刻）各自命名，不再互称「完整图」。
- 归派一句话改为「01-04 问时刻，05 问来源，06 问尺子」。
- 未来若改派名，先改 `topics/README` 的 mapping，不急着搬目录；编号 `01-06` 是稳定标识。
- 新论文的入档路径：先判 4+1+1，再判派；时刻只用于 01-04。

## 考虑过的选项

- **时刻主轴**：更贴 thesis，但 05/06 无处放，且派综合被打散；需要大迁移。
- **双目录矩阵**：双轴浏览，但两套权威、重复维护；3.7k 行规模不划算。
- **单页 crosswalk**（采用）：最小改动，保留派综合，给时刻轴一个可读入口。
