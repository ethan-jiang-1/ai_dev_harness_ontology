# ADR 0005：仓库自检工具作为文档纪律的可执行部分

- 日期：2026-11-09
- 状态：接受

## 背景

[ADR 0001](./0001-research-repo-over-code.md) 决定以文档为主要交付物，不引入代码目录；验证性实现放仓库外，靠 `EXP-xxx` 回链。这条边界保护了问题导向的目录结构，但也留下一个缺口：**文档纪律只能靠人肉 checklist**。链接、frontmatter 枚举、E/L 编号、论文清单与计数，全部是手工同步；2026-11-09 的评审发现 20/22 篇、manifest 双账、E-05 错挂、开源接缝标签漂移等问题，都能通过一个只读检查提前发现。

## 决策

1. **允许 `meta/tools/` 存放只读自检工具**，仅用于检查本仓库的文档一致性，不承载研究逻辑、不引入运行时依赖、不生成研究结论。
2. 首个工具是 [`check_repo.py`](../meta/tools/check_repo.py)：检查相对链接、frontmatter 枚举、E/Q/C/L 编号定义、论文/开源清单、manifest 覆盖、结论等级计数。退出码非零即失败。
3. **边界**：`meta/tools/` 不是代码仓的起点。任何需要模型调用、数据管线、实验运行的实现，仍按 ADR 0001 放仓库外；本仓库不设 `experiments/`，需要时只留 `EXP-xxx` 指针。
4. **执行时机**：每次结构性提交前跑一遍；结果写入 [`meta/state.md`](../meta/state.md) 的“最后自检”一行。暂不接 CI，避免把仓库变成工程仓。

## 考虑过的选项

- **纯人肉 checklist**（现状）：零代码，但已经证明会漂移；同一类错误反复出现。
- **接 CI / pre-commit hook**：最硬，但会把仓库的维护重心从研究拉到工程；当前规模不需要。
- **自检工具放仓库外**：符合 ADR 0001 的字面，但工具会丢失、版本与文档不同步；自检本身需要可复现。
- **`meta/tools/` 只读工具**（采用）：最小代码面，保留“文档为主”的边界，同时把可机械检查的纪律变成门。

## 后果

- 仓库多一个 `meta/tools/` 目录；README 的“支撑目录”需要登记它。
- 自检通过不等于研究成立：它只检查形式，不检查证据质量；语义审计仍需人/agent。
- 若未来工具增多，仍限制在 `meta/tools/` 一层，不建 `src/` 代码目录。
