# ADR 0007：不设外部资产前置

- 日期：2026-11-09
- 状态：接受

## 背景

2026-11-08 的“试点就绪”线把 3 个实验包（EXP-004/005/006）挂在一个 D0 资产门上：具名域、≥500 条带 `state_hash` 日志、200 题 + gold、3 人、单价/人时、2 名盲评 + 仲裁 + 财务签核。该线的前提是“内部企业试点”，但本仓库是个人研究档案：没有客户域、没有组织角色、没有采购单价，也不做对外客户交付。结果是 D0 把仓库堵在一个用户无法提供、也不需要提供的口子上。

更严重的是，同一份计划自己写着“不跑真实试点、不接客户数据”，D0 却要求客户数据与签核——这是把交付/采购 gate 误套到研究流程上的范畴错误。

## 决策

1. **研究档案不以外部客户资产为前置。** 结论上限仍是“已核”（见 [ADR 0001](./0001-research-repo-over-code.md)）；独立复现是加分项，不是阻塞项。
2. **任何要求用户提供资产/人/价/签核的 gate，必须由用户明确同意后才能存在**；agent 生成的计划不能自行创造人类前置条件。
3. **实验默认必须能用公开数据、合成域或仓库内材料启动**；需要外部资产的实验只能标为可选，不得出现在门厅或“当前阻塞”。
4. **D0/试点线已于 2026-11-09 删除**；`meta/implementation/`、`deliverables/pilot-playbook.md`、`experiments/EXP-004/005/006`、`_pilot-template.md` 不再存在。git 历史保留，供以后真要做企业试点时参考。
5. 若未来用户明确要做真实企业试点，另立计划并先取得用户对域/数据/人/价的书面同意；不复用本仓库的“当前状态”。

## 后果

- `meta/state` 不再有外部资产阻塞；实验清单只保留 EXP-001/002/003/007。
- 主动线是开源代码证据与 digest 消化；不设合成实验前置。
- “对外交付 no-go”只是审计结论，不是研究阻塞；不再驱动日常计划。

## 考虑过的选项

- **保留 D0 为 dormant 可选路径**：仍会在门厅制造“下一步取决于用户”的错觉；否决。
- **只删 D0、保留 implementation 目录**：目录里仍是客户试点语料，会再次被当成现行计划；否决。
- **删除整条线 + 记录 ADR**（采用）：去掉结构，保留纠错规则。
