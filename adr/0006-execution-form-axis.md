# ADR 0006：增加执行形态轴

- 日期：2026-11-09
- 状态：接受

## 背景

[ADR 0002](./0002-three-axes.md) 把 `topics/` 定为派主轴 + 时刻/部件两根横切索引。这套轴回答的是「本体凭什么起作用」与「在哪个时刻介入」，但中心问题还有后半句：**「以什么形式被执行」**。同一份本体可以只被塞进 prompt，也可以被编译成 SHACL 再求值；不区分形态，就会把「本体没被测量」和「本体被执行后无效」混成一句话。

2026-11-09 的评审用一个换词实验量化了这个缺口：26 个来源里 15 个的结论把「本体」换成「任意结构化上下文」仍成立；只有 3 个依赖 OWL/DL 语义。形态没有被单独记录，就无法解释这个配比。

## 决策

1. **增加第四根横切轴：执行形态**，不建目录，建一页 [`topics/execution-forms.md`](../topics/execution-forms.md)。
2. 形态取五档：`engine`（引擎求值）、`compiled`（编译成约束）、`context`（上下文注入）、`label`（只当标签）、`none`（未执行）。证据不足用 `unknown`。
3. 每个源卡新增 `execution_form` 字段；它与 `seam`（位置）正交，不合并。
4. 每个源卡新增 `evidence_role`：`execution-test` / `mechanism-only` / `harness-evidence` / `boundary-ruler`，用于区分「真的测了执行」与「只提机制/评测/边界」。
5. 形态轴不改变六派归属；派仍按主效应，形态只作横切索引。

## 后果

- 26 个来源全部落字段；当前配比 engine 4 / compiled 7 / context 2 / label 1 / none 12。
- E 层的影响列改用 P1a/P1b/P1c/P2/P3a/P3b，并标明「支撑/不支撑」；E-04 不再被当成「结构有效」或「来源偏向」的证据。
- 形态轴给了一个可证伪的问题（同一接缝、只换形态），但**不因此默认立项做实验**；需要时另立。
- 形态轴的初判来自 digest §3/§4/§8；改档要同时改卡、轴页与 digest 判定段，否则会漂移。

## 考虑过的选项

- **把形态并入 `seam`**：位置与形态是两个问题；合并会让「读路径授权」和「查询编译」都挤进一个值。
- **按形态建目录**：会与派轴打架，且同一形态跨多个派。
- **只给开源卡加形态**：论文侧仍然无法比较；不解决中心问题。
- **横切页 + 字段**（采用）：最小结构改动，保留派综合，给形态一个可计数入口。
